# Набор конкурентности логистики

Гонки и негативы изоляции логистики сквозь весь `cmd/api` (W2.30; AC-03…AC-06, `tdd-protocol.md` §2 шаг 6). Модульные гонки (`fleet/reservations`, `fleet/trips`, `fleet/review`, `fleet/inspections`) вызывают сервис напрямую. Здесь та же гонка идёт через HTTP: BFF и сессия dev-входа, шлюз операции (CSRF, право, модуль), Idempotency-Key, If-Match, пулы tenant DB по 4 соединения.

```text
backend/test/concurrency/
├─ doc.go             пакет без тега: go test ./... его не собирает
├─ main_test.go       TestMain: PostgreSQL (testcontainers) → фикстуры W1.04 без содержимого → cmd/api
├─ api_test.go        цель: сборка и запуск cmd/api на часах набора, сессии акторов, req/reply, race, tally
├─ shift_test.go      смена через API: машина → план → бронь → осмотр → старт → расход → завершение → сдача → приёмка
├─ reserve_test.go    AC-03: 100 параллельных броней, водитель и владелец, один ключ дважды
├─ start_test.go      S2-06: два старта одной брони, один ключ трижды, старт против снятия брони
├─ review_test.go     S2-10…S2-12: две приёмки, приёмка против доработки, проверка расхода, запись начисления
├─ defect_test.go     AC-04, S2-17: отказы выезда, два разрешения, два дефекта, разрешение против неисправности
├─ pool_test.go       AC-06: два одобрения пула, пересекающиеся одобрения (пропуск, пока W2.07 отвечает 501)
└─ isolation_test.go  строки изоляции логистики на настоящих объектах (AC-01, AC-02, AC-05)
```

## Команды

| Команда                                                                                | Что делает                                     |
| -------------------------------------------------------------------------------------- | ---------------------------------------------- |
| `go -C backend test -tags concurrency -count=1 ./test/concurrency/...`                 | весь набор (шаг CI `isolation/go-concurrency`) |
| `go -C backend test -tags concurrency -count=1 -run TestIsolation ./test/concurrency/` | только строки изоляции                         |
| `$env:CONCURRENCY_API_LOGS='1'`                                                        | вывести журнал `cmd/api` после прогона         |

Нужен Docker: без него набор падает, а не пропускается. На Windows конвейер задаёт `DOCKER_HOST=npipe:////./pipe/docker_engine` и `RYUK_RECONNECTION_TIMEOUT=5m` (W1.46); при ручном прогоне их задают так же.

## Правила набора

- Часы набора: `cmd/api` получает `APP_FIXED_NOW` = `harness.Now()` (01.10.2026 10:30 MSK), как набор изоляции. Периоды назначений фикстур считаются от этого «сейчас». Окна рейсов и броней берут каждое свой день после него (`newWindow`).
- Водитель смен — `a.driver-msk2`: его роль «Водитель» на Москва-1 (временное назначение) открывает машины фирмы. Так на стенде работает группа «Водители Север». У `a.driver-msk1` роль только на «своё». У `fleet.vehicles.read` нет столбца «своё», поэтому этот водитель не видит машин. В негативах он одно из мест; для гонки двух водителей (`TestAC03TwoDriversOneVehicle`) он на время теста получает роль на Москва-1 (`unitRole`). Временного водителя нет в `members.read` логиста (Q-W2.03-3), поэтому рейсы планирует владелец.
- Объекты другого водителя Москвы-1 (`crew theirs`) делает владелец для человека без аккаунта с функцией «Водитель» (`seedDriver`): владелец ведёт любой рейс. На них смотрит место `a.driver-msk2@a~theirs` — водитель смен с ролью на подразделении. Машины Москвы-1 ему видны по модели (W2.02, Q-W2.30-1), брони, рейсы, осмотры, дефекты, расходы и начисления другого водителя — нет (AUTH-05).
- У водителя в пути один рейс (`trips_active_driver_uq`). Тесты идут последовательно (`//nolint:paralleltest`). Раунд гонки закрывает свой рейс (`shift.close`).
- Фото и чеки — строки `files.objects` в состоянии `ready`, как в стек-тестах `cmd/api`. Объектного хранилища у цели нет.
- Строка изоляции (`isolation_test.go`) — пара «место × операция». Место — чужой актор и тенант пути. Строка проходит, если выполнено всё:
  - ответ совпадает с ответом на тот же запрос, где id объектов заменены несуществующими (`type`, `title`, `status`, `code`, `detail`);
  - статус и код соответствуют модели шлюза по фикстурам и контракту (`x-permissions` и `x-scope` операции берутся из `internal/api/catalog`, запрос строки сверяется с методом и шаблоном пути): нет членства — 404; начисления у функции «Водитель» — 403 `function_blocked`; действия нет ни в одном гранте подходящего вида области — 403 `forbidden_action`; операция без хендлера — 501; иначе 404 (у списка — 200, у подразделения в теле — 422 как у несуществующего);
  - id объектов нет ни в теле, ни в заголовках.

  После всех строк ETag объектов не меняются. Затем законный актор выполняет каждую команду и получает точный ответ живого объекта (`command.want`): успех или конкретный код отказа по состоянию, но не 404.

- Дефект чужого пакета набор не чинит. Тест остаётся, падающая строка попадает в `known` с вопросом и пропускается (`t.Skip("Q-W2.30-N: …")`, причина падения — в журнале строки). Строка из `known`, которая проходит, падает: дефект исправлен, запись нужно убрать.
