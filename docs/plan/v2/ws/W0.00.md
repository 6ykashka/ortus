# W0.00 · Протоколы v2 и перенумерация решений плана `D-13…D-52` → `PD-13…PD-52`

Этап 0 · подволна 0a · дорожка И (инфраструктура, процесс) · размер M · зависит от B-3 (согласие на префикс `PD-`; пользователь дал его, запустив план). Карточка — `docs/plan/v2/00-parallel-plan.md` §4 «Этап 0», содержание — §6. Старого брифа нет; ближайший — `docs/plan/ws/WS-00-analysis-fixes.md` (часть «внести D-25…D-52», заменённая перенумерацией по `D-plan-reconciliation.md` §4).

## 1. Цель

1. Убрать коллизию номеров: решения старого плана (`docs/plan`) получают префикс `PD-`, а `D-NN` остаётся за комплектом (`16-raid-glossary.md`, D-01…D-28) и планом 27 (кандидаты D-29…D-34). Замена делается скриптом с тестами, таблица соответствия лежит в `decisions.md`.
2. Свести журнал решений плана в одно место: D-25…D-52 из `00-master-plan.md` §10.3 переносятся в `decisions.md` как PD-25…PD-52. Для PD-13…PD-52 проставляется вердикт сверки с планом 27 (`D-plan-reconciliation.md` §5.2).
3. Перевести протоколы на этапы плана 27 (§6 плана v2): `orchestration.md`, `tdd-protocol.md`, `verification-protocol.md`.
4. Переписать `workflow.template.js`:
   - `args.stage` и `args.subwave`;
   - фаза «Контракт» (стюард) до исполнителей;
   - не больше 6 проверяющих одновременно (`chunked` поверх общего лимитёра);
   - цикл возврата ≤ 3;
   - новые поля схем отчёта и вердикта;
   - `RULES` ссылается на план v2.

## 6. Тесты первыми

Запуск: `node --test "docs/plan/scripts/*.test.mjs"` (с glob: каталог без glob на Windows в Node 22 даёт `MODULE_NOT_FOUND`).

(а) `renumber-decisions.test.mjs` — функция `renumber(text, {file})`:

1. `D-13`, `D-24`, `D-52` → `PD-13`, `PD-24`, `PD-52`.
2. `D-01…D-12` не меняются.
3. Диапазон `D-13…D-24` → `PD-13…PD-24`.
4. Повторный прогон ничего не меняет: `PD-13` не превращается в `PPD-13`.
5. `D-ID`, `D-130`, `XD-13` и `AD-13` не трогаются.
6. `D-53` → `PD-61`.
7. Атрибут `data-a11y-extra="D-29"` → `"PD-29"`.
8. Список файлов покрывает `docs/plan/{*.md, workflow.template.js, ws, drafts, analysis}` и не включает `docs/plan/v2/**`.

(б) `workflow-template.test.mjs` — шаблон выполняется с фейковыми `agent`, `parallel`, `pipeline`:

1. Пустой `args.ws` → ошибка; нет `args.stage` → ошибка.
2. Каждый `phase()` есть в `meta.phases`, а `meta` — чистый литерал.
3. WS вида `contract` исполняется в фазе «Контракт» раньше всех исполнителей, которые от него зависят (`dependsOn`, `needsContract: true`). По умолчанию WS контракт не ждёт; на точных `args` §8 плана v2 отказ W0.07 никого не пропускает. Неизвестный ID, самоссылка и цикл в `dependsOn` — ошибка; пропуск распространяется по цепочке.
4. Проверяющих одновременно ≤ `verifyConcurrency` во всех WS сразу; значение больше 6 урезается до 6. Порт проверяющего `6100 + полоса` уникален среди одновременно работающих и не зависит от порядка завершения агентов.
5. Вердикт `return` или `request-changes` → агент-продолжатель на той же ветке, повторная проверка всех страниц WS; максимум 3 возврата, затем `escalated: true`.
6. Схема отчёта требует `stage`, `step`, `stories`, `contractPr`, `isolationRows`, `mode`; вердикт — `mode`, `stage`.
7. Промпт исполнителя содержит порты слота (`5200+slot`, `7200+slot`, `8100+slot`), `COMPOSE_PROJECT_NAME=ortus-s<slot>` и запрет занимать порты проверяющих 6101–6106. Порт `6100 + полоса` получает проверяющий (план v2 §3.6, `orchestration.md` §4).
8. Промпт интегратора содержит тег `stage-<N>-` и путь к плану v2.
9. `node --check` на копии без `export`, обёрнутой в async-функцию, проходит.

(в) Проверка документов `--check` после перенумерации: 0 оставшихся `D-13…D-53` в файлах области.
