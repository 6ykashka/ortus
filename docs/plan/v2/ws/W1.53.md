## 1. Цель

Job `e2e (Playwright, режим mock)` (`.github/workflows/ci.yml`, `timeout-minutes: 40`) на GitHub прерывается по таймауту на двух последних прогонах main, упавших строк нет:

| Run | Коммит | Прошло строк | Итог |
|---|---|---|---|
| 39007960384 | W1.25 | все | `success`, 29 мин 58 с |
| 39013190845 | `be67adc` | 1015 из 1101 | `cancelled` по таймауту |
| 39017834520 | `3df8941` | 841 из 1122 | `cancelled` по таймауту (40 мин 16 с) |

Причина — один воркер в CI (`frontend/packages/e2e-kit/src/config.ts:83`, `workers: h.ci ? 1 : undefined`) и рост набора: 13:54 → 22:41 → 29:58 → больше 40 мин. По двум прерванным прогонам строка стоит 2,4–2,9 с, значит 1122 строки — 45–53 мин одним воркером. Этап 2 добавит ещё шесть страниц (оценка +300 строк, 56–67 мин).

Решение — шардирование Playwright `--shard i/N` в матрице GitHub, без изменения `workers` и `retries`:

1. Job `e2e-shard` — матрица `shard: [1…N]`, `fail-fast: false`, каждый шард вызывает `node tools/ci/pipeline.mjs --job e2e` с env `E2E_SHARD=<i>/<N>`. Имя шарда — `e2e шард <i>/<N> (Playwright, режим mock)`, `timeout-minutes: 20`.
2. Итоговая job с прежним id `e2e` и прежним именем `e2e (Playwright, режим mock)`: `needs: e2e-shard`, `if: ${{ !cancelled() }}`, падает, если результат матрицы не `success` (упал или пропущен любой шард). Имя обязательной проверки не меняется.
3. `pipeline.mjs`: env `E2E_SHARD` разбирается (`parseShard`) и передаётся аргументом `--shard=<i>/<N>` команде `pnpm run e2e` (pnpm 9 передаёт аргументы после имени скрипта дальше, до `playwright test`). Неверное значение — `fail` с причиной. Без env (локальный `ci:local`, `ci:job e2e`) команда прежняя.
4. Артефакты `playwright-report` и `test-results` — по шарду, имя `playwright-report-e2e-<i>`.
5. Число шардов и раскладка job workflow — в `pipeline.mjs` (`E2E_SHARDS`, `workflowJobs()`); `workflow.test.mjs` сверяет с ними `ci.yml`.

**N = 6** (ориентир постановки — 4). Шард 1122/6 ≈ 187 строк ≈ 7,5–9 мин плюс ≈ 2,5 мин накладных (checkout, install, браузеры, старт Vite и эталона) — 10–11,5 мин; после этапа 2 (≈ 1420 строк) — 12–13,5 мин, в пределе 15 мин. При N = 4 уже сейчас 11–13,5 + 2,5 = 13,5–16 мин, после этапа 2 — 16,5–19,5: предел 15 мин нарушается. Раскладка `--list`: 1122 строки делятся на 6 шардов по 187 (Playwright с `fullyParallel: true` делит по тестам, а не по файлам).

## 10. Риски и решения по умолчанию

| # | Риск / вопрос | По умолчанию |
|---|---|---|
| 1 | N = 6 вместо ориентира 4 | Расчёт в §1: при 4 шард уже сейчас до 16 мин и до 19,5 мин после этапа 2. 6 шардов + `e2e-stand` = 7 параллельных job, публичный репозиторий — минуты бесплатны, лимит Free — 20 параллельных job. N — одна константа `E2E_SHARDS`, `workflow.test.mjs` сверяет матрицу с ней |
| 2 | Воркеров > 1 на раннере вместо шардов | Не делается: нужна изоляция mock по контексту и доказательство `--repeat-each`; `workers`/`retries` в `e2e-kit` (W0.05) не меняются |
| 3 | Итоговая job при упавшей `build` | `if: ${{ !cancelled() }}`: шарды пропущены → итог `skipped` матрицы → итоговая `e2e` красная (раньше `e2e` была `skipped`, а пропущенная обязательная проверка GitHub засчитывает как пройденную). При отмене прогона (concurrency) итоговая не запускается |
| 4 | Накладные шарда (install, браузеры, старт Vite) ×6 | ≈ 2,5 мин на шард; время шардов — в отчёте |
| 5 | HTML-отчёты шардов не сливаются в один | Артефакт на шард (`playwright-report-e2e-<i>`) при падении; слияние blob-отчётов — не в объёме (предложение — integratorNotes) |
| 6 | Защиты ветки `main` сейчас нет (`gh api …/protection` → 404) | Имя итоговой проверки сохранено для будущей обязательной проверки (план §3.5) |
