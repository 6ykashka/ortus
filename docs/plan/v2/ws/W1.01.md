## 1. Цель

До первой изменяющей команды платформа даёт три общих механизма и собирает образы:

- **Idempotency middleware (S1-25, NFR-02, AC-07).** Каждая изменяющая операция контракта с заголовком `Idempotency-Key` проходит через `idem.Guard` в шлюзе `cmd/api` после проверки права. Пространство ключа — организация + актор + `operationId` (`components/common/parameters.yaml` `IdempotencyKey`: «Key is scoped to tenant+actor+operation. Reuse only for an identical request»). Повтор с тем же телом отдаёт сохранённый ответ с `Idempotency-Replayed: true`, другое тело — 409 `idempotency_key_reused`, параллельный повтор во время выполнения — 409 `idempotency_in_progress` с `Retry-After`. Записи — `core.idempotency_keys` tenant DB, хранятся 7 дней («Retain record at least 7 days»). Сервис с транзакцией пишет итог в той же транзакции, что и эффект (`idem.CompleteInTx`, 10 §3.5). Критерий AC-07: «100 повторов команды с одним ключом → один эффект» (`design/docs/15-quality-security.md:41`).
- **Аудит (S1-23, NFR-05).** `audit.Record` пишет `audit.events` tenant DB в транзакции изменения, `audit.RecordPlatform` — `platform_audit` control DB. Проверка полей по CHECK-ограничениям схемы, `request_id` из запроса, редакция restricted-полей `diff`. Таблицы только на вставку (`grants.sql`, Q-W0.06-3).
- **Outbox (S1-24, A-11).** `events.Publish` вставляет событие в `outbox.events` в транзакции изменения (API только вставляет). Worker (`cmd/worker`, роль `ortus_worker`) обходит организации, забирает события с арендой (`locked_until`, `FOR UPDATE SKIP LOCKED`), передаёт обработчикам реестра, при ошибке повторяет с экспоненциальной паузой, после `MaxAttempts` переводит в dead-letter. Ручной повтор — `worker retry`. Потребитель защищён от повторной доставки таблицей `outbox.inbox` (`events.Once`).
- **Образы (S0-02, П-3, Q-W0.04-4).** `backend/Dockerfile` — один образ `ortus-backend` с `cmd/api`, `cmd/migrate`, `cmd/worker`: сборка в `golang`, итог `distroless/static:nonroot`, базовые образы закреплены по digest. `frontend/apps/web/web.Dockerfile` — `ortus-web`: статическая сборка `@ortus/web` (Vite) в `node`, раздача из `nginx-unprivileged` (non-root, SPA-fallback). Контекст — корень репозитория. Шаг CI `build/images` (`tools/ci/pipeline.mjs`) собирает оба образа и больше не пропускается: если Dockerfile нет — шаг падает. Деплой — этап 3.

### 4.2 Публикует

```go
// internal/platform/idem
const HeaderKey = "Idempotency-Key"; const HeaderReplayed = "Idempotency-Replayed"
const DefaultTTL = 7 * 24 * time.Hour; const DefaultLease = 2 * time.Minute
var ErrInProgress, ErrKeyReused error
type Namespace struct{ TenantID, ActorID uuid.UUID; Operation string } // TenantID == uuid.Nil: identity и platform
type Record struct{ Namespace; Key string; Hash []byte }
type Outcome struct{ Status int; Header http.Header; Body []byte }
type Store interface {
    Begin(ctx context.Context, rec Record, now, leaseUntil time.Time) (*Outcome, error) // nil, nil — ключ захвачен
    Complete(ctx context.Context, rec Record, out Outcome, expires time.Time) error      // только из in_progress
    Release(ctx context.Context, rec Record) error                                       // только in_progress
}
type Stores interface{ For(ctx context.Context, tenantID uuid.UUID) (Store, error) }
func NewMemStore() *MemStore; func NewPGStore(db DB) *PGStore
type TenantStores struct{ Pools PoolSource; Platform Store }  // tenant → PGStore на пуле tenant DB, Nil → Platform
type Guard struct{ Stores Stores; TTL, Lease time.Duration; Now func() time.Time; Log *slog.Logger }
func (g *Guard) Serve(w http.ResponseWriter, r *http.Request, ns Namespace, next http.Handler)
func ValidKey(key string) bool
func FromContext(ctx context.Context) (Record, bool)
func CompleteInTx(ctx context.Context, tx DB, status int, header http.Header, body []byte) error

// internal/platform/audit
type Event struct{ ActorKind string; ActorID uuid.UUID; Action, TargetType string; TargetID, UnitID uuid.UUID
    Sensitivity, Reason, Result, RequestID string; Diff map[string]any }
type PlatformEvent struct{ ActorKind string; ActorID uuid.UUID; Action, TargetType string; TargetID uuid.UUID
    Reason, Result, RequestID string; Details map[string]any }
func ForRequest(ctx context.Context) Event           // актор из TenantContext (PersonID), request_id из запроса
func Record(ctx context.Context, db Execer, e Event) error
func RecordPlatform(ctx context.Context, db Execer, e PlatformEvent) error
func Redact(diff map[string]any, restricted ...string) map[string]any
var ErrInvalid error

// internal/platform/events
type Event struct{ Type, Aggregate string; AggregateID uuid.UUID; Payload any; AvailableAt time.Time }
func Publish(ctx context.Context, db Querier, e Event) (uuid.UUID, error)   // в транзакции изменения
func Once(ctx context.Context, db Execer, consumer string, eventID uuid.UUID) (bool, error) // outbox.inbox
type Message struct{ TenantID uuid.UUID; ID int64; EventID uuid.UUID; Type, Aggregate string; AggregateID uuid.UUID
    Payload json.RawMessage; OccurredAt time.Time; Attempts int }
type Handler func(ctx context.Context, m Message) error
type Registry struct{ /* type → handlers */ }; func NewRegistry() *Registry
func (r *Registry) Handle(eventType string, h Handler); func (r *Registry) Dispatch(ctx context.Context, m Message) error
type Outbox struct{ DB DB; Now func() time.Time; Lease time.Duration; MaxAttempts int; Backoff func(attempt int) time.Duration }
func (o *Outbox) Claim(ctx context.Context, limit int) ([]Message, time.Time, error)
func (o *Outbox) Published(ctx context.Context, id int64, lease time.Time) error
func (o *Outbox) Failed(ctx context.Context, m Message, lease time.Time, cause error) (dead bool, err error)
func (o *Outbox) DeadLetters(ctx context.Context, limit int) ([]DeadLetter, error)
func (o *Outbox) Retry(ctx context.Context, eventID uuid.UUID) error  // ErrNotDead, если события нет в dead-letter
type Worker struct{ Tenants func(ctx context.Context) ([]uuid.UUID, error); Pools PoolSource; Registry *Registry
    Batch int; Interval, Lease time.Duration; MaxAttempts int; Now func() time.Time; Log *slog.Logger }
func (w *Worker) RunOnce(ctx context.Context) (Stats, error); func (w *Worker) Run(ctx context.Context) error
```

`cmd/worker`: `worker [run]` — цикл до сигнала; `worker dead --tenant <uuid> [--limit N]` — dead-letter строками JSON; `worker retry --tenant <uuid> --event <uuid>` — ручной повтор. Env: `CONTROL_DB_URL` (роль `ortus_worker`), `TENANT_DB_HOST`, секрет `tenant_routing.secret_ref` (`TENANT_DB_URL` с ролью `ortus_worker`), `WORKER_POLL_INTERVAL` (1s), `WORKER_BATCH` (100), `WORKER_LEASE` (30s), `WORKER_MAX_ATTEMPTS` (10), `LOG_LEVEL`. Коды выхода: 0, 1 — сбой, 2 — конфигурация или аргументы, 3 — событие не в dead-letter.

Образы: `docker build -f backend/Dockerfile -t ortus-backend:ci .` (точка входа `/app/api`, `HTTP_ADDR=0.0.0.0:8080`; `--entrypoint /app/worker` и `/app/migrate`), `docker build -f frontend/apps/web/web.Dockerfile -t ortus-web:ci .` (порт 8080).

## 5. Операции и состояния (backend)

| Механизм | Случай | Результат |
|---|---|---|
| Guard | изменяющая операция с ключом, первый запрос | хендлер выполняется, ответ < 500 сохраняется |
| Guard | повтор, то же тело | сохранённые статус, заголовки (`Content-Type`, `ETag`, `Location`), тело; `Idempotency-Replayed: true`; хендлер не вызывается |
| Guard | повтор, другое тело или путь | 409 `idempotency_key_reused` |
| Guard | повтор во время выполнения | 409 `idempotency_in_progress`, `Retry-After: 1` |
| Guard | ключ < 16, > 128 символов или с недопустимым символом | 400 `malformed_request` |
| Guard | ключа нет | хендлер без Guard (обязательность заголовка проверяет обёртка strict server — 400) |
| Guard | ответ 5xx, 429, 409 повторяемого кода, паника | запись снимается, повтор выполняется заново |
| Guard | тот же ключ у другого актора или другой организации | отдельное пространство, выполняется заново |
| Guard | запись старше срока (7 дней; in_progress — аренда 2 мин) | ключ захватывается заново |
| Guard | сбой хранилища | 503 `dependency_unavailable` |
| audit | неверные `actor_kind`, `result`, `sensitivity`, пустые `action`/`target_type` | `ErrInvalid`, запись не делается |
| outbox | обработчик успешен | `published_at`, аренда снята |
| outbox | ошибка, попыток < Max | `attempts+1`, `available_at = now + backoff`, `last_error` |
| outbox | ошибка, попыток = Max | dead-letter: `available_at = 'infinity'`, `last_error` |
| outbox | аренда истекла | событие забирает другой worker; запись прежнего worker по старой аренде не применяется |
| outbox | `worker retry` | `attempts = 0`, `available_at = now`; не dead-letter → код 3 |
| outbox | событие без обработчиков | помечается опубликованным |
| inbox | повторная доставка тому же потребителю | `Once` → false |

## 10. Риски и решения по умолчанию

1. **Хранилище ключей вне организации.** В control DB нет таблицы `idempotency_keys`. Операции identity (`selectTenant`, `logout`, `markMyNotificationsRead`, `acceptInvitation`) и platform хранят ключи в памяти процесса (`MemStore`, срок 7 дней, очистка истёкших). По умолчанию так до control-миграции стюарда (номер 0004+ после `accounts.last_tenant_id` W1.03). → `decisionsNeeded`.
2. **Какие операции идемпотентны.** Каталог `catalog.Operation` не знает, есть ли у операции параметр `Idempotency-Key`. По умолчанию Guard срабатывает на изменяющей операции, если клиент прислал ключ; обязательность заголовка проверяет обёртка strict server. Точнее — поле `Idempotent` в каталоге (codegen `tools/gen`, стюард/интегратор). → `decisionsNeeded`.
3. **Dead-letter без колонки.** В `outbox.events` нет состояния dead-letter. По умолчанию dead-letter = `published_at is null and available_at = 'infinity'`, причина — `last_error`. Отдельная колонка `dead_at` — tenant-миграция стюарда. → `decisionsNeeded`.
4. **Ручной повтор только CLI.** Операции контракта для dead-letter нет; повтор — `worker retry`. Экран оператора — после контракта (этап 3, эксплуатация). → `decisionsNeeded`.
5. **Аренда in_progress = 2 мин** (больше `WriteTimeout` 30 с API). Команда без `CompleteInTx`, упавшая после фиксации эффекта и до записи итога, после аренды выполнится повторно. Поэтому сервисы с эффектом в tenant DB обязаны вызывать `idem.CompleteInTx` в своей транзакции (правило для W1.03+).
6. **Сохраняемые заголовки** — `Content-Type`, `ETag`, `Location`. Повторяемые ответы (5xx, 429, 409 `reservation_overlap`/`resources_unavailable`/`idempotency_in_progress`) не сохраняются (`errors.yaml` `retryable: true`).
7. **Полный валидатор запросов по схеме (Q-W0.09-9).** Требует встроенной спецификации в генерации (`tools/gen`, без неё сейчас) и новой зависимости (`kin-openapi`) — зоны интегратора и стюарда. В W1.01 не подключается; тела проверяют strict server и `DecodeStrict`. → `decisionsNeeded`.
8. **Образ `ortus-backend` один на три бинаря**, а не три образа: одна сборка Go, точки входа выбираются `--entrypoint`. `cmd/seed` в образ не входит (dev/e2e). `APP_ENV=prod` с `AUTH_PROVIDER=dev` `cmd/api` не запускает — до W1.03 контейнер запускается с `APP_ENV=dev|e2e`.
9. **`ortus-web` на `nginx-unprivileged`** (uid 101, порт 8080): статика + SPA-fallback, без прокси `/api` (деплой — этап 3).
10. **Правка `cmd/api` вне колонки «Владеет»** — только подключение Guard (иначе middleware не стоит «до первой изменяющей команды»). Отмечено в отчёте для интегратора.
