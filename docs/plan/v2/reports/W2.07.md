## Сделано

**Модуль `backend/internal/modules/fleet/pool/`** — надстройка над strict server тега Fleet (как `review`, `inspections`), девять операций контракта W2.51 в порядке проверок их описаний:

- `publish.go`: `publishDriverToPool` — нет approve ни в одной фирме 403; неизвестная и невидимая (`org_units.read`) фирма — одинаковый 422 «Подразделение не найдено.»; видимая без права 403; неизвестный, чужой, архивный и не водитель (функция на начало окна) — одинаковый 422 «Проверьте водителя.»; пустое и прошедшее окно 422; пересечение с неснятой публикацией (exclusion tenant 0014 тоже переводится в 409) или с рейсом водителя — 409 `resources_unavailable`. Псевдоним «Водитель #N» — следующий номер под advisory-lock тенанта. `listDriverPoolPublications` (scope read над домашней фирмой до страницы, `state`, `homeOrgUnitId`, курсор), `getDriverPoolPublication` (чужая — 404), `withdrawDriverPoolPublication` (If-Match, автор и комментарий, открытые запросы → `expired`, снятая и истёкшая — 409). Аудит и `fleet.pool.published.v1` / `withdrawn.v1` — без имени водителя.
- `catalog.go`: `listAvailableDrivers` — минимальная проекция AUTH-06 (псевдоним, квалификации, окно, условия, домашняя фирма, `publicationId`), без своих фирм (владелец видит все), без водителей с одобренным запросом в интервале.
- `request.go`: `requestDriverTransfer` — право на получателя 403 → публикация (`publicationId` или правило Q-W2.51-13; 404 «Водитель не опубликован в пуле.») → фирма-источник 422 → окно внутри свободного 422 → рейс (невидимый 404, чужой фирмы 422, с водителем 409) → один открытый запрос 409 «Запрос уже отправлен» (и `driver_transfers_open_uq`). Публикация блокируется `for update`.
- `transfer.go`: `getDriverTransfer`, `listDriverTransfers` (read над любой из фирм, `direction`, `status` по досчитанному статусу в SQL, курсор привязан к тенанту, участнику и фильтрам).
- `decide.go`: `decideDriverTransfer` — видимость 404 → рейс запроса `for update` → запрос `for update` (порядок модуля «рейс, затем запрос», возврат 1) → approve над источником 403 → If-Match досчитанной ревизии → статус 409. Одобрение: `pool.LockDriver` (`pg_advisory_xact_lock` по водителю), перепроверка рейса (другой водитель / начат или закрыт — 409), занятость (одобренные запросы и неоконченные рейсы водителя в окне — 409 `resources_unavailable`), временное назначение — строка `access.role_assignments` роли с `template_key = 'driver'`, `source = 'transfer'`, область `unit` подразделения рейса **без потомков** (без рейса — фирма-получатель, тоже без потомков с возврата 1), `valid = [startsAt, endsAt)`; водитель ставится на рейс; `policy_version` + `access.policy.bumped.v1` (W1.07); уведомление «Запрос водителя {псевдоним} одобрен|отклонён фирмой {источник}» (inbox W1.10) держателям `fleet.driver_transfers.request` и владельцам (возврат 1: без обхода всех людей тенанта). Отзыв: назначение `revoked` с `valid` до момента отзыва, `revoked_by`, водитель снимается с не начатого рейса.
- `rules.go` + `settle.go`: чистое правило `Settle` (Q-W2.51-4, Q-W2.51-15) — истечение открытого запроса к началу окна; `scheduled` / `active` / `closing` / `ended`; грант открыт, пока рейс водителя начат и не закрыт, закрывается приёмкой (`reviewed_at`) или отменой, иначе — концом окна; завершение к концу окна, к приёмке после окна или к моменту закрытия гранта; снятие с не начатого рейса. Чтение показывает досчитанное состояние сразу (статус, состояние гранта, ревизия +1). Запись: `SettleDB` / `SettleTx` — весь тенант (воркер), `SettleTrip` / `SettleTripTx` — запросы одного рейса (надстройка, команды рейса); блокируются только запросы, которые время меняет сейчас; срок меняется только у назначения `state = 'active'` (возврат 1).
- `server.go`: надстройка пропускает `reserveVehicle` (с рейсом), `releaseReservation`, `startTrip`, `reviewTrip` вниз без изменений и после успеха досчитывает запросы рейса команды (`SettleTrip`, срок `SettleTimeout`, по умолчанию 5 с) — грант временного водителя открывается в момент старта рейса и закрывается в момент приёмки, а не только на следующем проходе воркера.
- `owners.go` (возврат 1): `pool.ControlOwners` — владельцы организации по привязкам control DB (получатели уведомления помимо держателей права).

## Осталось fixme / открытые вопросы

`fixme` нет. Вопросы (значения по умолчанию — как сделано; внести в `docs/plan/decisions.md` — файл интегратора):

1. **Q-W2.07-1 · область временного назначения (продукт / безопасность, стюард контракта) — блокер.** По умолчанию Q-W2.51-15 и контракт (`TemporaryDriverGrant.tripId`: «The only trip the grant opens»; `requestDriverTransfer`: «never exceeds the trip of targetOrgUnitId and window») — область «рейс». Объектной области «рейс» в реестре authz нет, поэтому сделано: роль «Водитель» на подразделение рейса без потомков (без рейса — фирма-получатель без потомков). Что это открывает в сроке (закреплено тестами): рейсы — только свои (D22), машины подразделения и бронь на себя (нужны для брони на рейс), задачи, файлы, база знаний и занятость календаря подразделения — по шаблону «Водитель»; филиалы — нет; после окна, отзыва и приёмки — 404. Начатый, но не принятый рейс держит это без потолка (Q-W2.51-15 «без потолка» обоснован областью «рейс»). Варианты: (а) вид области `trip` в реестре authz + миграция `check` `scope_kind` + `Resource.Objects["trip"]` в модулях рейса W2.02–W2.06 (контрактный PR); (б) отдельная системная роль «Временный водитель» только с действиями рейса (без `tasks.read`, `knowledge.read`, `files.read` подразделения, `calendar.availability.read`); (в) принять область подразделения и потолок closing (конец окна + N суток).
2. **Q-W2.07-2 · рейс до начала окна (продукт).** По Q-W2.51-15 (`valid = [startsAt, endsAt)`) временному водителю рейс до окна не виден (`scheduled`); MSW W2.51 (Q-W2.51-4) показывает его «для подготовки к выезду». Альтернатива — нижняя граница гранта в момент одобрения.
3. **Q-W2.07-3 · открытие гранта при старте рейса (технический).** Q-W2.51-15 просит «в той же транзакции». Сделано: надстройка досчитывает рейс сразу после `reserveVehicle` с рейсом, `releaseReservation`, `startTrip`, `reviewTrip` (их транзакция уже закрыта, срок 5 с), воркер — каждые 30 с. Окно расхождения — сбой досчёта после команды до прохода воркера. Альтернатива — владельцы W2.02/W2.05/W2.06 вызывают `pool.SettleTripTx` в своей транзакции после блокировки рейса (готово).
4. **Q-W2.07-4 · отмена рейса (технический).** Операции отмены в этапе 2 нет; момент отмены после окна — момент досчёта (как MSW). Будущая отмена должна досчитать рейс (`SettleTripTx` в своей транзакции).
5. **Q-W2.07-5 · сид пула на стенде (продукт).** Публикации прототипа — люди без членства; сид добавил бы двух людей «Альты» (инвариант W0.06 `TestSeedTwice`, список сотрудников против MSW). По умолчанию сида нет: на стенде водителя публикует владелец через API (`publishDriverToPool`), псевдонимы на свежем стенде — с «Водитель #1». Альтернатива — сид в `seed demo` (W2.90) или W2.54 с правкой инварианта.
6. **Q-W2.07-6 · «действующий сотрудник» публикации (продукт).** Живой профиль (`archived_at is null`) домашней фирмы с функцией «Водитель» на начало окна; членство control DB не проверяется (как Q-W2.03-3).
7. **Q-W2.07-7 · перепроверка занятости при одобрении (продукт).** Кроме одобренного пересекающегося запроса — неоконченный рейс водителя, пересекающий окно: 409 `resources_unavailable` «Водитель уже назначен в это время.».
8. **Q-W2.07-8 · уведомления (продукт).** О решении (одобрен / отклонён) — держателям `fleet.driver_transfers.request` на фирму-получатель и владельцам (как `accountsWith` MSW), в транзакции решения; о новом запросе и об отзыве уведомлений нет (как MSW).
9. **Q-W2.07-9 · 422 без поля нарушения (технический).** Problem backend несёт только `detail` (тексты MSW: «Срок вне свободного окна водителя.», «Рейс другой фирмы.»…); `violations` с `field`/`code` (как в MSW) — не отдаются: в `problem.Body` их нет. Пределы тела (квалификации, условия, причина, комментарий) — без `detail` (возврат 1).
10. **Q-W2.07-10 · домашняя роль «Водитель» в области self (продукт / безопасность, возврат 1).** Шаблон «Водитель» — `default_scope: self` (фикстура `a.driver-msk2`; на стенде группа «Водители Север» — на фирму).
