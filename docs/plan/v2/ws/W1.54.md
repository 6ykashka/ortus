## 1. Цель

После W1.54 владелец организации (и сотрудник с `org_units.read`) в режимах `mock` и `stand`:

- открывает **«Структура»** из меню «Компания» (пункт «Структура» после «Пользователи и роли») и по прямому URL `/t/:tenantId/structure` (ADR-0001: страница — один сегмент, как `/t/:id/modules`; «/company/structure» задачи — это раздел «Компания» меню);
- видит дерево организации регион → фирма → подразделение (→ команда) по `listOrgUnits` (все страницы курсора): вид узла, название, «В архиве»;
- создаёт узел верхнего уровня («Добавить регион») и дочерний узел («Добавить» у узла) — `createOrgUnit` с `Idempotency-Key`; вид по умолчанию — следующий уровень (регион → фирма → подразделение → команда);
- переименовывает узел — `getOrgUnit` (свежий ETag) → `updateOrgUnit {name}` с `If-Match` и `Idempotency-Key`;
- переносит узел под другого родителя: выбор «Куда перенести» → `previewOrgUnitMove` (сколько вложенных подразделений и сотрудников переносится; кто получит и кто потеряет доступ, роль; «ещё N вне вашей области») → «Перенести» → `getOrgUnit` → `updateOrgUnit {parentId}` с `If-Match`;
- видит состояния: загрузка, пусто, ошибка с «Повторить», нет связи, организация только для чтения (текст словаря `tenant_read_only`), нет права (гейт оболочки по `org_units.read`), 409 и 422 с текстами словаря; раскладка 390/768/1440.

Шаг «структура» сценария выхода этапа J-1 (`e2e/journeys/stage1/owner-onboarding.spec.ts`) владелец выполняет через этот экран: регион, фирма и подразделение создаются кликами в интерфейсе. Остальные шаги J-1 не меняются.
