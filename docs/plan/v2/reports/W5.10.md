## Решения по умолчанию и вопросы

- **Q-W5.10-1.** Контракт требует «отдельное право» для корректировки и сторно, а в каталоге его нет. По умолчанию — дополнительно `inventory.consumption.override` (единственный «правящий» ключ склада, `sensitive`). Решение владельца: свой ключ `inventory.movements.correct`? Тогда — правка каталога стюардом.
- **Q-W5.10-2.** Резерв хранится по позиции без партии (в `inventory.reservation_lines` партии нет): при снятии `reserved` уменьшается у партий с более поздним сроком первыми; сумма `reserved` по позиции всегда равна сумме действующих резервов. Если нужен резерв «на конкретную партию» — колонка в миграции (стюард).
- **Q-W5.10-3.** Номенклатура — на подразделение; складская область открывает позиции подразделения склада, а не только лежащие на нём. Остатки без позиции на складе в список позиций не попадают, пока позиция не заведена.
- **Q-W5.10-4.** `expiresAt` резерва только хранится: автоснятия просроченных резервов нет (нужна задача воркера, не карточка W5.10).
- **Q-W5.10-5.** Корректировка «уменьшение» и сторно могут списывать просроченные партии (списание просрочки — штатный сценарий); расход и перемещение — нет.
- **Q-W5.10-6.** Курсоры страниц — смещение (`offset`), не привязаны к субъекту; списки короткие и упорядочены по стабильным ключам. `belowMinimum=false` не фильтрует (только `true`).
- **Q-W5.10-7.** Событие `inventory.movement.posted.v1` публикуется, события «остаток ниже минимума» нет (потребитель — W5.11/W6.13).
