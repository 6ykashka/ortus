## 1. Цель

1. **Порт `platform/notify/inbox`** — единственный путь записи и чтения `notify.notifications` (tenant 0003):
   - `Enqueue` — постановка уведомления адресату в транзакции производителя. **Проверка адресата при постановке**: живой профиль сотрудника, активное членство (control DB), право `required_permission` на подразделение `unit_id` по оценщику W1.04 в момент постановки; для `sensitive`/`restricted` — нет действующей функции `driver` (AC-05). Не прошёл — строки нет (исход `NotInAudience`), это не ошибка производителя. Повтор события (`recipient_person_id`, `source_event_id`) — одна строка (исход `Duplicate`).
   - `Consumer` — обработчик outbox (`events.Handler`): событие → адресаты → `Enqueue` в одной транзакции с `events.Once` (повтор доставки не создаёт второе уведомление).
   - `Inbox.List`, `Inbox.Summary`, `Inbox.MarkRead` — чтение и отметка. **Проверка адресата при выдаче**: каждая группа «право × подразделение × чувствительность» перепроверяется оценщиком при каждом чтении; отозванная роль скрывает уведомление и уменьшает `unreadCount` сразу (AC-10 для канала уведомлений).
2. **Три операции тега `Context`** (сейчас 501) — методы в `platform/tenantctx/mehttp/notifications.go` (Q-W0.18-2): `listMyNotifications`, `markMyNotificationsRead`, `getMyNotificationSummary` по контракту 0.4.0-stage1. `tenantId` — только активное членство субъекта, иначе 404 `not_found` (AC-02: чужой = несуществующий, пул чужой организации не открывается).
3. **Строки изоляции** трёх операций в `backend/test/isolation/me.yaml` — красные (`pending: W1.10`) до хендлера.

## 4. Контракты

Контракт не меняется (0.4.0-stage1, W0.08/W1.00). Публикуемые сигнатуры порта:

```go
package inbox

type Notice struct {
	Kind, Severity, Title, Body, Link string
	Object                            *Object   // ModuleKey, EntityType, EntityID
	Unit                              uuid.UUID // подразделение объекта; uuid.Nil — нет
	Permission                        string    // без этого права уведомление не выдаётся
	Sensitivity                       string    // normal | sensitive | restricted
	SourceEvent                       uuid.UUID // outbox.events.event_id; uuid.Nil — системное
}
type Rule struct{ Permission string; Unit uuid.UUID; Sensitivity string }
type Audience interface { Admits(ctx, tenantctx.TenantContext, Rule) (bool, error) }
type AuthzAudience struct{ E *authz.Evaluator }

func Enqueue(ctx, db DB, aud Audience, to tenantctx.TenantContext, n Notice) (Outcome, uuid.UUID, error)
type Recipients interface { Recipient(ctx, tenantID, personID uuid.UUID) (tenantctx.TenantContext, error) }
type Consumer struct{ Name string; Pools Pools; Recipients Recipients; Audience Audience; Route Route }
func (c *Consumer) Handle(ctx, events.Message) error

type Inbox struct{ Pools Pools; Audience Audience }
func (in *Inbox) List(ctx, tc, Query) (Page, error)
func (in *Inbox) Summary(ctx, tc) (Counter, error)
func (in *Inbox) MarkRead(ctx, tc, Mark) (int64, error)
```

Правила проверки адресата (`AuthzAudience.Admits`):

| Правило | Решение |
|---|---|
| без права, без подразделения, `normal` | выдаётся |
| без права, но с подразделением или чувствительностью | не выдаётся (fail-closed; `Enqueue` такое уведомление отклоняет `ErrInvalid`) |
| право + подразделение | `Permit(право, Resource{Unit})` оценщика W1.04 = nil; `forbidden_action`, `not_found`, `function_blocked` — не выдаётся; `dependency_unavailable` — ошибка |
| `sensitive` / `restricted` | дополнительно: нет действующей функции `driver` (AC-05) |

Ответы операций: 401 `session_expired` (шлюз); 404 `not_found` — `tenantId` не активное членство; 403 `tenant_suspended` — организация приостановлена (`tenantctx.Resolve`); 400 `malformed_request` — `limit` вне 1…200, неизвестный `filter`, неверный или чужой курсор; 422 `validation_failed` — `markMyNotificationsRead` без ровно одного из `notificationIds`/`upTo`, `notificationIds` пустой, длиннее 200 или с повторами; 503 `dependency_unavailable` — tenant DB недоступна (в сводке — организация с нулями, как `/me/context`).
