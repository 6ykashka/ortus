# 0013. D-12 · Категории расходов пилота

Статус: предложено
Дата: 2026-10-15 · Автор: агент W0.01 · Участники: владелец продукта, представитель пилотной компании
Решение комплекта: D-12 (`design/docs/16-raid-glossary.md`, «Решения, нужные для старта»)
Кто решает: Владелец продукта
Блокирует: S2-08 (шаг 2.6) по 16; в плане v2 — W2.00 (контракт fleet), W2.05 (расходы), W2.22 (экран водителя), W0.12 (`validateExpense`)
До решения агенты работают по рекомендации (план v2 §2, B-2).

## Контекст

- Прототип предлагает две категории — «Топливо», «Мойка» (`EXPENSE_CAT`, `ortus/models.js:163` итерации 14.10; в 03.10 — `:123`); SQL tenant 0002 — `fuel`, `wash`, `parking`, `toll`, `other`; LOG-08 — топливо, мойка, парковка, прочие.
- Касса 14.10 для подотчёта водителя и прораба ведёт свой список (`ortus/cash.js:179`: «Топливо», «Мойка», «Парковка», «Мелкий ремонт»). Его согласование с категориями рейса — этап 5 (W5.30), не это решение.
- Q-48 в журнале («как в прототипе, 2 категории») пересмотрен: план 27, шаг 2.6, ссылается на категории D-12 (анализ D §5.3).
- Расход — затрата в рейсе, не выплата и не начисление (глоссарий 16). Проверка расходов менеджером — шаг 2.8.

## Варианты

1. **Пять фиксированных категорий: топливо, мойка, парковка, платная дорога, прочее** — плюсы: совпадает с enum SQL 0002, проверка `validateExpense` простая; минусы: расхождение с выпадающим списком прототипа (две категории) — запись allowlist визуальной сверки. Цена: ноль.
2. **Справочник категорий, который ведёт владелец** — плюсы: гибкость для других отраслей; минусы: миграция enum в таблицу, права на справочник, отчёты по произвольным категориям. Цена: +1 история, контракт и экран настроек.
3. **Две категории как в прототипе** — плюсы: пиксельный паритет; минусы: расходится с SQL и LOG-08, «Парковка» и «Платная дорога» уходят в «прочее». Цена: ноль, но хуже данные.

## Решение

Рекомендация: «Топливо, мойка, парковка, платная дорога, прочее» (вариант 1).

## Последствия

- Проще: enum в контракте fleet (W2.00) = SQL 0002; тексты категорий — словарь `logistics-driver`.
- Сложнее: экран расходов водителя отличается от эталона списком категорий — запись allowlist (вид `label`, решение D-12).
- Сделать: W2.00 — enum в OpenAPI; W0.12 — `validateExpense` с пятью категориями; W2.22 — выпадающий список.
- Как проверим: unit `validateExpense` по каждой категории; e2e — водитель добавляет расход «Парковка».
