# W6.12 · Backend замера и сметы: версии, допработы, допсоглашение с подписью по SMS, шаблоны и расценки

Этап 6 · шаг 6.3 · вид backend · размер L · слот 2 (Vite 5202, Storybook 7202, API 8102, эталон 4102, `ORTUS_SLOT=2`, `COMPOSE_PROJECT_NAME=ortus-s2`). Страниц нет.
Зависит от: W6.11 (модуль `repairs`, объекты, прораб, работы), D-31 (подпись по SMS). Блокирует: W6.15 (финансы, документы, кабинет заказчика), W6.20/W6.22 (страницы на реальном backend).

## 1. Цель

Операции шага 6.3 тега Repairs поверх таблиц `repairs.*` (tenant 0050, 0051, 0054) в пакете `backend/internal/modules/repairs` — 23 операции.

| Группа | Операции | Что делает |
|---|---|---|
| Допработы | `listChangeOrders`, `proposeChangeOrder`, `rejectChangeOrder` | ДР-n прораба без цен (`proposed`), отказ с причиной из четырёх; черновик объекта и сданный объект — `change_order_closed` |
| Замер | `getMeasurement`, `putMeasurement` | Версия замера (помещения, итоги пола, стен, периметра и «мокрых»), новая версия пересчитывает только строки черновика «из замера» |
| Версии сметы | `listEstimates`, `getEstimate`, `createEstimateFromTemplate`, `createEstimateRevision`, `updateEstimateDraft`, `sendEstimate`, `recallEstimate`, `deleteEstimateDraft`, `diffEstimates` | Черновик по шаблону и замеру, новая версия (до договора) и допсоглашение (после), правка пакетом, отправка (фиксирует объёмы, для допсоглашения — номер, ДР → `sent`, документ), отзыв, удаление черновика, сравнение по идентификатору строки |
| Расценки и шаблоны | `listPriceItems`, `createPriceItem`, `updatePriceItem`, `listTemplates`, `getTemplate`, `updateTemplate`, `copyTemplate`, `saveProjectAsTemplate` | Справочник работ и материалов, шесть частей шаблона, копия, «сохранить объект как шаблон», стартовые шаблоны Ортуса |
| Подпись | `requestDocumentSignature` | Код из SMS заказчику через порт доставки (D-31, заглушка), в базе только HMAC кода, срок и число попыток |

Сервисные методы без HTTP-маршрута (их вызывает кабинет заказчика, W6.15): `ApproveEstimate` (согласование версии по ссылке) и `SignDocument` (ввод кода: допсоглашение подписано → версия действует, ДР → `signed`, работы ДР появляются у прораба, сумма договора меняется).

## 3. Решения по умолчанию

- Права: чтение версий и сравнение — `repairs.finance.read`; правка (черновик, отправка, отзыв, удаление, допсоглашение, отказ ДР) — `repairs.estimates.edit` вместе с `repairs.finance.read`; справочник и шаблоны — `repairs.catalog.manage`, чтение каталога также у `repairs.estimates.edit`; замер — `repairs.measurements.edit`; допработа — `repairs.changes.submit` и только прораб объекта; код подписи — `repairs.documents.send`. Скрытый объект — 404.
- Q-W6.12-1: ДР-раздел в допсоглашении создаётся пустым («Допработы · ДР-N»), строки с ценами сметчик добавляет из справочника; отправка пустой сметы — 422.
- Q-W6.12-2: стартовые шаблоны Ортуса (3 шаблона, 23 позиции справочника) копируются в организацию лениво — при первом чтении каталога пользователем с правом вести его, если справочник и шаблоны пусты (хука подключения модуля нет).
- Q-W6.12-3: документ допсоглашения создаётся при отправке в состоянии `wait` («Ждёт подписи заказчика»); `requestDocumentSignature` принимает `draft`, `wait` и повторный запрос из `sms` (новый код, попытки обнуляются); `signed`/`paid` — `repair_document_state`.
- Q-W6.12-4: код — 6 цифр, срок 10 минут, 5 неверных попыток гасят код (нужен новый); хеш — HMAC-SHA256 ключом сервера (`REPAIRS_SIGN_KEY`, без него — случайный ключ процесса).
- Замер: пока замера нет, он «виртуальный» версии 1; первая запись — версия 2 (если замер уже есть — следующая), `revision` = номер версии. «Мокрое» помещение — `wet` или название на «санузел».
- Объёмы: формулы пол/пол без санузлов/стены/стены без санузлов/санузлы/периметр/периметр без санузлов × коэффициент; штуки, мешки, рейсы, комплекты, литры — вверх, остальное — до десятых; суммы строк и скидка считаются в целых копейках с округлением «вверх от половины».

1. Unit: замер и формулы, округление, суммы и скидка, сравнение версий, коды подписи (хеш, срок, попытки).
