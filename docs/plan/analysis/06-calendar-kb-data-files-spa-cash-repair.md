## 2. Сводка

- Семь страниц одного приложения, выбираются по `state.pages[persona]`; ключи `calendar`, `knowledge`, `data`, `files`, `spa`, `cash`, `repair` (`Ортус CRM.dc.html:2861–2890`). Каждая страница — `<sc-if value="{{ pg.X }}">` + VM `xVM(db, …)`.
- Все семь страниц входят в `PAGE_MOD` (`:2328`), поэтому вход на страницу охраняется `gateVM` по праву `view` соответствующего модуля (`:3055–3061`); AccessGate рисуется вместо страницы (`:195–203`).
- Ключи прав прототипа (`ortus/models.js:62–72, 38–59`): календарь `calendar.read / calendar.bookings.create / calendar.bookings.manage`; база знаний `knowledge.read / knowledge.write`; данные `data.read / data.export`; файлы `files.read / files.upload`; касса `cash.read / cash.operations.create`; SPA `spa.appointments.read / spa.appointments.create / spa.services.manage / spa.completion.review / spa.export / spa.settings`; ремонт `repairs.projects.read / repairs.worklogs.create / repairs.projects.manage / repairs.worklogs.review / repairs.export / repairs.settings`. Канонические имена для репозитория — `docs/11-permissions.yaml:179–190` (`prototype_renames`).
- Модули ядра (календарь, база знаний, данные, файлы, касса) всегда «подключены» (`moduleOn` → `true` для не-отраслевых, `models.js:169`); SPA в «Альте» подключён по умолчанию, «Ремонт и стройка» — **отключён** (`mock-data.js:147`), поэтому «Объекты» по умолчанию показывают AccessGate «Модуль не подключён».
- Персонажи и доступ (роли `mock-data.js:167–179`): владелец — всё; логист (`m-kotova`) по умолчанию **без назначений** (видит только «Главная» и «Логистика»; остальные страницы — AccessGate «Нет права»), после назначения шаблона «Менеджер логистики» получает календарь (view/create/edit), данные (view/export), файлы (view), базу знаний (view); водитель — только база знаний в меню; массажист — «Мой день», календарь (view/edit), база знаний; прораб — «Объекты», задачи, база знаний.
- Вторая организация `t-lotos` (SPA «Лотос») имеет свою БД в mock-адаптере (`mock-data.js:42–80`): персонажи `owner@t-lotos`, `therapist@t-lotos`; в ней те же сиды SPA и календаря (минус ресурсы-машины), одно пространство базы знаний, своя касса `ca-lotos`, модули `logistics: off, spa: on, repair: off`.
- Сервер (mock) формирует ответ под участника: приватные страницы базы знаний отдаёт только владельцу, кассу — только с `cash.view`, брони-ТО машин — только тем, кто видит автопарк, `earnings` вырезает без финансового права (`ortus/api.js:70–97`).
- Серверные правила: перенос брони атомарно проверяет все ресурсы с буферами и предлагает 3 свободных слота (`api.js:454–464`, `models.js:282–300`); версия страницы базы знаний публикуется с проверкой базовой версии (`api.js:467–476`); завершение процедуры списывает материалы один раз, при нехватке — `done_pending` + открытый вопрос владельцу (`api.js:479–504`); касса — только сторно, без удаления (`api.js:507–526`); отметка прораба уходит «На проверке», факт меняется только при приёмке (`api.js:529–549`).
- Ответы API через `this.run(key, fn, okToast, {quiet})` (`:2445–2460`): успех → `db` заменяется, тост `ok`; ошибка → тост `error` (или `warn` для `offline`) с `e.message`, если код не в `quiet`.
- Карточка объекта (ремонт) — вариант 1a «Сводка» из `Объекты - варианты.dc.html`; вкладки «Замер … Кабинет заказчика» встроены через `<dc-import name="Ремонт и стройка" embedded tab on-tab on-status on-leads>` (`:2126`); дочерний макет хранит собственное состояние (не в `db`) и отдаёт в обзор сводку `onStatus` (`Ремонт и стройка.dc.html:871`).
- Раскладка общая для всех страниц: контейнер `max-width:1320px`, отступы `24px 28px 40px` (телефон `16px 14px 28px`), `gap:16px` (`:2844`); боковая панель 244 px при W ≥ 1080, рейл 68 px при 640 ≤ W < 1080, нижняя навигация при W < 640 (`:2830, 2843`).
- Готовность объекта в шапке — «принято + на приёмке» по сумме объёмов (`:4289–4290, 4320`); для заказчика — по закрытым актам (`docs/19-construction.md:91`).
- Демо-флаги (`:63–65`): «Нет связи» → любые команды падают с `offline`; «Конфликт брони» и «Сбой загрузки фото» на модули этого отчёта **не влияют** (`api.js:310, 327, 557`).
- Загрузка: единый скелетон «Загружаем рабочее пространство…» (`:182–190`) при смене персонажа (320 мс) и старте (500 мс); отдельных скелетонов страниц нет.

## 12. Инварианты и правила

1. Страница рисуется только при `can(mod,'view').ok`; иначе AccessGate; сервер отдельно скрывает поля/записи (`:3055–3061`, `api.js:70–97`).
2. Календарь: занятость = `[start − prep, end + clean]` по каждому ресурсу брони; перенос проверяет все ресурсы атомарно, конфликт объясняется именем ресурса и названием брони, предлагаются 3 слота (`models.js:282–300`; CAL-03/04 `docs/v0.1/01-technical-spec.md:72–74`).
3. Рейсы и ТО переносятся только в исходном модуле: `canMove` только для `source.kind === 'appointment'` (`:4131, 4140`; CAL-01).
4. Срок задачи ресурс не занимает (легенда `:1909`; `roadmap.js:14`).
5. База знаний: приватные страницы не возвращаются сервером, поиск — только по доступным; публикация создаёт неизменяемую версию с проверкой базовой (`api.js:93, 467–476`).
6. Данные: представление исходных сущностей с теми же правами; строка открывает исходную карточку; скрытое поле («Начисление») не участвует в фильтре/сортировке/выгрузке (`:1962, 4182, 4206`; DATA-05).
7. Файлы: всегда привязаны к родителю; открытие — проверка доступа к родителю и короткая ссылка; состояния reserved → uploaded → scanning → ready | rejected; до `ready` файл не подтверждение (`:1983, 1989`; FILE-02/03).
8. SPA: завершение списывает по техкарте один раз (`ap.status !== 'confirmed'` → `duplicate`); при нехватке факт услуги сохраняется, учёт — на решение владельца (`api.js:479–498`; SPA-03; D14 `docs/v0.1/08-domain-scenarios.md:296`).
9. Касса: операции не удаляются, исправление — сторно обратной операцией; сторнированную и сторно-операцию повторно сторнировать нельзя (`api.js:517–526`; CASH-02). Принятый расход водителя — предложение, проведение — отдельная операция с правом кассы (`:2031`).
10. Ремонт: факт по работе меняется только при приёмке; «Принять объём» — одна команда везде, повтор → `conflict`; при приёмке списываются материалы отметки (`api.js:542–549`; `docs/19-construction.md:93`). Отметка не может превысить план более чем на 10 % (`api.js:534`).
11. Без права финансов нет вкладок «Смета», «Финансы», «Оплата бригады», «Подрядчики», «Кабинет заказчика», карточки «Деньги» и пунктов очереди с суммами (`:4291, 4304, 4306`; `docs/19-construction.md:68, 94`).
12. Готовность в шапке = принято + на приёмке по объёмам; для заказчика — по закрытым актам (`:4320, 2052`).
13. Статус всегда = иконка + текст + цвет (чипы `ch`), не только цвет (`docs/design-system/components.md:8`).
14. Тост успеха — только после ответа сервера (`run` ставит тост после `await fn()`).
15. Любая изменяющая команда при «Нет связи» падает с `offline` и не меняет состояние (`api.js:52, 99–104`).
16. При `restricted`/`suspended` новые операции SPA, кассы, отметок прораба запрещены (`assertActive`), чтение сохраняется.

## 14. Открытые вопросы

1. **Конфликт базовой версии базы знаний** в демо не воспроизводится без второго актора; e2e нуждается в хуке мока (`api.js:471`).
2. **`kb.treeMax`** зависит от `s.w` (ширина окна), а не от W с учётом выбранной ширины кадра (`:4159` vs `:2829`) — на «390 · телефон» при широком окне дерево остаётся 300 px.
3. **Утечка данных «Альты» в «Лотос»**: календарь оставляет ресурс «Илья Васильев · водитель» с бронью «Рейс Р-208» (`mock-data.js:52–53`); файлы содержат «Север Логистик · документы» и «Машина Е 905 НА 77» (`:4218`); крошка SPA «Салон и SPA «Тихое место» · все специалисты» захардкожена (`:4235`).
4. **hiddenNote «Поле «Начисление» скрыто правами…»** показывается и владельцу, если поездок нет (`:4206`) — формулировка вводит в заблуждение.
5. **Сервер не проверяет права и подписку в `moveBooking`** (`api.js:454`), `assertActive` отсутствует в `reverseCashOp`, `acceptWorkLog`, `resolveIssue`, `saveKbPage`.
6. **Двойная отправка**: кнопки «Провести в …», «Опубликовать vN», «Отправить отметку на приёмку», «Принять объём», «Сторнировать» не блокируются по `busy` (только календарь и SPA) — в кассе и ремонте двойной клик создаст две операции/отметки.
7. **«Принять объём» на «Главной»** называется «Принять» и лишь открывает объект (`:4052`), тогда как README (`:154`) и `docs/19-construction.md:93` говорят об одной команде.
8. **Дата «сегодня»**: приложение — 1 октября 2026 (`:1890, 4095`), дочерний макет графика — 20 октября (`Ремонт и стройка.dc.html:134, 473`), даты отметок `at = HH:MM` текущего времени браузера (`api.js:13, 538`).
9. **Автор отметки** жёстко «Алексей Соколов» (`api.js:538`), автор версий базы знаний и кассовых операций — имя актора; дата версии `01.10.2026`, кассы `01.10`.
10. **Дочерние вкладки** (Замер … Кабинет заказчика) не ходят в API, не проверяют права, не пишут в кассу (подсказка «операции появились в кассе» ложна в контексте CRM); суммы в «Деньги» берутся из локального состояния макета.
11. **Пустые состояния** без текста: календарь при отсутствии ресурсов (невозможно по текущим фильтрам), журнал кассы «Лотоса», статья базы знаний при пустом поиске.
12. **Файлы**: список не ограничен областью/правами (кроме гейта), нет пагинации, размеры захардкожены.
13. **Бейдж вкладки «Документы»** у прораба учитывает `draft` (суммы скрыты, но счётчик виден) (`:4291`).
14. **Канонические имена прав** отличаются от прототипа (`docs/11-permissions.yaml:179–190`): `calendar.read → calendar.bookings.read`, `knowledge.write → knowledge.create/update`, `data.read → data.catalog.read/data.query`, `repairs.worklogs.* → repairs.work_logs.*`; `repairs.finance.read` — PROPOSED.
15. **Персонажа с `data.view` без `data.export`** в сидах нет — состояние «Выгрузить» disabled проверяется только через созданную роль.
16. **Единицы готовности**: в макете объёмы складываются напрямую (все работы в м²); в продукте доля — по стоимости в смете (RS-07, `docs/19-construction.md:92`).
17. ⚠ не найдено в источниках: поведение `module_readonly` для SPA/ремонта (баннер только для логистики, `:3086`), скелетоны отдельных страниц, порядок сортировки очереди в обзоре объекта (фиксирован порядком кода).

1. Семь страниц + дочерний макет: шаблон ~260 строк в основном файле (`:1887–2150`) + 465 строк дочернего шаблона; логика ~245 строк VM (`:4109–4352`) + ~435 строк дочерней логики.
