## 1. Цель

Ответ владельца на D-04: «→ 17: закрепить в CI и прогнать миграции заново — час работы, зато без двух версий».

1. Integration-тесты backend (testcontainers) и CI работают на одном образе — `postgres:17.11` по digest, тот же, что у стенда compose. Образ `postgres:16.4` и второй прогон миграций сняты.
2. Образ закреплён в CI явно: jobs `integration` и `isolation` в `.github/workflows/ci.yml` задают `PG_TEST_IMAGES` тем же digest; тест сверяет workflow, compose и хелперы.
3. Образ без digest testcontainers-хелперы не запускают (`PG_TEST_IMAGES=postgres:17` → ошибка до Docker): прогон воспроизводим.
4. Миграции control и tenant прогнаны заново на 17.11 (`go test -tags integration -count=1 ./migrations/...`).
5. ADR 0005 — итог («сделано в W2.49»), README стенда и комментарии compose без 16.4.

## 10. Риски и решения по умолчанию

- Комментарии «Проверено на PostgreSQL 16.4» в применённых SQL-миграциях (control 0001, 0002; tenant 0001) не правятся: файлы миграций неизменяемы после применения (W0.06, стюард). Проверка теперь — на 17.11 (этот WS); исправление комментария — решение стюарда (вопрос в отчёте).

- Провайдер D-05 с другой мажорной версией: `PG_TEST_IMAGES` остаётся переопределением (образ по digest) — прогон на версии провайдера без правки кода.
