## 1. Цель

1. **Пакет `backend/internal/platform/notify/mail`** на stdlib (`net/smtp`, `mime`, `mime/quotedprintable`, `net/mail`), без новых зависимостей:
   - `Message` и интерфейс `Sender` (`Send(ctx, Message) error`);
   - `SMTP` — отправитель: `EHLO`, `STARTTLS`, если сервер его предлагает, `AUTH PLAIN` при `SMTP_USERNAME`, `MAIL`/`RCPT`/`DATA`, `QUIT`; срок на всё письмо (10 с); без TLS — только при `AllowPlain` (`APP_ENV=dev|e2e`), в prod без `STARTTLS` — ошибка до `MAIL FROM`;
   - `Off` — доставка выключена (нет `SMTP_HOST` вне prod): письмо не уходит, в журнал — только маска адреса и тема;
   - `FromEnv` — конфиг `SMTP_HOST`, `SMTP_PORT`, `MAIL_FROM`, `PUBLIC_ORIGIN` (иначе первый `ALLOWED_ORIGINS`), `SMTP_USERNAME`/`SMTP_PASSWORD`; в prod всё обязательно и `PUBLIC_ORIGIN` — https;
   - `Invitations` — письмо приглашения по эталону «Оформление → Письмо» (`design-stage-1`, `Ортус CRM.dc.html:1424–1432`): отправитель «<организация> · через Ортус», текст «<кто пригласил> приглашает вас в «<организация>». Приглашение действует 7 дней.», кнопка/ссылка «Принять приглашение» → `<PUBLIC_ORIGIN>/auth/invitation#token=<token>`, подвал «Письмо отправлено по поручению организации. Если вы не ждали приглашения, просто удалите его.» и «Работает на Ортус» (`BRAND_DEFAULT.poweredBy = true`, оформления на сервере ещё нет);
   - `mailtest` — фейковый SMTP-сервер для тестов (STARTTLS с самоподписанным сертификатом, отказы по команде, разбор MIME).
2. **`inviteMember` (W1.06) отправляет письмо.** Токен из `invitations.Issue` не отбрасывается; письмо уходит **после COMMIT** обеих БД, без блокировок и соединений команды (Q-W1.41-1, возврат 1; первая версия слала его до COMMIT): сбой SMTP → компенсация (приглашение отозвано, спящие назначения и карточка удалены, аудит `access.invitation.revoke`) и 503 `dependency_unavailable`; 503 не сохраняется ключом идемпотентности, повтор приглашения проходит. Токен в открытом виде нигде не хранится (в control — только SHA-256), не пишется ни в аудит, ни в журналы, ни в ответ API.
3. **`cmd/api`** читает конфиг почты при старте (ошибка — код 2) и передаёт `Invitations` хендлеру назначений.
4. **Приглашение владельца оператором** — пути нет: `invitations.Issue` вызывает только `inviteMember`; провиженер (W1.02) создаёт карточку владельца, но приглашения не выпускает (Q-W1.03-6 открыт). Пакет готов к подключению: тот же `Invitations.SendInvitation` (integratorNotes).
5. **Стенд:** письмо видно в Mailpit API `GET /api/v1/messages` слота; приглашённый по ссылке принимает приглашение и видит организацию в `/me/context` (на это опирается W1.30).

## 4. Контракты

Контракт API не меняется (тег Access, `inviteMember` → 201 `Invitation` без токена; 503 `dependency_unavailable` уже в контракте операции). Внутренние интерфейсы:

```go
package mail
type Message struct{ FromName, To, Subject, Text, HTML string }
type Sender interface{ Send(ctx context.Context, m Message) error }
type Config struct{ Host string; Port int; From, Origin, Username, Password string; AllowPlain bool; Timeout time.Duration }
func FromEnv(getenv func(string) string, appEnv string) (Config, error)
func New(cfg Config, log *slog.Logger) Sender           // SMTP или Off
type Invitation struct{ To, Token, Business, Inviter string; Valid time.Duration }
type Invitations struct{ Sender Sender; From, Origin string }
func (s Invitations) SendInvitation(ctx context.Context, inv Invitation) error
func InvitationLink(origin, token string) string        // <origin>/auth/invitation#token=<token>

package assignments
type InvitationMail interface{ SendInvitation(ctx context.Context, inv mail.Invitation) error }
func (h *Handler) WithInvitationMail(m InvitationMail) *Handler
```

## 10. Риски и решения по умолчанию

| # | Риск / вопрос | По умолчанию |
|---|---|---|
| 1 | Когда отправлять письмо (Q-W1.41-1) | **Возврат 1: после COMMIT с компенсацией при сбое SMTP** (ревью: письмо в транзакции держало строку `tenants`, строку `access.policy_state` и два соединения пулов до 10 с). Первая версия: **до COMMIT, в транзакции команды.** Вариант «после COMMIT, при сбое — pending и журнал» тупиковый: повторное приглашение на тот же адрес — 422 «Участник с таким адресом уже есть.» на 7 дней, операции resend в контракте нет. До COMMIT: сбой SMTP → 503 и откат, повтор проходит; сбой COMMIT после отправки — ссылка в письме ведёт на 404/«отозвано», владелец видит 503 и повторяет. Цена — блокировка строки `tenants` на время SMTP (срок 10 с). Outbox с токеном под AEAD — когда понадобится повтор без участия владельца (этап 3, реальный SMTP) |
| 2 | Тема письма (Q-W1.41-2) | В эталоне темы нет: «Приглашение в «<организация>»» |
