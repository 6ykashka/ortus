# 15. Качество и безопасность — версия 0.2

Стратегия тестирования, модель угроз и вопросы обработки персональных данных. 1 октября 2026 года. Документ не является юридическим заключением.

## Пирамида тестов

| Уровень | Что проверяет | Инструмент | Когда |
|---|---|---|---|
| Unit (Go, TS) | Доменные правила: совместимость машины, загрузка по участкам, валидации, evaluator прав | `go test`, Vitest | Каждый PR |
| Integration | Репозитории, транзакции, ограничения БД, outbox | testcontainers-go (PostgreSQL, MinIO) | Каждый PR |
| Isolation suite | Чужой тенант, чужая фирма, функция driver, отзыв прав — по всем каналам | Go-тесты на фикстурах | Каждый PR, блокирует merge |
| Concurrency suite | Бронь, квота, идемпотентность, последний владелец | Go: N горутин против реальной БД | Каждый PR |
| Contract | Ответы API соответствуют OpenAPI; fuzz по схемам | Schemathesis | Nightly на dev |
| Component | Компоненты DS: состояния, клавиатура, aria | Testing Library, Storybook + axe | Каждый PR |
| E2E | Основной путь смены и негативные проверки из прототипа | Playwright (телефон 390, desktop 1440) | Каждый PR (smoke), nightly (full) |
| Load | p95 чтения ≤ 500 мс, записи ≤ 800 мс на профиле пилота; «шумный» тенант | k6 | Перед stage-релизом |
| Restore drill | Восстановление одного тенанта с файлами, RPO/RTO | Скрипт SRE | Перед пилотом, далее ежеквартально |

## Фикстуры изоляции

Один сид для всех негативных тестов:

- Тенант **A** «Холдинг»: Москва, Самара, Петербург × 4 фирмы. Тенант **B** «Чужой клиент» с теми же названиями ролей и фирм.
- Менеджер Москва-1; менеджер Москва-2; руководитель региона Москва; владелец.
- Водитель Москва-1; водитель Москва-2 во временном назначении на Москва-1.
- Пользователь с двумя ролями: «изменять» в Москва-1 и «читать» в Самара-2 (проверка перемножения).
- Пользователь с функцией driver и попыткой получить `fleet.earnings.read` через группу.

Каждый новый эндпоинт добавляет строку в матрицу: актор × объект × ожидаемый результат (200 / 403 / 404). Каналы: HTTP, Data Hub (count, фильтр, сортировка, агрегат), экспорт, поиск, файлы, уведомления, realtime, аудит.

## Критерии приёмки → тесты

| AC | Уровень | Сценарий |
|---|---|---|
| AC-01 | Isolation | Менеджер А подставляет ID склада/машины фирмы Б → 404, время ответа не различается заметно |
| AC-02 | Isolation | Сессия тенанта A с `tenantId` B → 404, запрос не открывает пул B |
| AC-03 | Concurrency | 100 параллельных броней одного интервала → 1 × 201, 99 × 409 |
| AC-04 | Integration + E2E | Блокирующий дефект или 4 фото из 5 → `trips.start` 409 |
| AC-05 | Isolation | Водитель: Trip DTO, `/earnings`, Data Hub, экспорт, поиск, аудит, уведомления — нет суммы и метаданных |
| AC-06 | Isolation | Временный водитель видит только согласованный рейс и срок; после срока — 404 |
| AC-07 | Concurrency | 100 повторов команды с одним ключом → один эффект |
| AC-08 | Contract | Публичный токен формы на `/vehicles` → 401/404 |
| AC-09 | Integration | Ответ v1 читается после публикации v2 по структуре v1 |
| AC-10 | Integration | Отзыв роли во время экспорта → выдача файла 403 |
| AC-11 | E2E | Read-only: чтение и экспорт работают, создание — 403 `tenant_read_only` |
| AC-12 | E2E | Отключение логистики с активным рейсом: новый рейс 403, текущий сдаётся |
| AC-15 | Restore drill | Данные, файлы и права одного тенанта совпадают; RPO/RTO измерены |
| BR-T1 | Isolation | Владелец A сохраняет оформление → `GET /tenants/B/branding` и `/public/branding/{slugB}` не меняются; PUT в чужой тенант → 404 |
| BR-T2 | Isolation | Аккаунт в двух тенантах: после смены организации приходят оформление, меню и термины только текущего тенанта; кеш клиента сбрасывается |
| BR-T3 | Contract | Цвет с контрастом ниже 4.5:1 сохраняется с `accent_used` ≥ 4.5:1; SVG с `<script>` отклоняется 422 |

## Модель угроз (STRIDE, верхний уровень)

| Угроза | Пример | Меры | Тест |
|---|---|---|---|
| Spoofing | Подмена `tenantId`, кража cookie | Resolver по membership, HttpOnly/Secure/SameSite, CSRF + Origin | Isolation, e2e CSRF |
| Tampering | PATCH чужих полей (`ownerUnitId`, сумма) | Строгие DTO, unknown fields → 400, отдельные команды transfer | Contract |
| Repudiation | Спор о приёмке или начислении | Аудит actor/time/target/reason/result, серверные timestamps | Integration |
| Information disclosure | Начисление через агрегат, счётчик, файл, лог | Field policy до сериализации, scope до count, логи без restricted | Isolation (AC-05) |
| Denial of service | «Шумный» тенант с экспортом и фото | Лимиты пулов, очереди с fairness, rate limit, асинхронный экспорт | Load |
| Elevation of privilege | Менеджер создаёт группу с правами и добавляет себя | Delegation closure, CODEOWNERS на authz | Unit + isolation |

Дополнительно до пилота: пентест основного пути, проверка зависимостей (SCA) и образов в CI, SBOM, политика ротации секретов, MFA для владельцев и операторов.

## Персональные данные

Ортус обрабатывает ФИО, телефоны, email, фото машин (на них могут попадать люди и номера), данные о рейсах и, позже, клиентов SPA. Вопросы ниже нужно закрыть с юристом до приёма реальных данных:

1. Роли сторон: клиент — оператор, Ортус — лицо, обрабатывающее данные по поручению? Нужен шаблон поручения/договора обработки.
2. Требование 152-ФЗ о локализации баз данных с ПДн граждан РФ на территории РФ → выбор размещения (D-05).
3. Уведомление Роскомнадзора, политика обработки ПДн, согласия сотрудников и клиентов SPA.
4. Сроки хранения и удаления после расторжения (PLAT-05), учёт резервных копий.
5. Медицинские сведения SPA не собираются без отдельного анализа (SPA-04).
6. Геоданные водителей в пилоте не собираются; появление GPS — отдельное решение.

Технические меры, не зависящие от ответов: шифрование хранилища и бэкапов, TLS везде, минимальный offline-кеш без финансовых данных, удаление локальных данных при logout, доступ поддержки только через `support_grants`.

## Доступность

Цель — WCAG 2.2 AA для основных сценариев; формальное соответствие заявляется после отдельного аудита. В CI: axe на компонентах и e2e-страницах. Вручную на каждом релизе: клавиатура, VoiceOver/TalkBack на пути водителя, масштаб 200 %.
