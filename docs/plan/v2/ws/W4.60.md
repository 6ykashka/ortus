## 1. Цель

Заменить ответы 501 операций W4.07 сервером control DB с поведением сценарного сервера W4.07 (`msw/billing/plans.ts`, `msw/platform/{pricing,usage,accounts,roles,audit}.ts`, `msw/branding/index.ts`, conformance `cases/billing-w407.ts`) и описаний контракта:

1. **Места и подписка.** `getTenantSubscription`, `getPlatformSubscription` — поля `tierCode`, `tierName`, `termMonths`, `priceVersion`, `monthlyAmount`, `periodAmount`, `seats` (`tenant_seat_usage`, безлимит — `limit: null`); `Tenant.seats`, `memberCount`, `tierCode`, `brand` во всех ответах `Tenant` оператора (список, карточка, создание, переименование, приостановка, возобновление).
2. **Тарифная сетка.** `getTenantPriceBook` (действующая, запланированная, версия оплаченного периода; без авторов); `listPriceBookVersions` (`includeCancelled`, `subscriptionCount`), `publishPriceBookVersion` (проверки черновика с `violations`, одна запланированная — 409, в одной транзакции закрыть действующую и вставить новую), `cancelPriceBookVersion`.
3. **Заявки на тариф.** `list/create/cancelSubscriptionChangeRequest` владельца (расчёт по действующей версии на момент заявки, SR-N, одна открытая — 409 `request_pending`, мест меньше занятых — 422 `tier_below_usage`, текущий тариф и срок — 422, журнал `platform_audit` от владельца); `listPlatformSubscriptionRequests`, `decidePlatformSubscriptionRequest` (отказ с причиной; одобрение — новая версия прав мест и условия периода, пробная/grace/read_only организация становится active; повышение — сразу, понижение — с конца оплаченного периода через планировщик биллинга, сдвиг, пока занятые места больше нового лимита); уведомления владельцам и `context.changed`.
4. **Использование.** `getPlatformUsage` — только метаданные control DB: сводка, сигналы с порогами 17-го документа, модули, строки организаций (снимок `tenant_usage_daily`, входы не позже «сейчас», Q-W4.07-7).
5. **Каталог аккаунтов и операторы.** `listPlatformUsers` (`q`, `tenantId`, `filter`, `counts`), `getPlatformUser` (участия), `lock/unlockPlatformUser` (причина, сессии отзываются), `resetPlatformUserMfa`; `listPlatformOperators` (`me`, `activeOwnerCount`), `invitePlatformOperator` (домен платформы, почта клиента — 422 `client_account`), `updatePlatformOperator` (`If-Match`, последний активный владелец — 409 `last_owner_required` под блокировкой, себя не менять, владелец — только активный со вторым фактором).
6. **Права ролей операторов** (Q-W4.07-14, Q-W4.07-18): `grants` Go = `PLATFORM_GRANTS` MSW, тест сверки; шлюз `/platform/**` проверяет x-permissions операции по роли (другой роли — 403 `forbidden_action` до хендлера).
7. **Оформление.** `getTenantBranding`, `updateTenantBranding` (новая неизменяемая версия, `If-Match "rev-N"`, контраст ≥ 4.5:1 шагами 4% к чёрному, производные акцента, термины, меню, `tenants.display_name`, журнал, уведомление владельцам, `context.changed`), `uploadBrandingAsset` (тип по байтам, SVG — XML-парсер с allowlist элементов и атрибутов, размер растрового знака PNG/JPEG/WebP ≥ 512 квадрат, 413); `TenantContext.branding` (`BrandingTheme`) в `getMyContext`/`selectTenant`; отдача файлов `GET /brand-assets/{sha}.{ext}` с `Content-Type` записи, `nosniff`, `CSP sandbox`.
8. **Шлюз cmd/api**: `getTenantPriceBook`, `list/create/cancelSubscriptionChangeRequest` открыты владельцу в `grace`/`read_only`/`suspended` (Q-W4.07-3, MSW `BILLING_ANY_STATE`); тег Branding смонтирован.
9. **Go-сид** шага 4.6: сетка v1–v2, условия периодов подписок, заявка SR-12 «Лотоса» (+ `setval` последовательности SR-N), оформление организаций сида, заметка отключённого оператора, снимки использования.
10. **Строки изоляции** `billing_w407.yaml`, `platform_w407.yaml`, `branding_w407.yaml` — снять `pending`; положительные строки команд (заявки в фикстурах — возврат 1; где команда меняет данные соседних параллельных строк или нужен `If-Match`/хранилище объектов — тесты стека и отклонение в отчёте); акторы-операторы support, billing, admin и строки отказа ролей.

`requestSubscriptionChange` (PATCH 0.1) в карточку не входит: его заменила заявка `createSubscriptionChangeRequest` (Q-16, D-33); остаётся 501 — вопрос в отчёте.

## 10. Риски и решения по умолчанию

- Q-W4.07-2: заявка — по версии, действующей в момент заявки; одобрение фиксирует её цену.
- Q-W4.07-3: биллинг владельца открыт в `grace`/`read_only`/`suspended`; `getTenantSubscription` в `suspended` закрыт, как в 0.1.
- Q-W4.07-5: стандартное оформление — версия 1 без строки; первое сохранение — версия 2 (сид пишет версии сида с автором-аккаунтом).
- Q-W4.07-6: файл оформления — base64 в JSON, байты в хранилище объектов под ключом `branding/<sha256>.<ext>`, отдаёт cmd/api по `/brand-assets/…` (бакет стенда приватный).
- Q-W4.07-14/18: шлюз отказывает роли до хендлера (403); строка `denied` в журнал пишется только командами сервиса (как W1.48).
- Q-W4.07-15: последний активный владелец проверяется под блокировкой строк операторов; роль автора перепроверяется там же (гонка — 403).
- Сброс второго фактора и блокировка — флаги control DB (Keycloak admin API на стенде нет); приглашённый оператор — аккаунт-заготовка без привязки к realm до первого входа.
- Понижение тарифа планировщик применяет фоновой задачей вместе с жизненным циклом подписки (`SUBSCRIPTION_SWEEP_INTERVAL`); пока занятые места больше нового лимита — сдвиг на сутки.
- Заявка SR-9 «Карго» в Go-сид не входит: у организаций без БД стенда нет членств (автор заявки — FK на членство).
