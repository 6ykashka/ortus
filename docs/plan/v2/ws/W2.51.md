## 1. Цель

1. **Пул водителей (S2-14, AUTH-06/07, AC-06).** В контракте 0.1 есть каталог пула, запрос, решение и чтение запросов; нет публикации водителя, временного назначения со сроком и автозавершения. Добавить по эталону (`Ортус CRM.dc.html` `pg.pool` :522, `poolVM` :3309, модалка `request` :2264; `ortus/api.js` `requestDriver`, `decideRequest` :541–552; `mock-data.js` `pool` :222):
   - публикация водителя своей фирмы в пул, чтение и снятие публикации (фирма-источник);
   - каталог пула и запрос — с названием домашней фирмы, ссылкой на публикацию (минимальная проекция AUTH-06);
   - запрос показывает фирме-источнику комментарий, рейс и автора; решение — автора, время и комментарий;
   - одобрение создаёт временное назначение (`TemporaryDriverGrant`: срок, рейс, состояние) и автоматически завершается (`completed`); после срока временный водитель получает 404 по рейсу (AC-06), начатый рейс можно безопасно закрыть (AUTH-07, D09);
   - фильтры запросов (входящие / исходящие, статус); MSW с состояниями, примеры, конформанс.
2. **«Данные» (S2-16, AC-14).** Проверить `listDatasets` / `queryDataset` на наборах эталона `dataVM` (:4183) «Автомобили», «Поездки», «Расходы»: колонки, фильтры, сортировка, пагинация, право набора, скрытое поле «Начисление». Добавить недостающее (право набора, тип объекта строки, варианты выбора, поиск по видимым полям, число видимых строк, признак выгрузки, подписи скрытых полей) и MSW наборов этапа 2.
3. **Q-W2.02-14.** Индекс `sched.reservations (bundle_id)` — миграцией tenant следующего свободного номера (0014) вместе с полями пула.
