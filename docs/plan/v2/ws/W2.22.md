## 1. Цель

После W2.22 водитель «Альты» (Илья Васильев, функция «Водитель») на телефоне (приоритет 390) и на компьютере в режиме `mock`:

- открывает «Сегодня» (h1 «Моя смена») и «Автомобили» из меню «Работа» и по прямым URL `/t/:tenantId/today`, `/t/:tenantId/cars` (ADR-0001);
- видит свою смену: шаги «Машина — Осмотр — Рейс — Сдача — Приёмка», карточку рейса (номер, название, состояние, «дата · окно · N точек · км · груз», требования к машине);
- **бронь (S2-02, S2-03):** список машин своей фирмы с совместимостью (`compat`): причины несовместимости, «Подходит рейсу: …», «Забронировать» → `reserveVehicle` (бронь с hold и сроком) → «Бронь подтверждена сервером · {машина} · держится до {holdExpiresAt}»; 409 → «Конфликт брони» и «Обновить список»; офлайн, пробный период и отключённый модуль — бронь недоступна с пояснением;
- **осмотр перед выездом (S2-04, S2-05):** чек-лист по версии (`getInspectionChecklist`), пять фото через сессии загрузки (`initiateUpload` → PUT → `completeUpload` → проверка файла), пробег (`odoError`), топливо, дефекты (критический — только перед выездом), панель «Осталось: …» (`inspMissing`);
- **выезд (S2-06):** «Выехать на маршрут» = `submitInspection` (departure) + `startTrip`; критический дефект — «Отправить на проверку менеджеру» → «Выезд заблокирован»; после «разрешить выезд» менеджера водитель сам нажимает «Выехать на маршрут» (Q-W2.00-2);
- **рейс (S2-07):** «Маршрут» с отметками «Прибыл» (только на устройстве), «Завершить рейс» → диалог `modal-finish-route` → `finishTripRoute`;
- **расходы (S2-08):** «Добавить расход»: категория (пять кодов D-12, ADR-0013), сумма, дата, литры для топлива, комментарий, фото чека (сессия загрузки) → `createTripExpense`; список «Принято сервером»;
- **сдача (S2-09):** «Осмотр при сдаче» (пробег ≥ пробега при выезде, новые дефекты без критичности, комментарий для менеджера) → «Сдать машину» = `submitInspection` (return) + `returnTrip` → «Ожидает приёмки менеджером» с итогами «Пройдено», «Расходы»; доработка — «Менеджер вернул смену на доработку», «Исправить: …»; «Смена принята».

Режим `stand`: backend W2.02, W2.04, W2.05 в `main` нет — строки `@stand` e2e пишутся с `test.fixme` и причиной (verification-protocol §2).

## 10. Риски и решения по умолчанию

1. **Заголовок.** Пункт меню «Сегодня», h1 «Моя смена» (эталон :665). Ожидание заглушки «Сегодня» в `access-gate.spec.ts` меняется на «Моя смена».
2. **Демо-кнопки не переносятся (PD-54):** «Демо: добавить фото», «Демо-фото чека», «Демо: открыть как логист», «Начать новую демо-смену». Подсказка под фото — без «Файлы остаются в браузере.» (файлы уходят на сервер). Allowlist.
3. **Снять бронь** («Отменить бронь», «Выбрать другую машину») — только с `fleet.reservations.manage` (Q-W2.00-1); у водителя шаблона кнопок нет. Allowlist.
4. **Выезд — две команды** (Q-W2.00-2): одно нажатие «Выехать на маршрут» шлёт осмотр и старт; если старт не прошёл (сеть), повтор шлёт только `startTrip` с уже принятым осмотром. После «разрешить выезд» — статус «Менеджер разрешил выезд: дефект признан некритичным» и «Выехать на маршрут».
5. **Срок брони** — `holdExpiresAt` (Q-W2.00-4), эталон «09:30». Allowlist.
6. **Фото.** Слот готов только после проверки файла сервером (`ready`); между передачей и проверкой — «Загрузка 100%». Офлайн-очередь фото («На устройстве · ждёт связи») — W2.24; в W2.22 нет связи — «Ошибка загрузки» и «Повторить». В режиме `mock` PUT по ссылке хранилища обслуживает e2e (`context.route`), проверку файлов завершает `POST /api/v1/dev/scenario {scanFiles}` — замечание владельцу адаптера (W0.13).
7. **Офлайн расходы и сдача** — очередь W2.24. В W2.22 без связи «Сохранить расход» и «Сдать машину» отправляют команду и получают тост «Нет связи с сервером. Операция не выполнена.»; бронь и выезд недоступны с пояснением эталона (D-09).
8. **Категории расходов** — пять кодов D-12 (ADR-0013: «W2.22 — выпадающий список»): `select` «Категория» вместо двух кнопок эталона. Allowlist.
9. **Нет рейса** — пустое состояние без эталона (03 §15 п. 11): «Рейсов на сегодня нет».
10. **Крошка «Автомобили»** — «{регион} / {фирма}» подразделения машин при `org_units.read`; у водителя права нет — крошки нет. Allowlist.
11. **Отметки «Прибыл»** — только на устройстве (03 §15 п. 8): `sessionStorage` вкладки по рейсу.
12. **Заглушки `@ortus/ui` `PhotoSlot`, `Stepper`, `SyncState`** (владелец W2.22 в `contract.ts`) — вне карточки (`routes/logistics/driver/`); пропсы заглушек расходятся с состояниями эталона (`local`/`done` вместо `queued`/`ready`). По умолчанию — части экрана в каталоге страницы, заглушки остаются; вопрос интегратору.
13. **Дата расхода по умолчанию** — дата рейса (эталон — «сегодня» демо 01.10.2026).
14. **Ожидание решения менеджера** — экран перечитывает смену каждые 10 с в состояниях «Дефект на проверке» и «Ожидает приёмки» (канала реального времени в mock нет).
15. **Сжатие фото (продолжение 17.10, ответ владельца D-08, ПДн §6).** Фото осмотра и чека сжимается на клиенте до 1600 px по большей стороне и перекодируется в JPEG 0,85 — EXIF с геоданными снимается; без декодера изображений — исходный файл.
16. **Хранилище режима mock в браузере.** Билет загрузки MSW указывает на `https://storage.example.invalid`; в браузере (Vite `VITE_ADAPTER=mock`) PUT по нему не обслуживается и проверка файла сама не завершается — e2e подменяет PUT маршрутом контекста и завершает проверку `scanFiles`. Для показа в режиме mock нужен обработчик в `adapter/src/msw/browser.ts` (владелец W0.13) — вопрос интегратору.
