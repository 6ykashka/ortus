## Вопросы и решения по умолчанию (`Q-W5.33-N`; в `decisions.md` вносит интегратор)

1. Выдача под отчёт проводится сразу (`issueCashAdvance` → `done`): «Получил(а)» только для входящего перемещения в пути.
2. Роль API хранит только ключи (`Role.permissions`), сумм лимитов нет: поля «Расход/Возврат/Выдача … до, ₽» показаны отключёнными с пояснением; флажки работают. Нужно поле в контракте ролей.
3. Фото чека: `purpose: expense_receipt`, владелец `cash/account` (в контракте нет purpose и родителя кассы для Files).
4. QR — `BarcodeDetector` + сумма из `s=` чека ФНС; где API нет — «QR не распознан. Введите сумму вручную.».
5. Срок отчёта (`dueDate`) ни в `CashAccount`, ни в `CashTransfer` не возвращается: страница читает необязательное `reportDueDate`, пока его нет — чипов срока нет.
6. `AdvanceReceipt.link` требует id объекта: «К чему относится» (свободный текст) уходит в `note`; имя принявшего чек в DTO нет — «Принят» без имени.
7. Шаблоны `driver`/`foreman` в `api/permissions.yaml`, `backend` и примерах не содержат `cash.advance.self`: водитель и прораб получают 403 на кассовые операции. e2e и тесты выдают ключ ролям; шаблонам — стюард.
8. `listCashTransfers` требует `cash.read`: держателю 403 («В пути» — из ответа своей команды в сеансе; дата выдачи — по журналу).
9. `listCashCategories` требует `cash.read`: у держателя 403 — сидовый справочник статей на клиенте (`categories.ts`).
10. Сид mock: нет роли «Кассир салона» в `listRoles`, `scopeOf` (`adapter/msw/core/project.ts`) отбрасывает область `account` — строка Морозовой в `company-users.md` переведена из `out-of-stage` в `label`.
11. «Чеки» — `h2` (эталон — `strong`); allowlist `label`.
12. Суммы — NBSP перед ₽ как в `cash.js`.
