## 3. Права (источник — `permissions.yaml`, разбор repair.md §3)

- «Финансы», «Оплата бригады», «Подрядчики», «Кабинет заказчика» — только с `repairs.finance.read` (владелец — всегда); без права вкладки в хосте нет, а прямой вход показывает отказ.
- «Документы» — всем с `repairs.projects.read`; суммы — только с finance.read (сервер).
- Действия: «Отправить на подпись» — `repairs.documents.send` (или `estimates.edit`); «Начислить по акту» — `repairs.crew.accrue`; «Провести выплату» — `repairs.crew.pay`; доступ подрядчика — `repairs.subcontractors.manage`; ссылка кабинета — `repairs.client_link.manage`; «Сдать объект» — `repairs.projects.hand_over`. Нет права — кнопки нет; сервер всё равно проверяет.
- Режим «только чтение» (модуль отключён) — кнопок действий нет.

## 5. Решения по умолчанию (в `decisionsNeeded`, Q-W6.24-N)

1. Хост вкладок до W6.20 — временный `repair.page.tsx` (замена целиком).
2. Кнопки «Демо: …» эталона не переносятся (Q-W4.00-repair-9): подпись — кодом в публичном кабинете W6.26.
3. «Сдать объект» (в эталоне нет): кнопка во вкладке «Документы», когда акт сдачи подписан, объект в работе и есть право; подтверждение диалогом.
4. Выплата бригаде — предложение операции в кассу (W5.31), не проводка: после «Провести выплату через кассу» начисление в статусе «Ждёт проведения в кассе» (в эталоне сразу «Выплачено»).
5. Срок доступа подрядчика при «Открыть доступ»: прежний срок, если он не в прошлом, иначе сегодня + 14 дней (в эталоне зашито «31.10»).
6. Ссылка кабинета: после выпуска адрес показывается один раз с кнопкой «Скопировать»; в списке — только статус (на сервере хранится хеш токена).
7. Превью кабинета строится по `getClientCabinet`-подобным данным объекта (имя, готовность, этапы) без запроса к публичной операции: у владельца токена нет.
