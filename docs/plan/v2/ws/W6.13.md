## 1. Цель

Сервер тега Repairs для шага 6.4 поверх `repairs.supply_requests`, `repairs.purchases`, `repairs.purchase_lines`, `repairs.project_stock` (tenant 0053): 11 операций.

| Операция | Что делает |
|---|---|
| `createSupplyRequest` | Заявка прораба на материал справочника с датой «Нужно к» (`repairs.supply.request` на объекте); номер `З-n` из последовательности тенанта; сданный объект закрыт |
| `listSupplyRequests` | Заявки видимых объектов (прораб — своих); фильтры `state`, `projectId`; стоимость и «свободно по складам» — только с `repairs.supply.manage` |
| `reserveSupplyRequest` | «Выдать со склада»: резерв на складе в модуле «Склад» (`request → reserved`); не хватает свободного — `repair_stock_insufficient`; не в `request` — `repair_supply_state`; `If-Match` |
| `issueSupplyRequest` | Кладовщик (`inventory.movements.post` в области склада) выдаёт зарезервированное: движение `issue`, остаток объекта растёт на стоимость по цене; `reserved → issued` |
| `consumeSupplyRequest` | Списание на объект (`issued/bought → used`): остаток объекта уменьшается; `If-Match` |
| `createPurchase`, `listPurchases` | Одна закупка на несколько заявок и объектов (`request → ordered`): поставщик, цены (по умолчанию Q-W6.13-1) |
| `receivePurchase` | Получение по чеку QR: заявки `ordered → bought`, стоимость разносится по объектам, остатки объектов растут; повтор — `repair_purchase_state` |
| `listProjectStock` | Остатки на объектах (количество и стоимость), только с `supply.manage` |
| `returnProjectStock` | Возврат излишков на склад: движение `receipt` в «Склад», расходы объекта уменьшаются |
| `transferProjectStock` | Перемещение остатка на другой объект: стоимость переносится, заявки того же материала на целевом объекте уменьшаются или закрываются |

## 3. Решения по умолчанию (в `decisionsNeeded` отчёта)

- Q-W6.13-1. Цена закупки и выдачи. В «Складе» нет денег, «средней цены склада» взять негде. По умолчанию: цена по Q-W4.00-repair-23 с вычетом первого звена — цена последней полученной закупки этой позиции, иначе цена справочника. Выдача со склада оценивается так же.
- Q-W6.13-2. Связь позиции справочника расценок с номенклатурой склада: поля в схеме нет. По умолчанию — совпадение названия (без регистра и пробелов по краям) среди неархивных позиций; нет совпадения — на складе нечего зарезервировать (`repair_stock_insufficient`), при возврате — 422.
- Q-W6.13-3. Перемещение остатка закрывает заявку целиком только состоянием `used` (другие состояния требуют склада или закупки по ограничению таблицы): уменьшенная часть остаётся на объекте.
- Движения `buy` (закупка на объект) и `use` (списание) модуль «Склад» не знает: остаток объекта ведёт `repairs.project_stock`; `issue` и `receipt` пишутся в «Склад» в той же транзакции.
