## Сделано

- **`backend/internal/platform/storage`** — частное объектное хранилище на stdlib (новых зависимостей нет):
  - `Signer` — AWS Signature Version 4: подпись заголовков (`Sign`) и presigned URL (`Presign`), канонический URI и запрос (`%20`, не `+`); сверено с четырьмя примерами AWS (GET Object, PUT Object, GET Lifecycle, List Objects) и примером presigned GET;
  - `S3` — клиент S3 path-style (MinIO): `PresignPut` (тип файла — подписанный заголовок), `PresignGet` (`Content-Disposition: attachment` с UTF-8 именем, RFC 6266/8187), `Stat`, `Open`, `Copy` (CopyObject, ошибка в теле 200 распознаётся), `Delete` (идемпотентно), `EnsureBucket`; ключи объектов и секреты не попадают в ошибки;
  - `Mem` — in-memory `Store` для unit-тестов; `Config`/`ConfigFromEnv` — `S3_ENDPOINT`, `S3_PUBLIC_ENDPOINT` (по умолчанию `S3_ENDPOINT`), `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`; без `S3_ENDPOINT` хранилище «не настроено», половинная настройка — ошибка старта;
  - `miniotest.Start` — MinIO на testcontainers с образом стенда (`MINIO_TEST_IMAGE` меняет), ждёт `/minio/health/ready` и создаёт бакет.
- **`backend/internal/modules/files`** — модуль файлов:
  - правила (`rules.go`): 20 МиБ (413 `payload_too_large`), MIME по назначению (фото осмотров и работ — только изображения; чеки — изображения и PDF; вложения задач и форм — ещё DOCX, XLSX, TXT, CSV), безопасное имя (не путь, без управляющих символов, ≤ 255), SHA-256, ключи `quarantine/<tenant>/<file>` и `files/<tenant>/<file>` (FILE-01), текст `downgrade_below_usage`, расчёт 10 ₽/ГиБ, детерминированный `quoteId`;
  - родители (`parents.go`): явный реестр `Parents` (`ParentKind`: модуль и вид `ObjectRef`, действие чтения родителя, допустимые назначения, SQL строки области `unit_id, project_id, person_a, person_b, title`); `FleetParents()` — рейс, бронь, машина, осмотр, расход (tenant 0002);
  - сессия загрузки (`upload.go`): `Initiate` — тело → вид родителя и назначение (422) → родитель виден (иначе 404) → `files.upload` на нём (иначе 403) → **резерв условным `UPDATE files.usage`** (0 строк → 409 `quota_exceeded`, текст эталона) → файл `reserved`, сессия `issued`, `quota_ledger reserve`, событие `files.upload.deadline_reached.v1` с `available_at = session_expires_at` одной транзакцией → presigned PUT на 15 минут; `Session` — только своя (чужая = 404), просроченная закрывается при чтении, `issued` → `uploaded`, когда объект в карантине; `Complete` — сверка `sha256` тела, наличия, размера, типа и SHA-256 содержимого объекта, затем одной транзакцией под `for update`: сессия `completed`, файл `scanning`, резерв → занято, `ledger commit`, событие `files.file.uploaded.v1`; повтор — 409 (один эффект); `Abort` — `issued`/`uploaded` → `aborted` с освобождением резерва и удалением объекта, `completed` → 409, закрытая → 204;
  - проверка (`worker.go`, `Worker`): `Scan` (событие `files.file.uploaded.v1`) — `BasicScanner` (сигнатура EICAR → `malware_detected`, фактический MIME ≠ заявленного → `mime_mismatch`, пропавший объект → `object_missing`); чистый файл копируется из карантина и становится `ready`, отклонённый — `rejected` с освобождением байтов (`ledger release`); события `files.file.ready.v1` / `files.file.rejected.v1`; `Expire` (событие истечения) закрывает живую просроченную сессию; оба обработчика идемпотентны; роль `ortus_worker`;
  - чтение (`read.go`): `File`/`Download` — файл виден, только если виден родитель (действие чтения вида на ресурсе родителя) **и** `files.read` покрывает его; невидимый родитель, чужой и несуществующий id — один 404 (AC-01, AC-02); видимый родитель без `files.read` — 403; скачивание только `ready` (иначе 409 `photo_not_ready`), presigned GET на 60 с, проверка на каждом запросе (AC-10); `List` — `scopeddb` с `files.read` по колонкам родителя и OR предикатов чтения каждого вида родителя — до пагинации; новые сначала; фильтры `status`, `purpose`; непрозрачный курсор, привязанный к тенанту, субъекту и фильтрам; `ownerTitle` из родителя;
  - «Хранилище» (`quota.go`): `Usage` — квота (`files.usage.limit_bytes`, до первой загрузки — 100 ГиБ), занято файлами (ledger) + оценка БД (`pg_database_size`), резерв, `writeStatus`; `Breakdown` — четыре группы эталона и модули-владельцы, каждая разбивка в сумме = `committedBytes`; `RequestChange` — `quote` (без записи) и `commit` по расчёту последних 60 минут, применение сразу (Q-12), 409 `downgrade_below_usage`, аудит `billing.storage.change` (sensitive);
  - strict-серверы (`server.go`): `Server` — тег `Files` (7 операций); `Billing` — базовый сервер тега: `getStorageUsage`, `getStorageBreakdown`, `requestStorageChange`; операции подписки отвечают 501, их накладывает W1.08 (`subshttp.NewBillingServer(files.Billing, subs)`, возврат 1). Ответы с `Cache-Control: private, no-store` и `X-Request-Id`.

## Осталось fixme / открытые вопросы

`fixme`, `t.Skip` нет. Решения по умолчанию, по которым сделано (вынести в `docs/plan/decisions.md`, раздел исполнителей этапа 1 — файл не мой; дублируются в `decisionsNeeded`):

1. **Имя файла.** В `files.objects` нет колонки имени, а `File.fileName` обязателен. До миграции стюарда (`files.objects.display_name text`) имя хранится параметром `name` заявленного типа: `declared_mime = image/jpeg; name="…"` (RFC 2045, RFC 2231 для кириллицы), API отдаёт тип без параметров. Перенос — `update files.objects set display_name = …` одной миграцией.
2. **Родители вложений.** Явный реестр `files.Parents`; виды пилота объявлены в `files.FleetParents()` по таблицам tenant 0002 (рейс, бронь, машина, осмотр, расход). Модуль fleet (W2.0x) заберёт их; новые модули регистрируют свои виды в `cmd/api`. Неизвестный вид — 422 при загрузке, файл такого вида не виден никому (fail-closed).
3. **Видимость файла.** Чтение вида родителя на его ресурсе **и** `files.read` в области родителя. Невидимый родитель → 404 (как несуществующий), видимый без `files.read` → 403, без `files.upload` → 403.
4. **Квота.** Источник — `files.usage.limit_bytes` tenant DB; строка создаётся при первой загрузке с лимитом 100 ГиБ (`DEFAULT_QUOTA` MSW). Синхронизация с `entitlements` control DB (`storage.bytes`) — владелец подписок (W1.08/W1.11).
5. **Что считает квота** (пересмотрено в возврате 1). Один итог `StorageUsage`: `committedBytes` (файлы + оценка БД `pg_database_size`) + `reservedBytes`. `writeStatus = blocked`, когда итог ≥ квоты; атомарный резерв считает тот же итог (`committed_bytes + reserved_bytes + pg_database_size + n ≤ limit + activity_reserve`); проверка понижения — тоже. `activity_reserve_bytes` (0) остаётся запасом формулы tenant 0001 сверх квоты — для закрытия начатых смен (Q-12), в `writeStatus` не входит. Вопрос в «Возврат 1».
6. **Понижение квоты** применяется сразу, если занято + резерв ≤ новой квоты (Q-12); резерв для начатых смен (PLAT-07) не реализован (Q-12, `activity_reserve_bytes = 0`).
7. **Хранение расчёта `quote`.** Таблицы нет: `quoteId` — UUID v5 от тенанта, объёма, текущей квоты и минуты выдачи; `commit` принимает расчёт последних 60 минут при той же квоте; `StorageChange.id` — UUID v5 от `quoteId`. Цена — 10 ₽/ГиБ в месяц (как MSW).
8. **Антивирус.** `BasicScanner` (EICAR + фактический MIME через `net/http` и `ftyp` HEIC). Подключение ClamAV или сервиса провайдера — интерфейс `files.Scanner`, выбор — D-05/ADR-0006.
9. **Отмена закрытой сессии** — по контракту: `completed` → 409, `expired`/`aborted` → 204. MSW (W0.13) отвечает 409 на `expired`/`aborted` — расхождение mock.
10. **Скачивание не готового файла** — 409 `photo_not_ready` (пример контракта и MSW); описание операции называет `file_not_ready`, такого кода в `errors.yaml` нет.
11. **Срок ссылки скачивания** — 60 с (контракт); MSW — 5 минут (расхождение mock).
12. **Часы.** Сессии и ссылки — по часам системы; `APP_FIXED_NOW` влияет только на оценщик (W1.04), иначе событие истечения в worker закрывало бы сессии e2e сразу.
13. **`depguard` в тестах модулей.** `internal/modules/**` не может импортировать сам себя из `_test`-пакета, `migrations`, `backend/test` и фикстуры: импорты в тестах помечены `//nolint:depguard` с объяснением. Предложение интегратору — разрешить их в `_test.go` правила `modules`.
