# W6.90 Выход этапа 6: объект от замера до сдачи

Этап 6 · выход · вид backend (тесты на стенде) · слот 1 (Vite 5201, API 8101, `ortus-s1`). Зависит от: W6.11–W6.15 (backend в `main`), W6.20–W6.24 (страницы в `main`).

## 1. Цель

Сквозной путь @stand «Объект от замера до сдачи» в `frontend/apps/web/e2e/journeys/stage6/` на трёх ширинах проекта (390 / 768 / 1440) и строки изоляции «Альта / Лотос» к нему. Путь идёт командами API из сессий владельца и прораба «Альты» (настоящий backend), заказчик действует по публичной ссылке, а страницы объекта сверяются глазами пользователя.

Путь: объект-черновик (D-17) → замер → смета по шаблону → отправка → согласие заказчика → «В работу» (работы из сметы) → прораб → отметки прораба (возврат, повтор, приёмка) → допработа и допсоглашение с подписью по SMS → график (из сметы, перенос с причиной, исполнитель, базовый план) → снабжение (заявка, закупка, приход, списание) → акт, начисление бригаде, выплата в кассу → доступ подрядчика → акт сдачи, подпись заказчика → «Сдать объект» на странице → кабинет закрыт (410), объект сдан, правки закрыты.

Вопросы — `Q-W6.90-N` в отчёт (`decisionsNeeded`) со значением по умолчанию.

## 3. Тесты

TDD: сначала спеки красными против настоящего стенда (red-коммит), затем правка сценария и селекторов до зелёного. Строки матрицы изоляции этапа 6 уже в `backend/test/isolation/repairs_w600*.yaml` и зелёные (хендлеры W6.11–W6.15 в `main`); здесь они дополняются сквозной проверкой на стенде: «Лотос» видит чужой объект как несуществующий (404), прораб без прав финансов — 403, водитель без роли ремонта — 403, без сессии — 401, неизвестная ссылка кабинета — 404.

Акты, акт сдачи и подрядчик в API не создаются (Q-W6.15-4, Q-W6.15-7): путь заводит их одной вставкой в базу организации стенда (помощник `stand-db.ts`, `docker exec psql` под учёткой стенда) и дальше идёт настоящими командами. Код подписи берётся из журнала `cmd/api` (заглушка порта SMS пишет его туда — «почта разработчика»).
