# W4.86 — CI в лимитах GitHub, сроки allowlist, инструменты e2e-stand и check-k6, шире стенд БЗ

Вид: docs/инфраструктура CI. Слот 3. Владеет: `.github/workflows/ci.yml`, `tools/ci/**`, `backend/test/load/check-k6.mjs` (+ `lib/port.mjs`, тесты), новые строки `@stand` в `frontend/apps/web/e2e/knowledge.spec.ts`. Правка CI согласуется с интегратором (CODEOWNERS).

## Задачи

1. Шарды: mock — 3835 строк, один воркер ≈ 13,6 строки/мин, поэтому `E2E_SHARDS = 20` (≈ 14 мин, лимит job 25). e2e-stand — 372 строки, ≈ 4,6 строки/мин в CI, поэтому матрица `e2e-stand-shard` (`E2E_STAND_SHARDS = 8`, свой compose на раннере, лимит 30 мин) и итоговая job `e2e-stand` с прежним именем.
2. `allowlist-lint` получает `ORTUS_STAGE` (`CURRENT_STAGE = 4`, env важнее) — в CI и `ci:local`.
3. `tools/ci/e2e-stand.mjs` пересылает аргументы после `--` (`--grep` заменяет `@stand|@mailpit`, список spec дописывается); шард — `E2E_SHARD=<i>/<N>`.
4. `check-k6.mjs`: двойник слушает порт, назначенный ОС (`FAKE_API_PORT` — явный), `BASE_URL` берёт фактический порт.
5. Строки `@stand` БЗ: публикация с If-Match, конфликт, перенос с dryRun, доступ узла, карта и «Проверить сотрудника», автоматизация, архив и восстановление.

## Критерии

`node --test tools/ci/*.test.mjs`, тесты `backend/test/load/test`, `e2e:stand -- --grep knowledge` на слоте 3, `check-k6` без `FAKE_API_PORT`, зелёный run GitHub на main (после влития).
