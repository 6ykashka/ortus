## 1. Цель

Критерий выхода этапа 1 (план v2 §4): «AC-01, AC-02, AC-10, AC-11 в CI (+ AC-07). Владелец пилота на стенде сам настраивает структуру и роли и приглашает сотрудников». Сделать его проверяемым одним официальным прогоном `CI=true corepack pnpm exec node tools/ci/e2e-stand.mjs --slot 14`:

1. **Сценарий владельца** (`e2e/journeys/stage1/owner-onboarding.spec.ts`, `@stand`). Владелец «Альты» (`owner`, Дарья Зимина):
   - создаёт структуру: регион, фирму, подразделение (`createOrgUnit`; экрана «Структура» нет — §10 п. 1);
   - на экране «Пользователи и роли» → «Роли» создаёт роль из шаблона «Менеджер логистики» и сохраняет её;
   - в диалоге «Пригласить участника» приглашает нового сотрудника с этой ролью в области новой фирмы;
   - письмо приходит в Mailpit слота; новый человек входит dev-провайдером впервые (`newcomer()` e2e-kit, W1.50), открывает ссылку письма, нажимает «Принять приглашение» и попадает в «Альту»;
   - сотрудник видит только своё: меню роли (пункты логистики и ядра по правам роли), без пунктов «Компании»; страница «Пользователи и роли» закрыта гейтом; `listMembers` в его области — только он сам;
   - владелец снимает назначение — у сотрудника пункт меню исчезает **≤ 5 с без перезагрузки** (канал реального времени, W1.07/W1.42/W1.49), а следующий запрос с отозванным правом сразу 403.
2. **Приёмочные строки** (`e2e/journeys/stage1/acceptance.spec.ts`, `@stand`):
   - AC-01: сотрудник области «фирма Б» запрашивает карточку участника фирмы А → 404, ответ и `code` как у несуществующего id, медианы времени не различаются заметно;
   - AC-02: сессия «Альты» с `tenantId` «Лотоса» → 404 (API) и в браузере — данных «Лотоса» нет;
   - AC-07: 100 повторов `createOrgUnit` с одним `Idempotency-Key` → один эффект (одно подразделение, повторы — replay);
   - AC-10: отзыв роли во время длинного чтения → следующая выдача 403 (выдачи файла на стенде этапа 1 нет — §10 п. 3);
   - AC-11: организация в `read_only` (оператор, `updatePlatformSubscription`) — баннер «Пробный период завершён.», чтение работает, создание → 403 `tenant_read_only` с текстом словаря; затем состояние возвращается.
3. **Все `@stand`-spec этапа 1 зелёные** в официальном прогоне вместе с новыми строками; `fixme` для строк, у которых backend уже есть, снимаются. Строка `@mailpit` W1.22 входит в прогон (Q-W1.22-13).
4. **e2e-stand поднимает `cmd/worker`** рядом с `cmd/api`: подсказки `context.changed` и входящие идут outbox → worker (W1.42). Без него п. 1 «≤ 5 с» не проверить.
