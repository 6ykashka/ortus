# 0003. D-02 · CI/CD-платформа

Статус: предложено
Дата: 2026-10-15 · Автор: агент W0.01 · Участники: DevOps, tech lead, интегратор
Решение комплекта: D-02 (`design/docs/16-raid-glossary.md`, «Решения, нужные для старта»)
Кто решает: DevOps
Блокирует: S0-02 (шаг 0.5) по 16; в плане v2 — W0.04 (CI), далее все критерии выхода этапов («CI зелёный»)
До решения агенты работают по рекомендации (план v2 §2, B-2).

## Контекст

- S0-02: линтеры, Spectral и полный валидатор OpenAPI, проверка дрейфа codegen, тесты, сборка образов. Правило 3 плана 27: набор изоляции блокирует merge с первого эндпоинта.
- Integration-тесты идут через testcontainers (PostgreSQL, MinIO): раннеру нужен Docker. Канон пиксельных baseline — Linux (PD-32).
- Каркас W0.03 уже сделан под GitHub: `.github/PULL_REQUEST_TEMPLATE.md`, `CODEOWNERS` (два владельца на `api/**`, миграции, authz, финансы), `gh` в среде. Решение плана PD-20 предлагает GitHub Actions.
- Удалённого репозитория пока нет (модуль Go — временный путь `github.com/ortus/ortus-crm/backend`).

## Варианты

1. **GitHub Actions** — плюсы: каркас и CODEOWNERS уже в этом формате, обязательные проверки и ревью двух владельцев «из коробки», готовые действия для Go, pnpm, Playwright, testcontainers; минусы: хостинг кода и раннеров вне РФ, если не использовать self-hosted runners; платные минуты для Linux-раннеров с Docker. Цена: ноль сверх плана.
2. **GitLab CI (self-managed или облако в РФ)** — плюсы: размещение в контуре D-05, свои раннеры; минусы: переписать workflow W0.04 в `.gitlab-ci.yml`, CODEOWNERS с обязательным одобрением — только в платных редакциях. Цена: перенос W0.04 и шаблонов (≈ 1–2 дня агента).
3. **Другая система (TeamCity, Jenkins)** — плюсы: если уже эксплуатируется командой; минусы: нет нативных CODEOWNERS и шаблонов PR, всё вручную. Цена: высокая.

## Решение

Рекомендация: «Та, что уже есть у команды (GitLab CI / GitHub Actions)». Если у команды своей системы нет — GitHub Actions (PD-20): каркас уже на ней. Код и раннеры для prod-pilot — с учётом D-05 (self-hosted runner в контуре размещения).

## Последствия

- Проще: W0.04 пишет `.github/workflows/` сразу; CODEOWNERS работает как есть.
- Сложнее: при выборе GitLab — перенос workflow, шаблона PR и правил ревью; модуль Go меняет путь при появлении remote (`go.mod`, интегратор).
- Сделать: DevOps называет систему и где живут раннеры; интегратор фиксирует remote.
- Как проверим: PR с намеренно красным тестом изоляции не сливается; дрейф codegen ловится job'ом.
