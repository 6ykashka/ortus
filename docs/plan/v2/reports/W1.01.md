## Сделано

- **`backend/internal/platform/idem`** (S1-25, NFR-02, AC-07):
  - `Guard.Serve` — изменяющая операция с `Idempotency-Key` (16–128, `[A-Za-z0-9._:-]`, иначе 400 `malformed_request`): повтор с тем же запросом отдаёт сохранённые статус, `Content-Type`/`ETag`/`Location` и тело байт в байт с `Idempotency-Replayed: true`; другой запрос — 409 `idempotency_key_reused`; повтор во время выполнения — 409 `idempotency_in_progress` и `Retry-After: 1`; ответы 5xx, 429 и повторяемые 409 (`reservation_overlap`, `resources_unavailable`, `idempotency_in_progress`) и паника снимают запись; сбой хранилища — 503 `dependency_unavailable`. Хеш — метод, путь, query и сырые байты тела;
  - `PGStore` на `core.idempotency_keys` tenant DB (захват одной командой `insert … on conflict … where expires_at <= now`, аренда in_progress 2 мин, хранение 7 дней), `MemStore`, `TenantStores` (организация → своя БД, identity/platform → `MemStore`);
  - `CompleteInTx` — итог команды в транзакции её эффекта; при потерянной аренде `ErrLeaseLost`, сервис откатывает эффект.
- **`backend/internal/platform/audit`** (S1-23, NFR-05): `Record` (`audit.events`) и `RecordPlatform` (`platform_audit`) в транзакции изменения, проверка полей по CHECK-ограничениям схемы (`actor_kind`, `result`, `sensitivity`, формат `action` `<домен>.<сущность>.<глагол>`), `request_id` из запроса, нулевые UUID → `null`; `ForRequest` (актор — человек из `TenantContext`, иначе service); `Redact` для restricted-полей `diff`.
- **`backend/internal/platform/events`** (S1-24, A-11): `Publish` (API, только вставка; тип `<домен>.<сущность>.<факт>.v<N>`, payload — JSON-объект), `Once` (`outbox.inbox`), `Registry` (явный, без `init()`; паника обработчика — ошибка), `Outbox` (аренда `FOR UPDATE SKIP LOCKED` с токеном `locked_until`, `Published`/`Failed` по токену, пауза 1 с·2ⁿ до 1 ч, dead-letter после `MaxAttempts`, `DeadLetters`, `Retry`), `Worker` (`RunOnce` по всем организациям, недоступная БД организации не останавливает остальные; `Run` до отмены).

## Осталось fixme / открытые вопросы

`fixme`, `t.Skip` и `pending` нет. Решения по умолчанию, по которым сделано (вынести в `docs/plan/decisions.md` как `Q-W1.01-*`, файл не мой):

1. **Q-W1.01-1 (технический). Ключи identity- и platform-операций** (`selectTenant`, `logout`, `markMyNotificationsRead`, `acceptInvitation`, `platform.*`): в control DB нет таблицы `idempotency_keys`. По умолчанию — `MemStore` процесса (7 дней, очистка истёкших); при нескольких репликах API или перезапуске повтор выполнится заново. Нужна control-миграция стюарда (`idempotency_keys` с `(actor_id, operation, key)`, номер 0005+ после `accounts.last_tenant_id` W1.03) — тогда `TenantStores.Platform` = `PGStore` на control DB без изменений кода Guard.
2. **Q-W1.01-2 (технический). Какие операции идемпотентны.** `catalog.Operation` не знает про параметр `Idempotency-Key`. По умолчанию Guard срабатывает на изменяющей операции, если клиент прислал ключ; обязательность заголовка проверяет обёртка strict server (400). Точнее — поле `Idempotent bool` в `catalog.Operations` (codegen `tools/gen`, стюард/интегратор); тогда Guard не будет кешировать «запросы-чтения» на POST (`queryDataset`, `findCalendarAvailability`) с лишним ключом.
3. **Q-W1.01-3 (технический). Dead-letter без колонки.** По умолчанию dead-letter = `published_at is null and available_at = 'infinity'`, причина — `last_error`. Отдельная колонка (`dead_at`) или состояние — tenant-миграция стюарда; код `Outbox` меняется в двух SQL.
4. **Q-W1.01-4 (продукт/эксплуатация). Ручной повтор** — только CLI `worker retry` (с записью в `audit.events`). Экран или операция оператора для dead-letter — после контракта (этап 3, эксплуатация).
5. **Q-W1.01-5 (технический). Полный валидатор запросов по схеме (Q-W0.09-9)** в W1.01 не подключён: нужен встроенный бандл в генерации (`tools/gen`, сейчас «без встроенной спецификации») и новая зависимость (`kin-openapi`) — зоны стюарда и интегратора. Тела проверяют strict server и `DecodeStrict`; обязательные заголовки — обёртка strict server.
6. **Q-W1.01-6 (технический). Правило для сервисов W1.03+:** изменяющая команда с эффектом в tenant DB вызывает `idem.CompleteInTx` в своей транзакции и откатывает эффект при `ErrLeaseLost`; иначе после падения процесса между фиксацией эффекта и записью итога повтор через 2 мин выполнится снова. Публикация событий — `events.Publish`, аудит — `audit.Record` в той же транзакции.
7. **Q-W1.01-7 (технический). Образы:** один `ortus-backend` на три бинаря (точка входа выбирается `--entrypoint`), `cmd/seed` в образ не входит; `ortus-web` на `nginx-unprivileged` без прокси `/api`. До W1.03 `cmd/api` в контейнере запускается только с `APP_ENV=dev|e2e` (`AUTH_PROVIDER=dev` запрещён в `prod`).
8. **Q-W1.01-8 (технический). Часы outbox:** аренда и паузы — по часам worker, «к сроку» — по более позднему из часов worker и `now()` БД. Хосты worker и PostgreSQL должны быть синхронизированы (NTP): отставание часов worker дольше аренды (30 с) даёт повторную доставку, её гасит `events.Once` у потребителя.
