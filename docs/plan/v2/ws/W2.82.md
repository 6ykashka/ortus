# W2.82 · design-preview `--ref` под хуком pre-push из linked worktree (`GIT_DIR`)

Этап 2 · вне реестра (постановка оркестратора) · вид: инструмент репозитория · размер S.
Слот 6: Vite 5206, Storybook 7206, API `127.0.0.1:8106`, свой эталон 4106, `ortus-s6`. Стенд не нужен.

## 1. Цель

`git push` из linked worktree падает на хуке `pre-push`: тест `tools/__tests__/design-preview.test.mjs`
«сервер --ref: отдаёт файл из тега» получает 404 вместо 200. Git экспортирует хуку
`GIT_DIR=<repo>/.git/worktrees/<name>`, а `tools/design-preview.js` вызывает
`git show <ref>:./<rel>` с `cwd=<dir>`: при заданном `GIT_DIR` без `GIT_WORK_TREE` git считает cwd
корнем рабочей копии, путь `./<rel>` указывает мимо `design/` — файла нет.

Воспроизведение: в worktree `$env:GIT_DIR=(git rev-parse --absolute-git-dir); node --test tools/__tests__/design-preview.test.mjs` — 15/16.

## 2. Решение

Источник `--ref` не зависит от `GIT_DIR` и cwd:

- дочерние вызовы git идут без переменных локального репозитория (`git rev-parse --local-env-vars`:
  `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_COMMON_DIR`, `GIT_PREFIX` и др.) — репозиторий
  находится по самому каталогу эталона;
- корень и префикс каталога считаются один раз (`git rev-parse --show-toplevel --show-prefix` из `<dir>`),
  файл читается `git -C <top> show <ref>:<prefix><rel>` — путь от корня репозитория;
- каталог вне git — 404 (как отсутствие файла).
