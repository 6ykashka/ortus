## Контекст

- `14-engineering.md`, «Стек»: React + TypeScript, Vite, TanStack Router + Query, PWA через Workbox; «Next.js — только если уже есть (D-01)».
- Кода продукта нет (план 27, «Исходное состояние»: «Ещё нет: репозитория…»). Каркас W0.03 содержит только заглушку `frontend/apps/web`.
- Сессию держит Go BFF: cookie `HttpOnly`, `SameSite=Lax`, Origin и `X-CSRF-Token` (`03-api-guide.md`, «Вход»). SSR и SEO не нужны: всё приложение за входом, публичны только формы по ссылке (4.2) и портал обращений (7.3).
- Водителю нужна PWA с офлайн-черновиками (S2-15, шаг 2.10).
- Решение плана PD-14 (Vite + React 19 + TypeScript + TanStack Router/Query) совпадает с этой рекомендацией; скил `vercel-react-best-practices` применяется без Next-специфики (PD-42).

## Варианты

1. **Vite SPA + Go BFF** — плюсы: простая сборка, статический хостинг за BFF, один origin (ADR-0001), PWA через Workbox, быстрый dev-сервер на порту слота агента; минусы: нет SSR, код-сплиттинг и предзагрузка — вручную (TanStack Router). Цена: ноль сверх плана.
2. **Next.js (App Router)** — плюсы: SSR и серверные компоненты, готовая маршрутизация; минусы: второй сервер (Node) рядом с Go BFF — сессия и CSRF в двух местах, сложнее PWA-офлайн, ограничения статического экспорта. Цена: +1 сервис в compose и в prod, переписать границу BFF.
3. **Vite SPA, но другой роутер (React Router)** — плюсы: привычнее команде; минусы: меньше типобезопасность search-параметров, на которых держится ADR-0001. Цена: низкая, но расходится с `14-engineering.md`.

## Решение

**Принято 17.10.2026** (ответ владельца продукта, `docs/plan/v2/po-answers-2026-10-17.md`, D-01): Vite + React + TS за Go BFF: один рантайм в проде, PWA, прототип переносится прямо; SSR не нужен внутреннему приложению. Публичные формы и кабинет заказчика — те же маршруты SPA.

Отличие от рекомендации: нет — ответ совпадает с рекомендацией.

Рекомендация до ответа (история):

Рекомендация: «Vite + React + TS, Go BFF отдаёт сессию; Next.js — только если уже есть код». Кода нет, поэтому — вариант 1: Vite + React 19 + TypeScript + TanStack Router и Query, PWA через Workbox (PD-14).

## Последствия

- Проще: один origin и одна сессия в BFF; dev-сервер на `5200 + slot`; e2e против статической сборки.
- Сложнее: маршрутные данные и предзагрузка — средствами TanStack Router; аудит бандла — вручную (скил `vercel-react-best-practices`, правила `bundle-*`).
- Сделать: W0.09 — каркас `apps/web` на Vite; W2.24 — PWA через Workbox.
- Если выбран вариант 2: пересмотреть ADR-0001 (маршруты), BFF (W0.09, W1.03) и харнесс e2e (W0.05).
- Как проверим: `corepack pnpm run build` собирает `apps/web`; e2e открывает `/t/t-alta/home` на порту слота.
