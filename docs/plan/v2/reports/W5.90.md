## Вопросы и решения по умолчанию (`Q-W5.90-N`, в `decisions.md` вносит интегратор)

- **Q-W5.90-1.** Сида салона нет (Q-W5.20-11, Q-W5.31-8): путь заводит склад, материал, услугу и кассу командами API и ничего не убирает (удаления в контракте нет) — стенд «Лотоса» копит записи прогонов под метками. Нужен сид (услуги с техкартой, склад, касса, визиты, привязанные к броням календаря) — владелец сида; тогда путь переходит на сидовые данные.
- **Q-W5.90-2.** Клиентов в продукте нет (Q-W5.20-10): форма «Записать клиента» берёт клиентов из существующих визитов (`clientsOf`), на пустом салоне через страницу записать нельзя; путь записывает через API (`clientId` — случайный uuid). Нужен справочник клиентов или поле «имя клиента» в визите.
- **Q-W5.90-3.** Страницы проверены по заголовку, имени данных прогона и прокрутке, а не по числам и состояниям (остаток 970 мл, «Завершено · списано», смена в журнале): селекторы реального backend не сняты; строки `@stand` страниц (fixme) принадлежат W5.11, W5.21, W5.32, W5.33 — их пора разморозить, backend всех в `main`.
- **Q-W5.90-4.** «Принять расхождение» другим сотрудником на стенде не проверено: у «Лотоса» два сотрудника (владелец и массажист без прав кассы). Проверено, что закрывший смену не решает её сам. Для второго решающего нужен сид роли «Администратор салона» с `cash.reconcile` (Q-W5.31-8).
- **Q-W5.90-5.** Строки изоляции модулей этапа 5 в матрице W1.04 положительными быть не могут (в фикстурах нет `spa`; `inventory` и `cash` — ядро, но данных нет); положительные строки живут в стенд-пути между организациями сида. Решение стюарда: добавить в фикстуры данные склада, кассы, SPA (WithInTenant, как `content_repairs.go`) и перенести строки в матрицу.
