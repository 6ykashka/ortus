# W5.11 · Экраны склада: «Склад» (остатки, резервы) и «Движения» на MSW

Этап 5 · вид: frontend · шаг 5.1 · источник: карточка W5.11 (план v2 §4 «Этап 5»), контракт `0.12.0-stage5` (тег Inventory, W5.00), `screens.yaml` (`inventory-stock`, `inventory-movements`, `no-reference`, B-6), `design/docs/v0.1/08-domain-scenarios.md` (материалы партиями, срок годности, отрицательных остатков нет), D-20 комплекта (FEFO) · размер: M.
Зависит от: W5.00 (контракт). Бэкенд W5.10 ещё не в `main`: страницы работают на MSW (режим mock), режим stand — `@stand-spec` с `test.fixme` и причиной «W5.10».
Слот исполнителя: 2 (Vite 5202, Storybook 7202, API 8102, эталон 4102, `ortus-s2`).

## 1. Цель

Две страницы модуля ядра `inventory` («Склад и материалы») в контуре организации:

| Ключ | Маршрут | Экран | Что на странице |
| --- | --- | --- | --- |
| `inventory` | `/t/:tenantId/inventory` | `inventory-stock` | вкладки «Остатки» и «Резервы», фильтры «Склад» и «Ниже минимума», остатки по партиям в порядке FEFO, правка номенклатуры (название, минимальный уровень, архив), «Новая позиция», «Новый склад», снятие резерва |
| `inventoryMovements` | `/t/:tenantId/inventory-movements` | `inventory-movements` | журнал движений (неизменяемый), «Новое движение» (приход, расход, перемещение, корректировка), «Сторно» |

Операции: `listWarehouses`, `createWarehouse`, `listInventoryItems`, `createInventoryItem`, `updateInventoryItem`, `listInventoryBalances`, `listInventoryReservations`, `releaseInventoryReservation` (создание резерва вызывают модули — SPA, ремонт, — ручной кнопки нет, Q-W5.11-2), `listInventoryMovements`, `postInventoryMovement`.

## 3. Решения по умолчанию (`Q-W5.11-N` — в отчёте)

- Q-W5.11-1. Экрана склада в эталоне нет (B-6): вид и тексты — по документам комплекта и по контракту; сверки с эталоном нет, allowlist `no-reference`.
- Q-W5.11-2. Резервы создают модули (запись SPA, закупка ремонта): на странице только список и «Снять резерв» (`inventory.movements.post`); `createInventoryReservation` реализован в MSW, ручной формы нет.
- Q-W5.11-3. Количества — десятичные строки контракта (`Quantity`), показ с запятой без хвостовых нулей и единицей позиции.
- Q-W5.11-4. Пункт меню «Склад» — владельцу и офису (группа «Общие модули»); «Движения» — вторая страница без пункта меню, вход — вкладка-ссылка страницы «Склад».
- Q-W5.11-5. Сторно движения: строки и склад берутся из исходного, причина обязательна; сторнировать сторно нельзя, второе сторно того же движения — 409.
- Q-W5.11-6. В ответе `InventoryMovement` нет направления корректировки, причины и ссылки сторно на исходное движение: в журнале корректировка и сторно показаны без знака, «уже сторнировано» не видно (отказ даёт сервер, 409). Предложение стюарду контракта: поля `adjustmentDirection`, `reason`, `reversesMovementId`.
- Q-W5.11-7. Срок годности партии («Срок истёк») страница считает сама по дате Москвы (`InventoryLotBalance` признака просрочки не отдаёт); предложение — поле `expired`.
- Q-W5.11-8. Тег Inventory не добавлен в `STAGE5_TAGS` (`scripts/contract.mjs` — стюард): хендлеры MSW покрыты своим тестом `adapter/test/inventory.test.ts`, кейсы conformance и примеры по операциям склада — W5.10 вместе с backend.
- Q-W5.11-9. Списки склада — первые 200 записей (`limit=200`) без «Показать ещё»; архивная позиция из списков исчезает (в `InventoryItem` нет признака архива), вернуть её из архива нельзя.
