## Осталось fixme / открытые вопросы

- `cash-self.spec.ts`: `test.fixme` «чек с фото → решение выдающего → «Принят»/«Переснять»» — без `@stand` в названии. Причина — backend: у Files не зарегистрирован родитель `cash/account` (`cmd/api/files.go`: только рейсы Логистики, задачи, формы, чаты), `initiateUpload` с `purpose: expense_receipt` отвечает 422 «Не удалось загрузить фото чека». Тот же пробел у `repairs/project` (`repair_evidence`) — отметка работ прорабом с фото и допработа на стенде невозможны; эти строки остаются в mock-блоках.
- Недоступно на стенде по backend/среде, в строки `@stand` не вошло: подпись ПЭП (`pep_login` отвечает 503: dev-вход без повторного входа; проверено только открытие окна и отказ), подпись документа ремонта заказчиком (порт SMS без провайдера), начисление и выплата бригаде и акты (backend создаёт только документ «Допсоглашение»; договор, акты и счета в main не создаются), создание подрядчиков.
- Продукт, не менялся (передать владельцам страниц): (1) `inventory` — при дубле артикула или названия склада backend отвечает 409 `conflict`, страница показывает ошибку только для `validation_failed` и молчит; (2) `repair-estimate` на 390 — таблица согласованной версии без полей ввода даёт axe `scrollable-region-focusable` (`.ox-rp-tablewrap`), axe строки проверяется на черновике; (3) сид: роль «Прораб» назначена по связи `self`, а права ремонта допускают область только «организация/подразделение/объект» — прораб без явной выдачи не видит объектов (`listRepairProjects` → 403); строки выдают роль на подразделение объекта и снимают через `undo`.
