## 1. Цель

1. **`suspendPlatformTenant`** (`POST /platform/tenants/{id}/suspend`, `TenantStatusChange {reason}`, `If-Match` ETag организации, `Idempotency-Key`): из `trial`, `active`, `grace`, `read_only` → `suspended`; уже `suspended`, `provisioning`, `closing`, `closed` → 409 `invalid_transition`. `tenants.state_reason` = причина, ревизия + 1, аудит `tenant.suspended` (цель `tenant`, `details` `fromStatus`, `toStatus`) в той же транзакции. Организация без строки подписки получает материализованную производную подписку (Q-W1.08-13), чтобы возобновление знало её состояние.
2. **`resumePlatformTenant`** (`POST …/resume`): только из `suspended`, иначе 409. Новое состояние — по подписке (`subscriptions.TenantStateFor`): `trialing` → `trial`, `active` → `active`, `grace`/`past_due` → `grace`, `read_only`/`cancelled` → `read_only` (Q-W1.00-3). Аудит `tenant.resumed`.
3. **`extendPlatformTrial`** (`POST …/trial-extensions`, `TrialExtension {days 1–30, reason}`, `If-Match` ETag подписки `"rev-N"`): разрешено, если подписка `trialing`, или `grace`/`read_only` после неоплаченного пробного периода (неручные права подписки — источника `trial`); оплаченная (`active`, `past_due`, `cancelled`, а также `grace`/`read_only` после оплаченного периода — источник `plan`) → 409 `invalid_transition` (Q-W1.00-6). Организация в `provisioning`, `closing`, `closed` → 409. `trialEndsAt` = позднейшее из текущего `trialEndsAt` и «сейчас» + `days` (только у `trialing`; у `grace`/`read_only` — от «сейчас», истёкшая строка trial не растягивается назад — замечание ревью W1.11). Подписка → `trialing`, права trial выводятся заново, ручные сохраняются, ревизия подписки + 1; организация из `grace`/`read_only`/`trial` → `trial` (приостановленная остаётся `suspended`). Аудит `subscription.trial_extended` (цель `subscription`, `target_id` — организация, `details` `days`, `trialEndsAt`, `fromStatus`, `toStatus`). Ответ — `Subscription` и ETag подписки.
4. **`listPlatformAuditEvents`** (`GET /platform/audit-events?tenantId&cursor&limit`): журнал `platform_audit`, новые сверху (по `id`), фильтр строк по праву роли оператора на тип цели до пагинации (`tenant`, `subscription` — `platform.tenants.read`; `account` — `platform.users.read`; `operator` — `platform.operators.manage`; `price_book` — `platform.pricing.manage`); неизвестный `tenantId` → 404; `details` — только скалярные параметры из белого списка (никаких `ownerEmail`, `requestHash`, текстов ошибок); курсор непрозрачный, привязан к оператору и фильтру.
5. **`updatePlatformTenant`** — только переименование (`name`, необязательная причина), `status` в теле → 422; то же имя — без изменений и без аудита; аудит `tenant.renamed`.
6. **Роли операторов** (`platform_operators.role`, `design/docs/17-users-and-billing.md` «Права», «Роли»): `platform.tenants.manage` — `owner`, `admin`; `platform.billing.manage` — `owner`, `admin`, `billing`; чтение организаций и аккаунтов — все роли. Отказ по роли — 403 `forbidden_action` и строка `platform_audit` с `result = denied`.
7. **Идемпотентность** — ключи `Idempotency-Key` identity- и platform-операций в control 0005 (`idempotency_keys`, пространство тенант + actor + операция: у операций `/platform/…` тенанта контекста нет, `tenant_id` = null, путь с `tenantId` входит в `request_hash` — комментарий миграции) вместо памяти процесса.
8. **Подключение (санкция интегратора):** `backend/cmd/api/main.go` монтирует `operators.Server`, встроив `platformhttp.Server`; `backend/cmd/api/app.go` — без `If-Match` 428 `revision_required` вместо 400 (Q-W1.11-9). `platformhttp/stage1b_stubs.go` заменяется целиком.
9. **Строки изоляции:** не оператор (аноним 401; `a.owner`, `b.owner`, `ab.member`, `a.driver-msk1` 404) для пяти операций; оператор `p.operator` (`owner`) → 200 на каждой операции, оператор поддержки → 403, несуществующая организация → 404. Строки оператора — `pending: W1.48` до подключения, снимаются коммитом подключения.

## 10. Риски и решения по умолчанию

1. **Причина** обязательна у всех трёх команд (5–500 после trim, Q-W1.00-1); у переименования необязательна.
2. **Возобновление** — по подписке (Q-W1.00-3). Без строки подписки (организация приостановлена до W1.48) — состояние до приостановки из `details.fromStatus` последней `tenant.suspended`, иначе `active`.
3. **Материализация подписки при приостановке** (Q-W1.08-13): если строки нет, пишется производная (`subscriptions.Derive`) с правами версии 1 — ревизия и ETag подписки не меняются, фоновый цикл W1.08 ведёт срок и во время приостановки.
4. **Продление** — из `trialing` или `grace`/`read_only` с правами источника `trial`; производная `grace`/`read_only` (без строки) имеет источник `plan` и считается оплаченной → 409. Организация в `suspended` остаётся `suspended`.
5. **ETag**: организация — `"N"` (W1.02), подписка — `"rev-N"` (W1.08); `If-Match` принимает обе формы. Два формата в одном теге — Q-W1.08-9, выравнивает стюард.
6. **Идемпотентность** — `operators.Keys` в control 0005 для всех identity- и platform-операций (через `idem.TenantStores.Platform`). Ответ сохраняется после коммита команды (не в её транзакции): при падении процесса между коммитом и сохранением повтор выполнит команду заново и получит 412 по `If-Match`.
7. **Журнал**: `target.name` — текущее имя организации (имя на момент действия не хранится); `details` — белый список скаляров; строки целей вне перечисления контракта не показываются.
8. **Порядок проверок команды**: 422 → 428 → оператор и роль (404/403) → организация (404) → 412 → 409.
9. **`a.owner`** — строки в `operators.yaml` для всех пяти операций (замечание ревью W1.11).
