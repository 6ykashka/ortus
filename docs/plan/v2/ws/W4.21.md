## 10. Риски и решения по умолчанию

- Права — в области формы (Q-W4.05-4): форма «Вся организация» видна и доступна для ответа с `forms.read` в любой области, остальное — роли организации; форма подразделения — роли организации и подразделения (с потомками по `include_descendants`, как оценщик).
- Модуль формы активен — установка в состоянии `enabled`; иначе приём закрыт (Q-W4.00-forms-16), шаблон недоступен.
- Номер ответа — последовательность тенанта, `R-%04d`; сид выставляет её после R-1012.
- «Принимать до» и подписи времени (`$at`, CSV) — по Москве (как MSW).
- Нонс гостя — без хранения: HMAC (ключ публичных ссылок, своя метка домена) от ссылки, версии, срока (2 часа) и случайной части; одноразовость — ключ дедупликации ответа `nonce:<sha256>` (`forms.responses.dedup_key`), повтор — 410 `nonce_used`; привязка к сессии браузера не делается (нет куки гостя).
- Загрузки гостя: модуль файлов вызывается с контекстом-«возможностью» (тенант, участник — id из нонса, без прав участника; токен, нонс и вопрос-файл проверил модуль форм); файл ответа гостя — только его (`uploaded_by` = id нонса) и готовый.
- Без `FORMS_PUBLIC_LINK_KEY` вне prod — ключ разработки с предупреждением в логе; в prod без ключа выпуск ссылки и операции гостя — 503 `dependency_unavailable`.
- Позиция «В конец» строки или записи БЗ — время добавления раньше самой старой строки (порядок БЗ — по времени добавления).
- Удаление по сроку (возврат 1): удаляются ответ, журнал, строки и записи БЗ; файл ответа — портом модуля файлов: `files.quota_ledger` только для вставки и ссылается на объект, поэтому строка `files.objects` остаётся `rejected` с кодом `retention_deleted`, занятые байты освобождаются записью `release`, объект удаляется из хранилища после коммита. Полное удаление строки файла — миграцией (состояние `deleted` или каскад журнала квоты) у стюарда, вопрос — в отчёте.
- Файлы ответов (возврат 2): загружает в форму тот, кто её видит (`forms.read` + `files.upload`); читает файл ответа (`listFiles`, `getFile`, скачивание) только загрузивший его, участник с `forms.responses.read` в области формы и тот, кто видит ответ, держащий файл (своё, связь с объектом при ключе в любой роли — Q-W4.00-forms-9); остальным файл не виден в списке и отвечает 404. Удаление по сроку блокирует строки файлов (`for update`), отправка ответа берёт их `for share`: ответ не ссылается на удалённый файл. Аудит `forms.responses.purged` на форму (число и номера ответов, число файлов), событие `files.file.rejected.v1` с кодом `retention_deleted` на файл. Нонс проверяется текущим и прежними ключами ссылок. Загрузки одного нонса сериализуются `pg_advisory_xact_lock`.
- Цена `HiddenFiles` (возврат 3): Hider общий для всех родителей, поэтому `HiddenFiles` вызывается при каждой операции с файлами. Участнику без `forms.read` нигде он ничего не закрывает: родитель `forms/form` закрыт ему правом чтения, читаются только его права. Без `forms.responses.read` нигде все чужие файлы ответов закрываются одним запросом. Ответы читаются только у форм, которые участник видит вне области своего ключа. Сузить по родителю запроса нельзя без правки интерфейса `files.Hider` (он не знает родителя) — вопрос Q-W4.21-16.
- Таблица `files.objects` в SQL модуля форм (возврат 3, принятое исключение до решения интегратора, Q-W4.21-16): `othersFilesSQL`, `filesOf … for share`, счёт загрузок гостя, `lockFilesSQL` читают и блокируют строки файлов ответов напрямую, в одной транзакции с ответами. Через порт `files.Service` блокировку в транзакции вызывающего не выразить без нового метода модуля файлов. Изменение схемы `files.objects` ловят integration-тесты форм (`TestSubmitWaitsForPurge`, `TestRetentionPurge`, `TestPublicUploadLimitParallel`, `TestHiddenFiles`).
- Строка аудита `forms.responses.purged` (возврат 3): `count` всех удалённых ответов формы и первые 10 номеров (`auditNumbers`).
- `{{file}}` после W2.79 (возврат 4): один плейсхолдер на собственные строки родителя и на `Share.Rows`. В `getFile`, скачивании и `listFiles` это всегда id читаемого файла, в загрузке — `null` (Share при загрузке не проверяются). Подстановка `uuid.Nil` для собственного scope открыла бы файлы ответов всем, кто видит форму (Q-W4.00-forms-9), или уронила бы запрос (тип `$2` не выводится, если `is null` стоит первым) — это ловит `TestOwnScopeReadsTheFile`.
- Объекты ответов сида (возврат 4, Q-W4.21-17): R-0988 и R-1012 — о прошлых рейсах эталона Р-171 и Р-196 с id PD-30 их номеров, как у `subjectOf` MSW. В `fleet.trips` сида стенда их нет (только Р-208 и Р-211). Подпись показывается как в эталоне. Видимость по связи — как в MSW (`state.ts sees`): ответ о рейсе, которого нет в тенанте, читает участник с `forms.responses.read` где-либо и `fleet.trips.read` где-либо (порт `Objects.Missing`). Новый ответ о таком рейсе не принимается. Если рейсы эталона нужны в журнале рейсов, их добавляет владелец сида рейсов.
