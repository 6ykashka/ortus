## 2. Сводка

- Ортус — мультитенантная платформа для сервисных компаний; общее ядро (пользователи и права, структура, модули, календарь, задачи, знания, формы, файлы, данные, уведомления) + отраслевые модули «Логистика» (P0), «Салон и SPA» (P1), «Ремонт и стройка» (P2) (`docs/v0.1/01-technical-spec.md:7,40–64`).
- Первый пилот — логистика: полная смена водителя «бронь → осмотр → выезд → маршрут и расходы → сдача → приёмка менеджером» (`01:17,254–264`; `08:100–111`).
- Главное продуктовое ограничение: **водитель не видит начисления, включая собственные**, ни в UI, ни в API, ни в данных, экспорте, файлах, уведомлениях; действующая функция `driver` блокирует это через любую роль или группу (`01:11,138`; `07:7`; `08:10`; `06:54`).
- Эффективный доступ = активное членство ∧ режим подписки ∧ установленный модуль ∧ разрешённое действие ∧ область объекта ∧ обязательные ограничения (`01:130`). Три отдельных действия в UI: «Подключить модуль бизнесу», «Разрешить работу с модулем роли», «Выбрать область действия» (`07:146`).
- Бронь ресурса атомарна и подтверждается сервером; список свободных — снимок (`01:74`; `08:52–53`). Два водителя на одну машину → ровно одна бронь (AC-03).
- Деньги, материалы, закрытие визита идемпотентны; проведённые записи исправляются сторно (`06:56`; `01:184`; `08:169`).
- Формы версионируются; ответ ссылается на версию; публичная форма не даёт доступ к справочникам (`01:116–118`; `07:13–16`).
- «Данные» — каталог разрешённых записей модулей, не вторая редактируемая копия; «Файлы» — фото/документы с квотой (`01:96–104`; `07:62–64`).
- Отключение модуля, окончание trial, уменьшение квоты не удаляют данные; показываются последствия (`01:146,208,210–212`).
- Одно адаптивное web/PWA-приложение; рабочие места водителя/мастера/прораба; офлайн — только черновики и ограниченный кэш, выезд/бронь/проводка требуют сервера (`01:220,170`; `07:105,162–168`).
- Структура холдинга: один тенант, 3 региона × 4 фирмы; независимые клиенты — отдельные тенанты/БД (`01:34`; `06:50`).
- Платформенный оператор работает в отдельной оболочке, видит тарифы/статусы/квоты, не видит бизнес-данные (`07:107`; `Ортус CRM.dc.html:1528`).
- Прототип реализует экраны всех модулей (итерации 1–7), включая не входящие в ТЗ v0.1: «Оформление», «Подписка и места», тарифную сетку, каталог аккаунтов, «Заявки», карточку «Объекта» (`README.md:117–155`; `docs/17`, `18`, `19`).
- Бэклог S0–S2 покрывает только ядро + логистику; формы-конструктор, канбан, знания, календарь недели, SPA, касса, склад, ремонт — S3+ (`docs/13-backlog-s0-s2.md:139`).
- Тестовая пирамида: unit, integration, isolation suite (блокирует merge), concurrency, contract (Schemathesis), component (axe), E2E Playwright 390/1440, load k6, restore drill (`docs/15-quality-security.md:7–17`).
- Коды ошибок API — RFC 9457 `Problem.code` (`docs/12-errors-and-events.md:28–65`); UI выбирает текст по `code`.
- Три стандартных расхождения прототипа с документами: ключи прав (`docs/11-permissions.yaml:180–190`), статусы тенанта (`docs/README.md:49`), меню владельца «Данные»/«Файлы» вместо «Хранилище данных» (`README.md:171`).
