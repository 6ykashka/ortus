## Сделано

- `backend/internal/platform/notify/inbox/` — порт входящих (единственный путь к `notify.notifications`):
  - `notice.go` — `Notice` и проверка по контракту (`Notification`) и CHECK tenant 0003: `kind` без версии, заголовок 1…300 и текст до 2000 символов, `link` — путь своего сайта (без `//`, `\`, пробелов, управляющих символов, ≤ 512), объект целиком, подразделение и чувствительность только вместе с правом; `KindOf` (тип события без `.vN`);
  - `audience.go` — `Audience`, `AuthzAudience` по оценщику W1.04: без права — только обычное уведомление без подразделения; с правом — `Permit(право, Resource{Unit})` (целый грант, поддерево подразделения, функция закрывает действие, владелец проходит, `forbidden_action`/`not_found`/`function_blocked` → «не адресат», `dependency_unavailable` → ошибка); `sensitive`/`restricted` — ещё и без действующей функции `driver` (AC-05);
  - `enqueue.go` — `Enqueue` в транзакции производителя: **проверка адресата при постановке** (живой профиль, `Audience` сейчас), исходы `Enqueued`/`Duplicate` (тот же `source_event_id`)/`NotInAudience`;
  - `recipients.go` — `PGRecipients`: профиль сотрудника → активное членство и владение из control DB, иначе `ErrNoRecipient`;
  - `consumer.go` — `Consumer` (обработчик outbox): `Route` → адресаты → `Enqueue` в одной транзакции с `events.Once`; повтор доставки ничего не добавляет, адресат без членства или вне аудитории пропускается, неверное уведомление — ошибка обработчика (повтор, dead-letter);
  - `inbox.go` — `Inbox.List`/`Summary`/`MarkRead`: **проверка адресата при выдаче** — группы «право × подразделение × чувствительность» перепроверяются при каждом вызове, лента, `unreadCount`, `latestAt` и отметка — только по видимым сейчас; keyset `created_at desc, id desc`;
  - `cursor.go` — непрозрачный курсор (base64url) с отпечатком организации, субъекта, фильтра и версии политики прав (`access.policy_state`): после смены прав старый курсор → `ErrBadCursor`.

## Осталось fixme / открытые вопросы

Решения по умолчанию, по которым сделано (decisionsNeeded):

1. Отметка «прочитано» в организации `grace`/`read_only` разрешена: это личное состояние, не данные организации (`Resolve(…, mutating=false)`, как MSW). Приостановленная организация — 403 `tenant_suspended`.
2. Сводка: список — активные членства видимых организаций в порядке каталога (как MSW); счётчики читаются у `trial/active/grace/read_only`; приостановленная организация и сбой её базы — `0`/`null` (сбой — предупреждение в лог, как `/me/context`), сводка не падает целиком.
3. `latestAt` — время последнего видимого уведомления (прочитанного или нет), как MSW (`mineAll`).
4. Уведомления, скрытые аудиторией, не отмечаются прочитанными ни по id, ни по `upTo`.
5. Курсор привязан к версии политики прав: после любой смены ролей или назначений (`policy_version`) старый курсор → 400 `malformed_request` (клиент начинает с первой страницы).
6. Уведомление с подразделением или с чувствительностью `sensitive`/`restricted` без права — отклоняется производителю (`ErrInvalid`); при выдаче такие строки (если записаны в обход порта) никому не показываются.
7. `sensitive`/`restricted` закрыты для действующей функции `driver` даже при праве, которое функция не закрывает (строже каталога `blocked_by_function`, AC-05).
8. Канал `notifications` раннера матрицы изоляции (README набора: «уведомления — W1.10») не добавлен: ему нужны уведомления в фикстурах (W1.04) и правка `matrix/` (W0.15). Утечки через уведомления (AC-05, R-03, отзыв роли, фирма-тёзка) проверены integration-тестами порта на тех же фикстурах W1.04.
9. Положительная строка `markMyNotificationsRead` в матрице не выражается (формат без `Idempotency-Key`, Q-W1.04-14): в `me.yaml` — только аноним 401; чужая организация в теле — `TestMarkMyNotificationsReadValidation` (404) и integration-тесты.
