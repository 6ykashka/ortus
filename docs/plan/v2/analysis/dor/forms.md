## 1. Инвентарь экранов

Ширины. Модуль не задаёт брейкпоинтов, вёрстка тянется (`flex-wrap`, `auto-fill`). Различия по ширине:
- навигация конструктора `position: sticky` при ширине корня модуля ≥ 780 px, иначе `static` и стоит над вопросами (`dc:837`, `ResizeObserver` `dc:541–545`);
- предпросмотр: `max-width` 390 px «Телефон» / 720 px «Компьютер» (`dc:1052`);
- сетки: плитки шаблонов `minmax(180px)` (`dc:34`), карточки настроек `minmax(360px)` (`dc:288`) — на 390 и 768 одна колонка, на 1440 две–три; сводка `minmax(320px)` (`dc:419`);
- лента ответов: список `flex 1 1 260px` + карточка `2 1 340px` — рядом от ~620 px, на 390 одна под другой (`dc:425–434`);
- вкладки прокручиваются по горизонтали (`dc:104`), меню «…» шириной `min(440px, 100vw − 32px)` (`dc:41`).

Отдельных макетов 390/768/1440 нет. Проверять на трёх ширинах по протоколу.

## 7. Вопросы владельцу продукта

Каждый вопрос со значением по умолчанию. До ответа агенты работают по умолчанию.

- **Q-W4.00-forms-1.** Черновик: в контракте только неизменяемые версии, в прототипе изменяемый черновик с автосохранением. **По умолчанию:** черновик хранится на сервере (`PUT /forms/{id}/draft` с ревизией, автосохранение 700 мс). При конфликте двух редакторов — 412 и сообщение «Черновик изменил другой редактор — обновите страницу». «Опубликовать» создаёт версию из черновика. Пара `createFormVersion` + `publishFormVersion` уходит из контракта.
- **Q-W4.00-forms-2.** Где живут настройки (доступ, срок, лимит, хранение)? **По умолчанию:** у формы, меняются без новой версии (док 20). Тело `FormPublish` убирается.
- **Q-W4.00-forms-3.** Как хранить ответы на вопросы выбора: подписью (прототип) или ключом варианта? **По умолчанию:** ключом (`o1`…), подпись берётся из версии. Условия и «Только если» правил сравнивают ключи. Старые версии сида со строковыми вариантами получают ключи `o1…` при переносе. `formVal` и CSV выводят подписи.
- **Q-W4.00-forms-4.** Блокировки публикации, которых нет в `api.js` (условие вниз / на удалённый вопрос, скрытый обязательный без значения, пустой вариант, «от» > «до»). **По умолчанию:** сервер проверяет всё, что проверяет `issues()`, с текстами UI дословно (закрывает Q-W4.20-4).
- **Q-W4.00-forms-5.** Типы вопросов: контракт расширяется до 21 типа прототипа (`money`, `url`, `int`, `scale`, `rating`, `statement`, `person`, `unit`, `select`, `email`, `phone`, `inn`)? **По умолчанию:** да, идентификаторы типов как в прототипе. `series` и `payment` в контракт не входят и в UI показываются неактивными с причиной.
- **Q-W4.00-forms-6.** Ключ вопроса: контракт `^[a-z][a-z0-9_]{0,63}$`, прототип допускает заглавные и «-». **По умолчанию:** сервер принимает `^[a-zA-Z][a-zA-Z0-9_-]{0,63}$` (включает оба). UI проверяет правило прототипа (2–60 символов, текст ошибки дословно). Ключи сида (`q-photos`) сохраняются.
- **Q-W4.00-forms-7.** Группы форм (FM-03: общие для организации): кто создаёт и удаляет, видны ли формы чужих подразделений в счётчике? **По умолчанию:** право `forms.manage` в области `tenant`. Имя — 2…80 символов, уникально без учёта регистра. Удаляется только пустая, без подтверждения. Счётчик и строки — только видимые участнику формы.
- **Q-W4.00-forms-8.** Кто может ответить на внутреннюю форму: в каталоге «права на отправку нет», в доке «с правом «Формы» в области формы». **По умолчанию:** ответить может тот, у кого есть `forms.read` в области формы. Нового ключа нет, `forms.responses.create: null` остаётся.
- **Q-W4.00-forms-9.** Кто видит ответы: в прототипе — все, у кого логистика на «Севере», остальные — свои. **По умолчанию:** `forms.responses.read` в области формы — все ответы, в области `self` — свои. Ответ, связанный с объектом (рейс), виден по связи `relation` тем, кто видит объект с правом `forms.responses.read` где-либо. Заглушка `seesLog` уходит.
- **Q-W4.00-forms-10.** Режим «По персональному приглашению» без механизма и экрана приглашений. **По умолчанию:** в этапе 4 режим виден, но неактивен с подсказкой «Появится позже: персональные приглашения со сроком» (отличие от эталона — в allowlist). Приглашения — кандидат в бэклог после этапа 4.
- **Q-W4.00-forms-11.** Проверять ли `forms.publish_public` при выборе «Все, у кого есть ссылка» и при публикации? **По умолчанию:** да. Без права вариант неактивен с текстом «Нужно право «Публичные ссылки»». Сервер отвечает 403.

В продукте — подписанный вебхук с повтором.» «Уведомить сотрудника» пишет во входящие.
- **Q-W4.00-forms-16.** Форма отраслевого модуля после отключения модуля. **По умолчанию:** приём ответов останавливается (как `form_intake` в предпросмотре отключения, Q-W1.24-6). Форма и ответы доступны для чтения.
- **Q-W4.00-forms-17.** Область формы «проект» (контракт разрешает, UI нет). **По умолчанию:** только «Вся организация» или подразделение, как в эталоне.
- **Q-W4.00-forms-18.** Проверка ответа (FORM-05): экрана нет, а правила «После принятия ответа» и публичные формы в БЗ ждут принятия. **По умолчанию:** ответ сотрудника сразу получает статус «Принят», ответ гостя — «На проверке». В карточке ленты появляются «Принять» и «Отклонить» для `forms.responses.review` (no-reference, allowlist). Ревизии («исправить до проверки») — после этапа 4.
- **Q-W4.00-forms-19.** Страница заполнения для сотрудников и гостей не нарисована. **По умолчанию:** рендер предпросмотра без панели предпросмотра. Шапка — логотип организации и название. Экран «Спасибо» как в предпросмотре без «Пройти ещё раз». Закрытый приём — «Приём ответов закрыт» (no-reference).
- **Q-W4.00-forms-20.** Скрытые вопросы из параметра ссылки `?id=…` у публичной формы (значение подменяемо). **По умолчанию:** параметры принимаются только для скрытых вопросов, как текст до 500 символов, и никогда для типов CRM и файлов. В ответе помечается, что значение пришло из ссылки.
- **Q-W4.00-forms-21.** Адреса ссылок: `f.ortus.app/{tok}` и `{slug}.ortus.app` эталона или маршруты SPA (D-01)? **По умолчанию:** `{origin}/f/{token}`, встраивание `{origin}/f/{token}?embed=1`, для сотрудников `{origin}/forms/{id}`. Токен неугадываемый, его можно отозвать.
- **Q-W4.00-forms-22.** Удаление по сроку хранения (90 дней / 1 год / 3 года). **По умолчанию:** ежедневное задание удаляет ответы старше срока вместе с файлами и строками/записями БЗ (D-26). Сокращение срока применяется к старым ответам с задержкой 7 дней и предупреждением в настройках (no-reference).
- **Q-W4.00-forms-23.** Варианты для вопросов CRM («Сотрудник», «Регион или фирма», «Объект CRM»). **По умолчанию:** сервер отдаёт только то, что отвечающий видит по своим правам, с поиском, до 50 строк. Ответ хранит ссылку и подпись на момент ответа.
- **Q-W4.00-forms-24.** Тест с баллами: где считать баллы. **По умолчанию:** сервер считает при отправке и хранит «набрано / максимум / пройден». Экран «Спасибо» показывает результат, если включено «Показывать результат после отправки». В ленте и CSV баллов нет (как в эталоне).
- **Q-W4.00-forms-25.** «Один ответ от сотрудника» и «Не больше ответов всего» при нескольких версиях. **По умолчанию:** считаются по форме целиком, через все версии. Повторная отправка — 409 «Вы уже отвечали на эту форму». При лимите — 410 и «Приём ответов закрыт».
