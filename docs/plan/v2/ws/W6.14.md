## 1. Цель

Шесть операций шага 6.5 тега Repairs поверх `repairs.schedule_*` (0052) в модуле `backend/internal/modules/repairs`.

| Операция | Что делает |
|---|---|
| `getSchedule` | Этапы, связи, базовый план, прогноз сдачи, запас и критический путь, замечания (нет исполнителя, исполнитель занят), журнал; без сумм. `ETag` — `schedule_revision` |
| `createScheduleFromEstimate` | Этапы по разделам согласованной версии сметы и технологии шаблона (`template_stages`): длительность = объём работ раздела ÷ выработка (1…30 раб. дней), связи «окончание → начало» с паузой; график один на объект |
| `previewScheduleChange` | Последствия переноса без записи: сдвинутые этапы, новый прогноз, просрочка, кого уведомим |
| `applyScheduleChange` | Перенос (начало, длительность, пауза) с причиной из семи; `If-Match`; начавшийся этап не сдвигается (`schedule_stage_locked`), без причины не сохраняется; запись в журнал, событие `repairs.schedule.changed.v1` в outbox |
| `setScheduleStageExecutor` | Исполнитель этапа без причины, запись в журнал, уведомление исполнителю (outbox) |
| `createScheduleBaseline` | Новый базовый план по допсоглашению: срок договора и `projects.due_on` обновляются только так; событие `repairs.schedule.baseline_set.v1` |

Прогноз сдачи и «Требует решения» (`schedule_slip`) в сводке объекта берутся из графика (до W6.14 прогноз равнялся сроку).

## 3. Решения по умолчанию

- Расчёт — порт `gsched` эталона (прямой и обратный проход, запас, `bind`) на рабочем календаре: пн–пт, праздники из `repairs.work_calendars` региона `RU`, без строки — фиксированные праздники РФ (Q-W6.14-1). «Сегодня» — часы приложения.
- День 0 графика — `projects.start_on`, иначе дата часов; начало графика — ближайший рабочий день.
- Сдача по договору — последний базовый план (`schedule_baselines`), иначе `projects.due_on`, иначе прогноз (просрочки нет). Прогноз — окончание последнего этапа без последователей.
- Веха «Сдача объекта» — обычный этап длительностью 1 в конце графика (в таблице вехи нет): для расчёта она совпадает с вехой эталона (Q-W6.14-2).
- Пауза `lagDays` в перемещении относится к связи, определяющей начало этапа (как MSW); у первого этапа предшественника нет — 422 `no_predecessor`.
- Замечание `no_material` не считается: связи заявки снабжения с этапом в таблицах нет (Q-W6.14-3).
- Права: `repairs.schedule.read` (график виден тем, кто видит объект), `repairs.schedule.shift` (перенос, исполнитель), `repairs.schedule.baseline` (только область организации/подразделения).
