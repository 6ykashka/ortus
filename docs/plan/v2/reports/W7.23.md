## Сделано

Новый пакет `backend/internal/modules/docs` (сервер тегов `Docs` — 45 операций — и `PublicDocs` — 2 операции), разбор `docs/plan/v2/analysis/dor/documents.md`, прототип `design/ortus/documents.js` (тег `design-2026-10-19`).

**Доступ.** Цепочка `docAccess` прототипа на снимке документов организации, читаемом в транзакции запроса (как в базе знаний W4.31): организация (заблокирован — нет доступа, приглашён — «после входа») → функция «Водитель» на финансах (всегда закрыто; карточка — 403 `function_blocked`, список документ не показывает) → владелец бизнеса → папки пути (роль области на корневой папке, назначения ролей папок `docs_folder_*`, записи списка; «Только выбранные» обрывает то, что дали уровни выше) → документ (режим, назначения, список) → владелец документа → временные доступы маршрута (одна версия, без комментариев, журнала и списка доступа). Права `docRights`: просмотр, комментарий, предложение, правка, управление, «Поделиться» (владелец бизнеса, уровень 5 или «Настраивать» от уровня «Комментирует»), выдать не выше своего уровня, экспорт, подпись, маршрут, преобразование. Недоступный документ — 404 как несуществующий (AC-01). Влияние на доступ (`gain/lose/up/down`) для переноса, списка документа и списка папки; `dryRun`.

**Папки, документы, версии.** Создание документа (версия 1; шаблон с проверкой связи; CSV листа; файлы PDF; скан ставит задание OCR, кроме метки `pdn`), переименование и метка (If-Match, 409 `document_locked` на маршруте, у подписанного и у копии PDF/A), перенос, архив и возврат (статус до архива из журнала), версии (срез, имя, восстановление как v+1), комментарии, ответы, закрытие обсуждения (автор или правящий), упоминание сотрудника без доступа — ожидание у автора, выдача доступа `grants` и «пропустить», внешние ссылки (токен выводится HMAC от ключа модуля и показывается один раз, в базах только дайджест `sha256:`; PIN — PBKDF2-SHA256 с солью, показывается один раз; срок до 30 дней, по умолчанию PIN и водяной знак включены, скачивание выключено; индекс control 0011 пишется первым и снимается при неудаче строки тенанта), журнал документа (аудит), каталоги шаблонов и шаблонов маршрутов, чтение маршрута. События — `docs.version.saved`, `docs.access.granted`, `docs.link.opened`, `docs.comment.mentioned`, `docs.job.done|failed` и др. (Q-W7.23-1), уведомления «Вам открыт доступ…», аудит чувствительных действий.

**Адаптер сервера документов (D-32, ADR-0016).** Порт `Engine`; реализация `OnlyOffice` (Р7-Офис и ONLYOFFICE — один протокол): подпись конфигурации сессии HS256 JWT общего секрета, ключ версии `t<тенант>.d<документ>.v<версия>`, права движка из уровня (режим понижается до уровня участника; на маршруте правка выключена), принудительное сохранение через командный сервис, выборка сохранённого файла только с хоста сервера (без перенаправлений, внутренний адрес для контейнеров). Без сервера (`NoEngine`, переменные не заданы) `openDocumentSession` отдаёт `editorAvailable: false`, подсказку «Редактор подключается» и подписанную ссылку на файл — документ открывается на просмотр (Q-W4.00-documents-1). Callback `docServerCallback`: JWT проверяет шлюз, тенант и документ берутся из ключа после проверки подписи, повтор того же ключа новую версию не создаёт, ключ старой версии — 409, версия от `forcesave` — отдельная, файл пишется в хранилище с учётом квоты. Публичная ссылка `openDocLink`: токен → индекс control → БД тенанта, PIN (неверный — 403 и счёт попытки, пять неверных за 15 минут — 429), отозванная или истёкшая — 410 `public_token_expired`, каждое открытие — в журнал и в событие.

**Задания и OCR.** Очередь `docs.jobs`; `convert/to_docx/to_xlsx/to_pdf`, `ocr`, `merge`, `split`, `compress`, `pdfa`; правила эталона («Сначала распознайте скан», «Это уже PDF», «Это уже PDF/A», 409 `job_in_progress`); процессор `ExecProcessor` запускает OCRmyPDF с Tesseract, qpdf и офис без оболочки (списки аргументов, пароль через файл, не в аргументах); результат — новая версия (OCR, сжатие) или новый документ рядом (остальное), байты считаются в квоту; слова с низкой уверенностью (TSV Tesseract) ждут проверки владельцем, решение «принять / оставить / исправить»; скан с меткой `pdn` не распознаётся (DOC-07); пароль файла при повторе используется в запросе и не хранится, повтор без пароля после отказа по паролю — 422 `file_password_protected`. Воркер `cmd/worker/docs.go` берёт очередь каждые `WORKER_DOCS_INTERVAL` (5 с).

**Подключение.** `cmd/api/docs.go` + строки в `main.go` и `app.go`; шлюз `cmd/api/gate.go`: операция с областью `docs-server-callback` идёт без сессии — проверяется JWT сервера документов, а `Idempotency-Key`, которого сервер не присылает, шлюз выводит из тела (Q-W7.23-2); `docs.Register` даёт оценщику места папок и документов и правила узлов для `explainAccess`. Сид `cmd/seed/docs.go` — демо «Альты»: шесть папок со списками, три шаблона и два шаблона маршрутов, шесть документов с версиями, комментарий с упоминанием, слова скана, два задания. Фикстуры изоляции `content_docs.go` — папка и документ каждого тенанта.

## Осталось fixme / открытые вопросы

Решения, по которым я сделал по умолчанию (перенести в `docs/plan/decisions.md`):

- **Q-W7.23-1.** События контракта с двумя именами (`docs.created`, `docs.moved`, `docs.shared`, `docs.approved`, `docs.signed`) не проходят проверку типа события платформы (`events.Publish`: не меньше трёх имён до версии). По умолчанию публикуются `docs.document.created.v1`, `docs.document.moved.v1`, `docs.document.shared.v1`; остальные — как в контракте; события папок — `docs.folder.*`. Стюарду: привести README к этим именам или ослабить проверку.
- **Q-W7.23-2.** `docServerCallback` объявляет `Idempotency-Key` обязательным, а сервер документов его не шлёт. По умолчанию шлюз выводит ключ из SHA-256 тела. Стюарду: сделать заголовок необязательным для этой операции.
- **Q-W7.23-3.** `saveDocVersion` («Сохранить версию»): с сервером документов просит его сохранить (командный сервис), без сервера нечему сохраняться — имя получает последняя версия, она и в ответе. Новая версия от правки приходит только callback'ом.
- **Q-W7.23-4.** `syncDocDataset` не реализована (нужны движок листа W7.20 и порт набора данных `data.query`); отвечает 501, строка изоляции `pending: W7.24` условная — владельца в плане нет.
- **Q-W7.23-5.** Шлюз пропускает операцию `docs.*`, только если у участника есть роль с этим ключом (области `tenant/unit/folder/doc/relation/self`), а модуль решает точнее. Сотрудник, которому открыли документ записью списка и у которого нет ни одной роли с `docs.read`, получит 403 до модуля. Шаблоны ролей организации новых ключей не получают (Q-W7.00-2). По умолчанию — как есть; решение: добавить `docs.read` и `docs.comment` в шаблоны или допускать записи списка в шлюзе.
- **Q-W7.23-6.** `initiateUpload` с `purpose=document` модуль файлов не принимает (нет вида и родителя `docs.folder` / `docs.document`). `createDocument` принимает готовые файлы назначения `document` того же участника под `docs.folder` или `docs.document`; файлы версий от сервера документов и заданий модуль пишет сам (через подписанный PUT хранилища). Нужна правка владельца файлов.
- **Q-W7.23-7.** PIN ссылки хранится как PBKDF2-SHA256 (стандартная библиотека, 120 000 кругов, соль — id ссылки и ключ модуля), а не argon2id из комментария миграции 0061: `golang.org/x/crypto` пока косвенная зависимость. Заменить при появлении прямой зависимости.
- **Q-W7.23-8.** Исправление слова OCR меняет данные слова и счётчик, но не переписывает текстовый слой файла (для этого нужна программа). Новая версия от проверки не создаётся.
- **Q-W7.23-9.** Сжатие версий и хранение: каждая версия считается в квоту своим файлом, «один раз по sha256» (DOC-08) не сделано; срок хранения файлов версий (1 год) не применяется.
- **Q-W7.23-10.** Задание в статусе `running` после падения воркера не возвращается в очередь: в `docs.jobs` нет времени начала (нужен столбец или аренда — миграция стюарда).
- **Q-W7.23-11.** «Пропустить» упоминание стирает упоминание в комментарии (отдельного признака в таблице нет); IP открытия ссылки не пишется (`ip_hash` пуст): строгий сервер не видит запроса.
- **Q-W7.23-12.** Источник «Главной» для документов (`docs.mention`, `docs.ocr`, `docs.returned`; позже `approve/sign/ack`) не добавлен: делать вместе с W7.24 одним пакетом; ожидания участника уже считаются в `my.wait`.
- **Q-W7.23-13.** Путь публичной страницы ссылки — `<PUBLIC_ORIGIN>/p/docs/<токен>` (нет макета, запрос W7.28).
- Реальные OCRmyPDF, Tesseract, qpdf и офис на этой машине не установлены: процессор проверен подставным запуском (аргументы, коды выхода, разбор TSV), с настоящими программами не прогонялся. Сервер документов (ONLYOFFICE) тоже не поднимался: протокол проверен сигнатурами и подставными HTTP-серверами.
- Маршрут, подпись, ознакомление (`startDocRoute` … `cancelDocRoute`) — W7.24: 501 `not_implemented`; чтение маршрута и ожидания по упоминаниям и OCR уже есть.
