## 1. Цель

После W4.13 владелец «Альты», логист (руководитель проекта LOG) и прораб (режим `mock`):

1. В проекте (`/t/:tenantId/tasks?project=<id>&view=people|workflow|automation`, ADR-0001 `?project=&view=`) видят вкладки **«Участники»**, **«Процесс»**, **«Автоматизация»** под шапкой проекта (вкладки «Доска / Участники / Процесс / Автоматизация», `role=tablist «Разделы проекта»`).
2. **«Участники»**: блок «Кто видит проект» с описанием уровня и переключателем «Открытый / Ограниченный / Закрытый» (`updateTaskProject`, тост «Доступ: {уровень}»; без «Настраивать» — `disabled`); добавление «Сотрудник» + «Роль в проекте» + «Добавить» (`setTaskProjectMemberRole`, «Роль назначена»); таблица «Сотрудник / Роль в проекте / Откуда доступ / Что может» (роль — select или 🔒, «Исключить {имя}» — `removeTaskProjectMember`, «{имя} исключён из проекта»; смена роли — «Роль изменена»); «Проверить доступ» (`checkTaskProjectAccess`: «{имя} может: {via} (роль «X»)» / «{имя} не может: {причина}») — у кого `tasks.members.manage` в проекте или `members.read`, иначе блок скрыт (Q-W4.00-tasks-7); «Роли проекта».
3. **«Процесс»**: чип «Действует v{N}» / «Черновик · действует v{N}», «Сбросить черновик» и «Опубликовать v{N+1}» (тосты эталона); «Статусы» (чипы с категорией, удаление при > 2, «Новый статус» + категория + «Добавить статус» перед первым «Готово», дубль — тост «Статус «X» уже есть»); «Переходы · {N}» (путь, кто, правила или «Без правил»; добавление «Название перехода», «Из любого» / статус, «В статус», «Добавить переход», ошибки-тосты «Назовите переход», «Переход должен вести в другой статус»); панель «Переход «{имя}»»: «Кто может», «Согласование» (режим, «При отказе вернуть в», «Согласуют все с правом…»), «Проверки и действия», «Удалить переход», «Изменения — в черновик». Каждая правка — `saveTaskWorkflowDraft` целиком (If-Match); ошибки публикации — тостом текстом сервера.
4. **«Автоматизация»**: правила («Когда … → …», «От имени {автор} · v{N} · запусков: {n}», «Включено», удаление), «Правил пока нет.», форма «Новое правило» (КОГДА / ЕСЛИ / ТОГДА, подсказка, ошибка в форме, «Добавить правило»), «Журнал запусков» («Запусков пока не было.»).
5. **Старая доска «Заявки»** (`/t/:tenantId/leads`, ADR-0001; вход — строка воронки в списке проектов): «Все проекты», крошка «Проект ЗАЯ · Заявки · Ремонт», `h1` «Заявки», пояснение воронки, «Канбан / Список», «Все исполнители / Мои задачи», «Задача» и форма (Название / Исполнитель / Приоритет / Срок), колонки этапов воронки и «Пусто», список и «Задач нет», карточка заявки (статус, исполнитель, приоритет, срок, «Перевести», «Нет права «Изменять» в модуле «Задачи»», чек-лист, «История и комментарии» с полем «Комментарий»), подпись о переходах. Решение судьбы — по умолчанию Q-W4.00-tasks-15: переносится как есть на API воронки (`flow: leads`, `fixed`).
6. Состояния: загрузка (скелетон `role=status «Загрузка»`), ошибка и «Повторить», нет связи (тост команды), нет права (гейт оболочки «Нет доступа к разделу «Задачи»»; без «Настраивать» — вкладки только для чтения), 390 px (раскладка flex-wrap эталона, таблица участников прокручивается в карточке — no-reference телефона, Q-W4.00-tasks-14).
