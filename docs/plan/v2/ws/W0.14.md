## 1. Цель

После W0.14 в `main` лежит пакет `frontend/packages/texts` (`@ortus/texts`) — единственный источник пользовательских строк этапов 0–2:

- **11 файлов-доменов** `src/<domain>.ts`: `shell`, `gate`, `banners`, `toast`, `errors`, `company`, `platform`, `logistics-manager`, `logistics-driver`, `home`, `screen-labels`. Значения — дословно из главного файла эталона 14.10 `design/Ортус CRM.dc.html` и `design/ortus/{api,models}.js` («ё», «», « · », « — », «…»).
- **Шаблоны — сообщения ICU MessageFormat** (`{name}`, `{n, plural, one {…} few {…} many {…} other {…}}`, `{x, select, … other {…}}`), а не функции: строки сериализуемы (контракт ключей, MSW, будущий backend) и проверяются одним парсером. Форматирование — `format(message, values)` из пакета (`Intl.PluralRules('ru-RU')`, числа — `Intl.NumberFormat('ru-RU')` с U+00A0).
- **`errors.ts` ключуется каноническими `Problem.code`** (реестр `design/docs/12-errors-and-events.md` v0.2 + PD-34: `seats_exhausted`, `request_pending`, `tier_below_usage`, `not_implemented`; клиентские `offline`, `timeout`, `upload_failed`), плюс тексты по HTTP-статусу для неизвестного кода и дословные сообщения mock-адаптера прототипа (`errors.mock.*`) для MSW. Карта «прототипный код ↔ канонический» не дублируется: она в `@ortus/domain` (`core/errors/map.ts`, W0.11).
- **`src/index.ts` генерируется** скриптом пакета `scripts/gen-index.mjs` (по файлам доменов); тест падает, если индекс устарел.
- Тесты-охранники: «каждый `Problem.code` имеет текст», «каждое сообщение — валидный ICU с полными формами множественного числа для ru», «одна строка-литерал — один файл», типографика, «ё», U+00A0, формат ключей, замороженный список ключей `contract/keys.json` (только добавление), покрытие статических тостов и сообщений `ApiError` эталона в границах этапов 0–2.

Новые домены (задачи и проекты, формы, база знаний, документы, чаты, касса, обращения, склад, SPA, ремонт, оформление, читалка документации) **не входят**: их файлы создают владельцы шагов своих этапов (D-plan-reconciliation §4, строка WS-08).

## 4. Контракты (публикует `@ortus/texts`)

```ts
import { shell, gate, banners, toast, errors, company, platform,
         logisticsManager, logisticsDriver, home, screenLabels, ALL, format } from '@ortus/texts';

type TextTree = { readonly [key: string]: string | TextTree };   // массивов нет, листья — ICU-сообщения
format(message: string, values?: Readonly<Record<string, string | number>>): string;
parseMessage(message: string): MessageNode[];                    // бросает IcuSyntaxError
argNames(message: string): string[];

format(company.modules.trial.title, { days: 12, date: '13.10.2026' }) // «Осталось 12 дней · до 13.10.2026»
format(errors.mock.company.seatsExhausted, { used: 10, limit: 10 })  // «Свободных мест нет: занято 10 из 10. …»
errors.problem.reservation_overlap                                   // текст по каноническому коду
errors.client.offline; errors.http.http409; errors.fallback           // клиентские состояния, статус, «Ошибка»
```

Правила словаря (дублируются в `README.md` пакета):

1. Значение — байт-в-байт из эталона; данные сида — только аргументами шаблона. Захардкоженные в эталоне строки («Временно, до 18:00 01.10», «Среда, 1 октября», «или выберите лимит от 50 ГБ») хранятся дословно с комментарием `// захардкожено в эталоне :NNNN`.
2. **Одна строка-литерал — один файл.** Если подпись нужна другому домену, он ссылается на файл-владелец (`home` берёт «Модуль не подключён» из `gate.chips.moduleOff`). Подпись пункта меню = заголовок страницы: хранится в `shell.nav.items`; файлы страниц держат заголовок, только если он отличается от подписи меню.
3. Сообщения `ApiError` mock-адаптера и тексты `Problem.code` — только в `errors.ts`; тосты успеха `run(…)` и прямые `toast('…')` — только в `toast.ts`.
4. Ключи — ASCII camelCase; исключение — словари `errors.problem` и `errors.client`, где ключ = значение enum API (`snake_case`). Массивов нет: перечисления — объекты с ключами-идентификаторами эталона.
5. Ключи из `contract/keys.json` не удаляются и не переименовываются; новые добавляются в конец файла и в `keys.json` (`node scripts/gen-index.mjs --keys`).
6. Шаблон — ICU: аргументы camelCase, `plural` — формы `one`, `few`, `many`, `other` (ru), `select` — с `other`; ASCII-апострофы и `{}` в тексте запрещены (типографика).

Если контракта соседа нет: `api/errors.yaml` (W0.07) ещё не в `main` — тест набора кодов читает реестр `design/docs/12-errors-and-events.md` + список PD-34 из теста; если `api/errors.yaml` появился, тест дополнительно требует текст для каждого его кода и клиентского состояния (сработает у стюарда при добавлении кода).

## 10. Риски и решения по умолчанию

1. **Формат шаблонов.** Старый бриф — функции TS; по умолчанию — ICU-строки (сериализуемы, общий валидатор, задача «проверка ICU»). Параметры не типизируются по сообщению: `format` бросает ошибку при пропущенном аргументе, тесты табличных кейсов закрывают шаблоны. Если понадобится строгая типизация — генератор `.d.ts` по `argNames` (аддитивно).
2. **Тексты канонических кодов без аналога в эталоне** (`malformed_request`, `csrf_failed`, `rate_limited`, коды чатов и смет и т. п.) написаны по колонке «Что делает интерфейс» реестра `docs/12`; помечены `// не из эталона` — подтверждает владелец продукта (decisionsNeeded).
3. **Справочники `models.js`** (`REASON` и др.) есть и в `@ortus/domain` (W0.11). Словарь держит `gate.reason` (5 × label/text) для гейта и «Проверки доступа»; паритет `domain.REASON` ↔ `texts.gate.reason` — кросс-тест интегратора на барьере (как в старом брифе §10 п.1). `TRIP_STATE`, `VEHICLE_STATE`, `MEMBER_STATE`, `TENANT_STATE` остаются в домене.
4. **Род в заголовках гейта** (ветка A «не подключён», ветка B «не подключена») — как в эталоне, два разных шаблона.
5. **`data-screen-label` для страниц без атрибута** — схема PD-37 «<Роль> · <подпись меню>», роль — персонаж рабочего места (`Владелец`, `Логист`, `Водитель`, `Оператор`); `tenants` → «Оператор · организации» (Q-43, значение придумано).
6. **`index.ts` генерирует скрипт пакета**, а не `tools/gen-barrel` интегратора (его ещё нет); при появлении общего генератора интегратор переключает скрипт `gen`.
7. **Без новых зависимостей**: `node --experimental-strip-types` печатает ExperimentalWarning — скрипт `test` запускается с `--no-warnings`; при переходе на Vitest (`vitest@4.1.11` уже в lock у `@ortus/domain`) тесты переносятся без изменений логики.
8. **E2E-сверка с эталоном** (старый бриф §6(а)) не делается в W0.14: страниц нет, а `labels.spec` страничных WS сверяет эталон и реализацию по тем же строкам.
