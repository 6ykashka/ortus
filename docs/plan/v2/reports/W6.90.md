## Вопросы (Q-W6.90-N, в `decisions.md` вносит интегратор)

- **Q-W6.90-1.** Акты, акт сдачи и подрядчик в API не создаются (Q-W6.15-4, Q-W6.15-7), сида ремонта на стенде нет. Значение по умолчанию: путь вставляет эти строки в базу организации стенда (`docker exec psql`, учётка из env-файла стенда), дальше всё — настоящими командами; код подписи читается из журнала `cmd/api`. Нужны операции или сид создания актов и подрядчиков, тогда шов убирается.
- **Q-W6.90-2.** У ремонта нет родителя файлов (`repair_evidence` загрузить нельзя). По умолчанию фото отметки и допработы кладётся вложением задачи (`task_attachment`): отметке нужен лишь готовый файл организации. Нужен родитель `repairs/project` для `repair_evidence`.
- **Q-W6.90-3.** Черновик создаётся только с `leadTaskId` (без него объект сразу «в работе», даже без прораба) — как в W6.11; в описании контракта это не сказано.
- **Q-W6.90-4.** Прораб на списание заявки до прихода получает 409 (права «списать» у него есть), а не 403. Принято как есть.
- Выплата проверена до статуса «предложена» (`proposed`): проведение кассиром (`MarkPaid`) потребителем события не подключено (Q-W6.15-3).
