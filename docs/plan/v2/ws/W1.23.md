## 1. Цель

Владелец бизнеса (и участник с правами `members.*`/`roles.*` в своей области) в разделе «Компания» → «Пользователи и
роли» (`/t/:tenantId/users`) видит и меняет доступ компании через API этапа 1:

- **Люди** — список участников с назначениями («{роль} · {область}[ · до {дата}][ · через группу «…»]»), статус
  («Активен», «Приглашён», «Заблокирован»), «Без роли — нет доступа к модулям», отметка функции «Водитель»; строка
  «{N} участников · без роли: {k} · мест занято {used} из {limit}»; «Пригласить»; «Назначить роль» у каждого; карточка
  сотрудника (функции, назначения, «Заблокировать» / «Разблокировать» — `updateMember`, «Почему доступно», «Передать
  владение»);
- **Группы** — карточки групп («{n} участника: имена», «Роли через группу: …»), создание группы и смена состава
  (`createGroup`, `setGroupMembers`, `deleteGroup`);
- **Роли** — список ролей (чипы «Системная», «Шаблон», «Своя», «{n} разрешений · назначена: {k}»), редактор роли
  `RoleEditor` (`@ortus/ui`), «Итоговые права роли», сохранение с ревизией (`updateRole`, `If-Match`), «Создать роль»;
- **Проверка доступа** — сотрудник × действие × подразделение → вычисленное право (`explainAccess`): «Разрешено» с
  основанием или причина отказа эталона («Модуль не подключён», «Нет права», «Нет доступа к объекту», «Запрещено функцией
  «Водитель»»), «Рабочее место сотрудника · вычислено», диалог «Почему доступно» (проверки по порядку, назначения,
  скрытые назначения — S1-14, no-reference);
- **диалоги** «Назначить роль» (роль, область «Вся организация / Регион / Фирма», «Действует до», итог и факты,
  текущие назначения и «Снять»), «Пригласить участника» (места, ошибки полей, «Все места тарифа заняты.»), «Создать
  роль» (пустая, из шаблона, копия), «Передать владение» (S1-16, no-reference), «Группа» (no-reference), «Почему
  доступно» (no-reference).

Подписи — дословно из эталона `design-stage-1`; где эталона нет — `no-reference` с решением; области «Касса» и
«Проект» в назначении, блок «Касса · остаток и лимиты» и роли модулей этапов 4–7 — `out-of-stage`. Четыре проверки
`verification-protocol.md` для трёх ключей в режимах `mock` (390 и 1440) и `stand` (backend всех операций уже в `main`).

Контракт не меняется. Операции (все — `0.4.0-stage1`, хендлеры в `main`, MSW W0.13):

| Проверка доступа | `explainAccess` |
| Места | `getTenantSubscription` (право `seats`), подключённые модули — `TenantContext.modules` из `/me/context` |

Сопоставления эталона и контракта (решения по умолчанию, §10):

- область: `tenant` → «Вся организация»; `org_unit` региона → «Регион {name}»; `org_unit` фирмы → «{Регион} / {Фирма}»;
  `self` → «Только назначенное лично»; `project` → «Проект» (имени проекта в этапе 1 нет — `out-of-stage` до W4.10,
  Q-W0.12-5); назначение из диалога: «Вся организация» → `{kind: tenant}`, «Регион»/«Фирма» → `{kind: org_unit,
  resourceIds: [id], includeDescendants: true}`; «Действует до» `YYYY-MM-DD` → `validUntil` = конец дня по Москве (UTC);
- статус участника: `active` → «Активен», `invited` → «Приглашён», `suspended` → «Заблокирован» (blocked эталона);
- вид роли: `builtIn` → «Системная»; имя совпадает с шаблоном каталога (`roleTemplates` `api/permissions.yaml` и
  `INDUSTRY.*.templates` эталона) → «Шаблон»; иначе «Своя»; роль функции «Водитель» — шаблон `driver`;
- права роли в редакторе: модуль каталога `api/permissions.yaml` → уровни (`view`…`settings`) → ключи; `restricted`
  ключи логистики — блок «Финансовые разрешения»; переключение уровня добавляет или снимает все ключи уровня, прочие
  ключи роли (в том числе `members.*`, `roles.*`) сохраняются как есть; частично выданный уровень — неопределённый флажок;
- места: лимит — право `seats` подписки, занято — участники `active` с аккаунтом и `invited` (Q-W1.00-10);
- «Проверка доступа»: действия эталона → ключи каталога (`fleet.view` → `fleet.vehicles.read`, `fleet.reserve` →
  `fleet.reservations.create`, `fleet.review` → `fleet.trips.review`, `fleet.earnings` → `fleet.earnings.read`,
  `spa.view` → `spa.appointments.read`, `repair.create` → `repairs.work_logs.submit`); объект — подразделение
  (`orgUnitId`): машин и рейсов в этапе 1 нет, выбор «Объект» — «Без конкретного объекта» и фирмы организации;
  `decisiveCheck`/`denyCode` → причина эталона (`module-installation` → «Модуль не подключён», `separation-of-duties` →
  «Запрещено функцией «Водитель»», `resource-scope` или назначения только вне подразделения → «Нет доступа к объекту»,
  иначе «Нет права»).
