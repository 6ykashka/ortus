## 1. Цель

После W2.21 логист (Котова, «Менеджер логистики» на «Москва / Север Логистик», пресет `logistics-ready`) и владелец в режиме `mock`:

1. Открывают **«Приёмка смен»** из меню (группа «Логистика», на телефоне — нижняя навигация «Приёмка») и по URL `/t/:tenantId/review` (`?trip=` — выбранная смена). Экран — как `pg.review` эталона (03 §7, `reviewVM` :3330–3382): крошка, заголовок, пояснение; очередь смен в состояниях `defect_review` → `submitted` → `rework` → `accepted` (порядок эталона) с чипом состояния; пусто — «Нет смен на проверке» с подсказкой (кнопки «Демо: открыть как водитель» нет — PD-54).
2. **Карточка дефекта** (`defect_review`): «Критический дефект · {модель} {номер}», «{рейс} · {водитель} · осмотр в {время}», «{зона}: {описание}», текст блокировки; «Дефект некритичный — разрешить выезд» / «Подтвердить неисправность» → `decideInspectionDefect` (`allow_departure` / `confirm_out_of_service`, `If-Match` свежего `getInspectionDefect`, `Idempotency-Key`), тосты «Выезд разрешён» / «Неисправность подтверждена, машина снята с рейса»; 409 — тост текстом сервера и перечитывание.
3. **Карточка смены**: заголовок «{рейс} · {название}», «{водитель} · {модель} {номер}», чип; «Пробег при выезде», «При сдаче», «Пройдено», «Топливо» (из осмотров `getInspection`); «Фото до и после» — пять ракурсов «Перед выездом» / «При сдаче» (`getFileDownload`, без файла — «нет»); «Осмотр и дефекты» (чек-листы, дефекты «{зона} · {описание} · при выезде|при сдаче[ · признан некритичным]», «Дефекты не отмечены», «Комментарий водителя:»); **проверка расходов** «Расходы в пути» (`listTripExpenses`: категория D-12, литры, дата, комментарий, «чек приложен», сумма; «Расходов нет»; «Итого заявлено») — расходы подтверждает приёмка (S2-11, 14 §1); «Начисление водителю за рейс» — только с `fleet.earnings.read` и только когда начисление есть (`getTripEarnings`).
4. **Решение** (`submitted`, право `fleet.trips.review`): «Замечания для водителя», «Что вернуть на доработку» (четыре раздела `ReworkStep`), «Вернуть на доработку» (`reviewTrip` `rework` + `steps[]`; проверки эталона «Опишите, что нужно исправить», «Отметьте хотя бы один раздел для доработки») и «Принять смену» → диалог `modal-accept-shift` «Принять смену {рейс}?» с «Что произойдёт» → `reviewTrip` `approve` (`If-Match`, `Idempotency-Key`), тост «Смена принята. Машина вернулась в пул». После решения — «Смена принята в {время}. Машина вернулась в пул свободных.» / «Возвращено водителю: «{комментарий}». Исправить: {разделы}.»
5. **Очередь блокирующих дефектов** (`logistics-defects`, no-reference, `/t/:tenantId/defects`, страница вне меню; вход — ссылка на «Приёмке смен»): вкладки «На проверке» / «Решённые» (`listInspectionDefects` по `state`), карточка дефекта (рейс, машина, водитель, зона, описание, время), комментарий решения, те же две команды; решено — чип и комментарий; 409 «уже решён другим» — тост и перечитывание; пусто.
6. **Начисления водителям** (`logistics-earnings`, no-reference, `/t/:tenantId/earnings`, вне меню; вход — ссылка на «Приёмке смен» для `fleet.earnings.read`): список по рейсам (рейс, водитель, сумма, кто и когда изменил), фильтр по подразделению (`orgUnitId`), итог; правка суммы владельцем (`fleet.earnings.manage`, `setTripEarnings` с `If-Match`); пусто; нет права — гейт оболочки; водителю — нет (D-10).
7. Состояния всех трёх: загрузка (скелетон), ошибка и «Повторить», нет связи (тост `run`), только чтение (команды недоступны), раскладка 390 / 1440.

## 5. Решения по умолчанию (вопросы — в отчёт)

1. Очередь дефектов и начисления — страницы вне меню (как «Хранилище», Q-W1.24-17): в меню эталона их нет; вход — ссылки на «Приёмке смен».
2. «Демо: открыть как водитель» не переносится (PD-54).
3. Проверка расходов — без кнопок на расход (в эталоне их нет): приёмка подтверждает все (`reviewTrip approve`), отклонённые и принятые помечаются чипом.
4. Строка диалога «Будет создано начисление водителю…» — при праве `fleet.earnings.read` (до приёмки начисления в контракте нет, эталон смотрит `trip.earnings`).
5. Категории расходов, которых нет в эталоне (`parking`, `toll`, `other`), — подписи D-12 владельца продукта: «Парковка», «Платная дорога», «Прочее».
