# W5.21 Страницы «Салон и SPA» (визиты, услуги и техкарты)

Этап 5 · дорожка Ф · шаг 5.2 · размер M · слот 3 (Vite 5203, Storybook 7203, API 8103, эталон 4103, `ortus-s3`) · вид `frontend`.
Зависит от: W5.00 (контракт `0.12.0-stage5`, тег Spa и экраны `spa-appointments`, `spa-services`). Backend SPA — W5.20 (после W5.10), поэтому страницы живут на MSW; режим stand — `test.fixme` с причиной.

## 1. Цель

Страница `spa` («Салон и SPA» у владельца и офиса, «Мой день» у специалиста; маршрут `/t/:tenantId/spa`) из эталона `Ортус CRM.dc.html` (`pg.spa` :1870–1900, `spaVM` :4242–4262, `completeAppointment`/`resolveIssue` в `ortus/api.js`) с расширением по контракту 0.12.0-stage5:

- вкладка «Визиты»: день, статус, карточка визита (время, услуга, длительность, клиент, кабинет, оборудование, буферы, техкарта), «Записать клиента» (`createAppointment` — специалист, кабинет, оборудование, буферы атомарно), «Перенести» (`rescheduleAppointment`), «Отменить» и «Не пришёл» (`cancelAppointment`), «Завершить процедуру» (`recordAppointmentPerformance`, затем `completeAppointment`), баннер «Учёт материалов не завершён» с решением владельца (`completeAppointment` с `overrides`);
- вкладка «Услуги и техкарты» (`spa-services`, no-reference B-6): список, «Новая услуга» (`createSpaService`), правка (`updateSpaService`, If-Match, ревизия растёт, записанные визиты держат снимок);
- состояния: загрузка, ошибка, нет связи, пусто, гейт.

MSW SPA (`frontend/packages/adapter/src/msw/spa/`): 11 операций тега Spa и `listInventoryItems` (сид салона — эталон `extra-data.js`: масло 250 мл, крем 12 г; визиты ap-1…ap-3 на календарных бронях b-a1…b-a3; конфликты ресурсов — по занятости с буферами календаря).

## 5. Решения по умолчанию (в отчёте — Q-W5.21-N)

| # | Вопрос | По умолчанию |
|---|---|---|
| 1 | В контракте нет справочника клиентов: `Appointment` хранит только `clientId` | Подпись клиента — из названия календарной брони (`«Услуга · Клиент»`); форма записи предлагает клиентов с визитами в окне ±30 дней |
| 2 | В эталоне две кнопки владельца («Списать остаток из резерва», «Принять фактический расход») — по контракту обе = `completeAppointment` с `overrides` | Обе передают фактом остаток на складе (`actualQuantity`), разные причины; требуют `inventory.consumption.override`, иначе текст «Решение примет владелец» |
| 3 | Блоки эталона «Остатки кабинета» и «Движения склада» | Не здесь: операции остатков и движений — страницы склада W5.10, W5.11; нехватка видна по ответу 409 `insufficient_stock` и баннеру |
| 4 | Контракт: нехватка → 409 без частичного списания (эталон списывал часть) | По контракту; баннер строится из визитов `performed_pending_posting` |
| 5 | Один экран на две роли | Вкладка «Услуги и техкарты» — только с `spa.services.read`; «Мой день» — заголовок и подпись специалиста (область «своё») |
