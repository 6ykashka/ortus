- `temporary-driver.spec.ts` «начатый рейс после окна» `@mock`: сдача после срока — командами водителя (`mockReturn`: `finishTripRoute`, осмотр при сдаче с пятью фото, `returnTrip`), как строка `@stand`: экран «Моя смена» в продолжении падает «Не удалось загрузить машины…» (`listVehicles` 403, Q-W2.32-2 → W2.61). - Строки `@known-defect` W2.32 (Q-W2.32-2, Q-W2.32-3) — владельцы W2.61 и W2.60, не W2.62.
- **Q-W2.62-1 (технический, backend W1.08 / modulesreg).** `modulesreg.Preview` отдаёт `object.entityType` = `fleet.trip` и пустой `moduleKey` — нарушает `ObjectRef` контракта (`entityType` — `^[a-z][a-z0-9_]{1,49}$`, `moduleKey` обязателен). MSW по умолчанию отвечает по контракту: `{moduleKey: fleet, entityType: trip}` (как уведомления рейса). Исправление — в `activity.go` (`EntityType: "trip"`) и `service.go` (`ModuleKey: key`).
- **Q-W2.62-2 (технический, как Q-W2.32-7).** Временный водитель без своих ролей после окна (не начатый рейс) и после приёмки получает на `listTripPlans`/`getTripPlan` 403 `forbidden_action` (шлюз: прав нет ни в одной роли), а не 404; ответ совпадает с ответом на несуществующий id, данных рейса нет. MSW повторяет стенд; mock-строки AC-06 записывают код явно (`hiddenAfterEnd`).
- **Q-W2.62-3 (W2.60).** MSW пропускает `submitInspection` при `draining` в шлюзе и закрывает осмотр перед выездом в хендлере (403 `module_read_only`). W2.60 в backend должен сделать так же (в `finishOnly` — только осмотр при сдаче); иначе поведение mock и стенда разойдётся на осмотре выезда.
