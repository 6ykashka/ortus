## 10. Риски и решения по умолчанию (вопросы — в отчёт)

1. «Список» — вкладка после «Доски» (как макет 1d), строки по разметке старой доски; no-reference (Q-W4.00-tasks-14).
2. Вкладки «Участники», «Процесс», «Автоматизация» — `ProjectSettingsTab({ tenantId, projectId, view })` W4.13 (`settings/index.ts`), подключение по `import.meta.glob`; до вливания W4.13 — пустая панель вкладки. Ключ кеша шапки проекта и вид данных (`{ data, etag }`) — общие с `settings/api.ts`.
3. «Я» в списках исполнителей — по имени из `/me/context` (`displayName`), как эталон (`me.name`); «Назначить меня» — исполнитель не передаётся, сервер назначает автора.
4. Закрытый проект (TP-03): подпись уровня — «Только участники проекта» (Q-W4.00-tasks-2, no-reference).
5. «Новый проект» — только с `tasks.projects.manage` в организации или подразделении (PD-53): у логиста кнопки нет.
6. Тексты отказов сервера (`detail`) — в тост и в форму дословно (эталон показывает сообщение модуля, `ЗП:340`).
7. Бейдж меню и источник «Главной» для задач требуют видов `tasks.*` в контракте «Требует решения» — вне W4.12 (вопрос в отчёт).
8. Возврат 1: название области проекта — `listOrgUnits` (право `org_units.read`), иначе `orgUnitName` ответа проекта (в контракте 0.10 его нет — вопрос стюарду Q-W4.12-10), иначе «—»; у логиста и водителя до поля — «—» (allowlist `tasks-board`, `tasks-projects`).
9. Возврат 1: ссылка на проект или задачу без доступа (404 или 403) — туда же, куда «нет доступа» без ссылки: список проектов, задача убирается из адреса (Q-W4.12-11). Ошибки форм «Новый проект» и «Новая задача» — только в форме, без тоста оболочки; коды оболочки — её текстом.
