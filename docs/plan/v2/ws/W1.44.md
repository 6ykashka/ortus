## 10. Риски и решения по умолчанию

- **Содержимое — по опции `WithContent()`.** Integration-тесты модулей (`files`, `notify/inbox`, `importer`) грузят те же фикстуры и сеют свои объекты, а затем проверяют списки и счётчики (`ab.member` без файлов, число уведомлений адресата). Если писать содержимое всегда, они изменятся. По умолчанию содержимое грузит только набор изоляции; ссылки разрешаются всегда (как `tenant:missing`). Вопрос — в отчёт (decisionsNeeded).
- **`a.manager-msk2 → 404` требует `members.manage`.** У роли «Менеджер логистики» его нет, поэтому шлюз ответил бы 403. По умолчанию `a.manager-msk2` получает вторую роль «Кадры» (`members.read`, `members.manage`) на Москва-2 с потомками: строка проверяет область импорта, а не шлюз. В YAML `a.manager-msk2` актором не был; integration-тесты используют его как адресата и владельца рейса Москва-2 — это не меняется.
- **Скачивание в наборе.** Без `S3_ENDPOINT` `getFileDownload` отвечает 503. Ссылка подписывается локально (`storage.S3.PresignGet` не ходит в сеть), поэтому цель получает фиктивный `S3_ENDPOINT=http://127.0.0.1:9`; загрузки в строках не доходят до хендлера (только отказы шлюза, `files_gate.yaml`).
- **Канал `notifications` раннера не добавляется.** Перепроверка адресата при выдаче выражается http-строками `listMyNotifications` с `present`/`absent`. Проверка адресата при постановке в очередь требует worker и outbox в цели набора (W1.42) — тогда канал имеет смысл. Вопрос — в отчёт.
- Изменяющие строки (`commitPeopleImport`, `markMyNotificationsRead`) с позитивным ответом не добавляются: строки набора идут параллельно на общих фикстурах, изменение состояния сломало бы соседние строки.
