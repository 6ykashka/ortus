## Расхождения и решения по умолчанию

Q-W6.15-1…9 внесены в `docs/plan/decisions.md`. Главные:

- Ставок бригады в контракте нет: пул акта = 40 % суммы акта, делится по принятым отметкам (Q-W6.15-1).
- Акты и счета в теге создаёт не операция (Q-W6.15-7): сид и последующие шаги; `pending_act` сервис не создаёт (Q-W6.15-2).
- Выплата — предложение вида `payroll` в кассу; состояние `paid` по проведению ставит `Service.MarkPaid`, потребителя события кассы в `cmd/worker` нет (Q-W6.15-3).
- Роль «Подрядчик» с областью объекта выдаёт потребитель событий `repairs.subcontractor.access_*.v1` (Q-W6.15-4).
- Ссылку на SMS отправляет необязательный порт `LinkSender` (заглушка пишет в журнал), без отправки `sentAt` не ставится (Q-W6.15-5).
- Строка изоляции `approveEstimateByClient` убрана: параметр `version` — число, а формат строк подставляет только ссылки (UUID), гость без `Idempotency-Key` получает 400 до хендлера; 404 и 410 проверяет `isolation_w615_test.go` (Q-W6.15-9).

## Для интегратора

- Новых зависимостей и скриптов нет. Переменные окружения: `PUBLIC_ORIGIN` (уже есть, начало адреса кабинета) и `REPAIRS_SIGN_KEY` (W6.12).
- Потребитель события проведения предложения кассы должен вызвать `repairs.Service.MarkPaid(ctx, tenantID, proposalID)` (`proposalID` — `source_id` предложения вида `payroll` с `source_kind = repair_payout`).
