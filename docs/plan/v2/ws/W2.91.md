# W2.91 · Осмотр сдачи обычной машины до начала окна рейса не даёт пустой интервал брони (Q-W2.75-3)

Вид: backend · этап 2 · шаг S2-20 (D-35, правило 6) · вне реестра §4 — постановка оркестратора · слот 1 (API 8101, compose `ortus-s1`).

## 1. Цель

Закрыть Q-W2.75-3 (и Q-W2.75-5). `releaseUsualSQL` (`fleet/inspections/submit.go`) ставил `during = tstzrange(lower, greatest(lower, $3))`; осмотр сдачи раньше начала окна рейса (рейс начат до окна по доступу с одобрения, docs/29) давал пустой интервал, `lower()` — NULL, `listReservations` отвечал 503 «Моя смена» водителя и подбору рейсов логиста.

## 2. Границы файлов

- `backend/internal/modules/fleet/inspections/**` (`submit.go`, `release_integration_test.go`);
- e2e `frontend/apps/web/e2e/journeys/stage2/temporary-driver-vehicle-shift.spec.ts`;
- `docs/plan/decisions.md` — строка Q-W2.91-1 (по постановке); этот бриф и отчёт.
- Не трогаю: `api/**`, миграции, остальные модули.

## 3. Входы

`design/docs/29-temporary-driver-vehicle.md`, `decisions.md` (Q-W2.70-9, Q-W2.72-1, Q-W2.75-3, Q-W2.75-5), отчёты W2.72, W2.78.

## 4. Контракты

OpenAPI и схема БД не меняются.

## 5. Решение (Q-W2.91-1)

Верх интервала брони (`during` и `occupied`) — `greatest(момент осмотра, lower + 1 микросекунда)`: интервал не пуст, `consumed` и история сохраняются, машина свободна фирме сразу (`vehicle_released_at`, статус «доступна»).

## 6. Тесты первыми

- integration `fleet/inspections` `TestReturnBeforeWindowKeepsReservationInterval`: окно брони начинается через час, осмотр сдачи сейчас; интервалы не пусты, `lower` не NULL, длина ≤ 1 с, машина «доступна», другой рейс её фирмы переходит в «Осмотр». Красный до правки SQL.
- e2e S2-20 `temporary-driver-vehicle-shift`: «полная смена» сдаёт сразу после выезда без ожидания окна; строка «Q-W2.75-3» — `test` с тегом `@stand` (без fixme и `@known-defect`).
