Этап 2 · подволна 2c · дорожка Т · AC-03…AC-06 · размер M · вид backend (страниц нет).
Зависит от W2.02 (бронь, `sched`), W2.04 (осмотры, решение по дефекту), W2.05 (старт рейса, расходы, сдача), W2.06 (приёмка, начисления). W2.07 (пул) в `main` нет — сценарий пула пропускается с причиной, пока операция отвечает 501. Блокирует W2.32 (выход этапа 2: AC-03…AC-06 автоматизированы).
Слот 5: API `HTTP_ADDR=127.0.0.1:8105` (цель набора берёт свободный порт loopback), `COMPOSE_PROJECT_NAME=ortus-s5` (не нужен: только testcontainers), `ORTUS_SLOT=5`.

## 1. Цель

Набор `backend/test/concurrency` (build tag `concurrency`, шаг CI `isolation/go-concurrency`, сейчас пропускается «нет backend/test/concurrency») проверяет логистику **сквозь весь `cmd/api`**: BFF, сессия dev-входа, шлюз операции (CSRF, право, модуль), Idempotency-Key, If-Match, пулы tenant DB по 4 соединения. Модульные гонки (`reservations`, `trips`, `review`, `inspections`) вызывают сервис напрямую; этот набор — ту же гонку через HTTP.

1. **Бронь (AC-03, CAL-04, I-01):** 100 параллельных `reserveVehicle` одной машины на одно окно (у каждой брони свой водитель) → ровно 1 × 201 и 99 × 409 `reservation_overlap`, одна живая бронь машины, отказанные водители ничего не держат; два водителя сами бронируют одну машину одновременно → один 201, один 409 (второй водитель — `a.driver-msk1` с ролью на Москва-1 на время теста).
2. **Старт рейса (S2-06):** два `startTrip` одной брони с разными ключами → один 201, один 409 `invalid_transition`; бронь потреблена один раз, одна строка аудита. Повтор одного ключа параллельно («двойное нажатие» телефона) → один эффект: 201 с тем же рейсом или 409 `idempotency_in_progress`.
3. **Приёмка (S2-10, S2-11, AC-05):** два менеджера одновременно принимают одну смену с одним If-Match → один 200, второй 412/409; одно решение в `fleet.trip_reviews`, машина свободна. «Принять» и «вернуть на доработку» одновременно → побеждает одно, состояние согласовано с победителем. Две проверки одного расхода → одна. Две записи начисления с одним If-Match → одна (412 второй).
4. **Решение по дефекту (S2-17, AC-04):** два `allow_departure` одного дефекта → один 200, второй 412/409; два менеджера разрешают два блокирующих дефекта одного осмотра одновременно → осмотр `approved`, рейс снова у выезда, бронь `hold`, выезд проходит; `allow` и `confirm_out_of_service` одного дефекта → одно решение, состояние по победителю.
5. **Пул (AC-06):** два одобрения одного запроса водителя → одно; пока `requestDriverTransfer` отвечает 501 (W2.07 не влит) — `t.Skip` с причиной.
6. **Негативы изоляции на настоящих объектах (AC-01, AC-02, AC-05):** фикстуры W1.04 не содержат рейсов, броней, осмотров, расходов и начислений, поэтому строки матрицы `backend/test/isolation` подставляют id машины («не рейс»). Здесь объекты создаются сменой через API, и таблица строк своим файлом (`isolation_test.go`) проверяет: чужая фирма (`a.manager-msk2`), наблюдатель другой фирмы (`ab.member`), водители той же фирмы с ролью на «своё» (`a.driver-msk1`, `a.driver-earnings`), водитель с временным назначением на ту же фирму (`a.driver-msk2`, чужой рейс), чужой тенант по своему пути (`b.owner`, `b.manager-msk1`) и по пути тенанта A (`b.owner`) не видят и не меняют машины, брони, рейсы, расходы, осмотры, дефекты, начисления — ответ совпадает с ответом на несуществующий id (статус и `Problem.code`), в теле и заголовках нет id объекта, списки его не содержат, изменения с настоящим If-Match не меняют ревизию. Водитель рейса: начисление — 403 `function_blocked`, в DTO рейса, во входящих, сводке, очереди решений и `/me/context` нет полей начисления (AC-05).

   **Уточнение возврата 1.** `a.driver-msk2` — водитель смен набора: только его роль на подразделении открывает машины фирмы (Q-W2.30-1). Поэтому «чужой рейс» для него — второй набор объектов, который владелец делает для другого водителя Москвы-1 без аккаунта (`crew theirs`); место строк — `a.driver-msk2@a~theirs`. Машины Москвы-1 этому месту видны по модели (W2.02), остальные объекты другого водителя — нет (AUTH-05). Строки, где чужой пакет отдаёт объект, остаются red-тестом с `t.Skip("Q-W2.30-N")` (§2).

## 10. Риски и решения по умолчанию

- Часы набора — `APP_FIXED_NOW` = `harness.Now()` (01.10.2026 10:30 MSK), как в наборе изоляции: периоды назначений фикстур считаются от них. Окна рейсов — свои дни после «сейчас».
- Один водитель — один рейс в пути (`trips_active_driver_uq`): тесты идут последовательно (`//nolint:paralleltest`), рейс раунда закрывается до следующего.
- Фото и чеки — строки `files.objects` в состоянии `ready` (как стек-тесты `cmd/api`): объектного хранилища у цели нет.
- Пул: пока W2.07 нет, тест пропускается по 501 с причиной; после W2.07 сценарий идёт по контракту (`DriverTransferCreate`, `decideDriverTransfer` с If-Match).
