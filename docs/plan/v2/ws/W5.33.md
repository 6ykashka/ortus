## 4. Решения по умолчанию (отступления — `Q-W5.33-N` в отчёте)

- Выдача под отчёт в контракте проводится сразу (`issueCashAdvance` → перемещение `done`): шага «Получил(а)» для выдачи нет; кнопка показывается только для входящего перемещения в пути (Q-W5.33-1).
- Роль в API хранит только ключи прав, полей сумм лимитов нет: флажки блока сохраняются через `permissions`, поля лимитов отключены с пояснением до расширения контракта ролей (Q-W5.33-2).
- Фото чека — файл Files, `purpose: expense_receipt`, владелец `cash/account` (отдельного purpose и родителя у кассы в контракте нет; Q-W5.33-3). QR: полезная нагрузка чека ФНС `t=…&s=…&fn=…&i=…`, сумма из `s`; в прототипе — подстановка 1260 (Q-W5.33-4).
- Срок отчёта (`dueDate` выдачи) в ответах контракта не возвращается (ни `CashAccount`, ни `CashTransfer`): страница читает необязательное поле `reportDueDate` счёта, пока его нет — чипы срока «Отчитаться до …», «Срок отчёта … прошёл», «Отчитаться сегодня» не показываются, остаются «Отчитались полностью» и «Выдано … · ДД.ММ» (Q-W5.33-5, нужна правка контракта стюардом).- Остальные расхождения контракта (подробно — отчёт): Q-W5.33-6 свободная связь чека → `note`, имя принявшего недоступно; Q-W5.33-7 шаблоны «Водитель»/«Прораб» без `cash.advance.self`; Q-W5.33-8 `listCashTransfers` требует `cash.read` (держателю 403 — «В пути» из ответа своей команды); Q-W5.33-9 `listCashCategories` требует `cash.read` (сидовый справочник статей на клиенте); Q-W5.33-10 сид mock без «Кассира салона» и области account; Q-W5.33-11 заголовок «Чеки» — `h2`.
