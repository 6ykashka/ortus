## 1. Цель

Один запрос проходит путь **браузер → BFF → API → control DB → tenant DB** с проверкой права (критерий выхода этапа 0 плана 27: «запрос проходит браузер → BFF → API → tenant DB с проверкой права»):

- `corepack pnpm run gen` (≡ `make gen`) генерирует из `api/dist/ortus.bundle.yaml` Go strict server по тегам (`backend/internal/api/<tag>/`), каталоги операций, кодов ошибок и прав (`backend/internal/api/catalog/`), роутер тегов `backend/cmd/api/router.go` и TS-схему `@ortus/api-client` (openapi-typescript); клиент — openapi-fetch. Повторный запуск не меняет файлы (дрейф ловит CI W0.04 `contract/codegen-drift`).
- `backend/cmd/api`: chi, slog JSON, `HTTP_ADDR` из env; общий конвейер `requestid → logging → recover → security headers → шлюз операции → роутер тегов`. Шлюз операции по каталогу OpenAPI: сессия (401) → CSRF и Origin на изменяющих (403) → оператор платформы (404) | членство и состояние организации (404/403) → право из `x-permissions` по grants tenant DB (403 `forbidden_action`) → хендлер. Тег без реализации отвечает 501 `not_implemented` после шлюза.
- `platform/{requestid,problem,httpx,session,session/dev,tenantctx}`; dev-провайдер BFF: `POST /api/v1/dev/login {"persona"}` и `POST /api/v1/dev/logout` (только `AUTH_PROVIDER=dev` и `APP_ENV≠prod`), cookie сессии `ortus_sid` (HttpOnly) и `ortus_csrf` (double-submit).
- `GET /api/v1/me/context` (`getMyContext`, тег `Context`): control DB (аккаунт, оператор, членства) + tenant DB каждой доступной организации через пул с проверкой sentinel (подразделения, `access.policy_state`, возможности из grants и владения).
- `frontend/apps/web`: каркас Vite + React 19 + TanStack Router и Query, `#app`, прокси `/api` из env (`ORTUS_API_ORIGIN`), dev-вход `?persona=` в сборке `--mode e2e` с `<html data-e2e-persona>` (контракт W0.05 §4.4), экран контекста `/`.
- Сквозные тесты: Go integration (testcontainers: миграции W0.06 + Go-сид) и Playwright smoke через харнесс W0.05 в режиме `stand`: позитивный кейс, 401 и 403.

## 10. Риски и решения по умолчанию

1. **Dev-вход вне контракта.** Операций входа нет в 0.2 (вход, logout, CSRF — W0.08). По умолчанию — служебные маршруты `/api/v1/dev/{login,logout}` вне OpenAPI (A-23 W0.16), только `AUTH_PROVIDER=dev` и не `prod`. W1.03 добавит OIDC по контракту W0.08.
2. **Имя cookie.** OpenAPI — `__Host-ortus_session` (требует `Secure`), `.env.example` — `ortus_sid`. По умолчанию `SESSION_COOKIE_NAME` (умолчание `ortus_sid`): на `http://127.0.0.1:<порт>` префикс `__Host-` невозможен. В prod — `__Host-ortus_session` + `Secure` (W1.03).
3. **Код для 500.** В реестре нет `internal_error`. По умолчанию непредвиденная ошибка → 503 `dependency_unavailable` с `detail` «Внутренняя ошибка»; вопрос стюарду (decisionsNeeded).
4. **Проверка права до W1.04.** Оценщик `permit()` — W1.04. До него `GrantAuthorizer`: владение (`owner_bindings`) → все tenant actions; иначе только grants области `tenant` из tenant DB (`role_assignments` × `role_versions`, личные и через группы), `x-permissions-mode` `all`/`any`. Области `unit/project/…`, `restricted`, функция `driver` (`function_blocked`), PD-53 — W1.04, fail-closed: не дают права на операцию без объекта.
5. **`capabilities` и `modules` в `/me/context`.** `capabilities` — из того же источника (владение → все tenant actions в области `tenant`; grants `unit` → `org_unit`, `resource` → `resource_pool`, `warehouse` пропускается — см. отчёт W0.07); `modules: []` до W1.07. `permissionVersion` — непрозрачная строка из `access.policy_state` организаций.
6. **`membershipId`.** Отдаётся `memberships.id` control DB (UUID сида `membership:<t>:<acc>`); примеры W0.07 используют id участника прототипа (`ortus:t-alta:m-owner`) — расхождение примеров и сида для W0.13/стюарда.
7. **Хранилище сессий** — в памяти процесса (dev/e2e); durable store — W1.03.
8. **Слот 13 вне диапазона 1…10.** `stand.mjs init` и `e2e-kit` принимают слот ≤ 10. Порты задаются явно (`PORT`, `HTTP_ADDR`, `REFERENCE_PORT`), env стенда — вручную (`ortus-s13`, порты + 1300).
9. **OpenAPI 3.1 и oapi-codegen.** Генератор v2.8.0 читает бандл 3.1 (проверено на 18 тегах). Пакет тега `context` совпадает с stdlib — потребители импортируют с псевдонимом (`contextapi`).
10. **Валидация запросов по схеме** (kin-openapi) не подключается: тела проверяет strict server и `DecodeStrict`; полный валидатор — вместе с первой изменяющей операцией (W1.01).
11. **Isolation-job CI** блокирующий с первого эндпоинта: набор изоляции — W0.15; порядок слияния 0c — W0.15 до W0.09 или вместе.
