## Решения по меню и состоянию модуля

Принято 6 октября 2026 года. Подробности — `docs/design-system/components.md` (`AppShell`, `AccessGate`).

| ID | Вопрос | Решение |
|---|---|---|
| D-23 | Что видно в меню владельца при разных состояниях отраслевого модуля | Подключён (`enabled`) — своя группа со всеми пунктами. Отключён с сохранённой историей (`draining`, `read_only`) — группы нет, в группе «Отключены · только чтение» внизу меню остаётся один пункт с названием модуля; страница открывается для чтения с баннером, новые операции закрыты. Ни разу не подключался или `disabled` после `owner_export` — в меню нет. Меню сотрудников (логист, водитель, прораб, мастер) не меняется: пункт остаётся, на странице — `AccessGate` с объяснением |

## Решения по формам

Принято 6 октября 2026 года по FORM-01…FORM-03 (`v0.1/01-technical-spec.md`), `02-architecture.md` «Шаблон кругового осмотра, отчёт прораба» и `POST /forms` (`FormCreate`: `orgUnitId`, `name`, `definition`).

| ID | Вопрос | Решение |
|---|---|---|
| D-24 | Как создаётся новая форма | «Новая форма из шаблона» в «Формах и опросах». Шаблоны: пустая форма и отзыв клиента (общие), круговой осмотр машины, ежедневный отчёт прораба, анкета клиента SPA (отраслевые — только при подключённом модуле). Обязательны название (уникальное в организации, не короче 3 символов) и область формы. Результат — черновик без версий и автоматизаций, ответы принимаются после публикации v1. Право — `forms.create`; в прототипе кнопка видна тем, у кого есть «Настраивать» (`forms.publish`). Шаблоны заданы в коде (`ortus/models.js → FORM_TEMPLATES`); свои шаблоны организации и копия существующей формы — открытый вопрос |
| D-25 | Каким должен быть конструктор форм (6 октября, заменяет экран D-24) | По функциональности как в Яндекс Формах, в оформлении Ортуса: плитки и список из 15 шаблонов, список форм с группами, страницы, 21 тип вопроса, условия «И / ИЛИ», скрытые вопросы, баллы, предпросмотр, настройки доступа, действия после ответа, сводка / лента / таблица и CSV. Без оплаты (FORM-05) и серии вопросов (FORM-06); вместо справочников Яндекс 360 — данные CRM. Подробно — `20-forms.md` |
| D-26 | Как сохранять ответы форм в Базу знаний (7 октября) | Действие «Сохранить в Базу знаний»: строкой в таблицу на странице или записью на страницу. Записи живут отдельным блоком под текстом и не создают версий страницы. Пишет автор правила с проверкой его прав при каждом запуске; для страницы «Все сотрудники» — отдельное подтверждение. Файлы не копируются, строки удаляются вместе с ответом по сроку хранения. Публичная форма — только после принятия ответа. Одна строка на ответ и правило, «Повторить» и «Перенести прошлые ответы». Подробно — `20-forms.md` |
| D-27 | Как устроен модуль «Задачи» (8 октября) | Проекты по мотивам Jira без своей системы прав: участие — роль с областью «проект», роли области действуют по уровню доступа (открытый — все права, ограниченный — чтение, закрытый — ничего). Процесс с версиями: переходы с правилами и согласованием; публикация не двигает задачи. Недоступный переход объясняет причину. Автоматизация от имени автора с проверкой прав, без циклов. Вложения и связи «входит в / состоит из» (до трёх уровней) по правам задачи, отдельных прав нет. «Заявки» остаются на воронке. Подробно — `21-tasks-projects.md` |
| D-28 | Как устроен модуль «Чаты» (10 октября) | Свой сервис чатов в Ортусе, а не мост в Telegram или Max. Виды: личные, рабочие группы, по роли в области, чаты записей (рейс, объект — создаются правилом), объявления. Состав — из «Пользователей и ролей»: роль в области, группа, связь с записью; по имени — назначение роли чата с областью `chat`. Права: политика вида → роль в чате → модуль «Чаты» в ролях → функция «Водитель». Личные чаты читают только двое. Срок хранения по видам содержимого (текст 3 года, вложения 1 год, отметки прочтения 30 дней), удержание для проверки; при заполнении места ограничиваются только файлы, поведение выбирает владелец чата. Подробно — `25-chats.md` |

## Допущения

- Пилот — логистика, один тенант-холдинг из 3 регионов и 12 фирм.
- Подписка в пилоте активируется оператором вручную, без онлайн-оплаты.
- Маршрут строится вручную; оптимизатора нет.
- Trial 14 дней / 10 мест / 5 ГиБ / grace 7 дней — гипотезы, настраиваются в env.
- Один человек — один PersonProfile в тенанте; объединение дублей вручную.

## Глоссарий

Один термин — одна сущность. В интерфейсе используется русский термин, в коде — идентификатор.

| Термин в интерфейсе | Код | Значение |
|---|---|---|
| Организация (в панели платформы) | `tenant` | Изолированный клиент платформы, своя БД |
| Бизнес | `tenant` | То же с точки зрения владельца |
| Подразделение: регион, фирма, филиал | `org_unit` (`region`, `company`, `branch`) | Область работы и доступа внутри тенанта |
| Юрлицо | `legal_entity` | Реквизиты, сторона документов |
| Аккаунт | `account` | Возможность войти, глобальна |
| Участник | `membership` | Аккаунт в конкретном бизнесе |
| Сотрудник | `person_profile` | Человек; может быть без аккаунта |
| Функция | `work_profile.function` | Водитель, массажист, прораб — профессиональный смысл |
| Роль | `role` | Набор действий |
| Назначение | `role_assignment` | Роль + область + срок |
| Область | `scope` | Где действует назначение |
| Действие / право | `action key` | `fleet.trips.review` |
| Модуль | `module` | Подключаемый набор функций |
| Подключение модуля | `module_installation` | Состояние модуля в бизнесе |
| Доступность по тарифу | `entitlement` | Коммерческое право на функцию и лимит |
| Пробный период | `trial` | — |
| Льготный период | `grace` | После окончания оплаты, до режима чтения |
| Хранилище | `files.usage` | Оплачиваемый объём файлов |
| Машина | `vehicle` | — |
| Бронь | `reservation` | Занятость ресурса на интервал (`hold` → `confirmed`) |
| Рейс | `trip` | Работа водителя на машине по маршруту |
| Осмотр (перед выездом / при сдаче) | `inspection` (`departure` / `return`) | — |
| Дефект, блокирующий дефект | `defect` (`severity=blocking`) | — |
| Расход | `expense` | Затрата в рейсе; не выплата и не начисление |
| Начисление | `earning` | Вознаграждение сотруднику; закрыто для функции driver |
| Приёмка смены | `trip review` | Решение менеджера: принять / вернуть |
| Пул водителей | `driver pool` | Межфирменный каталог с минимумом сведений |
| Передача водителя | `driver_transfer` | Согласованное временное назначение |
| Данные | `data hub`, `dataset` | Каталог разрешённых наборов модулей |
| Файлы | `files` | Фото и документы с квотой |
| Объект | `repairs.project` | Квартира, дом или помещение в ремонте; создаётся черновиком на этапе заявки «Замер», в работу переходит после договора |
| Объект-черновик | `objects.state=draft` | Объект до договора: замер и смета, без прораба и работ; в списке — фильтр «До договора» |
| Смета, версия сметы | `estimate`, `estimate.version` | Разделы, работы и материалы с ценами заказчика. Версия: черновик → у заказчика → согласована (действует) → заменена; согласованная версия не меняется |
| Допработа | `change_order` | Работа вне действующей сметы; предлагает прораб без цен, оценивает офис |
| Допсоглашение | `estimate.kind=change`, `agreement_no` | Новая версия сметы после договора; начинает действовать после подписи заказчика кодом из SMS |
| Шаблон объекта | `object_template` | Смета с формулами объёмов, технология графика, документы, чек-лист приёмки и материалы для вида ремонта; стартовый (Ортус, копия организации) или свой |
| Справочник расценок | `price_items` | Работы и материалы организации с единицей и ценой; цена копируется в строку сметы при сборке |
| Отметка прораба | `work_log` | Объём работы, бригада, материалы и фото за день; не меняет факт до приёмки |
| Приёмка объёма | `work_log review` | Решение владельца или менеджера: принять / вернуть отметку |
| Акт | `documents.kind=act` | Закрывает этап для заказчика; по закрытым актам считается готовность для заказчика и начисления бригаде |
| Бригада | `crew` (`person_profile` без аккаунта) | Рабочие объекта, учётные карточки без входа в CRM |
| Подрядчик | назначение с областью `project` | Внешняя компания с временным доступом к одному объекту |
| График работ | `schedule` | Этапы объекта с датами, связями и паузами |
| Базовый план | `schedule_baseline` | Сроки, утверждённые с договором; меняется только допсоглашением |
| Прогноз сдачи | `forecast_finish` | Дата сдачи по текущим срокам этапов |
| Критический путь | `critical path` | Этапы без запаса: их задержка сдвигает сдачу |
| Запас | `total float` | На сколько рабочих дней этап может сдвинуться без сдвига сдачи |
| Пауза | `schedule_link.lag_days` | Технологический перерыв между этапами в календарных днях; отрицательная — опережение |
