## Сделано

- **П-1 · `tools/ci/e2e-stand.mjs`** (новый) — оркестратор браузерного пути `/me/context` сквозь стек:
  - стенд compose (только `postgres`) → `migrate` → `seed` → `go build ./cmd/api` → API с `APP_ENV=e2e`, dev-входом, `HTTP_ADDR=127.0.0.1:(8100+N)` и `ALLOWED_ORIGINS` Vite слота → ожидание `GET /readyz` 200 → Playwright `--grep @stand` (Vite и эталон поднимает харнесс W0.05) → остановка API и `down -v` в `finally`;
  - env-файл стенда лежит во временном каталоге (`ortus-e2e-stand-s<N>.env`), корневой `.env` исполнителя не трогается;
  - перед стартом проверяются порты приложения слота (Vite, API, эталон), код 3;
  - итог считается по JSON-отчёту Playwright: нужен хотя бы один пройденный тест, 0 пропущенных и 0 упавших. Молча пропустить `@stand` нельзя;
  - `ORTUS_SLOT` > 10 в Playwright не передаётся: харнесс W0.05 принимает только 0…10, поэтому порты задаются явно через `PORT`, `HTTP_ADDR`, `REFERENCE_PORT`;
  - `--down` — только остановка (шаг `if: always()` в CI).
- **Конвейер `tools/ci/pipeline.mjs`:** новая job `e2e-stand` (needs `build`) с шагом `e2e-stand`. Локально без `ORTUS_SLOT` шаг пропускается с причиной: слот 0 — общий стенд интегратора, а `down -v` удалил бы его тома. В CI берётся слот 0. Без Docker шаг локально пропускается, в CI падает. `makeContext` получил поле `slot` из `ORTUS_SLOT`.
- **`.github/workflows/ci.yml`:** job `e2e-stand` (needs `build`, Node + Go + `pnpm install`) → `node tools/ci/pipeline.mjs --job e2e-stand` → шаг `if: always()` `node tools/ci/e2e-stand.mjs --down` → артефакт `playwright-report-stand` при падении. Проверено actionlint 1.7.12 в Docker.
- **П-4 · гейты в конвейере:**
  - корневой `test` дополнен `test:plan` (`docs/plan/scripts`, 73), `test:adr` (`docs/adr`, 108), `test:load` (`backend/test/load/test`, 194);
  - job `unit`: шаги `check-decisions` (`renumber-decisions --check`), `allowlist-lint`, `mcp-check` (`initialize` + `tools/list` без `--url`, без сети и без браузера);
  - job `build`: шаги `storybook` (`storybook:build` `@ortus/ui`) и `check-k6` (Docker, `grafana/k6`; охрана Docker, как у `images`).
- **Гейт `renumber-decisions --check` зелёный.** Ссылка D-NN узнаётся как ссылка комплекта по своей строке (абзацу Markdown) в двух случаях: рядом стоит пометка «D-NN комплекта» или «комплекта D-NN»; или в строке есть тема решения из `KIT_DECISIONS` (D-23 — `меню|модул|moduleOn|on/ro/off|navForBase|Отключены · только чтение`). PD-23 плана — pnpm, с этой темой не пересекается. Ссылки комплекта не меняются и печатаются отдельной строкой `комплекта: N ссылок`. `docs/plan/analysis/**` не правились.
- **П-5 · стенд одной командой.** `stand.mjs all [--slot N] [--force]` выполняет `init` (если нет `.env` или задан `--force`) → проверку портов → `up --wait` → `migrate all up` → `seed`. Если `.env` уже есть для другого слота, команда завершается с кодом 2 и подсказкой `--force`. Корневые скрипты: `stand` = `all`, `stand:down` = `down -v`.
- **П-6 · проверка портов и базы слотов.**
  - `stand.mjs up` (и `all`) до `docker compose up` пробует занять каждый опубликованный порт запускаемых сервисов на `127.0.0.1` и проверяет, что на нём никто не принимает соединения. Учитываются профили и явный список сервисов. Порты, которые уже держит сам проект (`docker compose ps --format json`), пропускаются, поэтому повторный `up` идемпотентен. Если порт занят, команда завершается с кодом 3 и называет адрес, переменную, сервис, подсказывает `Get-NetTCPConnection`, `lsof`, `netsh … excludedportrange` и `init --slot <N> --force`.
  - Слоты расширены до 0…20.
  - База слота N ≥ 1: MinIO 19000/19001, OTLP 14317/14318, остальные порты — как на слоте 0. Слот 0 (скелет и интегратор) не изменился.
  - На машине заняты `127.0.0.1:10000` и `127.0.0.1:11001` (`Get-NetTCPConnection`, процессы 29648 и 7828). Старые базы давали на них MinIO слотов 10 и 20, а OTLP попадал на 5217/5218 (Vite слотов 17–18) и 6117/6118.
  - Обновлены `README.md` стенда (запуск одной командой, проверка портов, таблица слотов 0/7/18) и комментарий `.env.example`.
