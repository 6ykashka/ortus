## 1. Цель

Оболочка W1.20 влита в ветку `ws/W1.49` от `main` (`git merge ws/W1.20`) и принимается без замечаний:

- **«Касса» массажиста — по праву**: пункт «Касса» рабочего места массажиста зависит от права `cash.*` участника, как
  `core([…, cash])` эталона (`navForBase` :2964, :3001; `M.can(db, mid, 'cash', 'view')`). Право массажиста «Альты» в
  эталоне — роль «Кассир салона» с областью «касса» (`ortus/cash.js` `installCash` :263–266, этап 5); в «Лотосе» такой
  роли нет, поэтому у `therapist@t-lotos` пунктов четыре: «Мой день», «Чаты», «Календарь», «База знаний»
  (`01-shell.md` §8.3, §20 п. 33). «Подотчёт» водителя и прораба остаётся пунктом профиля рабочего места: в эталоне он
  зависит от своего подотчётного счёта (`cashSelf` :2968), а не от права;
- **«Выйти» без запросов после выхода**: сначала уход с оболочки на `/auth/login`, кэш запросов очищается, когда
  оболочка уже размонтирована; ни один запрос оболочки не перезапускается (нет 401 в консоли);
- **канал реального времени** (ADR-0015, PD-58, протокол отчёта W1.07): `createRealtimeTicket` → WebSocket
  `/api/v1/realtime` с подпротоколом `ortus.realtime.v1` → кадр `auth`; `pong` на `ping`; `context.changed` —
  перечитать `/me/context`; `notifications.changed` — счётчик и список входящих; `session.ended` — перечитать
  `/me/context` (401 → «Нужен вход»); разрыв `seq`, закрытие 1001/1013/обрыв — переподключение с паузой и полное
  перечитывание; 4401 — новый билет. **501 и 404 билета гасятся молча** (до W1.42): без тоста, без повторов, без
  необработанного отклонения;
- замечания возвратов 2–3 W1.20 подтверждены закрытыми (баннер места по `tenantState.storageWriteStatus`, кадр загрузки,
  Escape → фокус на «Профиль»);
- evidence проверяющего W1.20 из неотслеживаемого `docs/plan/evidence/{shell,access-gate}/verify/` в корне main
  перенесено в ветку;
- четыре проверки `verification-protocol.md` для `shell` и `access-gate`.
