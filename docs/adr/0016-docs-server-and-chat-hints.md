# 0016. Сервер документов за адаптером, callback и подсказки чатов

Статус: принято (решение по умолчанию до ответа владельца по D-32; пересмотр — новым ADR со статусом «заменено 0016» у этого)
Дата: 2026-10-25 · W7.00 (стюард контракта этапа 7) · Участники: W7.12 (подсказки чатов), W7.23 (адаптер сервера документов), W7.24 (маршрут и подпись), tech lead, backend lead
Решение комплекта: D-32 (сервер документов), D-31 (порт доставки кода)
Кто решает: tech lead, backend lead (решение плана, а не комплекта); выбор сервера документов — владелец продукта (D-32)
Блокирует: W7.23, W7.25

Решения плана: PD-58 (канал реального времени), D-32, D-31. Вход шагов 7.1 (CHAT-01) и 7.2 (DOC-01…DOC-12).

## Контекст

Контракт этапа 7 (`0.12.0-stage7`) вводит «Документы» с совместным редактором и «Чаты» с доставкой сообщений. Требования:

- D-32: выбор Р7-Офис или ONLYOFFICE — на этапе 7, «в МВП — нет»; до выбора сервер документов — за адаптером, 52 формулы и защищённые диапазоны по ролям — критерии приёмки движка (Q-W4.00-documents-1, -11, -12).
- ADR-0015: канал реального времени — WebSocket-шлюз в `cmd/api`, кадры — подсказки без данных; для чатов Centrifugo пересматривается в DoR этапа 7 (Q-W4.00-chats-7).
- DOC-02: один документ — `files` ядра плюс расширение `documents`; DOC-08: версия на каждое сохранение движка, хранение по sha256.
- Сервер документов вызывает Ортус по HTTP при сохранении (ONLYOFFICE: callback с JWT) — запрос без сессии браузера и без `tenantId` в пути.

## Варианты

1. **Контракт оболочки: `openDocumentSession` + `docServerCallback`, движок за адаптером (рекомендуется).** Публичный контракт не знает движка: сессия — подписанная конфигурация (JWT), callback — межсервисная операция с проверкой подписи; операций правки блоков нет. Без движка документ открывается на просмотр. Плюсы: выбор D-32 не меняет контракт, mock и стенд работают без движка. Минусы: правка блоков и формулы у движка, их паритет — приёмка на файлах клиентов.
2. **Свой редактор (операции блоков в контракте).** Плюсы: независимость от лицензий. Минусы: сотни операций, формулы и совместная правка — отдельный продукт; противоречит D-32.
3. **Centrifugo для чатов с данными в канале.** Плюсы: история и присутствие. Минусы: второй контур прав и токен в JavaScript (ADR-0015 вариант 2), новый сервис.
4. **Подсказки `chat.changed` в шлюзе ADR-0015 (рекомендуется для чатов).** Кадр без данных, клиент перечитывает сообщения с `afterSeq`. Плюсы: одна модель прав, контракт проверяемый. Минусы: нет набора текста и присутствия (Q-W4.00-chats-7).

## Решение

Рекомендация по умолчанию — варианты 1 и 4.

- **Документы.** `GET /docs/{documentId}/open` (`openDocumentSession`) возвращает `DocSessionConfig`: `engine` (`none`, `r7`, `onlyoffice`), `editorAvailable`, ключ версии `documentKey` (`t<тенант>.d<документ>.v<версия>`, строчные UUID, меняется с каждой версией; тенант в ключе, потому что у callback нет ни сессии, ни `tenantId` в пути, а документ не уникален между схемами тенантов), URL файла (короткая подпись), пользователь, права (`edit`, `review`, `comment`, `download`, `print`, `fillForms`), защищённые диапазоны, подписанный `token` (JWT HS256, секрет адаптера — у шлюза и сервера документов). `POST /api/v1/internal/docs/callback` (`docServerCallback`) принимает кадр сервера документов (`key`, `status` 0–7, `url`, `users`, `forcesavetype`); заголовок `Authorization: Bearer <JWT>` (схема безопасности `docServerJwt`) проверяется до чтения тела, неверная подпись — 401 `session_expired`; и только после проверки подписи из ключа читается тенант (`t<тенант>.d<документ>.v<версия>`), по нему выбирается БД тенанта (control `tenants`, tenant_routing), документ и версия ищутся в ней — ключ одного тенанта не назовёт документ другого; неизвестный тенант или документ — 404 `not_found`, устаревшая версия в ключе — 409 `invalid_transition`, ключ не по формату — 422 `validation_failed`; статусы 2 и 6 сохраняют версию (`docs.version.saved.v1`, версия по sha256 учитывается в место один раз), ответ `{error: 0}`; повтор с тем же `Idempotency-Key` (ключ версии) безопасен. Отзыв доступа закрывает сессию на движке (внутренний вызов, не в контракте).
- **Публичные пути без тенанта (возврат 1 ревью).** `openDocLink` (`/public/doc-links/{token}/open`), `getPublicServicePage` и `submitPublicServiceRequest` (`/public/service/{slug}...`), операции над обращением по токену (`/public/service/requests/{token}/...`) не несут `tenantId`, БД у каждого тенанта своя (ADR 0006). Маршрут «токен или slug → тенант» — в control 0011 (`0011_public_docs_service_index.sql`): `public_doc_links` (дайджест токена → тенант, документ, ссылка), `public_service_tokens` (дайджест токена → тенант, обращение), `public_service_slugs` (глобальный реестр slug направлений); источник истины — таблицы тенанта (`docs.links`, `service.portal_tokens`, `service.directions.public_slug`), порядок выпуска, отзыва и поиска — как у публичных форм (control 0009, W4.05): сначала строка control, затем тенанта; не найден — 404, отозван или истёк — 410 `public_token_expired`. Публичные операции в матрицу изоляции не входят (нет организации в пути): строки W7.23b и W7.31b проверяют, что токен и slug одного тенанта не открывают данные другого.
- **Подпись.** Внутренний утверждающий подтверждает повторным входом (`pep_login`, Q-W4.00-documents-2); код по SMS — только заказчик и только через порт «доставка кода» (D-31, заглушка: `dependency_unavailable`).
- **Чаты.** Кадр сервера `chat.changed` (`chatId`, `lastSeq`) добавлен к `RealtimeServerMessage` (ADR-0015); адресат — участник чата, проверяется при постановке и при доставке; без текста, имён и файлов. Кадров `typing`, присутствия и подписки нет: аудитория считается на сервере.
- **Шлюз.** Путь `/api/v1/internal/` — без сессии, только подпись сервера документов; `public` — капабилити (токен ссылки, PIN). Ограничения частоты и размера тела — как у публичных форм.

## Последствия

- Проще: контракт не зависит от выбора D-32; mock-адаптер и стенд без движка показывают просмотр («Редактор подключается»); один канал реального времени на три потребителя (PD-58).
- Сложнее: адаптер (W7.23b) хранит ключи версий, подпись и повтор callback; паритет формул и защищённых диапазонов проверяется на файлах клиентов (приёмка движка).
- Нужно сделать: W7.12 — тип кадра в шлюзе и обновить тест `message_test.go`; W7.23 — классификация `/api/v1/internal/` в `cmd/api`, секрет JWT в окружении (`DOCS_SERVER_JWT_SECRET`), адаптер движка; W7.24 — порт доставки кода (D-31).
- Как проверим: conformance «Документы» (callback с подписью и без), integration `cmd/api` «callback → новая версия → `docs.version.saved.v1`», тест шлюза «`chat.changed` только участнику чата», e2e стенда «документ открывается на просмотр без движка».
