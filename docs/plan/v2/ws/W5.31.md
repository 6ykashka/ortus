## 3. Решения по умолчанию (`Q-W5.31-N` в отчёте)

- Деньги — целые копейки; остаток `balance_minor` ведёт сервер в одной транзакции с операцией (`select … for update` по кассе), физическая касса не уходит в минус → `insufficient_funds`.
- Область кассы: `account` (эквайринг входит в область кассы-ящика), подразделение кассы, «своё» (`self`) для держателя подотчёта; видимость списка — `ScopeQuery` по `cash.read` и `cash.advance.self`; «мои права» — предикаты в том же запросе.
- Лимиты ролей (`limit: amount`) читает порт `LimitSource`; хранилища лимитов в роли ещё нет (W5.33/стюард), по умолчанию — без лимита, владелец — без лимита всегда. Сверх лимита — 202 с заявкой (Q-W4.00-cash-2); согласует другой сотрудник с `cash.approve`, операция проводится от имени автора с `approved_by`, остаток проверяется заново.
- Предложение модуля — строка `cash.proposals` (ключ `вид:источник`, он же ключ идемпотентности); входной порт `Offer` для модулей и воркера; проведение — `source_claims` (повтор → `duplicate_source`).
- Остаток и ожидаемые суммы смены скрыты без `cash.balance.read` (поля `null`); закрытие вслепую.
