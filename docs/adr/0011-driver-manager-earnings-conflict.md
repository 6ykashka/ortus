# 0011. D-10 · Человек одновременно водитель и менеджер с начислениями

Статус: предложено
Дата: 2026-10-15 · Автор: агент W0.01 · Участники: владелец продукта, security, backend lead
Решение комплекта: D-10 (`design/docs/16-raid-glossary.md`, «Решения, нужные для старта»)
Кто решает: Владелец продукта
Блокирует: S1-13 (шаг 1.6) по 16; в плане v2 — W1.06 (назначения), W1.23 (диалог «Назначить роль»), W2.06 (начисления)
До решения агенты работают по рекомендации (план v2 §2, B-2).

## Контекст

- Глоссарий 16: «Начисление — вознаграждение сотруднику; закрыто для функции driver».
- S1-13: назначение роли с областью и сроком; delegation check; «конфликт функции driver → 409». Код — `separation_of_duties_conflict` («Финансовое право + функция driver», `12-errors-and-events.md`); для действий, закрытых функцией, — 403 `function_blocked`.
- AC-05: водителю не видны суммы и метаданные начислений нигде — Trip DTO, `/earnings`, Data Hub, экспорт, поиск, аудит, уведомления.
- План 27 ссылается на D-10 в шаге 1.6 как на «срок» назначения — это неточность (анализ C, «Противоречия», п.21): D-10 касается конфликта функций, срок назначения задаёт S1-13.

## Варианты

1. **Запрет совмещения в v1: назначение финансового права человеку с функцией driver → 409** — плюсы: AC-05 проверяется простым правилом, нет утечки собственных и чужих начислений; минусы: в маленьких компаниях «водитель-руководитель» получает две учётные роли вручную или не может видеть начисления. Цена: в плане (W1.06).
2. **Разрешить, скрывая собственные начисления** — плюсы: гибче для малого бизнеса; минусы: правило «кроме своих» во всех каналах AC-05 (агрегаты, счётчики, экспорт, поиск), риск утечки. Цена: высокая, отдельная матрица изоляции.
3. **Разрешить через два профиля сотрудника** — плюсы: явное разделение; минусы: противоречит допущению 16 «один человек — один PersonProfile в тенанте». Цена: изменение модели данных.

## Решение

Рекомендация: «Запрещено в v1» (вариант 1).

## Последствия

- Проще: `permit()` отказывает до чтения данных; изоляция AC-05 проверяется по функции.
- Сложнее: диалог назначения объясняет отказ (текст ошибки `separation_of_duties_conflict` — словарь `errors`); при смене функции на driver существующие финансовые назначения тоже конфликтуют — правило проверяется в обе стороны.
- Сделать: W1.06 — проверка при назначении и при выдаче функции; W1.23 — объяснение в диалоге; W2.06 — начисления только не-водителям.
- Как проверим: тест изоляции — пользователь с функцией driver и попыткой получить `finance.read` → 409; AC-05 по всем каналам.
