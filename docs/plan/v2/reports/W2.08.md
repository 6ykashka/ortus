## Сделано

**Движок `backend/internal/modules/data`** (реестр провайдеров и тег Data):

- `Provider` / `Registry` — модуль регистрирует наборы (`Spec`: источник строк `From`/`Where`, столбцы области права набора, поля — SQL-выражения, порядок, сортировка по умолчанию), как источники «Требует решения» W2.09.
- `listDatasets`: наборы установленного и не выключенного модуля (`active`, `read_only`, `draining`), право набора хотя бы в одной области (`ScopeQuery` ≠ `false`). Поле с `Restricted` (`Начисление`) — только при своём праве (оценщик закрывает `fleet.earnings.read` функцией «Водитель», AC-05), иначе только подпись в `hiddenFieldLabels`. `exportAllowed` — `data.export` и право набора; `permissionVersion` — `access.policy_state.policy_version`; операторы, `options`, `aggregatable`, `defaultSort` — как пример `listDatasets/ok`.
- `queryDataset`: неизвестный набор и набор выключенного модуля — 404 «Набор не найден.»; известный набор без права — 403 `forbidden_action`; скрытое и неизвестное поле в `select`, `filters`, `sort`, `groupBy`, `aggregates` — один 422 `validation_failed` «Поле недоступно: {key}.» с нарушением `unknown_field` (тело — как пример `queryDataset/validation_failed`); оператор вне `filterOperators`, неверные значения, поле вне группировки, занятый псевдоним — 422; границы схемы, которые strict server не проверяет (`select` 1…100, `filters` ≤ 50, значений ≤ 100, `sort` ≤ 5, `groupBy` ≤ 5, `aggregates` ≤ 20, `limit` 1…200, `search` ≤ 200, `cursor` ≤ 2048, перечисления, шаблон псевдонима) — 400 `malformed_request`.
- SQL: строки набора — подзапрос с предикатом области права набора (`scopeddb`, `{{scope}}`) до фильтров, поиска, сортировки, группировки и страниц; все значения запроса — параметры (decimal и date — текстом с приведением в SQL); поиск — подстрока без учёта регистра по видимым текстам, подписям выбора, числам (деньги — в рублях, как MSW) и датам; сортировка текстов и подписей — `collate "ru-x-icu"` (кириллица раньше латиницы, как `localeCompare('ru')` MSW), пустые — в конце при `asc`; группировка `count/sum/avg/min/max`; `visibleCount` до 10 000 + `visibleCountCapped`; время выборки ограничено (`DefaultTimeout` 10 с).
- Курсор — непрозрачный (смещение + отпечаток sha256 набора, участника, `permissionVersion`, фильтров, поиска, сортировки, групп и агрегатов; `select` и `limit` менять можно): чужой — 400 «Курсор не подходит к выборке.», испорченный — 400 «Неверный курсор выборки.».

## Осталось fixme / открытые вопросы

`fixme` нет. Вопросы (Q-W2.08-N; сделано по значению по умолчанию; внести в `docs/plan/decisions.md` — файл интегратора):

1. **Q-W2.08-1 · состояния модуля (продукт).** Наборы есть у модуля в `active`, `read_only` и `draining` (история читается, как чтения самого модуля и источники W2.09); MSW W2.51 — только `active`. Выключенный и не установленный — нет наборов, выборка — 404.
2. **Q-W2.08-2 · область строк (безопасность).** Строки — по области права набора (`fleet.*.read`), не пересекаются с областью `data.query`: шлюз требует `data.query` в любой области (`x-scope: effective-module-and-field-scopes`), как MSW. Пример: наблюдатель Самары-2 с правом менеджера в Москве-1 видит машины обеих фирм — как и через `listVehicles`.
3. **Q-W2.08-3 · отменённый рейс (продукт).** Не входит в «Поездки»: в эталоне нет такого статуса, вариантов «Статус» для него нет. Расходы отменённого рейса в «Расходах» остаются.
4. **Q-W2.08-4 · курсор (технический).** Непрозрачное смещение с привязкой к выборке; страницы — до 10 000-й строки (дальше `nextCursor` нет, как предел `visibleCount`). Устройство курсора MSW другое, контракт — общий.
5. **Q-W2.08-5 · сортировка текстов (продукт).** ICU `ru-x-icu`: кириллица раньше латиницы, без учёта регистра; числового сравнения внутри текста нет («Р-1000» раньше «Р-208»), у MSW — `localeCompare('ru', {numeric: true})`. Подписи выбора сортируются по подписи, как MSW.
6. **Q-W2.08-6 · агрегаты (продукт).** `avg` десятичного поля — с округлением до 2 знаков (MSW — до целого), `avg` денег — до копейки; сумма денег по нескольким валютам — пустая ячейка.
7. **Q-W2.08-7 · count (технический).** Всегда число строк; `fieldKey` у `count`, если передан, проверяется как поле (скрытое и неизвестное — 422).
8. **Q-W2.08-8 · псевдоним (безопасность).** Псевдоним агрегата не может повторять видимое поле или другой псевдоним (422 `alias`); совпадение со скрытым полем допускается — иначе ответ раскрыл бы его существование.
9. **Q-W2.08-9 · `queryDataset` — «только чтение» на шлюзе (технический).** Операция — POST, каталог `cmd/api` отмечает её `Mutating`, поэтому в организации в `grace` / `read_only` шлюз ответит `tenant_read_only`, хотя контракт — «Read-only POST». Шлюз и каталог операций — не владение W2.08; по умолчанию не тронуто (интегратору / стюарду: признак «читающая команда» для `queryDataset` и `findCalendarAvailability`).
10. **Q-W2.08-10 · значения фильтра (технический).** decimal — decimal или число текстом; date — date или `YYYY-MM-DD` текстом; choices — text или choices; money — только money; иначе 422 `values` «Проверьте значения фильтра: {key}.».
11. **Q-W2.08-11 · водитель в «Данных» (продукт).** Участник с функцией «Водитель» в «Поездках» и «Расходах» видит только свои рейсы даже с областью подразделения (D22, как `listTripPlans`). Шаблон «Водитель» прав `data.*` не имеет — правило важно для совмещающих роли.
12. **Q-W2.08-12 · начисление без строки журнала (продукт).** Принятый рейс без строки `finance.earnings` — 0 ₽ (как `listTripEarnings` W2.06), непринятый — пусто.
13. **Q-W2.08-13 · порядок групп (технический).** Без сортировки группы идут по полям группировки (MSW — по первому появлению); сортировать группированную выборку можно только по полям группировки и псевдонимам (иначе 422 `not_grouped`).
