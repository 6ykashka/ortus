- **Расчёт** (`schedule_calc.go`): порт библиотеки W6.10/W6.17 (`calendar.ts`, `cpm.ts`) на Go — рабочий календарь (дни недели и праздники), прямой проход (раннее начало по связям «окончание → начало» с паузой/опережением в календарных днях, `bind`), обратный проход (позднее окончание, запас), критический путь (невыполненные этапы с запасом 0). Начавшийся этап не сдвигается (фактическое начало). Контрольные числа объекта кв. 42 совпадают с библиотекой: сдача 27.11 (день 53) → прогноз 01.12 (день 57), +2 раб. дня, путь `s2→s3→s5→s7→s9→s10`, запас s8/s4/s6 = 1/5/9; перенос s3 с 10 на 12 дней даёт 04.12 (день 60, +5 раб. дней — сверено запуском TypeScript-библиотеки).
- **`getSchedule`**: этапы с датами, запасом и признаком критического пути, связи, базовый план, прогноз, просрочка в рабочих днях, праздники, замечания (`no_executor`, `executor_busy`), журнал; `ETag` = `projects.schedule_revision`. Видимость как у объекта (чужой — 404), право `repairs.schedule.read` (иначе 403).
- **`createScheduleFromEstimate`**: по согласованной версии сметы (`repair_estimate_not_approved`, неизвестная версия — 422 `estimateVersion`) и технологии шаблона объекта (`template_stages`): объём работ раздела ÷ выработка, округление вверх, 1…30 раб. дней; связь с паузой шаблона; без шаблона — этап на раздел; в конце этап «Сдача объекта» (1 день); повтор — 409.
- **`previewScheduleChange`** без записи: сдвинувшиеся этапы, новый прогноз, просрочка, кого уведомим (исполнители затронутых и сдвинутых этапов, «Заказчик» при смене даты сдачи).
- **`applyScheduleChange`**: перенос (начало, длительность, пауза) с причиной из семи (без причины — 422 `schedule_reason_required`), `If-Match` (412 `revision_mismatch`), начавшийся или выполненный этап — 409 `schedule_stage_locked`, у идущего этапа длительность не меньше прошедших дней; журнал `schedule_changes`, строка ленты объекта, событие `repairs.schedule.changed.v1` в outbox (в транзакции перенесённого).
- **`setScheduleStageExecutor`**: участник организации или имя без аккаунта, без причины, журнал, уведомление исполнителю (событие `repairs.schedule.changed.v1`, `kind: executor`).
- **`createScheduleBaseline`**: только по подписанному допсоглашению (`agreement_no` согласованной версии сметы); новая версия базового плана со снимком, срок договора `projects.due_on` обновляется только так; событие `repairs.schedule.baseline_set.v1`.
- **Сводка объекта**: прогноз сдачи в списке и карточке берётся из графика (раньше равнялся сроку), в «Требует решения» — `schedule_slip` («Сдача сдвигается на 01.12») перед `stage_no_executor`.

## Осталось fixme / открытые вопросы

1. **Q-W6.14-1.** Рабочий календарь — `repairs.work_calendars` региона `RU` (дни недели и праздники); если строки нет, пн–пт и фиксированные праздники РФ (1–8.01, 23.02, 8.03, 1.05, 9.05, 12.06, 4.11; переносы выходных не знает код). Интерфейса правки календаря в контракте нет — строку пишет тенант вне API. По умолчанию — как сделано.
2. **Q-W6.14-2.** Веха «Сдача объекта» — обычный этап длительностью 1 в конце графика (в `schedule_stages` вехи нет); прогноз сдачи — окончание последнего этапа без последователей; для расчёта совпадает с вехой эталона (длительность 1 → конец = начало). Длительность такого этапа можно изменить запросом. По умолчанию — как сделано.
3. **Q-W6.14-3.** Замечание `no_material` не вычисляется: заявка снабжения (`supply_requests`) не привязана к этапу графика. Появится, если W6.13 добавит связь. По умолчанию — не считать.
4. **Q-W6.14-4.** Разделы графика при сборке из сметы: первые три этапа — «Черновые работы», остальные — «Чистовые работы», последний — «Сдача» (как MSW); владелец шаблонов может ввести фазу в `template_stages`. По умолчанию — как MSW.
5. **Q-W6.14-5.** Срок договора для просрочки — последний базовый план, иначе `projects.due_on`, иначе просрочки нет. Базовый план создаётся только `createScheduleBaseline` по допсоглашению (первого утверждения вместе с договором в контракте нет); в сиде базовый план задаёт сид.
6. **Q-W6.14-6.** `lagDays` переноса относится к связи, определяющей начало этапа (как MSW); у этапа без предшественника — 422 `no_predecessor`. Длительность начавшегося этапа — не меньше прошедших рабочих дней плюс один. Подрядчик (видит только свои этапы) — W6.15, пока график виден всем, кто видит объект и имеет `repairs.schedule.read`.
7. **Q-W6.14-7.** События: `repairs.schedule.changed.v1` (перенос и смена исполнителя; в полезной нагрузке этапы, причина, старая и новая дата сдачи, кого уведомить) и `repairs.schedule.baseline_set.v1`. Доставка уведомлений получателям (consumer в `cmd/worker`) в карточку не входит — события лежат в outbox.
