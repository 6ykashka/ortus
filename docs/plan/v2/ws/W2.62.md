# W2.62 · MSW: draining модулей и роль «Временный водитель» (Q-W2.32-5, Q-W2.32-6)

Этап 2 · подволна 2e · дорожка Д · вид frontend (адаптер MSW) · карточка плана v2 §4 «Этап 2» (`W2.62`: AC-06, AC-12 · Q-W2.32-5, Q-W2.32-6). Зависит от W2.57 (временный водитель «только рейс», `main`) и W1.08 (шлюз модулей, `main`). Параллельно идут W2.60 (шлюз backend при `draining`) и W2.61 (страница «Моя смена» после срока) — их поведение MSW моделирует по постановке, не дожидаясь слияния.

Слот 8: Vite `5208`, Storybook `7208`, API `HTTP_ADDR=127.0.0.1:8108`, эталон `4108` (`E2E_OWN_REFERENCE=1`, `REFERENCE_REF=design-stage-2`), `ORTUS_SLOT=8`, compose `ortus-s8`. Стенд слота 0 и `docs/demo/**` не трогаются.

## 1. Цель

Сценарный сервер mock отвечает так же, как backend `main` (+ W2.60), в двух местах, где журни W2.32 держали mock-строки в `test.fixme`:

1. **Modules · draining (AC-12, Q-W2.32-5).** `previewModuleDeactivation` перечисляет процессы «Логистики» как `modulesreg.FleetTrips`: начатые рейсы (`on_route`, `returning`, `submitted`, `rework`) — `active_process`, `finish_allowed`, водитель рейса; назначенные не начатые (`assigned`, `inspection`, `defect_review`) — `closed`; начатые первыми. Отключение при начатом рейсе → `draining`: новые рейсы, брони и прочие команды — 403 `module_read_only` «Модуль «Логистика» отключается: можно только завершить начатую работу.»; завершение начатого открыто (`finishOnly` backend + W2.60: `returnTrip`, `finishTripRoute`, осмотр при сдаче, расходы, приёмка, начисление, снятие брони). Осмотр перед выездом при `draining` — 403. Когда начатых процессов не осталось, модуль сам становится `read_only` (как `Service.settle`). `/me/context`: `draining` · `finish_only` · `draining`.
2. **Пул · роль «Временный водитель» (AC-06, Q-W2.32-6).** Одобрение запроса создаёт системную роль `temporary_driver` (права — `role_templates.temporary_driver` каталога) и назначает её водителю: строка в области `self` на окно перевода (в продолжении `closing` — без конца, после конца назначения — `expired`) и строка в области `resource_pool` на машину рейса (и предложенные машины W2.71) — пока назначение `scheduled`/`active`. Машина рейса открыта временному водителю в `getInspectionChecklist`/`submitInspection` (как `inspections.Checklist`: машина своего активного рейса). После окна — только продолжение начатого рейса (D09); после приёмки рейс отвечает как несуществующий id. Роль вручную не назначается (409 `invalid_transition`).
3. Mock-строки W2.32 без `test.fixme`: AC-12 (`module-draining.spec.ts`) и AC-06 «начатый рейс после окна» (`temporary-driver.spec.ts`); обе строки AC-06 `@mock` — на узкой роли без домашней роли «Водитель».
