### 1.1 Ширины

В модуле нет медиазапросов. Раскладку задаёт ширина **контейнера** `cw` через ResizeObserver (Ч:438):
- `cw < 760` — узкая раскладка (Ч:513);
- `cw ≥ 1100` — три колонки (Ч:538);
- раскладка колонок — `gridCols` (Ч:541).

| Ширина окна | Раскладка |
|---|---|
| **390** | Одна колонка: список → чат (кнопка «К списку чатов») → сведения вместо чата. Высота ленты `calc(100vh - 290px)`. «Новый чат» — одна колонка (Ч:733). Политики — строки в одну колонку (`< 900`, Ч:767) |
| **768** | `cw` зависит от сайдбара оболочки: при `cw ≥ 760` — список 290 px + чат, «Сведения» **заменяют** чат; при `cw < 760` — как 390 |
| **1440** | `cw ≥ 1100`: список 290 + чат + сведения 330 px |

Макеты-варианты нарисованы фиксированной шириной 1280 px. Мобильного вида там нет: в «Дальше можно» он назван работой на будущее — «мобильный вид 1e для водителя» (В:734).

### 2.3 События, уведомления, «Главная», реальное время

- **Outbox** (`docs/12:121–127`, `25:355`): `chat.chat.created/archived`, `chat.member.joined/left`, `chat.message.posted/edited/deleted/expired`, `chat.ack.requested/done/overdue`, `chat.poll.closed`, `chat.quota.warning/full`, `chat.cleanup.done`, `chat.hold.set/released`, `chat.pdn.revealed` (всё `.v1`). Текст сообщения в payload не передаётся.
- **Потребители пересчёта состава** (`25:166`). Пересчёт запускают:
  - `members.assignment.*`;
  - изменение состава группы;
  - блокировка или увольнение участника;
  - смена прораба объекта (этап 6);
  - назначение водителя на рейс (этап 2, `fleet.trips`).
- **«Входящие»** (`Notification.kind`): `chat.mention`, `chat.direct`, `chat.important`, `chat.added` — есть в `js:416–418`, 520, 536. В контракте сейчас этих видов нет.
- **«Требует решения»** (`DecisionItem.kind` — шаблон аддитивный): нужен `chat.ack_pending` с `moduleKey: chat`, `params {chatTitle, dueDate}`. Документ добавляет «упоминания» и «заполненное место» (`25:20`, `25:380`) — `chat.mention`, `chat.storage_high` (кандидаты).
- **Реальное время.** Канал W1.07 уже есть: `/auth/realtime-tickets`, ADR-0015. По ADR в сокете ходят только подсказки без данных. В `RealtimeServerMessage.type` четыре значения: `context.changed`, `notifications.changed`, `session.ended`, `ping`. Тест шлюза явно отвергает `chat.message` (`backend/internal/platform/notify/realtime/message_test.go:156`). Документ (`25:354`) предлагает канал `chat:{id}` с `message.new`, `typing`, `read` — то есть с данными. Предложение: `chat.changed {chatId, seq}`, клиент перечитывает `listChatMessages?afterSeq`. Подробнее — §5, Q-…-7.

| — | `chat.external` | | По CHAT-05 отдельного вида чата нет → действие не используется (§7) |

### 3.2 Области (для W4.01)

- **`chat`** — объектная область. Назначение роли чата — это `Assignment {scope: {kind: chat, resourceIds: [chatId]}}`, как роли проекта. В прототипе так устроены «по имени» и владелец, созданный при создании чата (`js:513–514`). По PD-53 роль на чате вне этого чата права не даёт; это касается и меню (Q-W0.11-1: меню и гейты — `canAny`, команды — `can` с объектом).
- **`relation`** — связь с записью. Чатам нужны:
  - «прораб объекта» — `repairs` (этап 6), уже есть в `relationHas`;
  - «водитель рейса» — `fleet.trips.driver` (этап 2), в домене пока нет;
  - «исполнитель задачи» — `25:164`, в прототипе нет.

  Область должна вычисляться: состав пересчитывается сам.
- **`unit`** в каталоге — это `org_unit` в контракте. Источник «Роль в области» = роль + `orgUnitId` (+ потомки).
- `project`, `space`, `page`, `folder`, `doc`, `account` чаты не используют. Исключения: карточка документа и страница Базы знаний в сообщении — доступ проверяется при открытии в своём модуле. Ссылка права не даёт: «A reference never grants access», `ObjectRef`.

### 3.3 Ограничения функций и меток

- **Функция `driver`:**
  - чаты с меткой «Финансы» закрыты независимо от ролей (`js:110–112`);
  - `chat.pdn.read` блокируется (уже в каталоге и в `policy.go:48`).
- **Метка «ПДн»** (`sensitivity: pdn`): в прототипе её можно поставить (Ч:725), но в `chats.js` она **ни на что не влияет**. Q-…-14.
- **Личные чаты:**
  - читают только двое; владелец бизнеса их не читает (`js:97–99`);
  - доступ к личной переписке — только через удержание с причиной и журналом (CHAT-02);
  - сотрудник уволен или заблокирован → его личный чат у второго участника только для чтения (`25:172`); в прототипе: заблокированный не входит никуда (`js:93`), режима «только чтение у второго» нет.
- **Шаблоны ролей организации** (`25:318`):
  - владелец — всё;
  - руководитель фирмы — всё в своей фирме, кроме политик, удержаний, журнала и ПДн;
  - логист и диспетчер — read, write, direct, files, polls, create, announce;
  - водитель — свои чаты фирмы и рейсов, личные с диспетчерами;
  - прораб — чаты своих объектов, личные в организации;
  - бухгалтер — финансовые.

  В контрактных шаблонах этого нет. AUTH-09: новые действия в существующие роли сами не добавляются. Q-…-19.
