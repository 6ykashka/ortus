## Сделано

- **`backend/internal/modules/home`** — реестр источников и сервис операции `getMyDecisionQueue` (`GET /api/v1/me/decisions`, `x-scope: identity`):
  - `registry.go` — `Source` (`Module()`, `Cards(ctx, Query)`), `Query` (участник, состояние модуля источника, часы), `NewRegistry` (порядок регистрации = порядок очереди: логистика → организация → модули следующих этапов);
  - `service.go` — `Service.Queue`: `limit` 1…50 (вне — 400 `malformed_request` «limit: 1…50», как MSW); `tenantId` — активное членство личности (`tenantctx.Resolve`), иначе и для приостановленной организации — 404 `not_found` «Организация не найдена.» (как MSW); состояния модулей читаются один раз и только при зарегистрированном источнике модуля; источник модуля спрашивается при `active`, `read_only`, `draining`, источник ядра — всегда; сортировка устойчивая по тону (`danger → warn → info → neutral`), внутри тона — порядок источников и порядок источника; `total` до `limit`; `items: []` у пустой очереди; сбой источника или реестра модулей — 503 `dependency_unavailable` (ошибка Problem источника проходит как есть);
  - `server.go` — `Server` (`homeapi.StrictServerInterface`): аккаунт из сессии шлюза, `limit` по умолчанию 8, `Cache-Control: private, no-store`, `X-Request-Id`.
- **`backend/internal/modules/home/fleet`** — источник логистики (`Source{Pools, Authz}`, модуль `fleet`); каждый запрос — через `scopeddb` с предикатом `scopeQuery()` действия, к которому ведёт карточка:
  - `fleet.blocking_defect` (danger) — дефекты `in_review` с рейсом, `fleet.inspections.review` над подразделением машины (как очередь W2.04), старые первыми; `params`: `tripNumber`, `zone`, `description`, `driverName`; `object` — рейс; `occurredAt` — время отчёта;
  - `fleet.trip_review` (warn) — рейсы `submitted`, `fleet.trips.review` над подразделением рейса, по времени сдачи; `params`: `tripNumber`, `driverName`; `occurredAt` — `returned_at`;
  - `fleet.trip_without_driver` (info) — только при модуле `active`: рейсы `planned` без водителя, `fleet.routes.manage` над подразделением рейса, ближайшие первыми; `params`: `tripNumber`, `title`, `cargo`, `startsAt` (UTC RFC 3339), при запросе пула `requested` — `poolRequest: pending`, `poolHome` (подразделение водителя);
  - колонки области — только подразделение (территориальные гранты): «своё» водителя и проектная роль (PD-53) карточек не дают; не больше 200 карточек вида.
- **`backend/cmd/api/home.go`** — `homeServer(dir, pools, ev, states, now)` (реестр с источником логистики) и `moduleStates` (состояния `modulesreg.Service.Installations` по ключу контракта; синоним `logistics` уже приведён к `fleet`); **`main.go`** — одна строка `Home: homeServer(dir, pools, ev, moduleStates{S: modules}, cfg.clock())`.
- **`backend/test/isolation/home.yaml`** + сгенерированный `home_test.go`.

## Осталось fixme / открытые вопросы

`fixme`, `t.Skip` нет. Решения по умолчанию (вынести в `docs/plan/decisions.md` как Q-W2.09-N — файл не мой; дублируются в `decisionsNeeded`):

1. **Приостановленная организация** — 404 `not_found`, как в MSW (входящие W1.10 отвечают 403 `tenant_suspended`).
2. **Сбой одного источника** — вся очередь 503 `dependency_unavailable`, а не укороченный список без признака частичности (в контракте его нет).
3. **Модуль `read_only`/`draining`** — блокирующие дефекты и приёмка видны (завершение начатой работы), рейсы без водителя — только при `active` (как MSW).
4. **Порядок внутри вида**: дефекты — по времени отчёта, приёмка — по `returned_at`, рейсы без водителя — по началу плана (MSW — порядок массива сида).
5. **Предел 200 карточек вида** — `total` считает не больше 200 карточек каждого вида (для пилота — десятки машин).
6. **Источник логистики в `modules/home/fleet`** (каталог W2.09), а не в `modules/fleet/**` (W2.02–W2.06): импорт `modules/home` из подпакета — `//nolint:depguard` с пояснением; перенос к владельцу модуля логистики — по решению интегратора.
