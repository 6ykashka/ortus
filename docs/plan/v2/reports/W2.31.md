Метаданные проекта `device`: ОС, версия, браузер, движок, масштаб, фальшивая камера.

Как устроены проекты:

- Chromium запускается с фальшивой камерой (`--use-fake-device-for-media-stream`, `--use-fake-ui-for-media-stream`, `permissions: ['camera']`).
- Геолокация не выдаётся.
- iPhone по умолчанию идут на Chromium с профилем iPhone: viewport, DPR 3, UA Safari, касание.
- `E2E_DEVICES_WEBKIT=1` переводит iPhone на WebKit. Для этого нужен `playwright install webkit`.

`withDeviceProjects(config)` добавляет проекты устройств к проектам харнесса. Проектам 390/768/1440 он добавляет `testIgnore` каталога `e2e/devices/`, а у проектов устройств `testMatch` — только свои spec. Телефоны идут `matrix` + `driver-devices`, масштаб — `matrix` + `zoom`.

### Помощники — `e2e/devices/devices.helpers.ts`

- `cameraFrame` / `frame` — кадр 12 Мп (4032×3024). На Chromium — кадр видеопотока фальшивой камеры (`getUserMedia`, тыловая), на WebKit — холст. Геоданные добавляет `withGps` из W2.44.
- `snap` — касание слота, затем кадр в `input capture`. Файл пишется в каталог результатов теста: WebKit под Windows не читает файл из буфера.
- `storage` — тела PUT, сбой первых N попыток, задержка и канал (кбит/с):
  - Chromium — маршрут контекста;
  - WebKit — хранилище mock вкладки (W2.53) и обёртка XMLHttpRequest. Подключается через `prepareStorage` до запуска: на WebKit маршрут контекста не видит запросы service worker MSW.
- `slowNetwork` — глобальная задержка сценария `delay=<мс>` и троттлинг CDP Chromium (300 мс, 1,6/0,75 Мбит/с).
- `jpegInfo` — размер JPEG по SOF и наличие Exif.
- `watchGeolocation` — счётчик вызовов геолокации.
- `press` — касание или щелчок.

## Осталось fixme / открытые вопросы

`fixme` нет.

Пропуск «офлайн» на WebKit — только в режиме `E2E_DEVICES_WEBKIT=1`. При эмуляции без связи (`context.setOffline`) Playwright WebKit не читает и выбранный файл:
- `NotReadableError` при чтении холста и файла;
- на телефоне без связи файл читается нормально.

Офлайн на iPhone проверяют Chromium-профиль (зелёный) и полевой тест. Подробности — Q-W2.31-3.

Вопросы (значение по умолчанию, по которому сделано):

1. **Q-W2.31-1** — стенд полевого теста. Нужен адрес по HTTPS (камера, service worker и установка PWA без HTTPS не работают), учётные записи водителей и сид. По умолчанию — сид показа, «Альта Групп», «Илья Васильев», адрес выдаёт интегратор. До этого люди не могут начать полевой тест. Чек-лист готов.
2. **Q-W2.31-2 — дефект-кандидат продукта** (W2.22/W2.24, приоритет этапа 3).
   - Что происходит: выбранный в слоте файл не читается (`NotReadableError`; на iPhone так ведёт себя фото из iCloud без связи). Слот молча остаётся «Не снято», в консоли — `Unhandled rejection`, сообщения водителю нет.
   - Как воспроизвести: WebKit, офлайн-строка до пропуска.
   - По умолчанию — не исправлено: код не в «Владеет».
   - Предложение: ловить ошибку подготовки фото и показывать «Ошибка загрузки» с тостом. Подписи в эталоне нет — решение владельца продукта.
   - В поле проверяется шагом 17 чек-листа.
3. **Q-W2.31-3** — WebKit в CI. По умолчанию iPhone-проекты в CI идут на Chromium с профилем iPhone: `e2e:install` (W0.05) ставит только Chromium. Настоящий WebKit включается `E2E_DEVICES_WEBKIT=1` и требует `playwright install webkit`. Строка «офлайн» на WebKit пропускается — ограничение эмуляции, не продукта.
4. **Q-W2.31-4** — проекты устройств входят в полный `pnpm e2e` CI: 40 тестов, локально 1,3 мин на 4 воркерах, в CI (`workers: 1`) — около 5 мин. По умолчанию — входят. Альтернатива — отдельный шаг или шард.
5. **Q-W2.31-5** — масштаб 200 % эмулируется как масштаб браузера на окне 1280×800 (CSS 640×400). Системный крупный шрифт телефона (iOS «Размер текста», Android «Размер шрифта») эмуляцией не воспроизводится и проверяется в поле (шаг 18). Полный охват 200 % по страницам пилота — W3.05.
6. **Q-W2.31-6** — версии ОС в проектах взяты из UA дескрипторов Playwright 1.63: Android 14/13, iOS 18/16. Настоящие «текущая и предыдущая» версии выбираются в поле, раздел 1 чек-листа.
