## 1. Цель

Девять операций тега Fleet по контракту `0.6.0-stage2` (описания операций W2.51 — порядок проверок и коды):

- фирма-источник: `publishDriverToPool`, `listDriverPoolPublications`, `getDriverPoolPublication` (ETag), `withdrawDriverPoolPublication` (If-Match);
- фирма-получатель: `listAvailableDrivers` (минимальная проекция AUTH-06), `requestDriverTransfer`;
- обе стороны: `listDriverTransfers` (`direction`, `status`), `getDriverTransfer` (ETag), `decideDriverTransfer` (approve / reject / revoke, If-Match).

Одобрение создаёт временное назначение — строку `access.role_assignments` роли «Водитель» (`source = 'transfer'`, область — подразделение рейса без потомков, без рейса — фирма-получатель без потомков (возврат 1), `valid = [window.startsAt, window.endsAt)`), ставит водителя на рейс и поднимает `policy_version` (W1.07). Объектной области «рейс» в реестре authz нет — по умолчанию Q-W2.51-15 («область — рейс») решение Q-W2.07-1 (блокер возврата 1). Автозавершение (Q-W2.51-4, Q-W2.51-15):

- `requested` → `expired` к началу окна; снятие публикации — открытые запросы `expired`;
- начатый рейс (`inspection`…`rework`, `submitted`) открывает верхнюю границу гранта, назначение держится `closing` до приёмки или отмены;
- приёмка и отмена закрывают грант моментом события, отзыв — моментом отзыва (`state = 'revoked'`);
- `approved` → `completed` к концу окна (или к приёмке начатого рейса); не начатый рейс теряет временного водителя;
- у не начатого рейса доступ закрывает сам шлюз по `upper(valid)`, воркер переводит только статусы.

Досчёт — одна функция `pool.Settle` (транзакция тенанта на момент часов приложения): её вызывают воркер по расписанию (`cmd/worker`, `WORKER_POOL_INTERVAL`, 30 с, весь тенант — `SettleTx`) и надстройка cmd/api сразу после команд, меняющих состояние рейса (`reserveVehicle`, `releaseReservation`, `startTrip`, `reviewTrip`) — только запросы этого рейса (`SettleTrip`, срок `SettleTimeout`, 5 с). Блокируются только запросы, которые время меняет сейчас. Чтение показывает то же состояние лениво (статус, состояние гранта, ревизия), даже если воркер опаздывает.

Конкурентность: порядок блокировок модуля — рейс, затем запрос (решение, досчёт тенанта, `SettleTripTx` команд рейса); одобрения одного водителя сериализуются `pool.LockDriver` (`pg_advisory_xact_lock` по `person_id`); два одобрения одного запроса — одно 200, второе 409 или 412. Псевдоним «Водитель #N» — под advisory-lock тенанта.
