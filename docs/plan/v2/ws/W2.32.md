# W2.32 · Сквозная смена водителя на стенде (выход этапа 2)

Этап 2 · подволна 2d · дорожка Т · вид frontend (e2e) · карточка плана v2 §4 «Этап 2» (`W2.32`, «Выход из этапа 2»: полная смена водителя проходит на телефоне и у менеджера на стенде; AC-03…AC-06 и AC-12 автоматизированы). Зависит от всех W2.* в `main`; W2.50 (заменители интеграций: CSV, навигатор) не влит и в сценарии смены не входит. Решения владельца — `po-answers-2026-10-17.md`, ADR 0002–0013, Q-W2.07-1 («Временный водитель» — только рейс).

Слот 1: Vite `5201`, Storybook `7201`, API `HTTP_ADDR=127.0.0.1:8101`, эталон `4101` (`E2E_OWN_REFERENCE=1`, `REFERENCE_REF=design-stage-2`), `ORTUS_SLOT=1`, compose `ortus-s1` (`stand.mjs --slot 1`, после прогона `down -v`). Стенд слота 0 и `docs/demo/**` не трогаются.

## 1. Цель

Сквозные сценарии (журни) этапа 2 в `frontend/apps/web/e2e/journeys/stage2/`, пишет не автор экранов; каждый — `@mock` (390, 768, 1440) и `@stand` (стенд слота: compose + cmd/api + cmd/worker + MinIO, сид e2e-stand):

1. **Полная смена** (J2, «Путь проверки» шаги 3–8): бронь → осмотр с пятью фото, черновик осмотра на устройстве без связи и отправка после связи → выезд → расход по справочнику категорий (своя категория владельца) → «Завершить рейс» → осмотр при сдаче → сдача → приёмка менеджером на 1440 → машина свободна сразу (W2.56) → начисление у владельца; водитель начислений не видит (AC-05). Расширяет `driver-shift.spec.ts` (W2.90/W2.53), прежние строки не меняются.
2. **AC-04 · блокирующий дефект**: 4 фото из 5 — выезд закрыт («Осталось: 1 фото»), `startTrip` по осмотру с блокирующим дефектом — 409; менеджер на «Очереди блокирующих дефектов» назначает исполнителя и срок (W2.46) и решает; водитель выезжает.
3. **AC-03 · конкурентная бронь**: параллельные брони одной машины на пересекающиеся окна — ровно один 201, остальные 409; у проигравшего водителя «Конфликт брони» и «Обновить список».
4. **AC-06 · временный водитель пула** (Q-W2.07-1): публикация водителя «Север Логистик», «Запросить на рейс» фирмы «Юг Транс», «Одобрить» во «Входящих запросах»; в окне водитель видит только свой рейс и машину рейса; после срока у начатого рейса — только сдача; после приёмки — 404, как у несуществующего.
5. **AC-12 · отключение «Логистики» с активным рейсом**: «Затронет сейчас» с рейсом, `draining`; новый рейс — 403 `module_read_only`; начатая смена завершается, сдаётся и принимается; затем модуль — только чтение.
6. **«Путь проверки» в части пилота** (`@smoke`): восемь шагов основного пути (подключить «Логистику» → роль Котовой → водитель → бронь → осмотр и выезд → расход → сдача → приёмка) и семь негативных проверок эталона.

## 10. Риски и решения по умолчанию

- Стенд-строки идут во всех трёх проектах (вердикт e2e-stand считает пропуск ошибкой, Q-W2.53-8): водитель — контекст проекта, менеджер и владелец — свой контекст 1440; каждый проект — свой рейс (`label`), уборка `undo` возвращает сид.
- AC-06 на стенде: часов сервера не подменить (APP_FIXED_NOW нет в e2e-stand) — окно перевода короткое, от «сейчас» (≈ 3 мин), строка ждёт его конца; в mock — `now` сценарного сервера.
- AC-12 на стенде отключает «Логистику» «Альты» на время строки; уборка включает модуль снова.
- Расхождение mock и стенда (MSW не моделирует часть поведения) — строка mock `test.fixme` с причиной и владельцем адаптера; стенд — обязателен.
- Дефект чужого кода, найденный журни на стенде, — отдельная строка `test.fixme` с тегом `@known-defect` (вне grep e2e-stand `@stand|@mailpit`, чтобы вердикт «0 пропущенных» не краснел), основная строка проверяет остальное; после исправления — fixme снять, тег сменить на `@stand`.
- Playwright MCP в сессии не подключён — сервер `@playwright/mcp` из `.mcp.json` по stdio, как `tools/mcp-check.js`.
