## 1. Цель

Три флейка полного параллельного `ci:local` на Windows (22 CPU), которые проходят при `-p 1`:

1. **Провайдер testcontainers** (`cmd/seed`, `importer`, `org`, `authz`, `cmd/worker`): `get provider: rootless Docker is not supported on Windows, failed to create Docker provider`.
   **Причина (проверено).** testcontainers v0.44 ищет Docker по цепочке стратегий (`internal/core/docker_host.go`). Без `DOCKER_HOST` хост на Windows находит стратегия `dockerSocketPath`: `os.Stat("//./pipe/docker_engine")`. `Stat` именованного канала открывает его, и при параллельном старте пакетов возвращает `All pipe instances are busy`. Стратегия считает это «сокета нет», следующая — `rootless` — на Windows отвечает ошибкой, которую и видно. Результат кешируется `sync.Once` на процесс, поэтому повтор `tcpostgres.Run` в `accesstest.Start` (3 попытки) не помогает. Воспроизведение в scratchpad: 100 параллельных `os.Stat` канала — 88 ошибок «All pipe instances are busy»; 100 параллельных `winio.DialPipeContext` (так подключается клиент Docker при заданном `DOCKER_HOST`) — 0 ошибок.
   **Решение.** `pipeline.mjs` для шагов Go с Docker на win32 задаёт `DOCKER_HOST=npipe:////./pipe/docker_engine`, если он не задан: тогда стратегия `dockerHostFromEnv` берёт хост без `Stat`, а проверка идёт через `docker info` по каналу с ожиданием. Плюс ограничение `-p` для job `integration` на win32 (по умолчанию 4, env `ORTUS_GO_TEST_P`): меньше одновременных контейнеров на общем Docker. То же умолчание `DOCKER_HOST` — в `accesstest.Start` для прямого `go test`; бесполезный повтор убрать.
2. **`access/assignments`** `TestCreateAssignmentRacesExtendWorkProfile`, `TestUpdateRoleRacesCreateWorkProfile`: хелпер `race` (`sod_workprofile_integration_test.go`) считает, что команда модели доступа, не завершившаяся за `accesstest.Pause` (400 мс), уже взяла блокировку людей и ждёт политику. Под нагрузкой она ещё не дошла до блокировки, первой проходит команда W1.05, и тест ждёт конфликт не у той команды. Инвариант D-10 соблюдён (`noDriverWithEarnings` молчит), дефект в тесте.
   **Решение.** `accesstest` получает ожидание реальной блокировки: `World.Waiter` опрашивает `pg_stat_activity` и `pg_blocking_pids` базы удерживающей транзакции, пока команда не ждёт блокировку одного из известных backend'ов (или не завершилась). `race` сначала ждёт, что «моя» команда заблокирована удерживающей политику транзакцией (значит, людей она уже заперла: `InPeopleTx` берёт людей раньше политики), затем — что команда W1.05 ждёт одну из двух. Тем же ожиданием заменить `Running(Pause)` в остальных тестах `assignments` (`sod_concurrency`, `control`): под нагрузкой они проходили «впустую».
3. **`session/oidc/authhttp`**: `FATAL: sorry, too many clients already (SQLSTATE 53300)` (Q-W1.03-19). Каждый мир теста держит две `pgxpool` с `MaxConns` по умолчанию (`max(4, NumCPU)` = 22), два `sql.DB` суперпользователя от `NewDatabase` и два `sql.DB` мигратора до конца теста; тестов в пакете параллельно до `GOMAXPROCS` (22). `max_connections` контейнера — 100.
   **Решение.** `pool()` открывает пулы с `MaxConns = 4` (как `tenantctx.DefaultMaxConns` в `cmd/api`), закрывает пул мигратора сразу после миграций, а число живых миров ограничено бюджетом соединений кластера (семафор, ёмкость считается в `TestMain` из `max_connections`). `migratetest` не трогается: не во владении WS.

## 4. Контракты

API, миграции и контракт CI не меняются. Внутренние интерфейсы:

```js
// tools/ci/pipeline.mjs
// ctx.platform (process.platform), ctx.env (process.env)
// план шага: { cmds, env? } — env добавляется к окружению процесса команды
export const GO_TEST_P_ENV = 'ORTUS_GO_TEST_P';      // -p для integration; на win32 по умолчанию 4
export const WIN_DOCKER_HOST = 'npipe:////./pipe/docker_engine';
```

```go
// accesstest
func PID(tx pgx.Tx) uint32
// Waiter ждёт, пока в базе db появится backend (кроме known), ждущий блокировку одного из known (pg_blocking_pids),
// и возвращает его pid; false — cmd завершилась раньше. Падает через WaitLimit.
func (w *World) Waiter(db *pgxpool.Pool, cmd *Async, known ...uint32) (uint32, bool)
```
