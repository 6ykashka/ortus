## Контекст

- `14-engineering.md`, «Стек»: «`goose` (SQL-файлы) + собственный migration controller по тенантам», альтернатива — Atlas (D-06).
- Комплект даёт SQL-файлы: control 0001–0003, tenant 0001–0002 (`docs/db/`). S1-03: controller гонит миграции canary → партии → остальные, версия схемы — в `tenant_routing`.
- Номера миграций выдаёт стюард из блоков этапа (PD-59, план v2 §3.5); CI проверяет «номера уникальны и без дыр».
- Роли БД: `migrator` (DDL), `api_runtime` (только DML) — `14-engineering.md:81`.

## Варианты

1. **goose (SQL) + свой controller** — плюсы: SQL комплекта ложится как есть, простая библиотека Go, нумерованные файлы совпадают с PD-59; минусы: controller (canary, партии, статус по тенантам) пишется самими; нет декларативного diff. Цена: W1.02 (уже в плане).
2. **Atlas (декларативные схемы + lint миграций)** — плюсы: анализ опасных миграций, diff схемы; минусы: другая модель (схема как код), часть функций — в платной версии, controller по тенантам всё равно нужен. Цена: перевод SQL v0.2 и обучение.
3. **golang-migrate** — плюсы: популярен, простые up/down; минусы: слабее работа с Go-миграциями и встраиванием в свой controller, чем у goose. Цена: сопоставима с goose.

## Решение

**Принято 17.10.2026** (ответ владельца продукта, `docs/plan/v2/po-answers-2026-10-17.md`, D-06): goose: чистый SQL, встраивается в Go, защита от выполнения не по порядку. «Controller» для DB-per-tenant при одном пилотном тенанте — цикл по списку БД с canary.

Отличие от рекомендации: нет — ответ совпадает с рекомендацией.

Рекомендация до ответа (история):

Рекомендация: «goose + собственный controller» (вариант 1).

## Последствия

- Проще: SQL v0.2 переносится без изменений; `cmd/migrate` — тонкая обёртка над goose для control и одной tenant DB.
- Сложнее: проверки «опасных» миграций (блокирующие `ALTER`, перезапись больших таблиц) — ревью двумя владельцами по CODEOWNERS, а не инструмент.
- Сделать: W0.06 — goose и `cmd/migrate`; W1.02 — controller (canary → партии), версия в `tenant_routing`; W0.04 — CI-проверка нумерации.
- Как проверим: прогон всех миграций на чистой БД и на БД с прошлой версией; тест controller'а — тенант с упавшей миграцией останавливает партию.
