# 23. База знаний: пространства и подстраницы. Разбор Confluence и предложение для Ортуса

Версия 0.2 · 10 октября 2026 года. Статус: реализовано в прототипе — модуль `База знаний.dc.html` в CRM, данные и команды — `ortus/knowledge.js`. Макеты — `База знаний - варианты.dc.html` (корень), 1a–1e.

## Реализация в прототипе

- **Данные:** `installKnowledge` переводит прежние страницы в дерево (родитель, порядок, тип, режим доступа, список) и добавляет демо: «Логистика» (ограниченное, фирма «Север Логистик»), «Салон и SPA», «Ремонт и стройка», «Руководство» (закрытое), «Общее». Роли пространства — шаблоны `r-kb-lead`, `r-kb-editor`, `r-kb-author`, `r-kb-reader`; назначения с областью `space` и `page`. Марина Котова — руководитель «Логистики», Вера Котельникова — редактор.
- **Проверка доступа:** `kbAccess` — организация → пространство (роль или уровень) → родители со своим доступом → функция «Водитель» для финансовых страниц; возвращает цепочку причин. Сервер (`kbView`) отдаёт только видимые страницы, у каждой — `my.edit`, `my.create`.
- **Команды:** `kbCreateSpace`, `kbCreateNode`, `kbPublish` (версия, конфликт, ознакомление), `kbSetStatus`, `kbSetAccess`, `kbMove`, `kbArchive`, `kbAck`, `kbRequest`, `kbDecide`, `kbSetMember`, `kbToggleRule`, `kbCheckReview`, `kbRunSection`.
- **Пока нет:** блоки внутри текста (только абзацы), правка таблиц и загрузка файлов, «Общий фрагмент», запросы доступа в «Требует решения» на «Главной», срок назначения по запросу задаётся фиксированно (30 дней).

## Что есть сейчас

- Пространства «Логистика», «Салон и SPA», «Руководство» с плоским списком страниц, без вложенности.
- Доступ страницы — `all` или `owner`: «Политика начислений водителям» видна только владельцу.
- Правка с публикацией новой версии, история версий, конфликт при устаревшей базовой версии.
- Таблицы на странице, строки добавляет действие формы (D-26).
- Права `core.knowledge`: `knowledge.read/create/update/publish`, области `tenant`, `unit`, `project`.

## Как это устроено в Confluence

**Пространство.** Своё дерево содержимого, главная страница, шаблоны, автоматизация и доступ. Создаётся пустым или из шаблона; доступ можно скопировать из другого пространства, администратор задаёт доступ по умолчанию для новых.

**Роли пространства.** Доступ к пространству задаётся ролями вместо набора отдельных галочек. Роли по умолчанию: Admin (всё в пространстве), Manager (люди и содержимое, без настроек), Collaborator (создаёт и правит), Viewer (читает и комментирует). Администратор продукта создаёт до 10 своих ролей. Роль назначают людям, группам, командам, гостям и классам пользователей («все пользователи Confluence»). Тот, кто управляет доступом, не может выдать роль с правами, которых нет у него самого.

**Дерево содержимого.** В одном дереве лежат страницы, живые документы, папки, доски, базы данных, смарт-ссылки и видео. Элементы вкладываются друг в друга, переносятся и копируются вместе с вложенными, архивируются и восстанавливаются. Для массовой уборки в старших тарифах есть менеджер содержимого: архив, удаление, смена владельца и статуса.

**Страница.** Черновик и публикация, история версий со сравнением и откатом, статус, владелец, согласования, комментарии, метки. Блоки показывают дочерние страницы, дерево, фрагмент другой страницы; синхронизированный блок повторяет один текст на нескольких страницах. Живой документ правят вместе без публикации.

**Доступ к странице.** «Общий доступ» в трёх состояниях: все в пространстве правят; все читают, правят выбранные; только выбранные. Ограничение просмотра наследуют все вложенные элементы, ограничение правки — нет. Страница, которую человек не может читать, не показывается ему ни в дереве, ни в блоках. Администратор пространства видит все страницы и может снять ограничения. Запрос доступа уходит по очереди: владельцу, создателю, последнему редактору, администратору пространства.

**Автоматизация.** Правило «триггер → условия → действия» на уровне сайта или пространства. Триггеры: страница опубликована, изменена, скопирована, перенесена в архив, добавлена метка, по расписанию, ручной запуск со страницы. Действия: опубликовать страницу из шаблона, скопировать, переместить, архивировать, уведомить. У запусков есть месячный лимит.

**Доски и базы данных.** Доска — схемы, блок-схемы, стикеры, связь с задачами Jira. База данных — поля и записи с представлениями; лежит в дереве и получает права пространства.

## Что неудобно в Confluence

- Ограничение правки не переходит на подстраницы: большой раздел закрывают постранично. Массово поменять доступ ветки штатно нельзя, только приложениями.
- В списке доступа страницы — люди и группы. Если ограничение поставил ушедший сотрудник, страницу открывает только администратор (в старших тарифах — ключом администратора).
- Доступ складывается из двух слоёв: роли пространства и ограничения страниц. Почему сотрудник не видит страницу, показывает проверка прав пользователя — она есть только в старших тарифах.

## Принципы для Ортуса

1. **Одна система прав.** Пространство — область в «Пользователях и ролях», как проект в «Задачах» (D-27). Участник пространства — назначение роли с областью пространства. Своих списков прав у базы знаний нет.
2. **Наследование из структуры.** У пространства есть область — организация, регион или фирма — и уровень доступа: открытое (роли области действуют полностью), ограниченное (все в области читают, пишут участники), закрытое (только участники и владелец бизнеса).
3. **Подстраница наследует доступ целиком.** И чтение, и правку. Своё значение у подстраницы может только сузить круг читателей; правку можно выдать отдельно тем, кто видит страницу. Изменение родителя сразу действует на подстраницы с доступом «Как у родителя».
4. **Роли и связи вместо фамилий.** В списке доступа — роль в области («Водитель» в «Север Логистик»), группа, связь с записью CRM («прораб объекта») и, по исключению, сотрудник. Новый сотрудник с ролью получает доступ сам; страницы уволенного переходят руководителю пространства.
5. **Функции защищают данные.** Финансовая страница закрыта для функции «Водитель» независимо от ролей и групп, как начисления (AUTH-03).
6. **Скрытое не видно нигде.** Недоступная страница пропадает из дерева, поиска, блока «Подстраницы» и ссылок. Руководитель пространства видит всё и может объяснить, почему сотрудник не видит страницу.
7. **Последствия до сохранения.** Изменение доступа, перенос и копирование показывают, сколько страниц изменится и кто получит или потеряет доступ.
8. **Версии.** Как сейчас: черновик, публикация, история, конфликт устаревшей версии. Плюс статус, владелец, срок пересмотра и ознакомление по роли.

## Роли пространства

Шаблоны ролей в «Пользователях и ролях», область — пространство. Своих ролей у пространства нет.

| Роль | Может | Аналог в Confluence |
|---|---|---|
| Руководитель пространства | Всё, плюс участники, доступ к страницам, автоматизация, шаблоны; видит все страницы | Admin и Manager |
| Редактор | Создаёт и правит любые страницы, публикует, перемещает, архивирует | Collaborator |
| Автор | Создаёт страницы и правит свои; публикует через редактора | — |
| Читатель | Читает, комментирует, отмечает «Ознакомлен» | Viewer |

Руководитель пространства назначает только роли, права которых есть у него самого, как при `roles.assign`.

## Доступ к странице

- **Режимы:** «Как у родителя» (по умолчанию), «Читают все, правят выбранные», «Только выбранные».
- **Кого выбирают:** роль в области, группу, связь с записью CRM (прораб объекта, водитель рейса, исполнитель задачи), сотрудника. Для каждого — «Читает» или «Правит».
- **Проверка:** организация (активный участник) → пространство (роль или уровень доступа) → каждый родитель → страница → функция и чувствительность страницы. Правка требует «Правит» на самой странице или у родителя, если у страницы «Как у родителя».
- **Заблокированный сотрудник** остаётся в списке с пометкой «Приостановлен», доступ не действует.
- **Запрос доступа** получает владелец страницы, затем руководитель пространства, затем владелец бизнеса. Если сотрудник вне области пространства, одобрение создаёт назначение «Читатель» с областью этой страницы и сроком.
- **Перенос** под другого родителя пересчитывает доступ; диалог показывает, кто потеряет доступ.
- **«Требует решения»** на «Главной» — запросы доступа и страницы с наступившим сроком пересмотра.

## Типы в дереве

| Тип | Что это | Доступ |
|---|---|---|
| Страница | Текст, блоки, вложения, версии | Свой или как у родителя |
| Папка | Группа без текста | Задаёт доступ подстраницам |
| Таблица | Колонки и строки; строки вручную или из ответов формы (D-26) | Как у страницы; строку из формы правят через ответ |
| Схема | Доска: блоки, стрелки, подписи; встраивается в страницу | Как у страницы |
| Файл | PDF, документы Office, фото с предпросмотром и версиями; занимает квоту | Как у страницы, плюс проверка файла (FILE-02) |
| Запись CRM | Ссылка на форму, задачу, рейс, объект со статусом | Открывается, только если есть доступ к записи |

Блоки страницы: «Подстраницы» (обновляется сам), «Схема», «Таблица», «Запись CRM», «Файл или документ», «Общий фрагмент».

## Правка, версии, ознакомление

- Черновик сохраняется сам, правят вместе, видно, кто сейчас в черновике.
- Публикация создаёт версию; сравнение любых двух версий; старая версия восстанавливается как новая.
- Статус: «Черновик», «На проверке», «Действует», «Устарела». Владелец и срок пересмотра; за 14 дней до срока — задача владельцу.
- Ознакомление: при публикации редактор просит роль или группу подтвердить, что прочитали версию. Видно «4 из 5», есть напоминание. Подтверждение хранит номер версии.

## Шаблоны

- **Шаблон пространства:** подстраницы, их доступ по ролям, правила. Стартовые шаблоны Ортуса копируются в организацию, свои — «Сохранить пространство как шаблон».
- **Шаблон раздела:** ветка подстраниц с доступом по связи с записью CRM («Объект ремонта», «Новый сотрудник»). Разделы, созданные раньше, при правке шаблона не меняются.

## Автоматизация

Движок правил «Задач» (D-27): «когда — если — тогда», от имени автора с проверкой прав при каждом запуске, изменения правила не запускают другие правила, журнал с остановками и ошибками.

- **Триггеры:** страница опубликована, статус изменился, наступил срок пересмотра, страница создана в разделе, по расписанию, события модулей (объект перешёл на этап, акт подписан, сотрудник получил роль, ответ формы принят).
- **Действия:** создать раздел из шаблона, переместить, архивировать, сменить статус или владельца, попросить ознакомиться, создать задачу, добавить строку в таблицу, уведомить роль.

## Новые права для `11-permissions.yaml`

Новые типы областей: `space` (пространство), `page` (страница с подстраницами), `relation` (связь с записью CRM).

```yaml
core.knowledge:
  label: База знаний
  actions:
    knowledge.read:              { level: view,     label: Читать,                    scopes: [tenant, unit, space, page, relation] }
    knowledge.comment:           { level: view,     label: Комментировать,            scopes: [tenant, unit, space, page] }
    knowledge.create:            { level: create,   label: Создавать страницы,        scopes: [tenant, unit, space, page], note: "свои страницы автор правит этим же правом" }
    knowledge.update:            { level: edit,     label: Править любые страницы,    scopes: [tenant, unit, space, page, relation] }
    knowledge.publish:           { level: review,   label: Публиковать и проверять,   scopes: [tenant, unit, space, page], note: "было level: settings" }
    knowledge.organize:          { level: edit,     label: Перемещать и архивировать, scopes: [tenant, unit, space] }
    knowledge.access.manage:     { level: settings, label: Доступ к страницам,        scopes: [tenant, unit, space], sensitivity: sensitive, note: "выдаёт только то, что имеет сам" }
    knowledge.members.manage:    { level: settings, label: Участники пространства,    scopes: [tenant, unit, space], sensitivity: sensitive }
    knowledge.spaces.manage:     { level: settings, label: Создавать пространства,    scopes: [tenant, unit] }
    knowledge.automation.manage: { level: settings, label: Настраивать автоматизацию, scopes: [tenant, unit, space], sensitivity: sensitive }
    knowledge.export:            { level: export,   label: Выгружать,                 scopes: [tenant, unit, space], sensitivity: sensitive }
```

## API (набросок)

- Пространства: `GET /kb/spaces`, `POST /kb/spaces` (шаблон, область, уровень), `GET /kb/spaces/{id}/tree` — только видимые узлы, руководителю — все со значками.
- Узлы: `POST /kb/nodes` (пространство, родитель, тип, шаблон), `PATCH /kb/nodes/{id}`, `POST /kb/nodes/{id}/move` и `/copy` (с подстраницами; `dryRun` возвращает `lost[]`).
- Доступ: `PUT /kb/nodes/{id}/access` (`dryRun` → `affected`, `gained[]`, `lost[]`), `GET /kb/nodes/{id}/explain?member=` — цепочка причин, `GET /kb/spaces/{id}/access-map`.
- Версии и ознакомление: `POST /kb/nodes/{id}/versions` (`If-Match` базовой версии), `POST /kb/nodes/{id}/ack`.
- Запросы: `POST /kb/nodes/{id}/requests`, `POST /kb/requests/{id}/approve`, `POST /kb/requests/{id}/deny`.
- События: `kb.node.published`, `kb.node.moved`, `kb.access.changed`, `kb.review.due`, `kb.request.created`, `kb.ack.requested`.

## Что не берём сейчас

- Блоги пространств, живые документы без публикации, видео.
- Публичные ссылки и анонимный доступ: страницы для клиентов публикуются в кабинет заказчика или на страницу направления (`22-client-requests.md`).
- Язык запросов и блоки-отчёты, кроме «Подстраниц» и записи CRM.
- Своё оформление пространства: оформление организации общее (`18-branding.md`).
- ИИ-помощника.
