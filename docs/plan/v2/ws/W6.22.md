# W6.22 Снабжение, «Шаблоны и расценки», склад объекта (страницы на MSW)

Этап 6 · подволна 6b · шаг 6.4 · дорожка Ф · размер L · вид `frontend`, слот 4.
Зависит от: W6.00 (контракт `0.12.0-stage6`, MSW `repairs`, пресет `repairs-ready`), W6.10 (домен: справочники подписей). Блокирует: W6.90 (сквозной сценарий), W6.20 (встраивает вкладку «Снабжение» объекта).

## 1. Цель

Страницы снабжения и справочников «Ремонта и стройки» на сценарном сервере (режим `mock`), по эталону `design-2026-10-19` (`Ремонт и стройка.dc.html`, `hubVM`, `catVM`) и разбору `docs/plan/v2/analysis/dor/repair.md` §1.3, §2.2, §7.

| Ключ | Маршрут | Эталон | Содержание |
|---|---|---|---|
| `repair-supply` | `/t/:tenantId/repair-supply` | `data-screen-label="Снабжение и склады"` (:724–829); h1 в CRM — «Снабжение» | Вкладки «Заявки · N», «Закупки · N», «Остатки», «Движения»; решение по заявке (выдать со склада или в закупку), форма «Новая закупка», «В работе», приход по чеку QR, остатки на объектах (вернуть на склад, переместить на объект) |
| `repair-supply-tab` | вкладка «Снабжение» карточки объекта (встраивает W6.20: `SupplyTab`) | `data-screen-label="Снабжение"` (:532–545) | Заявки одного объекта, статусы `SUPX`, действия |
| `repair-supply-request` | форма во вкладке «Снабжение» объекта (прораб) | no-reference (Q-W4.00-repair-6, B-6) | «Новая заявка на материал»: материал справочника, количество, «Нужно к» |
| `repair-catalog` | `/t/:tenantId/repair-catalog` | `data-screen-label="Шаблоны и расценки"` (:614–721) | Шаблоны (просмотр, правка формул объёма, «Сделать копию») и справочник расценок (поиск, фильтр, цена в строке, «Новая позиция») |

Пункты меню — манифест W1.20 (`repairSupply` — `repairs.supply.manage`, `repairCatalog` — `repairs.catalog.manage`).

## 3. Входы

- Контракт тега Repairs: `listSupplyRequests`, `createSupplyRequest`, `reserveSupplyRequest`, `issueSupplyRequest`, `consumeSupplyRequest`, `createPurchase`, `listPurchases`, `receivePurchase`, `listProjectStock`, `returnProjectStock`, `transferProjectStock`, `listPriceItems`, `createPriceItem`, `updatePriceItem`, `listTemplates`, `updateTemplate`, `copyTemplate`, `listRepairProjects`; склад — `listWarehouses`, `listInventoryBalances`, `listInventoryMovements`, `listInventoryItems` (модуль «Склад», этап 5).
- Подписи, чипы, виды движений: `@ortus/domain/modules` (`SUPPLY_CHIPS`, `MOVEMENT_KINDS`, `SUPPLIERS`, `FORMULAS`, `CATALOG_SECTIONS`) — дословно из эталона.

## 4. Экраны и состояния

Каждая страница: загрузка (скелетон), ошибка (alert + «Повторить»), пусто (тексты эталона), только чтение (модуль отключён или организация в чтении — команды недоступны), нет права (AccessGate оболочки), офлайн (тост «нет связи»). Раскладка: 1440 — таблицы целиком; 390 — прокрутка таблиц в контейнере (`min-width` 900 / 720 / 640 / 860 как в эталоне), цели нажатия ≥ 44 px.

## 5. Тесты, которые пишутся первыми

e2e-скелеты `repair-supply.spec.ts`, `repair-catalog.spec.ts`, `repair-supply-tab.spec.ts` (`test.fixme`) → Vitest на модель (суммы, подписи срока, распределение закупки, цена по умолчанию, фильтры справочника, формулы строки шаблона) → экранные тесты на MSW (`renderMockApp`, пресет `repairs-ready`) → снятие fixme в e2e.

`corepack pnpm --filter @ortus/web exec vitest run`, e2e `mock` на `mobile-390` и `desktop-1440` (`--grep repair-`), проходка Playwright MCP по `verification-protocol` §4, `lint`, `typecheck`, `test`.

## 7. Решения по умолчанию (вопросы — Q-W6.22-N в отчёте)

| # | Вопрос | По умолчанию |
|---|---|---|
| 1 | «Остатки» и «Движения» складов в MSW нет: операции «Склада» (W5.10) не реализованы | Вкладки читают контракт «Склада»; при `not_implemented` блок показывает «Данные склада недоступны» с «Повторить». «Остатки на объектах» (вернуть, переместить) работают на тегe Repairs. Склады для возврата — из `listWarehouses`, при недоступности — из `available` заявок |
| 2 | Кнопки «Демо: …» за чужие роли (Q-W4.00-repair-9) | Не переносятся: «Демо: кладовщик выдал» → «Выдать прорабу» (право `inventory.movements.post` или владелец); «Демо: получено, чек по QR» → поле «Чек по QR» и «Получено»; «Демо: прораб забрал» не переносится. Отличия — allowlist |
| 3 | «Шаблоны и расценки» по плану входят в W6.22, DoR вынес их в W6.25 | Делаю здесь целиком (`repairCatalog`); при появлении W6.25 каталог маршрутов не пересекается |
| 4 | Цена закупки по умолчанию (Q-W4.00-repair-23) | Пустая цена в строке закупки — сервер подставляет «средняя цена склада → последняя закупка → справочник»; форма показывает подсказку эталона, сумма по введённой цене |
| 5 | If-Match (ревизия заявки, закупки, позиции, шаблона) | Ревизия из последнего ответа: `"rev-<N>"` (форма MSW; у Go-модуля будет сверена на `stand`) |
| 6 | Форма заявки прораба (no-reference) | Материалы — `listPriceItems?kind=material`; поля «Материал», «Количество», «Нужно к»; после отправки — тост и строка в списке; до дорисовки — по разбору Q-W4.00-repair-6 |
