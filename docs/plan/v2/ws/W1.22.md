## 1. Цель

- **`/auth/login` — экран входа** (S1-05): кнопка «Войти» ведёт в BFF `startLogin`
  (`GET /api/v1/auth/login?returnTo=<путь>`, OIDC Code + PKCE, 302 к провайдеру). Путь возврата — `?next=` (ADR-0001),
  проверенный по шаблону `returnTo` контракта; чужой или кривой — `/`. Вход оператора (`next=/platform…`) подписан как
  отдельный вход управления платформой (realm операторов выбирает BFF по `returnTo`, Q-W1.03-1). Состояния: начальное;
  переход к провайдеру (кнопка занята); ошибка входа `?error=<code>` (сессия истекла, отказ, сервис недоступен). На
  загрузке экран **не делает запросов к API** (выход W1.49 проверяет, что после `logout` запросов нет).
- **`/auth/invitation#token=…` — принятие приглашения** (S1-06): токен читается из фрагмента ссылки письма (W1.41,
  Q-W1.41-3), фрагмент убирается из адреса, токен живёт в `sessionStorage` вкладки до принятия (переживает уход к
  провайдеру входа). `inspectInvitation` → бизнес, маска почты, срок, статус. Не вошёл — «Войти и принять»
  (`startLogin`, `returnTo=/auth/invitation`); вошёл — «Принять приглашение» (`acceptInvitation`) → перечитать
  `/me/context` → стартовая страница бизнеса и тост. Состояния: действует; почта не совпадает (403) с выходом
  «Войти под другим аккаунтом»; истекло (410 / `expired`); отозвано; уже принято; мест нет (409 `seats_exhausted`);
  не найдено (404 / 422 / нет токена); сбой загрузки с «Повторить».
- **Панель входящих** в слоте шапки (S1-26, контракт C-7 W1.20: `src/features/inbox/InboxPanel.tsx`): события
  организации (`listMyNotifications`, страницы по курсору, «Показать ещё»), точка непрочитанного, переход к записи по
  `link` (путь внутри организации, цель авторизуется заново при открытии), отметка прочитанным при переходе
  (`markMyNotificationsRead` с `notificationIds`), «Прочитать все» (`upTo` последнего события), счётчик колокола
  (`getMyNotificationSummary`, ключ оболочки `NOTIFICATION_SUMMARY_KEY`) обновляется. Состояния: загрузка; пусто
  «Новых событий нет»; есть непрочитанные; прочитано всё; ошибка и офлайн с «Повторить».
- Четыре проверки `verification-protocol.md` для трёх ключей: e2e mock 390/1440 (+768), e2e stand (backend в `main`),
  проходка Playwright MCP, ревью. Пиксельной и структурной сверки нет (`no-reference`), кроме подписей поповера
  «Уведомления» эталона (`:124–135`): они сохраняются дословно.

## 10. Риски и решения по умолчанию

1. **Ссылка приглашения** — `/auth/invitation#token=` (Q-W1.41-3), маршрута `/auth/invite/:token` нет: токен в пути
   попал бы в журналы. ADR-0001 правит интегратор.
2. **Токен до входа** — `sessionStorage` вкладки (не `returnTo`: путь возврата уходит в URL `startLogin` и журналы BFF).
   Удаляется после принятия, на «не найдено», «отозвано», «истекло».
3. **Ошибки callback** BFF отдаёт JSON-ошибкой на `/api/v1/auth/callback`, а не редиректом. Экран входа уже понимает
   `?error=<code>`; редирект `completeLogin` → `/auth/login?error=<code>` — вопрос backend (decisionsNeeded).
4. **Режим mock**: service worker MSW не перехватывает навигацию, поэтому `startLogin` в e2e mock имитирует
   `page.route` (302 на `returnTo?persona=…`); на стенде dev-провайдер отвечает 503 `dependency_unavailable`
   (`startLogin` без OIDC) — это поведение BFF, e2e stand проверяет адрес навигации.
5. **`link` уведомления** — путь внутри организации (`/users` → `/t/<tenantId>/users`, отчёт W1.10, примеры контракта).
6. **Q-W1.49-6** (канал после повторного входа): вход — всегда навигация через BFF (новая загрузка вкладки), кэш и
   канал начинаются заново; принятие приглашения сессию не меняет — перечитывается `/me/context`.
7. **`/auth/dev`** (ADR-0001, «только local и e2e») не делается: dev-вход `?persona=` (PD-54) покрывает e2e и
   локальную разработку.
8. **Выход** «Войти под другим аккаунтом»: `logout`; при `endSessionUrl` — уход к провайдеру (иначе он снова войдёт тем
   же аккаунтом), без него — сразу `startLogin` с возвратом на приглашение.
9. Тексты экранов — в своих каталогах (`texts.ts`), подписи эталона — из `@ortus/texts` (`shell.popovers`, `errors`).
   Перенос в домены `auth`/`inbox` словаря — стюард (integratorNotes).
10. Stand: уведомлений на стенде нет (производителей в `cmd/worker` ещё нет, сид их не пишет) — строки `@stand`
    проверяют пустую ленту, сводку и отметку; сквозное принятие приглашения — `@mailpit` (нужен Mailpit, Q-W1.41-7).
