## Осталось fixme / открытые вопросы

`fixme` нет. Вопросы (Q-W2.51-N, значения по умолчанию — как сделано; внести в `docs/plan/decisions.md` — файл интегратора):

1. **Q-W2.51-1 · права публикации (технический).** Новых ключей нет: публикация и снятие — `fleet.driver_transfers.approve` (тот, кто отпускает водителя), чтение публикаций — `fleet.driver_transfers.read`. Альтернатива — ключ `fleet.driver_pool.publish` (ломает дословность ключей 11 и требует правки шаблонов, `catalog_data.go`, сида W1.04).
2. **Q-W2.51-2 · экран фирмы-источника (продукт).** В эталоне нет ни публикации, ни входящих запросов (демо-кнопки «Одобрить» / «Отклонить» не переносятся, PD-54). По умолчанию W2.23 строит на «Ресурсном пуле» для участника с `approve` на свою фирму блок входящих запросов (`direction=incoming`, кнопки с подписями демо «Одобрить» / «Отклонить») — no-reference; публикация в этапе 2 — сидом и API (экран — после решения).
3. **Q-W2.51-3 · один открытый запрос (продукт).** На опубликованного водителя — один `requested` (эталон `api.js:544`), а не на пару «водитель — рейс» (MSW W2.00): второй запрос с другого рейса или фирмы — 409 «Запрос уже отправлен».
4. **Q-W2.51-4 · автозавершение (продукт; уточнено в возврате 1).** Назначение заканчивается по `window.endsAt`; начатый и не закрытый рейс (`inspection`…`returning`, `submitted`, `rework`) держит его в `closing` до приёмки или отмены (D09, AUTH-07): сданный после окна рейс приёмка ещё может вернуть на доработку, и временный водитель её делает. `completedAt` — момент приёмки (`acceptedAt`), если он позже конца окна. Не начатый к концу окна рейс теряет временного водителя. Нерешённый запрос истекает к началу окна; снятие публикации — открытые запросы `expired`, одобренные — до конца окна или отзыва. До начала окна назначение `scheduled`, рейс временному водителю уже виден (подготовка к выезду).
5. **Q-W2.51-5 · псевдоним пула (продукт).** «Водитель #N» выдаёт сервер (следующий номер организации); имя видит только фирма-источник; после одобрения фирма-получатель видит псевдоним + «· временно» (как эталон), имя и телефон — вне контракта этапа 2. Ограничение (возврат 1): `DriverAvailability.driverMemberId` (обязательное с 0.1) и `DriverTransfer.driverMemberId` отдают фирме-получателю настоящий id участника — ломать 0.1 нельзя; в контракте записано, что чужая фирма не разрешает его через members/people API (404, как отсутствующий), W2.07 не должен давать такого разрешения.
6. **Q-W2.51-6 · подписи наборов (продукт).** Подписи — эталона `dataVM`: «Автомобили», «Поездки», «Расходы» (план — «Машины», «Рейсы», «Расходы»). Варианты выбора — `VEHICLE_STATE`, `TRIP_STATE`, `EXPENSE_CAT` эталона + подписи W2.40; статус расхода — как эталон («Принят» после приёмки смены, иначе «Заявлен водителем»).
7. **Q-W2.51-7 · выгрузка и виды (продукт).** Операции выгрузки нет (эталон — демо-тост): `exportAllowed` только включает кнопку; «Сохранить вид» — личный, в браузере (тост эталона «Вид сохранён · личный»), контракта нет.
8. **Q-W2.51-8 · подпись скрытого поля (безопасность).** `hiddenFieldLabels` раскрывает существование поля «Начисление» (как `hiddenNote` эталона), без ключа и значений; скрытое и неизвестное поле в выборке — одинаковый 422.
9. **Q-W2.51-9 · номер 0014 (технический).** Параллельно идут W2.24, W2.30, W2.44, W2.47, W2.53, W2.54; если один из них откроет tenant-миграцию раньше слияния W2.51, 0014 получает первый влитый (очередь резерва, `api/README.md`).
10. **Q-W2.51-10 · срок запроса внутри окна публикации (продукт; возврат 1).** Срок временного назначения не выходит за свободное окно, опубликованное фирмой-источником (AUTH-07): окно запроса вне `freeWindow` — 422 (`window`, `outside_free_window`). 15. **Q-W2.51-15 · доступ временного водителя в `closing` (технический; возврат 2).** Грант — строка `access.role_assignments` (`source = 'transfer'`, область — рейс; без рейса — фирма-получатель).
