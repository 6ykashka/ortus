## Осталось fixme / открытые вопросы

- `fixme`/`skip` нет.
- **PD-53 и видимость разделов.** Со строгим `can` пользователь только с объектными ролями не получает `view` модуля без объекта: Котова (`r-pm @ fleet`, `r-agent @ svc-grz`) не прошла бы гейт раздела «Задачи»/«Обращения» (`gateVM` → `M.can(…, 'view')`), а сервисный `view` эталона (`service.js:222`) скрыл бы ей обращения. По умолчанию: гейты и меню — `canAny` (учитывает объектные роли), команды — `can` с объектом; модульные движки (`projCan`, `kbAccess`, `seesDir`, `cashAccess`) работают с грантами как в эталоне. Нужна запись в `docs/plan/decisions.md` (файл W0.01) рядом с PD-53.
- **Единый `entryHas`.** В эталоне knowledge-вариант не знает `who:'all'` и не исключает заблокированных, documents-вариант — исключает. Ядро: заблокированный не входит никуда, `all` — все остальные. Влияет на W4.30 (БЗ) — расхождение с эталоном в пользу безопасности (PD-60).
- **Канонические коды** взяты из `ND/docs/12-errors-and-events.md` (v0.2, с кодами чатов) и 17/D-34. После слияния W0.07 нужен тест «каждый код `api/errors.yaml` ∈ `CANON_CODES`» (интегратор).
- **Паритет** сейчас против `design/ortus/models.js` 03.10: функции ядра в 14.10 не изменились, кроме `scopeLabel` (+7 видов), `rolePermKeys` (+2 ключа кассы) и `CORE`; их ожидания взяты из 14.10 литералами. После обновления `design/` до 14.10 (W0.02) тест паритета должен остаться зелёным; тогда в него стоит добавить объектные виды `scopeLabel` и роли кассы в `rolePermKeys`.
- **Маркер заглушки.** `tools/repo/workspace.test.mjs` (W0.03) требует `@stub Owner: W0.11` в первых трёх строках `src/index.ts`, хотя владелец заменяет заглушку целиком. Маркер оставлен в комментарии с пояснением; интегратору — ослабить проверку для заменённых заглушек.
