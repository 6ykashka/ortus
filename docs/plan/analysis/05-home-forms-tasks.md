## 2. Сводка

- Три страницы в одном SPA-шаблоне: `pg.home`, `pg.forms`, `pg.tasks`; переключение — ключ `pages[persona]` (`Ортус CRM.dc.html:2856–2865`). Рендер — один `renderVals()`, данные для страниц считают `homeVM`, `formsVM`, `tasksVM`.
- «Главная» — стартовая страница владельца и логиста (`DEFAULT_PAGE`, `:2327`), не закрыта гейтом никогда (`:3054`). Состоит из приветствия, «Начало работы» (только владелец), очереди «Требует решения», карточек «Сегодня в работе», сбоку «Рейсы сегодня» и «Последние события».
- Очередь «Требует решения» собирается из 9 источников (рейсы, SPA, ремонт, подписка, место, сотрудники без роли, свои задачи), сортируется по тону danger → warn → info → neutral, показывает максимум 8 (`:4042–4064, 4100`).
- «Формы и опросы»: список форм слева, справа три вкладки «Конструктор / Версии / Ответы». 10 типов полей, разделы, порядок кнопками ↑↓, обязательность, условие «Показывать, если» по полям выше типа `bool`/`choice` (`:4454, 4500`).
- Черновик живёт в `state.fdraft` до публикации; публикация через диалог-подтверждение создаёт новую неизменяемую версию, смена типа поля даёт новый ID `id-vN` (`api.js:421`).
- Ответы показываются по структуре своей версии; различаются «Не показывался по условию» и «Не ответил» (`:4528`). Журнал автоматизации: «Ответ R-… принят → Задача T-…» (`:1695`).
- Связь с логистикой: каждый отправленный осмотр водителя (выезд/сдача) создаёт ответ формы `fm-insp` по действующей версии и одну задачу менеджеру; повтор по ключу `tripId:kind:rev` дубля не создаёт (`api.js:38–50`).
- Логист (роль «Менеджер логистики») видит формы только для чтения: нет действия `settings` (`forms.publish`) — чип «Только просмотр · нет права «Настраивать»» (`:1598, 4457`).
- «Задачи»: проекты (`db.projects`), два процесса — `tasks` (Новая → В работе → На проверке → Готово) и `leads` (Новая → Замер → Смета → Договор → Объект) (`models.js:128–136`). Виды «Канбан» и «Список», фильтр «Все исполнители / Мои задачи».
- Статус меняется только кнопками «Перевести», набор которых задан `TASK_FLOW`; сервер проверяет переход и чек-лист (`api.js:430–437`). Перетаскивания нет намеренно (`:1810`, `README.md:79`).
- Задача из автоматизации помечена «⚡ из ответа формы», критический дефект даёт приоритет «Срочно» (`api.js:49`); у логиста в меню счётчик новых задач (`:2993`).
- Карточка задачи: статус, исполнитель, приоритет, срок, «Создана автоматизацией», переходы, чек-лист, связанные объекты (ответ/рейс/машина/форма → переход в исходный раздел), история и комментарии (`:1773–1807`).
- Все изменения идут через `this.run(key, () => api.X(), toastText)`: `busy` на время запроса, тост по ответу сервера, ошибка — тост с текстом `ApiError.message` (`:2445–2460`).
- Офлайн (флажок «Нет связи») блокирует все команды домена: `assertNet` → «Нет связи с сервером. Операция не выполнена.» (`api.js:52`). Конец пробного периода (`restricted`) методы форм и задач **не** блокирует — `assertActive` в них не вызывается (`api.js:415–451`).
- Брейкпоинты: `mobile = W < 640`, `rail = 640 ≤ W < 1080`, боковая панель с подписями от 1080 (`:2830, 2843`). Ширина `W` берётся из селектора «Ширина» демо-панели или окна.
- У организации «SPA «Лотос»» (`t-lotos`) есть задачи (проект `salon`, ключ `SPA`) и нет форм (`forms: []`) — страница форм там падает в `formsVM` (см. §10).

## 4. Общая оболочка — что нужно знать домену

### 4.1 Раскладка и брейкпоинты
- `W` = `min(frame, state.w)` при выбранной ширине демо-панели, иначе ширина окна; `mobile = W < 640`, `rail = !mobile && W < 1080` (`:2829–2830`).
- Боковая панель `nav[aria-label="Основная навигация"]`: ширина 244px с подписями при ≥1080, рейл 68px (только иконки, подпись визуально скрыта) при 640–1079 (`:150–169, 2843`). На телефоне — `nav[aria-label="Навигация"]` снизу: первые 3 не-«план» пункта + «Ещё» (открывает лист «Все разделы») (`:2192–2201, 3025–3028`). Подписи в нижней панели укорочены: «Модули и место» → «Модули», «Пользователи и роли» → «Люди», «Рабочее место логиста» → «Логист», «Ресурсный пул» → «Пул», «Приёмка смен» → «Приёмка» (`:3026`).
- `main#ox-main` прокручивается; контейнер `max-width: 1320px` (у водителя 680px), отступы `24px 28px 40px` на десктопе и `16px 14px 28px` на телефоне (`:172–173, 2844`). Тост снизу 20px / 76px на телефоне (`:2844`).
- Активный пункт меню: `aria-current="page"`, bg `var(--ox-accent-soft)`, fg `var(--ox-accent)`, weight 600; hover `background:#EBEFE9` (`:155, 3022`). Бейдж в меню: pill min-width 20px, bg accent, fg #FFFFFF, 12px/600 (`:160`).
- Шрифты: Golos Text; моноширинный IBM Plex Mono для ID задач (`:14, 1746`). Иконки Material Symbols Rounded. `button:disabled{opacity:.45;cursor:not-allowed}`; `:focus-visible` — outline 2px accent (`:21–22`).

### 4.2 Навигация домена
- `CORE_ITEMS`: `tasks: ['Задачи','task_alt']`, `forms: ['Формы и опросы','dynamic_form']` (`:2974`). Пункт показывается, если `M.can(db, mid, k, 'view').ok` (`:2975`).
- Владелец: группа «Обзор» → «Главная»; группа «Общие модули» → `tasks, forms, calendar, knowledge, data, files, cash` (`:2980–2988`).
- Логист: «Обзор» → «Главная»; «Общие модули» → `tasks, forms, calendar, knowledge, data, files`, бейдж у «Задачи» = число задач с `assignee === 'Марина Котова'` и `status === 'Новая'` (жёстко по имени, `:2993–2994`).
- Прораб: «Общие модули» → `tasks, knowledge` (`:3000`). Водитель и массажист — без задач и форм (`:2998–2999`).
- Бренд-меню может переименовать/скрыть пункты `tasks`/`forms` (`brandNav`, `:2944–2957`); `home` защищён от скрытия (`BR_LOCK`, `:2349`).

### 4.3 Гейт, загрузка, ошибки
- `gateVM`: для `home` — всегда `none`. Для `tasks`/`forms` (`PAGE_MOD`) — `M.can(db, mid, mod, 'view')`; базовые модули всегда «подключены» (`moduleOn` возвращает `true` для не-отраслевых, `models.js:169`), поэтому единственный вариант — чип «Нет права» (warn, icon `lock`), h1 «Нет доступа к разделу «Задачи»» / «Нет доступа к разделу «Формы»» (имя из `CORE[k].name`: «Задачи», «Формы»), текст «Ни одна ваша роль не разрешает его просматривать. Владелец бизнеса может добавить действие в роль.», без кнопки (`:3055–3060, 195–203`).
- Скелетон: `div[role=status][aria-label="Загрузка"]` с 4 пульсирующими блоками (#DFE4DC / #E6EAE3, `ox-pulse 1.4s`) и текстом «Загружаем рабочее пространство…» (`:182–190`); показывается при `loading` (старт `api.load()` 500 мс, смена персонажа 320 мс, `:2432, 2470`).
- Ошибка загрузки модулей: `div[role=alert]` «Не удалось загрузить модули прототипа: {текст}» (`:191–193`).
- Тост: `div[role=status|alert][aria-live=polite]`, bg #1C2A26, fg #FFFFFF; иконки ok `check_circle` #8FD3AE, warn `cloud_off` #F0C76E, error `error` #F2A99E, info `info` #A9C8EA; скрывается через 4200 мс (`:2313–2317, 2440–2444, 2895–2901`).
- `run(key, fn, okText)`: `busy=key` → по успеху `db = r.db`, тост ok; по ошибке тост `e.message` тоном `error` (для `offline` — `warn`) и `db = e.db` (`:2445–2460`). Все методы домена возвращают `{data, db}` (`api.js:99–104`).
- Окно подтверждения (`modal.kind === 'confirm'`): `div[role=dialog][aria-modal=true][aria-labelledby=dlg-title]`, max-width 560px, на телефоне прижато к низу с радиусом `16px 16px 0 0`; кнопки «Отмена» и `confirmLabel` (во время `busy` — «Выполняем…»); Esc и клик по подложке закрывают (`:2203–2228, 2406–2410, 3955–3968`).

### 4.4 Демо-панель и триггеры состояний
- «Персонаж»: `select` со значениями `operator`, `owner`, `manager`, `driver`, `therapist`, `foreman`, `owner@t-lotos`, `therapist@t-lotos` (`:32–47`); смена → `setPersona` → скелетон 320 мс.

- «Нет связи» (checkbox) → `setOnline(false)`: тост warn «Нет связи. Черновики сохраняются на устройстве», чип «Нет связи» в шапке, баннер «Нет связи.» (`:63, 2484–2490, 3087–3089`).
- «Сбросить» → `reset()` — полная переинициализация (`:60, 2436–2438`).
- Конец trial: владелец → «Модули и место» → `confirmTrialEnd` (`:2735–2747`) либо оператор → статус «Ограничен». Эффект в домене: баннер «Пробный период завершён.» (`:3085`) и карточка в очереди «Главной» (`:4053`).

## 5. Страница «Главная» (`pg.home`)

### 5.1 Идентификатор и доступ
- Ключ `home`; подпись меню «Главная», icon `home`; группа «Обзор» (`:2981, 2992`).
- Персонажи: owner (`m-owner`), manager (`m-kotova`); `owner@t-lotos` (`MEMBER_BY`, `:2324`). Стартовая страница для них (`:2327`).
- Гейта нет (`:3054`). Данные ограничены `view()` адаптера: рейсы/машины/задачи/события приходят уже отфильтрованными по правам (`api.js:70–97`).

### 5.2 Раскладка
- `section[aria-labelledby=h-home]`, колонка, gap 20px (`:1815`).
- Порядок: шапка (контекст, h1, summary) → карточка «Начало работы» (условно) → двухколоночный flex-wrap: основная колонка `flex:999 1 520px` («Требует решения», «Сегодня в работе») и `aside flex:1 1 300px` (`:1837–1838, 1870`).
- Брейкпоинты: при ширине контента ≥ 836px (1440) aside справа; при 768 (рейл, контент ≈644px) aside переносится под основную колонку; при 390 — всё в одну колонку, карточки очереди переносят кнопку на новую строку (`flex-wrap`, `:1841`). Сетка «Сегодня в работе»: `repeat(auto-fit, minmax(min(100%,240px),1fr))` (`:1853`).
- Липких элементов нет; скролл — общий `main#ox-main`.

## 8. Инварианты и правила

1. Опубликованная версия формы неизменяема: публикация всегда `versions.push` новой записи, старые не трогаются (`api.js:423–424`; текст на странице `:1583`).
2. Ответ привязан к `version` и отображается по полям **своей** версии (`:4524–4528`); «Не показывался по условию» (условие `showIf` не выполнено по значениям ответа) отличается от «Не ответил» (`null`/`''`) (`:4528`).
3. Смена типа поля = новое поле: ID получает суффикс `-vN`, старые значения не переписываются (`api.js:421`, диалог `:4445`). Смена подписи ID сохраняет (`:4494`).
4. Условие «Показывать, если» ссылается только на поля выше и только типов `bool`/`choice` (`:4500`); при удалении поля-источника условие снимается у зависимых (`:4479`).
5. Публиковать нельзя без полей и с пустой подписью (`api.js:418–419`); кнопка «Опубликовать» выключена, если черновик совпадает с действующей версией (`:4484`).
6. Право на правку форм — действие `settings` (`forms.publish`); без него конструктор только для чтения, сервер отклоняет публикацию (`:4457`, `api.js:416`).
7. Один осмотр → один ответ → одна задача; повтор по ключу `tripId:kind:rev` не создаёт дубля (`api.js:41–42`); критический дефект → приоритет «Срочно» (`api.js:49`).
8. Статус задачи меняется только переходами `WORKFLOWS[flow].flow`; сервер проверяет и пишет системный комментарий «Статус: A → B» (`api.js:433–436`).
9. «Готово» заблокировано, пока есть невыполненные пункты чек-листа — и в UI (`:4399`), и на сервере (`api.js:434`).
10. Перетаскивания в канбане нет; кнопки переходов — основной способ (`:1810`, `README.md:79`).
11. Задача видна, если её проект в области гранта с действиями `tasks` **или** она назначена на актёра (`api.js:87–90`); проекты других областей не показываются (`:1725`).
12. Создавать задачу можно только внутри проекта (`tk.canCreate = canCreate && !!proj`, `:4377`); исполнитель — только активный участник, не водитель (`:4381`).
13. Очередь «Требует решения» сортируется danger → warn → info → neutral, показывает ≤ 8, статус дублируется иконкой и подписью (`:4043, 4063–4064, 4100`; `components.md:43`).
14. «Начало работы» показывается только владельцу и исчезает при 3/3 (`:4098`).
15. Все мутации — через адаптер и `run`; тост успеха только после ответа сервера (`:2445–2460`; `components.md:34`).
16. Любая команда без связи отклоняется с «Нет связи с сервером. Операция не выполнена.» (`api.js:52`).
17. Статус всегда = иконка + текст + цвет (`README.md:41`, `components.md:8`); цвета тонов фиксированы `TONES` (`models.js:11–17`).
18. Минимальная высота интерактивных элементов 44px для полей и primary-кнопок, 40px для вторичных, 34–36px для вспомогательных (см. размеры выше; `README.md:44`).

## 10. Открытые вопросы

1. **Формы у «Лотоса»**: `forms: []` → `formsVM` падает на `f.draft` (`:4421–4422, 4456`). Пустого состояния списка форм нет — нужно спроектировать («Форм пока нет» ⚠ не найдено в источниках) либо скрывать пункт меню.
2. **Приветствие по реальным часам** (`:4091`) при захардкоженной дате «Среда, 1 октября» (`:4095`) — e2e должен фиксировать время (Playwright `clock`) или проверять регулярным выражением.
3. **Просрочка** `due === '01.10' && priority === 'urgent'` (`:4363`) — суррогат; реальное правило сравнения дат ⚠ не найдено в источниках.
4. **Статус «Отменена»/«Отказ»** есть в `flow`, но не в `statuses` → на доске колонки нет, отменённая задача видна только в списке с чипом `TASK_TONE` (`models.js:124–126`). Нужно решить: колонка/фильтр «Отменённые».
5. **Прораб и чужой процесс**: задачи `leads`, назначенные на него, попадают в «Мои задачи» без проекта и отображаются по процессу `tasks` (пустые колонки, нет переходов) (`:4360–4361`). Нужен процесс по проекту задачи (`wfOf`) в UI, как на сервере (`models.js:137`).
6. **`ownerScope`** меняет только подпись области на «Главной», не фильтрует очередь и карточки (`:4093`).
7. **Источники SPA/ремонт в очереди** читаются без проверки `moduleOn` (`:4051–4052`); при отключённом модуле вопросы всё равно всплывут.
8. **Публикация/задачи при `restricted`**: `assertActive` не вызывается (`api.js:415–451`), хотя баннер обещает «Новые операции ограничены» (`:3085`). Нужно решить политику для форм и задач.
9. **Автор/дата версии** захардкожены «Дарья Зимина» / «01.10.2026» (`api.js:423`) — в реализации брать актёра и серверное время.
10. **Бейдж «Задачи»** считается по имени «Марина Котова» (`:2993`), а не по актёру; у владельца бейджа нет вовсе.
11. **`fm.listMax`** использует `state.w` окна вместо `W` рамки (`:2880`) — при «Ширина 390» на широком окне список остаётся 280px.
12. **Права**: прототип использует `tasks.manage` (`models.js:64`), каталог — `tasks.update` + `tasks.transition` (`11-permissions.yaml:58–59`); `forms.responses.create` отсутствует в каталоге, где есть `forms.create`/`forms.manage` (`:64–67`). `prototype_renames` (`:180–190`) этих пар не содержит.
13. **HTTP-адаптер** не содержит `publishForm`, `createTask`, `moveTask`, `toggleTaskCheck`, `commentTask` (`api.js:573–627`); OpenAPI-пути для форм/задач ⚠ не найдены в источниках (бэклог относит их к S3+, `13-backlog-s0-s2.md:139`).
14. **SQL-схемы** таблиц задач/форм/проектов в `docs/db/*.sql` ⚠ не найдены (есть только `scope_kind … 'project'` в `tenant_0001_core.sql:153`).

## 11. Факты для плана

1. Три страницы домена рендерятся одним шаблоном `<x-dc>` и тремя VM: `homeVM` (73 строки), `formsVM` + 3 помощника (115 строк), `tasksVM` (62 строки) — объём логики небольшой, основная работа — разметка и состояния.
