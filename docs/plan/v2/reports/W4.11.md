## Осталось fixme / открытые вопросы

Решения по умолчанию, принятые в коде (в `decisionsNeeded` — для `docs/plan/decisions.md`):

1. Доступ к проекту для описаний («Откуда доступ», «Что может», согласующие, «Проверить доступ», автор правила) считает модуль по грантам участников; совпадение с оценщиком держит `TestAccessParity` (10 акторов × 9 задач трёх уровней × 5 действий + строки `ScopeQuery`). Несколько ролей проекта складываются, имя — первой (Q-W4.01-10).
2. Участники — только активные члены организации; владелец — «Системная роль, вся организация», в «Людей» не считается; уведомление владельцам получает и сам действующий (как `owners()` эталона).
3. Дефект → задача: проект с процессом, чья область — подразделение машины или ближайший предок, при равенстве — старейший; иначе проект всей организации; нет проекта — задачи нет (очередь S2-17 работает как прежде). Исполнитель — назначенный дефекту, иначе владелец проекта. Тексты истории без эталона: «Создана по дефекту осмотра: {зона} — {описание}», «Решение по дефекту: {из} → {в}. Дефект признан некритичным — выезд разрешён» / «Неисправность подтверждена — машина недоступна»; описание задачи «{зона}: {описание}\nРейс {номер}. Выезд заблокирован до решения по дефекту.»
4. `listFiles`: вложения задач, которые участник не читает (закрытый проект без роли, TP-03), скрыты через `files.Hider` (`hiddenTasks` cmd/api).
5. `TaskPatch`: `null` и отсутствие поля для `assigneeMemberId`/`dueAt` не различаются (сгенерированный тип без nullable) — снять исполнителя или срок PATCH-ем нельзя.
6. Удалённое вложение только отвязывается от задачи (файл остаётся в `core.files`, корзины нет).
7. Текст `doc_route` без эталона: «Статус задачи меняется маршрутом документа — решения в «Документах»».
8. `removeTaskFile`: порядок MSW — If-Match (428/412) раньше вложения и права; отсутствующее вложение — 404 «Файл уже удалён» (возврат 1, `d405db06`).
9. `checkTaskProjectAccess`: `members.read` должно покрывать область проекта, и проект должен быть виден запросившему (иначе 404) — строже MSW.
10. `relatedObjects`/`customFields` при создании игнорируются (как MSW).
11. Тексты конфликта ревизии — по объекту: задача «Задачу уже изменили…», правило «Правило уже изменили…», проект и процесс — «Данные изменились. Обновите страницу и повторите.».
12. Строки матрицы «чужой id в теле → 422» (родитель, файл, сотрудник правила) формат YAML не выражает — их держат integration-тесты модуля; строки команд с If-Match — `tasks_w411_ifmatch_test.go`.
