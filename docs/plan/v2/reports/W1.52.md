## Вопросы и решения по умолчанию

- **Q-W1.52-1** (decisionsNeeded): статус карточки с истёкшим или отозванным приглашением — в enum `Member.status` нет `expired`. По умолчанию — `active` без `userId` (карточка без аккаунта, места не занимает — как у сервера). Альтернативы: `invited` (как MSW, но клиент посчитал бы место, которого у сервера нет); `suspended`; новое значение enum (правка контракта — стюард).
- Время истечения — по `now()` control DB, как места сервера (`freeSeats`), а не по часам приложения (`APP_FIXED_NOW`): статус и места не расходятся.

## Для интегратора

- `cmd/api` не тронут: `people.Server` без явного `Invitations` читает приглашения из control DB своего `kit.ControlDirectory`. Явное подключение (`Invitations: peoplemod.ControlInvitations{DB: control}` в `newAccessServer`) — по желанию.
- `updateMember` (W1.43, `access/assignments/members.go`) строит `Member` сам (`memberRow.apiStatus`): для карточки с действующим приглашением ответ PATCH — `active`, а отказ смены статуса — «У сотрудника нет аккаунта…» вместо «Участник ещё не принял приглашение.» (как MSW). Вне границ W1.52; `invitations.Pending` экспортирован — follow-up владельцу `access/assignments`.
- Клиент (W1.23 и адаптер): места — `invited` без условия на `userId` + `active` с `userId`; MSW `seatsUsed` требует `userId` и у приглашённого — на сервере его нет. Владельцу адаптера — либо оставить `userId` в MSW и учесть, что сервер его не отдаёт, либо убрать условие из `seatsUsed`.
- Индекса `invitations (tenant_id, person_profile_id)` нет; `Pending` — один запрос на страницу по `tenant_id` и списку профилей (таблица маленькая). Если понадобится — миграция стюарда.
- Новых зависимостей нет; корневой `package.json` не менялся.
