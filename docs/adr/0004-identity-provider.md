# 0004. D-03 · Провайдер входа (IdP)

Статус: предложено
Дата: 2026-10-15 · Автор: агент W0.01 · Участники: архитектор, security, DevOps, backend lead
Решение комплекта: D-03 (`design/docs/16-raid-glossary.md`, «Решения, нужные для старта»)
Кто решает: Архитектор, security
Блокирует: S1-05 (шаг 1.3) по 16; в плане v2 — W1.03 (BFF с OIDC), W1.22 (экраны входа), профиль `keycloak` стенда W0.06
До решения агенты работают по рекомендации (план v2 §2, B-2).

## Контекст

- S1-05: BFF с OIDC Code + PKCE, HttpOnly cookie, CSRF, Origin, logout. S1-06: принятие приглашения (токен → проверка email → membership). Шаг 3.3: MFA для владельцев и операторов до пилота.
- `14-engineering.md`, «Стек»: «Keycloak, общий realm клиентов + отдельный **клиент** операторов», а 16 предлагает отдельный **realm** операторов — документы комплекта расходятся.
- R-09: Keycloak — отдельная эксплуатационная нагрузка (JVM, обновления, резервирование).
- Решения плана PD-18 и PD-41 («Keycloak не в фазе 1») противоречат плану 27: OIDC в этапе 1. Dev-провайдер остаётся только для local и e2e (план v2 §3.6).
- Аккаунт глобален, участие — в бизнесе (`account` / `membership`, глоссарий 16): IdP хранит только аккаунт, права — в Ортусе.

## Варианты

1. **Keycloak (self-hosted), общий realm клиентов, отдельный realm операторов** — плюсы: OIDC, PKCE, MFA, политики паролей и брутфорс-защита без кода, размещение в контуре D-05, разделение операторов на уровне realm; минусы: эксплуатация JVM-сервиса (R-09), тема входа под бренд — отдельная работа. Цена: профиль compose и realm-экспорт (W1.03), сопровождение.
2. **Keycloak, один realm и отдельный клиент операторов** (`14-engineering.md`) — плюсы: проще конфигурация; минусы: операторы и клиенты делят политики и пользователей realm, ошибка конфигурации даёт оператору вход в клиентский контур. Цена: та же.
3. **Управляемый OIDC-провайдер облака из D-05** — плюсы: нет эксплуатации; минусы: зависимость от провайдера, ограничения брендирования и MFA, перенос пользователей при смене облака. Цена: интеграция и проверка функций провайдера.
4. **Свой вход в BFF (пароль + TOTP)** — плюсы: полный контроль; минусы: безопасность хранения паролей, восстановления, брутфорса — на команде. Цена: высокая, не рекомендуется.

## Решение

Рекомендация: «Keycloak, общий realm клиентов, отдельный realm операторов» (вариант 1). Расхождение с `14-engineering.md` («отдельный клиент операторов») решающий закрывает этим ADR; до решения W1.03 делает отдельный realm — из него проще перейти к клиенту, чем наоборот.

## Последствия

- Проще: MFA (3.3), сброс пароля, политика сессий — настройками; приглашение — через ссылку Ортуса и регистрацию в realm.
- Сложнее: Keycloak в стенде (≈ 1 ГБ памяти) — только профилем `keycloak` compose; e2e агентов — через dev-провайдер, Keycloak-smoke гоняет интегратор (план v2 §3.6).
- Сделать: W0.06 — профиль `keycloak`; W1.03 — realm-экспорт с двумя realm, BFF; W3.03 — MFA. `OIDC_REDIRECT_URL` — один origin (ADR-0001).
- Как проверим: Keycloak-smoke на стенде (вход, logout, CSRF без токена → 403); оператор не входит через клиентский realm.
