## 1. Цель

1. **Шлюз WebSocket** `GET /api/v1/realtime` (ADR-0015, вариант 1) — `http.Handler` пакета `backend/internal/platform/notify/realtime`, который `cmd/api` монтирует рядом с генерируемым `router.go`:
   - проверка `Origin` при апгрейде — точное совпадение с `ALLOWED_ORIGINS` (CSWSH), иначе 403 `origin_not_allowed` до апгрейда; подпротокол `ortus.realtime.v1` обязателен (иначе 400 `malformed_request`);
   - первый кадр — `{"type":"auth","ticket":…}` не позже 10 с, иначе закрытие с кодом **4401**; билет одноразовый, 60 с, привязан к сессии и аккаунту, в URL и журналы не попадает;
   - кадры сервера — только подсказки без данных (`context.changed`, `notifications.changed`, `session.ended`, `ping`) с `seq` на соединение и `at`; потерянная подсказка — разрыв `seq` (клиент перечитывает всё);
   - heartbeat: `ping` каждые `heartbeatSeconds`, нет `pong` за два интервала — закрытие; на каждом такте сверка сессии: сессия удалена — `session.ended` `logout`, истекла — `expired`, затем закрытие;
   - ограничение очереди на соединение (переполнение — пропуск подсказки с разрывом `seq`), лимит соединений на аккаунт, лимит размера входящего кадра, снятие дедлайнов `http.Server` с перехваченного соединения, закрытие всех сокетов при остановке `cmd/api`.
2. **Билеты** — интерфейс `Tickets` (выдать / погасить) и реализация в памяти `MemTickets` (хранится только SHA-256 билета, срок по часам `Clock`, одноразовость, ограничение размера). Операцию `createRealtimeTicket` в BFF подключает W1.03 (ADR-0015 «Нужно сделать»), ответ строит `TicketResponse`.
3. **`policy_version` и событие отзыва:** `BumpPolicy` — в транзакции изменения прав увеличивает `access.policy_state.policy_version` и пишет в outbox `access.policy.bumped.v1` (`personIds` затронутых, пусто — все участники). Вызывают все команды, меняющие роли, назначения, группы, модули (W1.06, W1.08, W2.07, W4.x).
4. **Ретрансляция в `cmd/worker`:** `Relay` — обработчик outbox `access.policy.bumped.v1`: люди организации → аккаунты по `memberships` **этой** организации control DB → `pg_notify('ortus_realtime', …)` подсказкой `context.changed` (пачками до лимита 8000 байт). `Relay.HintPersons` — тот же путь для `notifications.changed` (W1.10).
5. **Слушатель в `cmd/api`:** `Listener` — `LISTEN ortus_realtime` на выделенном соединении control DB, разбор подсказки → `Hub.Deliver` + инвалидация кеша; при обрыве — переподключение с паузой и **ресинхронизация** (всем соединениям `context.changed` и `notifications.changed`, кеш прав сброшен: пропущенные уведомления не теряются молча).
6. **Кеш прав с инвалидацией по `policy_version`:** `PolicyCache` — декоратор `authz.Source` (W1.04): субъект (функции и гранты) и подключённые модули переиспользуются, только пока `policy_version` организации не изменился и запись моложе `MaxAge` (1 с) по часам `Clock`; версия сверяется на **каждой** проверке (`VersionMaxAge = 0` по умолчанию) или кешируется не дольше `VersionMaxAge` с немедленной инвалидацией по подсказке. Новые запросы после транзакции отзыва блокируются сразу (AC-10), гранты, у которых кончился период, — не позже `MaxAge`.
7. **Отзыв ≤ 5 с (S1-15, `02-architecture.md` «Revocation»):** сервер — сразу после коммита; интерфейс — outbox (опрос worker ≤ 1 с) → `pg_notify` → шлюз → `context.changed` ≤ 5 с. Тест со временем через `Clock` (кеш, билеты, сессии) и сквозной integration-тест с замером.
8. **Изоляция:** подсказка уходит только аккаунтам, чьё членство в **той же** организации связано с затронутыми людьми; одинаковый `person_profile_id` в другой организации, чужой аккаунт и другой аккаунт той же организации подсказку не получают; билет одного аккаунта не открывает канал другого.
