# Квоты пилота: 100 мест и 100 ГБ — порядок действий оператора

WS W2.48 · решения D-08 (ответ владельца продукта 17.10, [ADR-0009](../../adr/0009-pilot-load-profile.md)) и D-33 · версия 18.10.2026.

Профиль пилота (D-08): 60 машин, 80 сотрудников, до 60 человек одновременно. Пробный тариф `start` даёт 10 мест — пилоту этого мало. Поэтому оператор вручную ставит 100 мест и 100 ГБ. Тарифов и мест в пилоте нет (D-33): подписку активирует оператор, а лимит мест (`seats`) и подсчёт занятых мест остаются.

Порядок проверен на стенде: `frontend/apps/web/e2e/journeys/pilot/pilot-quotas.spec.ts` (`@stand`). Шаги spec — помощники `journeys/pilot/quotas.ts`. Шаг 2 spec выполняет фрагмент из этого документа дословно: он читает блок `js` ниже и меняет только три значения в начале. Правка фрагмента сразу проверяется на стенде.

## 1. Что ставится и где это видно

| Квота | Значение | Где хранится | Кто её применяет | Где видно |
|---|---|---|---|---|
| Подписка | `active` до конца пилота | control DB: `subscriptions` | шлюз: после конца срока — `grace` на 7 дней, затем только чтение (PLAT-05) | оператор: чип организации, «Оплата»; владелец: карточка статуса на «Модули и место» |
| Места | 100 | control DB: `entitlements`, ключ `seats`, `sourceType: manual` | приглашение, импорт людей, возврат участника: сверх лимита — 409 `seats_exhausted` | оператор: «Места с входом: — из 100»; владелец: «Пригласить участника» → «Свободно мест: N из 100» |
| Место (запись оператора) | 100 ГБ = 100 ГиБ = 107 374 182 400 байт | control DB: `entitlements`, ключ `storage_quota_bytes`, `manual` | никто (см. ниже) | оператор: «Место: — из 100 ГБ» |
| Место (лимит организации) | 100 ГБ | tenant DB: `files.usage.limit_bytes` | загрузка файла: сверх лимита — 409 `quota_exceeded`; баннер «место заполнено» | владелец: «Модули и место» и «Хранилище» — «из 100 ГБ» |

Что есть до шагов оператора:

- Новая организация на пробном тарифе `start` получает 10 мест и 100 ГиБ (`subscriptions.DefaultQuotaBytes`).
- Лимит места организации `files.usage` по умолчанию тоже 100 ГиБ.
- 5 ГиБ из `02-architecture.md` §11 — гипотеза дизайна, в коде её нет.

Значит, без оператора пилот упирается только в места: 80 сотрудников при 10 местах.

**Две записи места не связаны (Q-W2.48-1).**

- Ручное право оператора `storage_quota_bytes` не меняет `files.usage.limit_bytes`.
- Смена лимита владельцем не меняет право оператора.

Поэтому шаг 4 проверяет лимит у владельца. Если лимит не 100 ГБ, его ставит владелец. Это проверено на стенде: лимит организации 50 ГБ остался 50 ГБ и после записи оператора.

«ГБ» в интерфейсе — гибибайты: 100 ГБ = 100 × 2³⁰ байт, как подписи «Хранилища» и MSW `DEFAULT_QUOTA`.

## 2. Что нужно заранее

1. Организация создана, владелец вошёл. Создание — `createPlatformTenant`, только через API: кнопки в интерфейсе нет (Q-03).
2. У оператора есть права:
   - «Видеть подписки» (`platform.billing.read`);
   - «Рассматривать заявки, менять подписки и лимиты» (`platform.billing.manage`), причина обязательна.
3. Известны:
   - дата конца пилота — последний день по Москве;
   - основание: номер договора или обращения.

## 3. Порядок

### Шаг 1. Оператор: найти организацию

1. Войти в «Ортус · Платформа» и открыть «Организации-клиенты».
2. Выбрать организацию. Карточка до изменения: «Места с входом: — из 10», «Место: — из 100 ГБ».

### Шаг 2. Оператор: поставить подписку и квоты

В этапе 1 нет формы правки подписки. В интерфейсе оператора три команды: продлить пробный период, ограничить, снять ограничение (Q-W2.48-2).

Квоты ставит запрос `updatePlatformSubscription` из той же вкладки оператора. Он идёт с cookie-сессией, `X-CSRF-Token`, `Idempotency-Key` и `If-Match`.

1. Открыть консоль браузера: F12 → Console.
2. Вставить фрагмент и поправить три значения в начале.
3. Нажать Enter.
4. Ответ `200` и подписка с правами — готово.

```js
// Квоты пилота (W2.48, D-08): 100 мест и 100 ГБ до конца пилота.
const ORG = 'Название организации'; // как в списке «Организации-клиенты»
const UNTIL = '2027-01-31T21:00:00Z'; // конец пилота: 21:00 UTC = конец дня по Москве (здесь — 31.01.2027)
const TICKET = 'Пилот D-08 · договор № …'; // основание ручных прав
const GiB = 2 ** 30;
const csrf = decodeURIComponent(/(?:^|;\s*)ortus_csrf=([^;]+)/.exec(document.cookie)?.[1] ?? '');
const list = await (await fetch('/api/v1/platform/tenants?limit=200', { credentials: 'include' })).json();
const org = list.items.find((t) => t.name === ORG);
if (!org) throw new Error(`нет организации «${ORG}»`);
const url = `/api/v1/platform/tenants/${org.id}/subscription`;
const cur = await fetch(url, { credentials: 'include' });
const sub = await cur.json();
const right = (key, value) => ({ key, sourceType: 'manual', sourceRef: TICKET, value, validUntil: UNTIL });
const day = new Date(Date.parse(UNTIL) - 1).toLocaleDateString('ru-RU', { timeZone: 'Europe/Moscow' });
const body = {
  planKey: sub.planKey, // тариф прежний
  status: 'active', // D-33: подписку пилота активирует оператор
  periodEndsAt: UNTIL,
  cancelAtPeriodEnd: false,
  manualEntitlements: [
    ...sub.entitlements.filter(
      (e) => e.sourceType === 'manual' && !['seats', 'storage_quota_bytes'].includes(e.key),
    ),
    right('seats', 100),
    right('storage_quota_bytes', 100 * GiB),
  ],
  reason: `${TICKET}: 100 мест и 100 ГБ до ${day}`, // 5–500 символов, видна в «Журнале действий»
};
const r = await fetch(url, {
  method: 'PUT',
  credentials: 'include',
  headers: {
    'Content-Type': 'application/json',
    'X-CSRF-Token': csrf,
    'Idempotency-Key': crypto.randomUUID(),
    'If-Match': cur.headers.get('ETag'),
  },
  body: JSON.stringify(body),
});
const result = { status: r.status, body: await r.json() };
console.log(result.status, result.body);
```

Что делает запрос:

- **Тариф.** Тариф прежний, его права (`plan` или `trial`) остаются в подписке. Ручное право скрывает право тарифа того же ключа (W1.08).
- **Срок.** У ручных прав срок обязателен. Он равен концу пилота, как `periodEndsAt` подписки.
- **Другие ручные права** подписки фрагмент сохраняет.
- **Журнал.** В «Журнале действий» видна только причина, значений прав там нет. Поэтому причина называет квоты и срок.

### Шаг 3. Оператор: проверить

Перезагрузить «Организации-клиенты» и выбрать организацию:

- «Места с входом: — из 100»;
- «Место: — из 100 ГБ»;
- «Оплата: Оплачено до <последний день пилота>». Подпись этапа 1: оплаты в пилоте нет (D-33).
- «Журнал действий»: первая строка — с причиной шага 2.

### Шаг 4. Владелец: проверить и при необходимости поставить лимит места

Вместе с владельцем (или по его снимку экрана):

1. «Модули и место» → «Место организации»: «… из 100 ГБ».
2. «Хранилище» → «Место организации»: «… из 100 ГБ».
3. Если на «Хранилище» не 100 ГБ (лимит меняли раньше), владелец ставит лимит сам (Q-W2.48-1):
   1. «Новый лимит» — «100 ГБ».
   2. «Рассчитать».
   3. «Применить».
   4. Тост «Лимит места: 100 ГБ».

   Строка расчёта может показать цену («Лимит 100 ГБ · 1 000 ₽ в месяц», 10 ₽ за ГиБ, W1.09). В пилоте её не взимают (D-33, Q-W2.48-5).
4. «Пользователи и роли» → «Пригласить»: «Свободно мест: N из 100». N — 100 минус занятые места: участники с входом и приглашённые.

### Шаг 5. Продление и конец пилота

- **Продление.** Повторить шаг 2 с новой датой `UNTIL`: подписка и ручные права получат новый срок.
- **Конец пилота без продления.** Когда наступает `periodEndsAt`, подписка переходит в `grace` на 7 дней, затем в «только чтение». Этим управляет фоновый цикл `cmd/api`: в `prod` — каждую минуту, в dev и e2e — выключен (`SUBSCRIPTION_SWEEP_INTERVAL`).
- **Места после срока.** Ручные права истекают в тот же момент, места возвращаются к 10 тарифа. Новые приглашения — 409 `seats_exhausted`, участники с входом остаются.
- **Место после срока.** Лимит `files.usage` не меняется (Q-W2.48-1).

## 4. Откат

Вернуть подписку, как была:

1. GET подписки (`getPlatformSubscription`), ETag.
2. PUT с прежними значениями:
   - `planKey`, `status` и срок этого статуса (`trialEndsAt`, `periodEndsAt` или `graceEndsAt`);
   - `manualEntitlements` без `seats` и `storage_quota_bytes`;
   - причина — почему откат.

Так возвращает подписку уборка spec (`putSubscription` из `e2e/_stand/stand.ts`). Лимит места владелец меняет на «Хранилище».

## 5. Ответы, кроме 200

| Ответ | Причина | Что делать |
|---|---|---|
| 412 `revision_mismatch` | подписку изменили между GET и PUT | выполнить фрагмент ещё раз: он читает свежий ETag |
| 428 `revision_required` | нет `If-Match` | фрагмент запущен не целиком |
| 422 `validation_failed` | `detail` — «Неверные поля: …» или «Укажите причину изменения.». Поля: `reason` (5–500 символов), `manualEntitlements` (нет срока, основания или `sourceType: manual`), `status` (в пилоте нельзя `past_due`, `cancelled`), `cancelAtPeriodEnd`, `planKey` | поправить значение |
| 403 | у оператора нет `platform.billing.manage` или сессия не оператора | войти оператором с правом |
| 404 | организации нет | проверить `ORG` |
| `нет организации «…»` | имя не совпало со списком | скопировать имя из «Организации-клиенты» |

## 6. Проверка на стенде

`pilot-quotas.spec.ts`, две строки на трёх проектах:

1. Оператор ставит «Альте» квоты пилота. Проверяются:
   - карточка оператора и журнал;
   - «из 100 ГБ» на «Модули и место» и «Хранилище»;
   - квота «Хранилища» равна праву оператора;
   - «Свободно мест: N из 100» и `seats = 100` в `getTenantSubscription` владельца;
   - возврат подписки.
2. Лимит места организации был 50 ГБ. После квот оператора он остаётся 50 ГБ. Владелец ставит 100 ГБ на «Хранилище» (шаг 4 п. 3), итог — «из 100 ГБ» на обеих страницах.

Пилотной организации в сиде нет, поэтому строки идут на «Альте». Подписку и лимит места возвращает фикстура `undo`.

Строки меняют общую подписку «Альты», поэтому запуск — в один поток, как `e2e-stand` в CI. Например:

- весь прогон: `node tools/ci/e2e-stand.mjs --slot N`;
- только этот spec: `playwright test e2e/journeys/pilot --workers=1` с окружением stand.
