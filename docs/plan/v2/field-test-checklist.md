# Чек-лист полевого теста: камера, загрузка фото и офлайн на телефонах водителей (S2-19)

Подготовил W2.31 19.10.2026. История — S2-19 «Матрица устройств для камеры и офлайна, ранний полевой тест» (`docs/plan/v2/stories-s2-17-19.md`), риск R-04 комплекта: камера и офлайн в PWA ведут себя по-разному на iOS и Android. ADR-0010 требует проверить офлайн-сдачу в поле.

Тест проводят люди: водители пилота или команда с их телефонами. Агент подготовил этот чек-лист. После теста агент сводит результаты по разделу 8. Результат нужен до выхода этапа 2. Найденные дефекты идут в приоритеты этапа 3 (S2-19 п. 4).

Автоматическая часть — Playwright-проекты устройств `devices-*` (раздел 9). Они эмулируют экраны и сеть, но не заменяют настоящую камеру, Safari, сотовую сеть, выгрузку вкладки из памяти и установку PWA.

## 1. Матрица устройств

Нужно минимум четыре телефона: два Android с Chrome и два iPhone с Safari. В каждой паре один телефон — на текущей версии ОС, второй — на предыдущей. Хотя бы один iPhone должен быть с шириной экрана 390 pt (iPhone 12–14, 16e). Лучше брать телефоны самих водителей пилота, а не флагманы команды.

## 2. Подготовка

1. **Стенд по HTTPS.** Камера через браузер, service worker и установка PWA работают только по `https://`. Локальный адрес `http://<ip>:5173` для теста не годится. Адрес стенда, учётную запись водителя и сид выдаёт интегратор (вопрос Q-W2.31-1). По умолчанию: сид показа, организация «Альта Групп», водитель «Илья Васильев», рейс «Р-208 · Северный маршрут».
2. Телефон заряжен больше чем на 50 %. Записать заряд в начале.
3. Данные сайта стенда очищены. Android: Chrome → Настройки сайтов → Хранилище. iOS: Настройки → Safari → Дополнения → Данные сайтов. Старые установленные иконки «Ортус» удалены.
4. Выбраны три места связи:
   - хорошая связь — 4G/5G или Wi-Fi;
   - слабая — подвал, парковка, край зоны покрытия;
   - без связи — режим полёта.
5. В одной вкладке телефона работает только один пользователь. Выход через меню «Выйти» удаляет неотправленное без предупреждения (Q-W2.24-5). Поэтому выходить можно только после шага 12.
6. Секундомер. Время загрузки считается от снимка до статуса «Загружено».
7. Для запуска приложения есть два варианта. На Android используется установленное приложение (шаг 1). На iPhone один проход делается в Safari, а второй — с иконки «На экран «Домой»»: у установленного PWA на iOS своё хранилище, и камера работает иначе.

## 4. Что фиксировать на каждом телефоне

- Время каждой загрузки фото: хорошая и слабая связь. Медиана и максимум.
- Повторы: сколько раз пришлось нажимать «Повторить», сколько раз снимать заново.
- Потери черновиков: что пропало после перезапуска (шаг 8), выгрузки из памяти (шаг 16) и смены сети.
- Задвоения: два расхода, две сдачи, лишние фото (менеджер видит их в «Приёмке смен»).
- Все тосты и сообщения об ошибках — дословно, со снимком экрана.
- Сеть: оператор, тип (4G/5G/Wi-Fi), уровень сигнала в слабом месте.
- Заряд батареи в начале и в конце. Нагрев телефона, если заметен.
- Общее время смены от брони до «Ожидает приёмки менеджером».

## 7. Проведение

1. Один проход по разделу 3 на каждом телефоне матрицы. На iPhone — два прохода: в Safari и с установленной иконки.
2. После каждого телефона заполнить столбец бланка. Снимки экранов и записи передать файлами в задачу полевого теста. В репозиторий файлы не кладутся: снимки содержат данные пилота.
3. Если найден блокер (не уходит сдача, пропал черновик, задвоился расход), тест на этом телефоне не останавливать: записать шаг, время и идти дальше.

## 8. Сведение результатов (агент)

1. Заполненные бланки сводятся в `docs/plan/v2/field-test-results-<дата>.md`: матрица «телефон × шаг», медиана и максимум времени загрузки, список потерь и задвоений.
2. Каждое отклонение — запись с телефоном, шагом, дословным текстом и ссылкой на снимок. Классы:
   - **блокер** — сдача или расход не дошли, потерян черновик, данные задвоены;
   - **major** — нужен обход, подпись не та, лишний шаг;
   - **minor** — косметика.
3. Блокеры и major идут в приоритеты этапа 3 (S2-19 п. 4). Вопросы, меняющие поведение, — в `docs/plan/decisions.md` через интегратора.
4. Расхождения, которые воспроизводятся эмуляцией, становятся новыми строками в `frontend/apps/web/e2e/devices/` (red-тест до исправления).

## 9. Автоматическая часть (Playwright, режим mock)

Проекты устройств описаны в `frontend/apps/web/e2e/devices/projects.ts`, spec — в `e2e/devices/*.spec.ts`. Проекты 390/768/1440 эти spec не запускают.

```powershell
$env:ORTUS_SLOT='1'; $env:E2E_OWN_REFERENCE='1'; $env:E2E_FRESH_SERVER='1'
corepack pnpm --filter @ortus/web exec playwright test e2e/devices --project="devices-*"
# iPhone на настоящем движке WebKit (нужен `playwright install webkit`):
$env:E2E_DEVICES_WEBKIT='1'; corepack pnpm --filter @ortus/web exec playwright test e2e/devices --project="devices-iphone-*"
```

Что проверяет каждый телефон матрицы:

- профиль: касание, `pointer: coarse`, геолокация не выдана и не запрашивается;
- камера: `input accept="image/*" capture="environment"`. Кадр 12 Мп (фальшивая камера Chromium, на WebKit — холст) с GPS уходит JPEG ≤ 1600 px без геоданных, все пять ракурсов;
- сбой загрузки и «Повторить»;
- офлайн-черновик осмотра и расход на устройстве;
- медленная сеть: одна команда при двойном касании;
- путь водителя целиком;
- манифест PWA. На Chromium дополнительно — `Page.getInstallabilityErrors` без ошибок.

Масштаб 200 % (окно 1280×800, CSS 640×400): нет прокрутки вбок, команды не закрыты, axe без serious/critical.

Чего эмуляция не покрывает и что поэтому проверяется только в поле:

- настоящая камера и выбор «Снять фото» / «Медиатека»;
- HEIC с iPhone;
- выгрузка вкладки из памяти;
- сотовая сеть и переключение сетей;
- установка PWA на iOS;
- ITP Safari;
- крупный системный шрифт;
- офлайн на WebKit: при эмуляции без связи Playwright WebKit не читает и выбранный файл, поэтому строка «офлайн» на WebKit пропускается.
