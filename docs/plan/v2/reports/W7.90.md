## Сделано

Три отдельных сквозных пути @stand в `frontend/apps/web/e2e/journeys/stage7/`, каждый проходит на трёх ширинах проекта (390 / 768 / 1440), своё имя на прогон (метка проекта и времени), сидовые данные не меняются, роли и назначения снимает уборка.

1. `chats.spec.ts`. Владелец «Альты» выдаёт логисту (модератор) и водителю роли с действиями чатов (посева ролей чатов нет, Q-W7.11-21), «Что изменится» (`dryRun`) не создаёт чат, затем создание рабочего чата и состав из источников. Лента с нумерацией подряд, «Важное» только модератору (`chat_content_forbidden` у водителя) и «Ознакомлен», опрос (голос, закрытие, голос после закрытия — отказ), непрочитанные и `markChatRead`, правка автором и история версий, чужую правку отказ 403, удаление модератором с причиной (в ленте остаётся пометка, текст пуст), закрепление, задача из сообщения, политика вида (`dryRun`), хранение, очистка (`dryRun`), юридическая блокировка и её снятие, архив закрывает отправку. Страница «Чаты» у водителя: чат в списке, без горизонтальной прокрутки.
2. `docs.spec.ts`. Текстовый документ в папке сида, переименование по If-Match (без него отказ), именованная версия и восстановление, комментарий с упоминанием, доступ списком (`dryRun`, затем запись), внешняя ссылка с ПИН (неверный ПИН и отозванная ссылка — отказ, верный — открывается без сессии), задание PDF в очереди, маршрут: `dryRun`, запуск, возврат без комментария (422), возврат с причиной, отмена, повторный запуск, согласование (автор не ждёт сам себя в «Ознакомить» — маршрут завершён), `ackDocument` без запроса — 422, запрос кода подписи без повторного входа — отказ зависимости, журнал действий, архив. Страница документа открывается по `?doc=`.
3. `service.spec.ts`. Клиент без входа: страница направления «Массаж», без согласия 422, неизвестное направление 404, обращение и личная ссылка. Сотрудник: обращение в очереди направления, маска телефона и явное открытие, публичный ответ виден клиенту, заметка нет, исполнитель/приоритет по If-Match, задача, компенсация, пауза «Ждём клиента» (подпись клиента «Ждём вашего ответа»), ответ клиента возвращает в работу, решение без итога 422, вывод по сотруднику для обращения не о сотруднике — 422, оценка клиента (9 — 422, повторная — отказ), повторное открытие, перенос в «Грузоперевозки» (новый номер, старый в `oldKeys`, ссылка клиента ведёт на новый), создание «по звонку», отчёт, оценки. Страница «Обращения» открывается без горизонтальной прокрутки.

## Найденные дефекты и вопросы (`Q-W7.90-N`, в `decisions.md` вносит интегратор)

- **Q-W7.90-1 (дефект W7.23, вне моих каталогов).** `createDocComment` без `mention` отвечает 503 `dependency_unavailable`: в `backend/internal/modules/docs/comments.go` пустое упоминание пишется как `NULL` в `docs.comments.mention` (`not null`), в логе `null value in column "mention" ... (SQLSTATE 23502)`. Правка в одну строку: передавать `[]uuid.UUID{}` вместо `nil` (и то же в `ReplyComment`, строка около 153). Путь комментирует с упоминанием (работает). Значение по умолчанию: пока дефект не исправлен, комментарии без упоминания на стенде недоступны. Пропуск (`test.fixme`) не добавлял — пропуск в `e2e:stand` красный.
- **Q-W7.90-2.** Посева ролей чатов нет (Q-W7.11-21): путь выдаёт роль сам (создание роли и назначение, уборка в конце). Нужен посев шаблонов `chat_*` организациям и роли «Участник чатов» в сиде «Альты», тогда путь использует сидовые роли.
- **Q-W7.90-3.** На стенде раздел «Документы» открыт только владельцу (нет ролей документов у остальных), поэтому «Ознакомить» с автором как единственным адресатом закрывается сразу, а шаги «Утвердить · ПЭП» недоступны (dev-вход без повторного входа, 503). Нужен сид роли «Делопроизводитель/Сотрудник» с `docs.*` и стенд подписи, тогда путь добавляет ознакомление другим сотрудником и подпись.
- **Q-W7.90-4.** «Вывод по сотруднику» (`shareServiceConclusion`) проверен только отказом 422 «Обращение не касается сотрудника»: в сиде нет обращения «о сотруднике», которое можно решать без изменения общих данных. Нужна сидовая жалоба на сотрудника или публичный тип с привязкой сотрудника.
- **Q-W7.90-5.** Строки `@stand` страниц «Чаты» (`chat.spec.ts`: `test.fixme` «backend чатов — W7.11, ещё не в main») устарели: backend влит. Размораживает владелец страницы (W7.13).
- Задание PDF проверено только постановкой в очередь: программ задач документов (`ocrmypdf`, `qpdf`, `soffice`) на стенде нет (предупреждение воркера), итог не ждётся.
