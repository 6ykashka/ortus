## 10. Риски и решения по умолчанию

- Доступ к узлам решает модуль: перенос `kbAccess` домена на снимке БЗ организации (пространства, узлы, люди, роли, назначения, группы, функции, подразделения) — одна транзакция чтения на запрос. Предикат `scopeQuery` строкам БЗ не подходит (цепочка домена с функцией, сроками и списками), видимость фильтруется в коде, как у календаря W4.40.
- Q-W4.00-knowledge-15: роль с областью «своё» (`self`) с `knowledge.read` читает открытые и ограниченные пространства всей организации (как домен и MSW; шлюз `knowledge-space-node` её пускает).
- Q-W4.04-1: модуля «Ремонт и стройка» до этапа 6 нет — у правила `section` пустой список объектов, `runKnowledgeSection` — 404 «Объект не найден»; связь «прораб объекта» никого не охватывает (порт `Relations` для этапа 6). Раздел «ЖК Речной · квартира 42» в сиде есть (как в домене), прорабу он виден после этапа 6 (в MSW — уже сейчас, объекты эталона в срезе).
- Q-W4.04-8: смена области пространства — `knowledge.spaces.manage` роли, покрывающей новую область, или владелец бизнеса, и только когда область меняется (по описанию операции, MSW — только владелец).
- Q-W4.04-6: «Утвердить» — шлюз `knowledge.publish` и право правки узла; перенос — шлюз `knowledge.organize`, право правки узла и создания в новом родителе.
- §5 п. 25: дубль названия у `createKnowledgePage` ищется только среди видимых страниц.
- Порядок сотрудников (карта, влияние, «по уровню», кандидаты) — по ФИО (в БД нет порядка прототипа); пространств — по созданию (сид пишет время создания по порядку эталона); ролей-кандидатов — по названию.
- Время версий, журналов, запросов — моменты UTC часов приложения (`APP_FIXED_NOW` вне prod); «сегодня» для сроков пересмотра — дата по Москве.
- Узел «Файл» сида: строка `files.objects` (`knowledge_attachment`), подпись размера — из `bytes`, число страниц — параметр `pages` типа (`application/pdf; pages=4`).
- `CompleteInTx` идемпотентности не используется (как календарь W4.40): ответ сохраняет шлюз идемпотентности.
