## Сделано

- **`backend/internal/platform/authz`** — оценщик (покрытие 94,7 % с integration, 97,7 % без `pg.go` — unit):
  - `Permit(ctx, tc, action, Resource)` — `permit(c,a,r,t)` 02-architecture §5: **каждый grant целиком** (действие ∈ версия роли, вид области зарегистрирован, область покрывает ресурс, параметры гранта допускают ресурс, период содержит «сейчас» часов приложения). Отказ: `function_blocked` (действие закрыто функцией, `blocked_by_function`), `forbidden_action` (объекта нет; объект виден субъекту через `Resource.ReadAction`, но действия на нём нет; `owner_only` у не-владельца; правило действия), `not_found` (объект не виден — как несуществующий, AC-01). Владелец — все действия, кроме закрытых его функцией; правила действия действуют и на владельца, список доступа объекта — нет;
  - `Admit(ctx, tc, Operation)` — допуск шлюза: грант засчитывается, только если `x-scope` операции допускает вид его области (таблица `xScopes` на все 22 tenant-значения `x-scope` каталога, тест полноты); `all`/`any`; `x-scope tenant-owner` — только владелец. `Gateway` — адаптер к `tenantctx.Authorizer` (`Permit` без `x-scope` — только область организации) и `Admit`;
  - `ScopeQuery(ctx, tc, action, Columns, argStart)` — OR предикатов целых разрешающих грантов, до пагинации и счётчиков; владелец `true`, закрытое функцией и `owner_only` — `false`; объектный вид без колонки — `false` (PD-53); `ACLPredicate` списка доступа сужает предикат всех, кроме владельца;
  - `Capabilities(ctx, tc)` — `/me/context`: владелец — действия ядра и подключённых модулей без закрытых функцией (как MSW W0.13: 59 у владельца «Альты», П-14), участник — действия действующих грантов с их областью без закрытых функцией и `owner_only`;
  - `Explain(ctx, tc, action, Resource)` — решение и причина по каждому гранту в терминах `GrantExplanation.mismatch` контракта (`out_of_scope`, `other_object`, `object_scope_without_object`, `function_blocked`) — ядро `explainAccess` W1.06;
  - **реестр видов** `NewRegistry`/`PilotKinds` (явный, без `init()`): `tenant`, `unit` (поддерево через `org.unit_closure`, `Descendants`), `self`, объектные `project`, `warehouse`, `resource` (PD-53); `FutureKinds` — `space`, `page` (W4.01), `account` (W5.00), `repair_object` (W6.00), `folder`, `doc`, `chat`, `relation`, `service_direction` (W7.00). Соответствие контракту: `unit ↔ org_unit`, `resource ↔ resource_pool`;
  - **хуки** (интерфейсы + реализации пилота): `ObjectACL` (+`ACLPredicate`; `InheritedACL`), `GrantParam` (`LimitAmount` — `limit: amount`), `Rule` (`NotAuthor`), `owner_only` и `blocked_by_function` — из `Policy` (таблицы с тестом дрейфа против `api/permissions.yaml`);
  - `PGSource` — `Source` и `UnitTree` поверх `tenantctx.Pools`: гранты (прямые и через группы, живые роли, `valid @> $at`), функции (`work_profiles.valid @> $at`), подключённые модули, предки подразделения. Время — **часы приложения**, не `now()` базы (Q-W0.09-11). Кеша нет: отзыв роли действует со следующей проверки (AC-10).
- **`backend/internal/platform/scopeddb`** — `For`, `Query`, `QueryRow`, `Exec`, `One`, `InTx`: предикат `ScopeQuery` встаёт на место `{{scope}}` (ровно одного, иначе `ErrNoScope`), аргументы нумеруются после аргументов запроса; `One` — «нет строки» → `not_found`, чужой и несуществующий id идут одним запросом (AC-01).
- **`backend/cmd/api`** (по карточке: «env.Clock в cmd/api», П-14): шлюз вызывает `Admit` с `x-scope` операции (`gate.go`, необязательный интерфейс `operationAdmitter`), `/me/context` получает возможности из оценщика (`main.go`), `GrantAuthorizer` W0.09 в production больше не используется; `APP_FIXED_NOW` (RFC 3339, только `APP_ENV ≠ prod`) — часы оценщика.
