## 1. Цель

После WS-08 в репозитории есть пакет `@ortus/texts` — единственный источник всех строк интерфейса, которые видит пользователь прототипа (подписи кнопок, заголовки, тексты гейтов и баннеров, тосты, сообщения `ApiError` мок-сервера, тексты диалогов, `aria-label`, `data-screen-label`), разложенных по 19 файлам доменов и зафиксированных тестами на дословность («ё», «»/«·»/«—», U+00A0 в суммах), на отсутствие дублей между файлами и на совпадение с живым эталоном `127.0.0.1:4173`. Страничные WS волн 1–2 берут подписи из словаря, а не перепечатывают их (00 §10 п.6: «иначе 12 агентов будут переписывать одни и те же строки»), поэтому структурная сверка `labels.spec` каждой страницы (verification-protocol §3 п.4) проходит по одним и тем же байтам.

### 4.2 Потребляет

Только WS-01 (workspace, `tsconfig.base.json`, ESLint/Prettier, Vitest в корне). Ничего из `@ortus/domain` не импортируется (словарь должен быть листом графа зависимостей, чтобы `packages/domain` и `packages/ui` могли его импортировать без цикла). Множественное число считается внутренним `_plural.ts` (4 строки), входы — число и три формы из самого словаря.

### 4.3 Правила словаря (дублируются в `README.md` пакета)

1. Значение — байт-в-байт из прототипа: «ё» сохраняется, кавычки только «», разделители « · » и « — », многоточие «…», неразрывный пробел U+00A0 в суммах и единицах («46,2 ГБ» — обычный пробел, как в прототипе `M.num(x) + ' ГБ'`, но «1 250 ₽» — U+00A0 из `toLocaleString('ru-RU')`, 02 §7.3).
2. Данные сида (имена, даты, суммы, идентификаторы) в словарь не входят — только шаблоны. Исключение: строки, захардкоженные в прототипе (`«Временно, до 18:00 01.10»` `:2816`, `«или выберите лимит от 50 ГБ»` 02 §5.5) — хранятся дословно с комментарием `// захардкожено в прототипе :NNNN` и ссылкой на Q-ID.
3. Одна строка — один файл: lint-тест запрещает одинаковые значения в двух файлах; общие кнопки («Отмена», «Закрыть», «Выполняем…») живут только в `shell.modal`.
4. Все сообщения `new ApiError(...)` — только в `errors.ts`; все `okText` из `run(...)` — только в `toast.ts`; UI-строки страниц — в файле домена.
5. Ключи — ASCII camelCase; никаких индексов в именах (`item1`), никаких значений-массивов кроме перечислений прототипа (легенда, палитра, персонажи).
6. После волны 0 ключи из `contract/keys.json` не удаляются и не переименовываются; владелец страницы добавляет ключи только в свой файл (мастер-план §3.3).
