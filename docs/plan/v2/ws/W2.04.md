## 1. Цель

1. **Модуль `modules/fleet/inspections`** — backend восьми операций тега Fleet по контракту `0.5.0-stage2`:
   - `getInspectionChecklist` — текущая версия чек-листа вида (`departure` | `return`) для видимой машины; встроенная версия 1 (пункты `DEP_CHECKS`/`RET_CHECKS` эталона, ракурсы `PHOTO_SIDES`) публикуется в `fleet.checklist_versions` при первом обращении;
   - `submitInspection` — осмотр по версии чек-листа: выезд — по брони (`reservationId`), сдача — по рейсу (`tripId`); недостающие ракурсы и пункты → 409 `inspection_incomplete` «Осмотр не завершён: …» / «Сдача не завершена: …»; фото — только `ready`-файлы родителя осмотра (бронь или рейс, назначение `inspection`), иначе 409 `photo_not_ready` «Не все фото загружены на сервер»; пробег меньше начального → 422 `odometer_decrease`; дефекты `defects[]`; повторная попытка того же вида — `attempt + 1` (tenant 0011);
   - **блокирующий дефект при выезде** (S2-05, S2-17): осмотр `requires_review`, дефект `in_review` (очередь `fleet.defects`, tenant 0010), рейс `defect_review`, машина «Недоступна · критический дефект на проверке», бронь удерживается за рейсом (`confirmed`), менеджерам области и владельцу — уведомление «Критический дефект: {машина} {номер} — {зона}. Выезд заблокирован.» через порт входящих W1.10 (проверка адресата при постановке);
   - `listInspections`, `getInspection` — видимые осмотры (менеджер — по подразделению машины, водитель — свои);
   - `listInspectionDefects` (очередь менеджера, старые первыми), `getInspectionDefect`, `decideInspectionDefect` — `allow_departure` | `confirm_out_of_service`, If-Match, повтор после чужого решения — 409 `invalid_transition` «Дефект уже решён.», аудит, событие `fleet.defect.decided.v1`, уведомление водителю.
2. **Подключение в `cmd/api`** отдельным файлом `cmd/api/fleet_inspections.go` (W2.02 параллельно подключает свои операции тега Fleet — конфликт механический): сервер-наложение `inspections.NewServer(base, svc)`, без базы остальные операции тега отвечают 501.
3. **Строки изоляции** — `backend/test/isolation/fleet_inspections.yaml` (`pending: W2.04` до хендлера) и отказы шлюза `fleet_inspections_gate.yaml` (без `pending`, с `code`).

## 4. Контракты

Контракт не меняется (`0.5.0-stage2`, W2.00). Публикуемые Go-сигнатуры:

```go
package inspections

type Service struct {
	Pools      Pools            // tenantctx.Pools
	Authz      Authorizer       // *authz.Evaluator: Permit, ScopeQuery
	Recipients inbox.Recipients // адресат по person_profile_id (control DB)
	Audience   inbox.Audience   // проверка адресата при постановке (inbox.AuthzAudience)
	Now        func() time.Time // часы приложения (APP_FIXED_NOW вне prod); nil — time.Now
}
func (s *Service) Checklist(ctx, tc, vehicleID uuid.UUID, kind string) (fleetapi.InspectionChecklist, error)
func (s *Service) Submit(ctx, tc, fleetapi.InspectionCreate) (fleetapi.Inspection, error)
func (s *Service) Inspection(ctx, tc, id uuid.UUID) (fleetapi.Inspection, error)
func (s *Service) Inspections(ctx, tc, PageQuery) (fleetapi.InspectionPage, error)
func (s *Service) Defects(ctx, tc, DefectQuery) (fleetapi.InspectionDefectPage, error)
func (s *Service) Defect(ctx, tc, id uuid.UUID) (fleetapi.InspectionDefect, error)
func (s *Service) Decide(ctx, tc, id uuid.UUID, ifMatch string, fleetapi.DefectDecision) (fleetapi.InspectionDefect, error)

type Server struct{ fleetapi.StrictServerInterface; S *Service } // наложение на базовый сервер тега
func NewServer(base fleetapi.StrictServerInterface, s *Service) Server // nil — остальные операции 501
```

Соответствие хранения (tenant 0002/0010/0011) и контракта:

| Контракт | Хранение |
|---|---|
| `Inspection.status` `submitted` / `approved` / `requires_review` / `rejected` | `inspections.state` `submitted` / `approved` / `blocked`; `rejected` = `blocked` с подтверждённой неисправностью (дефект `confirmed_out_of_service`) |
| ракурс `rear`, `odometer`, `front`, `left`, `right`, `cargo` | `inspection_photos.role` `back`, `odometer`, `front`, `left`, `right`, `cargo` (одна строка на ракурс); все фото (и `damage`) с `capturedAt` — `answers.photos` |
| `fuelPercent` 0…100 | `fuel_level` (`quarter` ≤ 37, `half` ≤ 62, `three_quarters` ≤ 87, `full`) + точное значение в `answers.fuelPercent` |
| `checks[]`, `reportedDamage` | `answers.checks`, `answers.reportedDamage` |
| `memberId` | `submitted_by` (person profile) |
| рейс брони | `sched.reservations.source_type = 'fleet.trip'`, `source_id` = рейс; машина — `sched.resources(kind 'vehicle', ref_id)` |
| машина «Недоступна · …» | `vehicles.service_note` («критический дефект на проверке» / «неисправность подтверждена»), `service_state = 'out_of_service'` после подтверждения; открытый блокирующий дефект (`defects_blocking_open_idx`) |

Ответы: 404 `not_found` — чужой, несуществующий и невидимый объект одинаково (AC-01, AC-02); 403 `forbidden_action` — объект виден, действия нет; 409 `inspection_incomplete`, `photo_not_ready`, `invalid_transition`, `reservation_expired`, `reservation_overlap`; 412 `revision_mismatch`, 428 `revision_required`; 422 `validation_failed`, `odometer_decrease`.

Области: осмотры и дефекты читаются по `fleet.inspections.read` над подразделением машины и «своими» людьми (`submitted_by`/`reported_by`, водитель рейса); очередь и решение — `fleet.inspections.review` над подразделением машины; отправка — `fleet.inspections.submit` над рейсом (подразделение рейса, водитель рейса, автор брони), видимость рейса — `fleet.trips.read`.

События outbox: `fleet.inspection.submitted.v1`, `fleet.defect.blocking_reported.v1`, `fleet.defect.decided.v1` (идентификаторы и состояния, без ПДн). Уведомления: `fleet.defect.blocking_reported` (critical; право `fleet.inspections.review` на подразделение рейса), `fleet.defect.decided` водителю (info / warning).
