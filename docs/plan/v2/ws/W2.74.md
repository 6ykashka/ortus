# W2.74 · Экран временного водителя S2-20 (D-35): выбор машины, подтверждение, осмотр на выбранной

Этап 2 · вид frontend · дорожка Ф · слот 2 (Vite 5202, Storybook 7202, API `127.0.0.1:8102`, свой эталон 4102, `E2E_OWN_REFERENCE=1`, compose `ortus-s2`). Карточка — план v2 §4 «Этап 2», строка W2.74; постановка интегратора 21.10. Зависит от W2.71 (контракт `0.7.1-stage4`, MSW S2-20 — в `main`). Режим `stand` — после W2.72 (backend S2-20; при старте не в `main`, строки `@stand` — `test.fixme` с причиной «W2.72», снимает W2.75).

## 1. Цель

«Моя смена» водителя, которому при одобрении запроса пула (или логистом, правило 9) предложены машины рейса — по макетам `design/Временный водитель - варианты.dc.html` 1c–1e (тег `design-2026-10-19b`), DoR `docs/plan/v2/analysis/dor/s2-20-temporary-driver-vehicle.md` §1.4–§1.6, правила 5, 8, 9:

1. **1c, две машины** — «Выберите машину», «До {срок}. Вторую бронь снимем сразу после выбора.», карточки предложенных машин («Ваша обычная» / «Поставил логист», характеристики, место, «Подходит рейсу: масса, объём, длина, температура», «Взять эту машину»), «Нужна другая машина — напишите логисту в чат рейса {рейс}.» без ссылки (Q-W2.70-4). Других машин фирмы рейса нет.
2. **1d** — лист «Берёте {модель}?»: что станет со второй машиной, что дальше осмотр, кто увидит осмотр, «Поменять машину после выбора может только логист.», «Взять и начать осмотр» (`chooseReservation`) и «Назад».
3. **1e** — осмотр перед выездом на выбранной машине: статус «Бронь подтверждена сервером · {модель} до {конец окна}» и «{модель} {номер} освобождена в {время}», подзаголовок «{модель} · {номер} · {ваша обычная / поставил логист}», «Осмотр увидят …». Чек-лист этапа 2 без изменений (Q-W2.70-3).
4. **1c, одна машина** — «Машина на сегодня», «… Подтверждать бронь не нужно: первый снимок осмотра закрепит её за вами.», «Начать осмотр» → осмотр (вариант (b), Q-W2.70-2).
5. **1c, машины нет** — «Машину ещё не поставили» без «Написать логисту» (Q-W2.70-4).
6. Выбор только со связью (правило 5, D-09): офлайн «Взять эту машину» и «Взять и начать осмотр» недоступны с причиной; очередь отправки выбор не ставит.
7. 409 `offer_closed` — понятное сообщение и перечитывание смены.
8. У временного водителя нет «Подтвердить бронь» и «Забронировать» ни на «Моей смене», ни на «Автомобилях»; «Автомобили» — только предложенные машины.
9. Свой водитель с двумя машинами логиста (Q-W2.70-6) — тот же выбор. Смена своего водителя без предложения (W2.22) не меняется, начатый рейс — без `listVehicles` (W2.61).

## 3. Данные

- `listReservations` — брони рейса смены с `offerGroupId`, предложенные водителю: `held` до `chooseUntil` (выбор), `confirmed` (выбрана или единственная), `released` (`releasedAt`, `releaseReason`).
- `listVehicles` — предложенные машины (модель, номер, характеристики, место). Название невыбранной машины после выбора сервер не отдаёт — экран помнит его с момента выбора.
- `chooseReservation` — `POST /fleet/reservations/{id}/choose`, Idempotency-Key; 200 → тост «Бронь подтверждена сервером. Начните осмотр», перечитывание; 409 `offer_closed` → сообщение и перечитывание.
- Названия фирм водителю не видны (нет `org_units.read`, в `TripPlan`/`Vehicle` их нет) — подписи с фирмами берутся из `listOrgUnits`, если право есть, иначе — нейтральные формулировки (вопрос стюарду в отчёте).
