## Сделано

**Модуль `files` (`backend/internal/modules/files/`, владелец W1.09).**

- `ParentKind.Shares` / `Share` / `FilePlaceholder` (`{{file}}`): расширение области чтения родителя — своё действие чтения и своя строка области, зависящая от родителя и от самого файла. `NewParents` отклоняет расширение без действия, без `{{id}}` или без `{{file}}`.
- `fleet.trip` — одно расширение: `fleet.inspections.read` в области машины (`usualVehiclePhotosSQL`). Строка есть, только когда файл — фото поданного осмотра этого рейса (роль из `fleet.inspection_photos` или фото повреждения из `answers.photos`) и машина осмотра — обычная машина одобренного запроса пула этого рейса (`driver_transfers.home_vehicle_id`, `vehicle_decision = 'approved'`, то же условие, что `visibleSQL` осмотров W2.72). Подпись — номер рейса. Рейсы, закрытые пулом субъекту (`{{hidden}}`), закрыты и здесь.
- `getFile`/`getFileDownload` (`file()`): при отказе родителя (not_found / forbidden / function_deny) — проверка расширений (`shared`: действие расширения и `files.read` над его строкой). Сбой проверки родителя (иная ошибка) — ответ, расширение его не маскирует.
- `listFiles`: латеральный union строк родителей и расширений с колонкой `via`; одна строка области на файл (`order by via limit 1`) — файл не дублируется у фирмы рейса и владельца.
- Загрузка (`permitUpload`) проверяет только родителя: через расширение к рейсу ничего не загружается (404).
- Закрытые Hider id читаются не больше одного раза на запрос (`closedIDs`, `closedParams`).

Остаётся 404 для фирмы машины: фото осмотра машины фирмы рейса (в т. ч. на рейсе с одобренной обычной машиной, когда водитель взял машину фирмы рейса), фото рейса вне осмотра, чеки, осмотр без одобрения обычной машины (`declined`), рейс без запроса пула; сам рейс (`getTrip`) — 404, как в 0.6.2. Другой тенант — 404.
