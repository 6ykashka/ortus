## 1. Цель

Ответ владельца 17.10 (модель данных 4): «sha256 файла с предупреждением о повторе, время съёмки фиксирует сервер». По контракту W2.52 (`FileDuplicateWarning`, `InspectionPhoto.serverCapturedAt`, `duplicateWarning`):

1. **Повтор фото в осмотре.** `submitInspection` для каждого фото ищет более ранние (по `(created_at, id)`) проверенные файлы тенанта (`state in ('scanning','ready')` — не отклонённые и не незавершённые загрузки) с тем же sha256 по `files_sha256_idx`; найденное — `duplicateWarning {code: duplicate_sha256, firstSeenAt, previousCount, sameOwner}` закрепляется с фото на момент отправки (колонки `duplicate_*` в `fleet.inspection_photos`, у фото повреждения — в `answers`); `getInspection`/`listInspections` отдают его менеджеру в очереди и приёмке. Это предупреждение, не отказ: осмотр принимается. Прежние файлы не раскрываются (ни id, ни владельцев, ни рейсов). `sameOwner` — прежний файл того же владельца (бронь, рейс) или фото того же осмотра.
2. **Серверное время съёмки.** `serverCapturedAt` — момент `completeUpload` сессии загрузки (`files.upload_sessions.completed_at`, часы сервера; без сессии — `files.objects.created_at`), закрепляется в осмотре при отправке; `capturedAt` устройства остаётся подсказкой. Присланные клиентом `serverCapturedAt` и `duplicateWarning` в `InspectionCreate` отбрасываются; у осмотров до W2.43 — из колонок 0017, значения клиента из `answers` не отдаются.
3. **Повтор у файла.** `completeUpload` и `getFile` отдают `File.duplicateWarning` по тому же правилу (по умолчанию Q-W2.52-7 (а)); серверное время приёма модуль files уже пишет (`completed_at` — `Service.now`, часы стены, не `APP_FIXED_NOW`).
