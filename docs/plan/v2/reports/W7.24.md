## Сделано

Девять операций тега `Docs`, которые W7.23 оставил с ответом 501, поверх схемы `docs` (tenant 0061) и модуля «Задачи».

**Маршрут** (`docs/route.go`, `route_ops.go`, `route_store.go`, `route_logic.go`). До шести шагов «Согласовать / Утвердить / Ознакомить / Подпись заказчика», режимы «все сразу / по очереди / достаточно одного» (`stepWaiting` прототипа в Go: `routeStep.waiting`), срок шага в рабочих днях. Запуск: проверки в порядке прототипа (шаги, согласующие, автор — 409 `separation_of_duties_conflict`, утверждающий с правом `docs.sign`, адресаты, заказчик), текущей версии даётся имя «На согласование», статус `in_route`, документ закрыт для правки (`d.lock` и при активном маршруте после подписи), зеркальная задача, временные доступы («Комментирует» согласующему без доступа на время шага, «Читает» утверждённой версии с «оставить» адресату ознакомления), уведомления, события `docs.route.started.v1`, `docs.route.step.started.v1`, `docs.ack.requested.v1`. `dryRun` отдаёт «Что произойдёт» и ничего не пишет. «Сохранить маршрут как шаблон папки» — только с `docs.templates.manage` (без права флаг молча не действует).

**Решения.** `decideDocRoute`: только участник текущего шага (403 «Сейчас решение ждут: …»); ознакомление подтверждает сам сотрудник (422), утверждение — подписью (422); возврат без комментария — 422 «Напишите, что доработать» (правило `commentOnBack`), статус `returned`, правка открыта автору, временные доступы сняты. `resumeDocRoute` — автор маршрута или владелец бизнеса, только после новой версии (422 «Сначала внесите правки…»), решения возвращённого шага сбрасываются, шаг стартует заново. `cancelDocRoute` — автор или владелец бизнеса; статус `draft`, доступы сняты, задача закрыта. Решения идут в одной транзакции под замком строки маршрута.

**Ознакомление.** Адресаты шага — аудитория на момент шага без автора и заблокированных (`entryHas`), отметка пишет версию, время, устройство в `docs.acks`, повтор — без дубля; шаг закрывается, когда отметились все; `closeDocAck` — автор или владелец, неознакомившиеся остаются в листе.

**Подпись (D-31).** `requestDocSignCode` → `confirmDocSign`. Вызов подтверждения живёт в `docs.routes.rules.sign` (таблицы нет, миграцию не просили): способ, участник, дайджест кода (HMAC от ключа модуля, сам код не хранится), срок 10 минут, неверные попытки. Три неверных ввода — 422 `sign_code_invalid` с «Осталось попыток: N», четвёртый — 429 `rate_limited`; неверная попытка сохраняется (транзакция коммитится, ответ — отказ). Порт `Signer`: `ConfirmLogin` (повторный вход: пароль или код второго фактора) и `SendCode` (код по SMS). Без провайдера — 503 `dependency_unavailable`. После подписи: статус `approved` (заказчик — `signed`), поля CRM замораживаются (`frozen`), в очередь ставится задание PDF/A-копии с данными листа согласования (`pdfa` для PDF, `to_pdf` для текста и таблицы), события `docs.document.approved.v1` / `docs.document.signed.v1`, аудит помечен чувствительным.

**Задача-зеркало (Q-W4.00-documents-3, -18).** Порт `docs.RouteTasks` (`create`, `sync`, `MayCreate`), реализация — новый файл `backend/internal/modules/tasks/doc_route_port.go` (по образцу `forms_port.go`): задача «Согласовать: …» с карточкой `doc_route`, приоритет «Высокий», метка «документ», статус «На проверке» / «В работе» (после возврата) / «Готово» / «Отменена», исполнитель — кто ждёт (после возврата и на шаге заказчика — автор), срок шага, системные комментарии с автором действия. Ручные переходы закрыты (`invalid_transition`, причина `doc_route` — уже была в W4.11). Системный проект «ДОК · Документы · маршруты» (ключ «ДОК», процесс «С согласованием», доступ «открытый») создаётся при первом запуске под advisory-замком; выбранный проект — с проверкой «Создавать» (403 «Нет права создавать задачи в проекте…»). Адаптер `cmd/api/docs_sign.go`.

**«Главная».** Новый источник `backend/internal/modules/home/docs` (виды `docs.approve`, `docs.sign`, `docs.ack`, `docs.returned`, `docs.mention`, `docs.ocr`, параметры `documentTitle`, `dueDate`, `byName`, объект — документ): порт `docs.Service.HomeWaits`, подключён в `cmd/api/home.go`. `my.wait` документа получил виды `approve`, `sign`, `ack` для участника текущего шага; карточка маршрута (`getDocRoute`, `getDocument`) собирается из одной загрузки и показывает законченный маршрут, `done` ознакомления, заказчика с маской телефона.

**Подключение и сид.** `cmd/api/docs.go`: `Signer` по настройке (`DOCS_SIGN_STAND_SECRET` — только вне prod), `Tasks` на сервисе задач; `homeServer` принимает сервис документов. Сид `cmd/seed/docs.go`: законченный маршрут договора аренды (прототип `rt-0`: согласовать → утвердить, способ `pep_sms`).

## Осталось fixme / открытые вопросы

Решения, по которым я сделал по умолчанию (перенести в `docs/plan/decisions.md`):

- **Q-W7.24-1.** Системный проект «ДОК · Документы · маршруты» создаётся при первом запуске маршрута; владелец проекта (колонка `owner_id` обязательна) — автор первого маршрута; доступ «открытый»; для него `tasks.create` автора не проверяется (маршрут создаёт задачу сам). Для выбранного проекта проверка `tasks.create` есть. Решение: нужен ли владелец-владелец бизнеса и роль «Руководитель проекта».
- **Q-W7.24-2.** Повторное подтверждение входом (`pep_login`) требует шага повторной аутентификации у провайдера (OIDC) — его в платформе нет. Порт `Signer` готов; без него подпись — 503. На стенде и в e2e вместо него `DOCS_SIGN_STAND_SECRET` (не prod, не короче 8 знаков): пароль или код второго фактора равны секрету. Код по SMS (`pep_sms`) — через порт доставки; SMS отложены (D-31), канала нет, `SendCode` отвечает `ErrNoDelivery` → 503. Решение владельца: как подтверждать вход (повторный вход в Keycloak с `max_age`, TOTP платформы) и когда включать SMS.
- **Q-W7.24-3.** Шаг «Подпись заказчика» принимается и ждёт: в контракте нет публичной операции подписи по ссылке из SMS (W7.31b), а решение шагом заказчика участником недопустимо (403 «Сейчас решение ждёт … (заказчик подписывает по ссылке из SMS)»). Закрыть шаг можно только отменой маршрута, пока не появится публичный контур.
- **Q-W7.24-4.** PDF/A-копия: ставится задание (`pdfa` для PDF, `to_pdf` для текста и таблицы) с данными листа согласования в параметрах (`approvalSheet`); вставка листа в файл и второй шаг PDF/A для не-PDF — в процессоре, которому нужны программы (на этой машине не установлены). `DocSignResult.pdfaCopyId` при ответе пуст (копия появится позже).
- **Q-W7.24-5.** Правило `escalate` («Эскалация после срока») хранится, но не исполняется: просроченного шага нет планировщика (в прототипе правило только записывается). Нужен периодический процесс воркера и текст уведомления.
- **Q-W7.24-6.** Без миграций: вызов подписи — в `docs.routes.rules.sign`, пометка «ознакомление завершено досрочно» — в `docs.route_steps.external` шага `ack`; статус `returned` и `cancelled` документа: возврат — `returned`, отмена — `draft` (подписанный `approved` остаётся). Таблица вызовов подписи и колонка начала шага (для эскалации и «Q-W7.23-10») — миграция стюарда, если понадобится.
- **Q-W7.24-7.** Согласующий, у которого после шага или возврата не осталось доступа, видит документ как несуществующий (404, AC-01) — по цепочке доступа; решения возвращённого шага начинаются заново (старые решения шага удаляются, в журнале документа остаются).
- **Q-W7.24-8.** События: `docs.document.approved.v1` и `docs.document.signed.v1` (Q-W7.23-1), добавлены `docs.route.step.started.v1`, `docs.route.resumed.v1`; уведомления вида `docs.route.approve|ack|sign|returned|done`. Тексты уведомлений и карточек «Главной» — по прототипу, словарь клиента — W7.26.
- **Q-W7.24-9.** `syncDocDataset` по-прежнему 501 (`pending` в изоляции): нужны движок листа (W7.20) и порт набора данных; к маршруту не относится.
