## 1. Цель

После W2.01 у backend есть Go-копия чистых правил логистики, которые сейчас живут в `@ortus/domain/modules/logistics` (W0.12, эталон `design/ortus/models.js:125–163, 322–389` 14.10):

- `Compat` (совместимость машины с грузом рейса, тексты причин), `TempLabel`;
- `Legs` (загрузка после каждой остановки, масса и объём отдельно);
- `InspMissing` (чего не хватает в осмотре выезда или сдачи);
- `OdoError` (ошибка поля «Пробег»);
- `ValidateExpense` (ошибки формы расхода по полям);
- справочники, на которые они опираются: `VEHICLE_STATE`, `TRIP_STATE`, `PHOTO_SIDES`, `DEP_CHECKS`, `RET_CHECKS`, `DEFECT_ZONES`, `FUEL`, `EXPENSE_CAT`.

Сервер повторно проверяет то же, что клиент показывает в предпросмотре (`analysis/03-logistics.md` I3, `08-requirements.md` п. 18: «расходы валидируются на клиенте и сервере одинаково»). Одинаковость обеспечивают **общие табличные фикстуры** `testdata/fleet-rules/*.json`: Go-тесты и тест паритета TS в `@ortus/domain` читают одни и те же входы и ожидания. Ожидания дополнительно сверяются с эталоном 14.10 (`models.js`) в тесте TS. Расхождение любой из трёх сторон (фикстура, TS, Go) роняет тест.

Тексты — дословно из эталона, включая неразрывный пробел U+00A0 в числах (`int()` = `toLocaleString('ru-RU')`).

## 4. Контракты (Go, пакет `github.com/ortus/ortus-crm/backend/internal/domain/fleetrules`; меняются только аддитивно)

```go
// Типы (поля и JSON-имена — как в types.ts W0.12)
type VehicleState string // free reserved on_route review unavailable
type TripState string    // planned assigned inspection defect_review on_route returning submitted rework accepted
type TempRange [2]float64
type Vehicle struct{ ID, Unit, Model, Plate, Body string; PayloadT, VolumeM3, LengthM float64; Temp *TempRange; Odometer float64; State VehicleState; Depot, Note string; HeldBy *string }
type Cargo struct{ WeightT, VolumeM3, LengthM float64; Temp *TempRange; Kind string }
type Stop struct{ Time, Name string; Op StopOp; W, V float64 }
type Trip struct{ ID string; Cargo Cargo; Stops []Stop } // поля рейса, нужные правилам
type FormValue  // значение поля формы: строка ввода, число или пусто (null / нет поля)
type Photo struct{ State PhotoState }
type InspectionDraft struct{ Photos map[string]*Photo; Odometer FormValue; Fuel string; Checks map[string]bool }
type ExpenseDraft struct{ Amount FormValue; Date string; Receipt *Photo }
type CompatCheck struct{ Key, Label, Icon string; OK bool; Value, Need string }
type CompatResult struct{ Fit, OK bool; Checks []CompatCheck; Reasons []string }
type Leg struct{ Stop; WAfter, VAfter float64; WPct, VPct *float64 }
type ExpenseErrors struct{ Amount, Date, Receipt string } // пустая строка — поле без ошибки

// Правила
func TempLabel(t TempRange) string
func Compat(v Vehicle, trip Trip) CompatResult
func Legs(trip Trip, v *Vehicle) []Leg                       // WPct/VPct = nil без машины
func InspMissing(d InspectionDraft, kind InspectionKind, minOdo float64) []string
func OdoError(value string, minOdo float64) string          // "" — ошибки нет (null эталона)
func ValidateExpense(e ExpenseDraft) ExpenseErrors
func (e ExpenseErrors) OK() bool; func (e ExpenseErrors) First() string // первая ошибка — для ответа validation

// Справочники (копии, порядок как в эталоне)
func VehicleStates() []StateEntry[VehicleState]; func TripStates() []StateEntry[TripState]
func PhotoSides() []Option; func DepChecks() []Option; func RetChecks() []Option; func FuelLevels() []Option
func DefectZones() []string; func ExpenseCategories() []ExpenseCategory
```

Числа — по правилам JS, чтобы тексты совпадали байт в байт:

- `num` = `String(n)` с заменой `.` на `,` (кратчайшее представление, экспонента с `1e21` и до `1e-7`);
- `int` = `toLocaleString('ru-RU')`: до 3 знаков дроби, округление «половина от нуля» по кратчайшему десятичному представлению, группы по 3 через U+00A0, знак минуса сохраняется у `-0`;
- разбор строки ввода = `Number(String(x).replace(/\s/g, ''))`: пробелы JS (`\s`, включая U+00A0, U+202F, U+FEFF) удаляются; пустая строка → 0; `Infinity`, экспонента, `0x`/`0o`/`0b`; иначе NaN;
- `Math.round` (половина вверх, к +∞) в `Legs`.

Формат фикстур `testdata/fleet-rules/` (JSON, UTF-8, общий для Go и TS):

## 10. Риски и решения по умолчанию

| # | Риск / вопрос | По умолчанию |
|---|---|---|
| 1 | Где лежат фикстуры: корень `testdata/` или `testdata/` пакета Go | Корень репозитория `testdata/fleet-rules/` (как в карточке): их читают и Go (`../../../../testdata`), и Vitest (`import … with JSON`), ни одна сторона не владеет чужим каталогом |
| 2 | Поведение JS на краях ввода (`' '` → 0, `0x14A02` → 84 482, `Infinity`, `'1,5,0'` → NaN) | Копируется как есть: сервер и клиент обязаны давать одинаковые тексты. Сужение формата ввода — продуктовое решение (вопрос в отчёте), до решения — как эталон |
| 3 | Неизвестное состояние машины: в JS `compat` падает (`VEHICLE_STATE[x].icon`) | В Go — без паники: доступность `false`, значение = ключ состояния, иконка пустая. Общие фикстуры такой кейс не содержат (эталон бросает исключение); его фиксирует отдельный Go-тест |
| 4 | `Legs` с нулевой грузоподъёмностью/объёмом: в JS `Infinity`/`NaN`, в JSON — `null` | В Go так же (`+Inf`/`NaN` в `*float64`); фикстуры такие машины не содержат, валидация машины — W2.02 |
| 5 | Пробег и суммы на сервере придут числом (OpenAPI), а правило принимает строку ввода | `FormValue` принимает и строку, и число, как JS; `OdoError` — строку (`strconv.FormatFloat` числа даёт тот же текст, что `String(n)` JS) |
| 6 | `queued`-фото засчитываются в `InspMissing`, а сервер мока требует `ready` (`03-logistics.md` п. 790) | Правило копируется как в эталоне; дополнительная проверка `ready` — в командах W2.04/W2.05 |
| 7 | Округление `int()` дробных разностей пробега (`87371.0005 − 84370`) | Как ICU: по кратчайшему десятичному представлению double, до 3 знаков, «половина от нуля»; ожидания фикстуры сняты с Node 22 (ICU) и сверяются с эталоном |
