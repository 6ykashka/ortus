## Осталось fixme / открытые вопросы

`fixme` нет. Отступление от протокола: e2e-тест назначения написан после страницы, а не скелетом `fixme` до неё. Страничные тесты (модель и экран на MSW) были красными до кода. Вопросы (значение по умолчанию — как сделано; внести в `decisions.md` — интегратору):

1. **Q-W2.46-1 · кандидаты в исполнители (продукт / технический).** Список берётся из `listMembers` в области `members.read`. Менеджер фирмы в сиде MSW видит только водителей своей фирмы и не видит себя, поэтому форма у него не показывается: назначает владелец, менеджер видит строку исполнителя. Сервер принимает назначение от любого держателя `fleet.inspections.review`. Варианты: (а) как сделано; (б) стюард добавляет в контракт источник кандидатов — фильтр `listMembers` по праву над фирмой (`permission=fleet.inspections.review&orgUnitId=…`) или `memberId` в `TenantContext`, чтобы показать «Назначить себе».
2. **Q-W2.46-2 · комментарий назначения (технический).** У `DefectAssignment.comment` нет колонки (tenant 0017). Комментарий уходит текстом уведомления исполнителю, в аудите есть только признак комментария. При назначении себе текст не сохраняется. Альтернатива — колонка `assignment_comment` следующей миграцией (стюард) и поле в `InspectionDefect`.
3. **Q-W2.46-3 · срок (продукт).** Срок не раньше «сейчас» по часам приложения, верхней границы нет. На экране срок вводится по московскому времени (UTC+3, как все времена страницы), без пояса организации.
4. **Q-W2.46-4 · уведомление исполнителю (продукт).** Важность warning. Объект — рейс дефекта, без рейса объекта нет. Видимость — пока у исполнителя есть `fleet.inspections.review` на фирму машины. Прежнему исполнителю при переназначении ничего не шлётся.
5. **Q-W2.46-5 · строки изоляции команд с If-Match (технический, к Q-W2.52-14).** «id другой сущности / другой организации у своих актёров → 404» матрица не выражает: strict server отвечает 428 до хендлера. Это проверяет integration (`TestAssignRejects`).
