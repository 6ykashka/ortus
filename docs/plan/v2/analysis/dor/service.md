## 1. Инвентарь экранов

### 1.1. Встроенный модуль `Обращения.dc.html` (эталон 1b + 1c)

Ширина. Модуль меряет **ширину своего контейнера** (`ResizeObserver`, О:335–337). Порог — 860 px (О:372: `wide = cw ≥ 860`, `narrow = cw < 860`). Других переключений по ширине нет. Таблица очереди держит `min-width: 900px` и прокручивается по горизонтали (О:124–125) — на 390 и 768 будет горизонтальная прокрутка внутри карточки. Карточка обращения — две колонки на flex-wrap: основная `flex: 1 1 520px`, боковая `flex: 0 1 360px; min-width: 280px` (О:160, О:274). На 390 и 768 боковая колонка уходит вниз, на 1440 колонки стоят рядом.

### 3.3. Ограничения функций и правила

- Функция «Водитель» ключи `service.*` не блокирует; мастер, прораб и водитель ролей в направлении не получают (22 §«Новые права»). Обращения доходят до них задачами и благодарностями. Блокировку не вводим (Q-…-15).
- Назначить исполнителем можно только участника, который видит направление и имеет `reply` (S:225, S:292).
- Утечка PD-53 в эталоне: `can('edit')` без объекта даёт Котовой кнопки во всех направлениях, но видит она только ГРЗ, потому что `serviceView` фильтрует. На сервере каждая команда проверяется с объектом-направлением: `can(…, project = d.project)`. Гейт меню — `canAny` (Q-W0.11-1).
- Телефон в любом ответе API — только маска. Полный номер — только ответом `revealServiceClientPhone` или автору обращения по звонку.
