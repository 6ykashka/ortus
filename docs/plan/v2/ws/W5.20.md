## 1. Цель

Сервер тега `Spa` контракта (11 операций) поверх схемы `spa` (tenant 0044): услуга — длительность, буферы до и после, цена, оборудование и техкарта (расход материалов на визит) с ревизиями; запись клиента занимает практика, кабинет и оборудование целиком (одна бронь `sched.bookings` + резервации `sched.reservations` с `occupied = окно ± буферы`, один 409 `resources_unavailable` на гонке); факт выполнения хранится отдельно от учёта (`performed_pending_posting` — «незавершённый учёт»); завершение списывает материалы по техкарте ровно один раз в одной транзакции со складом (`inventory`), нехватка оставляет факт выполнения и статус (AC-07, SPA-03).

## 3. Решения по умолчанию (`Q-W5.20-N` в отчёте)

- Окно записи — `startsAt + durationMinutes` из услуги на момент записи; занятость всех ресурсов — окно ± буферы услуги (простой шаблон `08-domain-scenarios.md` §5.2). Снимок услуги (ревизия, длительность, буферы, цена, оборудование, техкарта) хранится в визите: правка услуги задним числом визит не меняет, расход считается по снимку.
- Ресурсы: практик — `people.person_profiles.id` (строка `sched.resources` вида `person` создаётся при первой записи), кабинет и оборудование — `sched.resources` видов `room`/`equipment` подразделения визита, активные; рабочий день ресурса (CAL-05) проверяется как в календаре.
- Права: `spa.appointments.create/perform/complete` — над подразделением визита или «своим» (`self` — практик визита); завершение дополнительно `inventory.consume` на склад списания (целевое право практика, не общий выпуск), поправка расхода — `inventory.consumption.override` и причина. Склад вне области — 404.
- Единицы техкарты: `ml`/`g`/`piece`; позиция склада в `litre`/`kg` принимает техкарту в `ml`/`g` по явному пересчёту (÷1000, только без потери шестого знака); `ml` ↔ `g` не пересчитываются (SPA-02).
- Нехватка материала или просроченная партия — 409 `invalid_transition` с причиной `insufficient_stock`/`lot_expired`; транзакция завершения откатывается целиком, факт выполнения (отдельная команда) и статус `performed_pending_posting` остаются; повтор после поправки остатка списывает один раз (`spa.completions` — первичный ключ по визиту). Повтор уже завершённого — тот же ответ без второго списания.
- Завершение предлагает кассе приход «визит» на `finalPrice` (иначе цену снимка) через порт `CashOffers` (ключ `visit:<id>`, идемпотентно); сумма 0 — предложения нет. Деньги клиента визит не получает.
- Клиент (`clientId`) — идентификатор без справочника (клиентской базы в продукте пока нет): проверяется только форма.
