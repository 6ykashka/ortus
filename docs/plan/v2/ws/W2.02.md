## 1. Цель

После W2.02 backend отвечает на операции автопарка и брони тега Fleet контракта `0.5.0-stage2` поверх tenant DB, а не 501:

| Операция | История | Что делает сервер |
|---|---|---|
| `listVehicles` | S2-01, S2-02 | машины области `fleet.vehicles.read` (предикат `scopeQuery` до пагинации), фильтры `orgUnitId` (поддерево, только сужает), `bodyType`, `minPayloadKg`, `availableFrom` + `availableUntil` (свободна на интервале: исправна, не в рейсе, без действующей брони, пересекающей интервал); вычисляемые `status`, `statusNote`, `heldByTripId` |
| `createVehicle` | S2-01 | регистрация машины в подразделении, где есть `fleet.vehicles.manage`; аудит, idempotency |
| `reserveVehicle` | S2-03 | атомарный hold машины **и** водителя (`sched.reservations`, один `bundle_id`) на окно, срок `holdExpiresAt` = сейчас + `reservationTtlMinutes` (30 по умолчанию); с `tripId` — совместимость с грузом рейса (`fleetrules.Compat`, 409 `vehicle_incompatible` с причинами через «; »), рейс → «Осмотр перед выездом»; занятый интервал — 409 `reservation_overlap` |
| `getReservation`, `listReservations` | S2-03 | брони области `fleet.reservations.read` (машина подразделения или «свои»: водитель, автор); истёкший hold читается как `expired` |
| `releaseReservation` | S2-03 | снять действующий hold (`fleet.reservations.manage`, If-Match); рейс брони возвращается в «Запланирован» |

**AC-03:** 100 параллельных броней одной машины на одно окно → ровно один 201 и 99 × 409 `reservation_overlap`; пул tenant DB — 4 соединения, как у `cmd/api`; без взаимоблокировок.

`modules/sched` — ядро расписания (A-06, `design/docs/10-data-model.md`): ресурсы (`sched.resources`), hold комплекта ресурсов одной транзакцией под блокировкой ресурсов, истечение holds перед вставкой, снятие и потребление. Им пользуются бронь W2.02, назначение машины W2.03 и старт рейса W2.05.

Go-сид: семь машин «Альты» (`logisticsSeed('t-alta')` = `mock-data.js` 14.10) в `cmd/seed/fleet.go` с id PD-30 (`seedID("t-alta", "v1")`), как у MSW.

## 4. Контракты

Контракт не меняется (только реализация `0.5.0-stage2`). Внутренние интерфейсы (аддитивно):

```go
// package sched — ядро расписания (A-06)
type Kind string                    // vehicle | person | room | equipment (sched.resources.kind)
type Claim struct{ Kind Kind; Ref, Home uuid.UUID }
type Window struct{ Start, End time.Time } // [Start, End)
type HoldRequest struct {
    Bundle uuid.UUID; Claims []Claim; Window Window; ExpiresAt time.Time
    SourceType string; SourceID uuid.UUID; CreatedBy uuid.UUID; Now time.Time
    Replaces uuid.UUID // продолжение 17.10: заменяемый комплект (прежний hold рейса) — снимается внутри Hold после блокировки ресурсов
}
type OverlapError struct{ Claim Claim; Index int } // errors.Is(err, ErrOverlap)
func Hold(ctx, tx pgx.Tx, r HoldRequest) error                       // блокирует ресурсы, истекает holds ≤ Now, вставляет строки
func Release(ctx, tx pgx.Tx, bundle uuid.UUID, now time.Time) (int64, error) // ErrNotHeld; новая revision
func Consume(ctx, tx pgx.Tx, bundle uuid.UUID, now time.Time) (int64, error) // для W2.05; ErrNotHeld, ErrExpired
```

Отображение строк на контракт:

- `Reservation.id` = `bundle_id`; строка ресурса `vehicle` даёт `vehicleId`, строка `person` — `driverMemberId` (`people.person_profiles.id`, как `Member.id`); `window` = `during`, `timeZone` — пояс подразделения машины (`org.units.time_zone`; в `sched.reservations` пояса нет); `state`: `hold` до срока → `held`, `hold` после срока и `expired` → `expired`, `confirmed` → `held`, `released`, `consumed`; `tripId` — `source_id` при `source_type = 'fleet.trip'`; без рейса `source_type = 'fleet.reservation'`, `source_id = bundle_id`.
- `Vehicle.status` (03 §17.3): обслуживание (`service_state` ≠ `ok`) или блокирующий дефект `open|in_review|confirmed_out_of_service` → `maintenance` (+ `statusNote`: `service_note` / «критический дефект на проверке» / «неисправность подтверждена»); рейс `on_route|returning` → `in_use`; `submitted|rework` → `blocked`; рейс `assigned|inspection|defect_review` или действующий hold → `reserved` (+ `heldByTripId`); иначе `available`.
- `bodyType` `refrigerated` ↔ `reefer` в SQL; длины — метры ↔ миллиметры; `equipment` — `refrigerator` у машины с температурным режимом (колонки нет, §10 п. 4).
