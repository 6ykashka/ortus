# W2.104 — флейк изоляции TestIsolationFormsPublicW490/W483 на Windows

Вид: backend (тестовая оснастка). Владеет: `backend/test/isolation/target_test.go` (общая фикстура цели).

## Причина

Запрос гостя `getPublicUploadStatus` держит транзакцию ссылки и берёт вторую связь пула арендатора (Session/File модуля
files). Пул арендатора — `tenantctx.DefaultMaxConns` = 4 связи. Параллельные тесты всех модулей забивают пул такими
держателями, запросы ждут друг друга 20-30 с, выходят за `WriteTimeout` API (30 с), соединение рвётся и прокси набора
отвечает 502 «proxy error: EOF» (`forms_public_w490_test.go:362`, `forms_public_w483_test.go:130`). Отдельным запуском
(`-run`) конкуренции нет — зелёный. Проверенная и отвергнутая гипотеза: медленный отказ закрытого порта S3 на Windows
(Stat к хранилищу при этом не вызывается).

## Решение

Прокси набора пропускает не более двух запросов в API одновременно (`limitInFlight`, `maxInFlight = 2`): два запроса
требуют не более четырёх связей, никто не голодает.

## Проверка

`GOFLAGS=-p=2 go -C backend test -tags isolation -count=1 ./test/isolation/...` три раза подряд; `node tools/ci/pipeline.mjs --job isolation`.
