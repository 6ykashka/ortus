# W2.44 · Геоданные фото вырезаются на клиенте до загрузки (модель данных 4, ПДн §6)

Этап 2 · вид: frontend · работа после показа (резерв W2.41…W2.50, `decisions.md` «Ответы владельца 17.10», строка W2.44) · размер S.
Зависит от: W1.24 (`modal-upload`, `putObject`), W2.22 (`photos.ts`, сжатие холстом до 1600 px) — влиты в `main`.
Слот исполнителя: 6 (Vite 5206, Storybook 7206, API 8106, эталон 4106, `ortus-s6`). Новых страниц нет; поведение страницы `driver-today` не меняется визуально.

## 1. Цель

Ответ владельца 17.10 (модель данных 4): «EXIF-геоданные вырезать на клиенте (ПДн §6)»; D-08 — сжатие до 1600 px по длинной стороне. В W2.22 геоданные снимались только перекодированием холстом; без декодера (HEIC в Chromium и Firefox, битый файл, нет `createImageBitmap`) уходил исходный файл с GPS. Цель — **ни один путь подготовки фото не отправляет геоданные**:

1. Холст декодирует файл → сжатие до 1600 px и JPEG 0,85 (как W2.22), затем контрольный проход вырезания метаданных.
2. Холст не декодирует → вырезание метаданных из байтов без перекодирования:
   - JPEG — COM и все сегменты APPn, кроме нужных декодеру APP0 (JFIF), APP2 `ICC_PROFILE` и APP14 `Adobe` (уходят APP1 Exif и XMP, APP2 `MPF` и FlashPix, APP6 GPMF GoPro с GPS, APP13 Photoshop/IPTC и прочие сегменты производителей), и всё после EOI основного изображения (вторые кадры MPF с собственным Exif); ориентация сохраняется минимальным Exif с одним тегом Orientation (возврат 1);
   - PNG — `eXIf` и текстовые чанки (`tEXt`, `zTXt`, `iTXt`: XMP и «Raw profile type exif»), всё после `IEND`;
   - WebP — чанки `EXIF` и `XMP `, флаги VP8X, размер RIFF;
   - HEIF/HEIC/AVIF — данные элементов `Exif` и `mime` `application/rdf+xml` (по `iinf`/`iloc`, способы 0 и 1) обнуляются на месте: структура боксов и `ftyp` (сниффинг сервера) сохраняются. Разбор строгий (возврат 1): элемент Exif или XMP, данные которого не найдены (битый `iloc` или `infe`, обрезанный `meta`, HEIF-бренд без `meta`, способ 2), — исключение, загрузка падает, оригинал не уходит.
3. Тот же лёгкий проход — в общем диалоге загрузки (`modal-upload`, W1.24): фото без сжатия, но без геоданных.

## 4. Контракты

Без изменений. Публикуемый интерфейс модуля загрузки:

- `stripMetadata(bytes: Uint8Array): Uint8Array` — копия без геоданных и прочих метаданных съёмки; неизвестный формат — тот же массив;
- `stripFileMetadata(blob: Blob): Promise<Blob>`;
- `prepareImage(file: File): Promise<Blob>`, `fitSize`, `MAX_SIDE` (перенесены из `photos.ts`, там — реэкспорт).

## 10. Риски и решения по умолчанию

- HEIC без декодера не сжимается (D-08 выполняется только при декодировании) — уходит исходный размер без геоданных; ограничение сервера 20 МБ (`files.MaxBytes`) действует.
- `iloc` способ 2 (сборка из других элементов) не разбирается: у элемента Exif или XMP это исключение (возврат 1; на практике не встречается). Внешняя ссылка данных (`data_reference_index` ≠ 0) — данных в файле нет, вырезать нечего.
- Удаляются и иные метаданные (камера, серийный номер, миниатюра Exif) — по ПДн §6 это допустимо и проще, чем вырезать только GPS IFD.
