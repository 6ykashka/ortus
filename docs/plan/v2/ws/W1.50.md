## 1. Цель

1. **`POST /api/v1/dev/login` принимает тело `{persona, email, displayName}`.** Поля `email` и `displayName` необязательны; без них вход прежний (только аккаунты сида и фикстур изоляции, неизвестный subject → 401 `session_expired`).
2. **Новый человек (только `APP_ENV=dev|e2e`).** Если subject персоны не найден в `accounts` (issuer `urn:ortus:dev`), а в теле есть корректный `email`, аккаунт создаётся так же, как при первом входе OIDC: `oidc.PGAccounts.Upsert` с `issuer = urn:ortus:dev`, `subject = persona`, `email_norm = lower(trim(email))`, `display_name = displayName` (пусто — адрес, как `Identity.Name` OIDC), без членств. Затем выпускается сессия; ответ — тот же `200 {userId, csrfToken}`.
3. **Повторный вход** того же subject — тот же аккаунт (поиск по `(issuer, subject)` находит его; `email`/`displayName` повторного входа аккаунт не меняют). Гонка двух первых входов сходится на `on conflict (issuer, subject)` — один аккаунт.
4. **Где создание запрещено (одинаковый отказ 401 `session_expired`, 12 R5):**
   - `APP_ENV` не `dev`/`e2e` (в prod маршрут и так не монтируется — `config.go` запрещает `AUTH_PROVIDER=dev` с `APP_ENV=prod`; пакет `dev` отказывает сам, если ему передали другое окружение или не передали хранилище);
   - персонаж-псевдоним (`owner`, `manager`, …) — его subject из сида, создавать его «под чужим именем» нельзя;
   - issuer операторов (`op-N`, `operator`) — оператор платформы не заводится dev-входом;
   - нет `email` или он некорректен (не `local@domain`, длиннее 254, с пробелами/управляющими символами); `displayName` длиннее 200 символов или с управляющими символами.
   Заблокированный (`locked`) или удалённый аккаунт — 401, как раньше.
5. **e2e-kit:** `persona.ts` — `newcomer(email, displayName)` → тело dev-входа нового человека с детерминированным subject `new-<адрес>` (повторный вход — тот же аккаунт), `isNewcomerSubject`. Список `PERSONAS` (персонажи эталона) не меняется.
6. **`cmd/api`** передаёт dev-провайдеру окружение и хранилище аккаунтов OIDC (`oidc.PGAccounts` control DB) — одна опция в `app.go`, одно поле `deps`, одна строка `main.go` (через интегратора, как W1.41).

## 4. Контракты

Контракт API не меняется: `/api/v1/dev/login` вне OpenAPI (W0.09). Тело входа расширено необязательными полями (строгий разбор, лишние поля — 400 `unknown_field`, как раньше):

```json
{ "persona": "new-i.novikov@alta.example", "email": "i.novikov@alta.example", "displayName": "Иван Новиков" }
```

Внутренние интерфейсы:

```go
package dev
type Creator interface { // oidc.PGAccounts, authhttp.Accounts
	Upsert(ctx context.Context, id oidc.Identity) (oidc.AccountRef, error)
}
type Option func(*provider)
// Newcomers: subject вне сида с e-mail создаёт аккаунт (issuer urn:ortus:dev); только appEnv dev | e2e и c != nil.
func Newcomers(appEnv string, c Creator) Option
func Routes(r chi.Router, m *session.Manager, accounts Accounts, opts ...Option) // прежние вызовы компилируются
```

```ts
// frontend/packages/e2e-kit/src/persona.ts
export interface NewcomerLogin { persona: string; email: string; displayName: string }
export const NEWCOMER_PREFIX = 'new-';
export function newcomer(email: string, displayName: string): NewcomerLogin;
export function isNewcomerSubject(value: string): boolean;
```
