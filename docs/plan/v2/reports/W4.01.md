## Сделано

**Оценщик `backend/internal/platform/authz`.**

1. **Виды этапов 4–7** (ADR-0014 п. 3): `ModuleKinds()` — `space`, `page`, `folder`, `doc`, `account`, `chat`, `repair_project` (объектные, PD-53) и `relation` (люди связи записи `Resource.Related`, предикат по `Columns.Related`; без объекта, Q-W4.02-1). `Kinds()` = `PilotKinds()` + `ModuleKinds()`, их регистрирует `New`. `FutureKinds` пуст: `repair_object` заменён на `repair_project`, `service_direction` не вводится (Q-W4.02-4). Имя `Scope.kind` равно ключу каталога.
2. **RS-08**: `project` — только проект «Задач» (направление «Обращений» — сервисный проект задач); объект ремонта — `repair_project`. Тест: роль на проект не покрывает объект ремонта с тем же id, и наоборот.
3. **Иерархия объектов** (ADR-0014 п. 4): `Resource.Ancestors` (предки своего вида), `Columns.Paths` (SQL-массив «объект и предки»). Хук `ObjectResolver` в `Evaluator.Places` даёт место объекта (`Place`: подразделение, содержащие объекты, предки, контейнер, ветка узлов). Резолверы вызываются цепочкой: страница → её пространство → подразделение и уровень. Сбой — `dependency_unavailable`. Резолверы регистрируют модули-владельцы таблиц (W4.31, W7.23, W5.x).
4. **Уровень контейнера** (`projAccess` W4.10, `kbAccess` W4.30): `Container` / `ContainerColumns`, `ProjectContainer`, `SpaceContainer`. Территориальные гранты (`tenant`, `unit`, интерфейс `Territorial`) дают: в открытом контейнере — всё, в ограниченном — только чтение (возврат 1: действия чтения регистрирует модуль, `Evaluator.ContainerReads`), в закрытом — ничего; пустой уровень = закрытый. Роль на контейнере, `self` и `relation` от уровня не зависят; в проекте своя роль заменяет территориальные гранты (возврат 1, `Container.RoleReplaces`). TP-03 (Q-W4.10-4): закрытый проект закрыт и владельцу, кроме его роли в проекте — гранты владельца читаются только в этом случае. KB-04 (Q-W4.30-9): закрытое пространство владелец видит. То же правило в `ScopeQuery`: условие на колонку уровня; у владельца — `level in ('open','limited') or <его гранты>`.
5. **ACL на узлах** — `NodeACL`, ACL оценщика по умолчанию, правила в `Evaluator.NodeRules`. Режимы `inherit` / `edit` / `listed`; записи `all`, `member`, `group`, `role` (+ подразделение; роль на объекте действует только на нём), `relation`. Ветка проверяется сверху вниз. Если читать даёт только роль на узел, проверка начинается под самым глубоким таким узлом. `listed` без записи субъекта — `Denied` (404). Правку решает ближайший узел со своим режимом: записи «правит», руководитель (`NodeRule.Manage` из роли объектного вида — возврат 1), автор с `NodeRule.Create`; остальным — новый ответ `Forbidden` (403, узел виден). Запись «правит» даёт правку тому, кто видит узел (`ACLGrant`). Записи `group` — через `GroupSource` (`PGSource`/`TxSource.Groups`, группы читаются, только когда встретилась запись группы). Владелец списки проходит.
6. **`Explain`**: место объекта определяется как в `Permit`. `other_object` теперь по `Covers` (предок совпадает). Сбой зависимости при выборе ответа на отказ возвращается, а не превращается в «запрещено» (Q-W1.04-21). Сбой `Covers` — `dependency_unavailable`.
