# W7.12 Шлюз WebSocket: подсказка чата chat.changed

Этап 7 · шаг 7.1 · размер M · вид `backend`, страниц нет. Зависит от W1.07 (канал `platform/notify/realtime`), W7.00 (кадр `chat.changed` в контракте 0.12.0-stage7, ADR-0016).

## 1. Цель

Довести подсказку чата до сокета: `chat.changed {chatId, lastSeq}` без текста, имён и файлов (ADR-0015). Клиент перечитывает `listChatMessages?afterSeq`. Решение по умолчанию Q-W4.00-chats-7: шлюз ADR-0015, без `typing` и присутствия; Centrifugo — отдельным ADR при необходимости.

## 2. Границы файлов

Пишу только в `backend/internal/platform/notify/realtime/**`, этот бриф, `docs/plan/v2/reports/W7.12.md`. Не трогаю `api/**`, хранение чатов (W7.11).

## 3. Что делаю

- `Hint` получает `ChatID`, `LastSeq`; `Validate` принимает `chat.changed` (chatId и lastSeq > 0 обязательны, только аккаунты, без причины и сессий), остальные типы с chatId отвергает; кадр `Hub.message` несёт оба поля.
- Аудитория — участники чата, проверяются дважды: при постановке (`ChatPublisher.Publish` берёт состав у `ChatAudience`, пустой состав — подсказки нет, ошибка источника — отказ) и при доставке (`ChatFanout` в `cmd/api` пересекает адресатов с актуальным составом, ошибка источника — подсказка не уходит, закрыто по умолчанию).
- Снять `t.Skip` с `TestHintChatChangedAcceptedPendingW712`, строка `TestHintValidate` становится ok.

## 4. Тесты первыми

Unit: `TestHintValidate` (chat.changed), `TestHintChatChangedAcceptedPendingW712`, `TestHubDeliversChatChanged`, `TestChatPublisher*`, `TestChatFanout*`, шлюз по сокету — чужой аккаунт не получает; `EncodeHint`/`DecodeHint` с полями чата.

## 5. Изоляция

Строки канала живут в пакете (решение 11 брифа W1.07): `TestGatewayChatChangedMembersOnly` — не участник чата и аккаунт другой организации не получают подсказку ни при постановке, ни при доставке.
