### 1.2 Ширина

Модуль не различает 390/768/1440: медиазапросов нет, превью 1280×860 (`ЗП:318`), макеты 1a–1e — фиксированные 1280 px. Поведение на узких экранах следует из flex-wrap:

- список проектов — таблица `min-width:620px` внутри карточки с `overflow-x:auto` (`ЗП:33–36`): на 390 и 768 прокручивается по горизонтали;
- панель «Новый проект» (`flex:0 1 440px; min-width:300px`) на ширине меньше примерно 900 px уходит под список;
- доска — `grid-template-columns: repeat(auto-fit, minmax(200px,1fr))` (`ЗП:127`): на 390 — одна колонка, на 768 — три;
- карточка задачи (`flex:0 1 420px; min-width:300px`, `ЗП:144`) на узком экране уходит под доску. Кнопки «назад к доске» нет, только «Закрыть задачу»;
- диалог «Новая задача» — `width:min(720px,100%)`, отступ 16 px, тело `max-height:68vh` с прокруткой (`ЗП:98–101`);
- таблица участников — `min-width:640px` с горизонтальной прокруткой (`ЗП:202–205`);
- вкладки — `overflow-x:auto` (`ЗП:84`).

Для 390 в макетах нет ни одного экрана: телефонная раскладка будет no-reference (Q-…-14).

### 1.3 Подробно

**Загрузка и ошибки модуля.** «Загружаем проекты…» (`ЗП:22`; пока не загружены `models.js` и БД, `ЗП:349`). При ошибке импорта появляется тост «Не удалось загрузить модуль: {message}» (`ЗП:333`). Отдельного экрана ошибки загрузки списка нет. Общий тост `role="status"` внизу по центру (`ЗП:315`). Ошибки команд показываются тостом, если они не встроены в форму (`ЗП:339–341`; оболочка гасит `validation`, `transition`, `forbidden` и показывает сообщение модуля).

**tasks-projects (`ЗП:24–47`).**
- Заголовок «Проекты», подпись «Видны проекты, где у вас есть право «Задачи · Читать»», кнопка «Новый проект» (только при `canNew`).
- Таблица: «Проект / Область / Доступ / Людей / Открыто». В строке: плашка ключа, название, подзаголовок «{владелец} · процесс v{N}», «· воронка заявок» или «· процесс не настроен» (`ЗП:361`). «Область» — имя подразделения или «Вся организация». «Доступ» — чип «Открытый» (`public`) / «Ограниченный» (`visibility`) / «Закрытый» (`lock`), у воронки — «Воронка» (`filter_alt`). «Людей» — участники с доступом без владельца, у проекта без процесса — «—». «Открыто» — задачи не в категории «Готово» (у проекта без процесса — не «Готово», «Объект», «Отказ»).
- Пусто: «Проектов, доступных вам, пока нет» (`ЗП:44`). Это видит прораб: роль `r-foreman @ self` в наследование не идёт (`models:200`).
- Подсказка: «Права в проекте отдельно не настраиваются: действуют роли из «Пользователей и ролей» с областью фирмы, региона или самого проекта. Одна роль — одинаковые права во всех проектах.» (`ЗП:46`).
- Клик по строке открывает доску проекта; по «Заявки · Ремонт» — `onNav('leads')`, то есть старую доску (`ЗП:362`).
- В списке: проекты с `projCan(view)`, все воронки и все проекты без процесса (`ЗП:352`). Например, «Салон · Тверская» у «Лотоса» виден с подписью «процесс не настроен».

**tasks-project-new (`ЗП:48–71`, `356–373`).** Это боковая панель, а не мастер (в 1a — мастер в три шага).
- «Новый проект», закрыть (`aria-label="Закрыть"`).
- «Название» (placeholder «Например, «Ремонт · ЖК Речной»»). «Ключ» (`maxlength=6`, заглавные; заполняется сам по названию, `autoKey` `ЗП:524`; подсказка «Номера задач: {KEY}-101, {KEY}-102… Ключ уникален в организации.»).

- «Кто видит проект» — радиогруппа: «Открытый» — «Все с правом «Задачи» в области видят и работают с задачами»; «Ограниченный» — «Все в области видят; создают и меняют задачи участники проекта»; «Закрытый» — «Только участники проекта и владелец бизнеса» (`ЗП:323`). По умолчанию — «Ограниченный».
- «Процесс» — переключатель «Простой / С согласованием / Копия проекта». Для копии появляется выбор проекта-образца «{KEY} · {name} · v{N}». Пояснения (`ЗП:370`): простой — «Новая → В работе → На проверке → Готово. «Принять» и «Вернуть» — у руководителя проекта.»; с согласованием — «… «Согласовать»: достаточно одного согласующего, автор свою не согласует, при отказе — «В работе».»; копия — «Статусы и переходы копируются один раз и дальше меняются независимо. Правила автоматизации копируются выключенными.»

- После создания: тост «Проект «X» создан», открывается вкладка «Участники» созданного проекта (`ЗП:372`).
- Ошибки (`api:644–659`): «Создавать проекты может роль с правом «Задачи · Настраивать»», «Название — не короче 3 символов», «Ключ — 2–6 заглавных букв или цифр, первая — буква», «Ключ {K} уже занят», «Выберите область проекта», «Выберите проект, процесс которого копировать».

**tasks-board (`ЗП:89–142`).**
- Фильтры-чипы «Все», «Мои», «Ждут моего согласия · {N}» (`ЗП:389–390`). «Мои» — `assignee === me.name`. «Ждут» — есть согласующий переход, доступный мне, или маршрут документа ждёт меня.
- Быстрое создание (только `projCan(create)`): поле «Новая задача — Enter» и кнопка «Задача». Пустое поле открывает диалог, с текстом — создаёт задачу сразу (тост «Задача создана», открывается её карточка; `ЗП:525`).

- Карточка на доске: тема; чип связи «↳ {parentId}» у подзадачи или «☰ {готово}/{всего}» у родителя (`ЗП:499`); чип согласования (`how_to_reg`) — «Ждёт вас», «На согласовании» или «Маршрут документа»; моноширинный id, чип приоритета («Срочно», «Высокий», «Обычный», «Низкий»), срок «ДД.ММ», инициалы исполнителя (`title` — имя).

Причины: «не больше 30 файлов на задачу», «больше 20 МБ», «пустой файл», «такой тип не принимаем» (`ЗП:517–521`).

Без флажка открывается карточка новой задачи.

## 3. Права и области

### 3.1 Глаголы эталона → действия каталога

Эталон проверяет пять глаголов роли `actions.tasks` (`models:181`). Каталог (`api/permissions.yaml:99–133`) уже содержит все 10 действий (`tasks.approve`, `.members.manage`, `.workflow.manage`, `.automation.manage` добавлены из d21:109–116). Новых ключей не нужно.

|---|---|---|
| `view` «Читать» | `tasks.projects.read`, `tasks.read` | видимость проекта и задач, кандидаты в исполнители, родитель |
| `create` «Создавать» | `tasks.create` (+ `files.upload` при вложениях) | быстрое поле, диалог |
| `edit` «Менять статус» | `tasks.transition`, `tasks.update` (исполнитель, приоритет, чек-лист, связи, вложения) | переходы, поля карточки |
| `review` «Согласовывать» | `tasks.approve` | согласующий переход, «Вернуть на доработку» |
| `settings` «Настраивать» | `tasks.members.manage`, `tasks.workflow.manage`, `tasks.automation.manage`; удаление чужого файла; доступ проекта | вкладки «Участники», «Процесс», «Автоматизация» |
| `M.can(tasks, settings)` без области | `tasks.projects.manage` (tenant, unit) | «Новый проект» |

Шаблоны ролей проекта есть в каталоге: `project_manager`, `project_approver`, `project_executor`, `project_viewer` (`api/permissions.yaml:637+`, `default_scope: project`). Они совпадают с `r-pm`, `r-approver`, `r-exec`, `r-viewer` эталона (`mock:175–178`). Исключение: `project_manager` содержит `tasks.projects.manage`, у которого нет области `project` (Р-10).

### 3.2 Уровень доступа проекта (`models:194–213`)

- Своя роль в проекте даёт все глаголы роли.
- Системная роль владельца в эталоне даёт всё, включая закрытый проект. TP-03 от 17.10 и W4.10 (Q-W4.10-4): закрытый проект — только по роли в самом проекте.
- Унаследованная роль (область `tenant` / `unit`, покрывающая `p.unit`, не `project` и не `self`): в открытом проекте — все глаголы роли, в ограниченном — только `view`, в закрытом — ничего.
- Заблокированный сотрудник — ничего.

### 3.3 x-scope операций

- `tenant-or-org-unit` — `createTaskProject`.
- `tenant-org-unit-project` — проектные операции, `createTask`, автоматизация, процесс, участники.
- `tenant-org-unit-project-self` — `listTasks`, `getTask`, `updateTask`, `transitionTask`, файлы, связи. Вариант `self` нужен для задач, где я исполнитель вне видимых проектов; эталон отдаёт их в проекции (`api:205`).

По PD-53 (B-4, ответа нет) роль `@ project` не даёт права вне проекта. Поэтому «Новый проект» у Котовой в реализации пропадает. Гейт и меню — `canAny` (Q-W0.11-1).

### 3.4 Области W4.01

Модулю нужна только область `project` (уже есть в `scope_kind`, tenant 0001:155) с `scope_ref` = проект задач. Области `space`, `page`, `folder`, `doc`, `account`, `chat`, `relation` модулю не нужны. Исключение — косвенно `doc`: задачи маршрутов документов живут в проекте ДОК (`docs.js:520`) или в «проекте папки» (`README:242`), это W7.

RS-08 (Q-81): тем же словом `project` в API ремонта названы объекты. W4.01 должен закрепить: `scope_kind='project'` — только проект задач, а объект ремонта получает свой вид (Q-…-1). `self` в наследование проекта не входит (`models:200`): роль прораба `@ self` с `tasks: view, create` не даёт видеть ни одного проекта.

### 3.5 Ограничения функций

- Функция «Водитель» в эталоне добавляет только надпись «финансы скрыты» в «Что может» (`ЗП:449`). Финансовых полей у задачи нет; «Сумма» есть только в 1d.
- В каталоге действий `restricted` у `core.tasks` нет, `sensitive` — `tasks.members.manage` и `tasks.automation.manage`.
- С пользовательскими полями (TP-05, S3) появится правило «функция driver не видит финансовые поля задачи». В этапе 4 — только надпись, как в эталоне.
- Правило автоматизации проверяет `edit` автора при каждом запуске (`api:157`). Отозванное право — запуск `error` и событие владельцам.
