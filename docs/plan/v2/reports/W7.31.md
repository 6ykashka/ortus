## Осталось fixme / открытые вопросы

Все со значением по умолчанию, по которому сделано; решения записаны в `decisionsNeeded` отчёта (файл `docs/plan/decisions.md` не правил).

- **Q-W7.31-1.** Миграция 0062 правлена на месте (ключ направления — кириллица, автоответ без автора, `messages.seq`). Стюард подтверждает или переносит правки в свой PR.
- **Q-W7.31-2.** «Обращения» — ядро или подключаемый модуль (`CORE_MODULES`, W7.00). По умолчанию вне реестра `modulesreg`: шлюз модуля не применяется, источник «Главной» — ядровой.
- **Q-W7.31-3.** Файлы клиента: в `files` нет назначения (`purpose`) и родителя для обращения → `initiate/completePublicServiceUpload` отвечают 503; вложения сотрудника — id готовых `files.objects`, имя «Файл» (имён в БД файлов нет). Нужны правка `files.purpose` стюардом и родитель `service/request` у W1.09.
- **Q-W7.31-4.** «Возврат денег — через кассу»: предложение кассе (`cash.Offer`) требует сумму, в `ServiceCompensationSet` её нет → запись в обращении и строка ленты; порт `CashPort` есть, адаптер не подключён. Нужна сумма в контракте.
- **Q-W7.31-5.** Пометка «касается сотрудника» (`about`): в контракте нет операции и поля, автопометки от модулей работ нет → ставится только сидом/БД. Нужен `aboutMemberId` в создании или автопометка по исполнителю работы (Q-W4.00-service-12).
- **Q-W7.31-6.** Задача из обращения идёт через порт форм `CreateFormTask` (источник задачи `forms/response`, связь с обращением — в связанных объектах). Нужен родовой порт «задача из модуля» у владельца W4.11.
- **Q-W7.31-7.** Портал: телефон обязателен (в БД он `not null`, в контракте необязателен) → 422; `workToken` и `fileIds` публичной отправки игнорируются (модулей работ и загрузок нет).
- **Q-W7.31-8.** Воркер: эскалация владельцу (+1 рабочий день) сделана в возврате 1; напоминание «Ждёт клиента» через 3 рабочих дня и авто-«Решено» ещё через 4 не сделаны — по значению по умолчанию Q-W4.00-service-3 они ждут каналов доставки W7.37.
- **Q-W7.31-9.** Ревизия черновика направления хранится в теле (`_rev`), первое сохранение после публикации — ревизия 2 (как MSW): в `direction_drafts` колонки нет.
- **Q-W7.31-10.** `paused_at` лежит на строках таймеров `first`/`resolve`; если у «Ждёт клиента» не осталось бегущих таймеров (как у ГРЗ-55), пауза нигде не записана — сдвигать нечего.
- **Q-W7.31-11.** Тип обращения в БД называется видом (`complaint`), а не `d-mas:complaint`, как в mock: `typeId` страницы W7.32 и адаптера надо брать из `listServiceDirections.types`.
- **Q-W7.31-12.** Паритет возможностей `/me/context`: сид даёт диспетчерам ГРЗ `service.*`, а в стадиях mock `service` ещё нет → `parity_integration_test.go` не сравнивает `service.*` стенда; фильтр снимается вместе с подключением стадии (строка интегратора W7.30).
- **Q-W7.31-13.** Оценка решения клиентом ≤ 3 попадает в очередь «Низкие оценки» (строка `service.ratings`, статус `open`), 4–5 — сразу `seen`.
