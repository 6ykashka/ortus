## 2. B-4 · Роли с объектной областью и проверка права без объекта (PD-53)

В прототипе 14.10 проверка `M.can(db, участник, модуль, действие)` без указания объекта засчитывает любую роль, в том числе выданную на один проект, пространство базы знаний, чат или кассу (`v2/analysis/B-domain-modules.md`, факты 4 и 6). Примеры из демо-данных:

- Марина Котова — участник одного проекта (роль `r-pm` на проекте `fleet`) — получает настройку задач (`tasks.settings`) **во всей организации** и может создать любой проект;
- автор одной страницы базы знаний получает право создавать и править страницы везде, включая закрытые;
- водитель-исполнитель задач проекта получает `tasks.edit` за пределами проекта.

В реализации это утечка прав. План v2 предлагает исправить, а отличие от эталона записать в allowlist.

| ID | Вопрос | Варианты | По умолчанию до ответа | Нужно к | Ответ |
|---|---|---|---|---|---|
| PD-53 | Даёт ли роль, выданная на объект (проект, пространство, страницу, папку, документ, чат, кассу, объект ремонта), право там, где объект не указан (создать проект, настроить модуль)? | (а) не даёт: право без объекта считается только по ролям с областью организации, региона или фирмы; объектная роль работает только на своём объекте; (б) даёт — как в прототипе, тогда это поведение фиксируется явно и проверяется тестами | (а) Не даёт. Роль с объектной областью не даёт права без объекта; расхождение с эталоном — в allowlist с PD-53. Пункт меню модуля при этом виден, если у человека есть хотя бы одна роль в модуле | шаг 1.4 · W0.11 (`access/can`), W1.04 (оценщик), W4.01 | |
