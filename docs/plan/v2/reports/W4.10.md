## Осталось fixme / открытые вопросы

`fixme`/`skip` нет. Решения по умолчанию (бриф §10), их нужно внести в `docs/plan/decisions.md` (файл не мой):

1. **TP-03 и владелец.** «Закрытый значит закрытый»: закрытый проект — только по роли в самом проекте, системная роль владельца его не открывает (в эталоне открывает). Владелец видит проект через «Проверить доступ» и аудит, при нужде назначает себя наблюдателем. В проекции такой проект владельцу не показывается; задачи, где он исполнитель, видны, как в эталоне.
2. **Старая доска: PD-53 и доступ проекта (исправлено в возврате 1).** `moveTask`, `toggleTaskCheck`, `commentTask`, `createTask` сначала проверяют право модуля «Задачи» где-либо (`canAny`, как `assertCan` эталона без области) — до поиска задачи. Затем объект: в проекте с процессом — `projCan` (TP-03, PD-60: закрытый — только по роли в проекте, унаследованный доступ в ограниченном — только чтение); в воронке «Заявки» без процесса — `can(tasks, verb, unit проекта, {project})` по PD-53 (роль проекта — в своём проекте, территориальная — в своей области). В эталоне проверка шла без области: любой грант `tasks.edit` в организации давал право на чужой проект. `createProject` — право «Задачи · Настраивать» вне проектов, Котова через `r-pm @ fleet` проект не создаёт.
3. **Видимость проекта = доступ (PD-60).** В эталоне `projVisible` показывает закрытый проект тому, у кого роль области, хотя `projAccess` даёт `null`. В домене закрытого проекта в списке нет.
4. **`initProjectWorkflow`.** В эталоне `pj()` требует процесс, поэтому команда на проекте без процесса не выполнялась никогда. В домене проект ищется без процесса: простой процесс и «ограниченный» доступ. Нужно ли запрещать это для воронки «Заявки» — решает W4.13 (судьба старого канбана).
5. **Проверки до изменений (PD-60).** `updateProject` и `setTaskField` сначала проверяют, потом меняют; в эталоне при ошибке в названии или описании успевали сохраниться доступ и исполнитель.
6. **Невидимый родитель.** `checkParent` отвечает `forbidden` «Нет доступа к задаче X», как в эталоне. По политике 404 ядра (`denyAccess`) должно быть `not_found` — выбор за W4.00 и W4.11 по контракту.
7. **Новые тексты** для случаев, на которых адаптер эталона падал (`TypeError`): «Задача не найдена», «Пункт чек-листа не найден», «Правило не найдено», «Проект не найден» (`not_found`). Их нужно добавить в словарь ошибок вместе с контрактом tasks (W4.00).
8. **«Лотос».** Стадии `normProjects` у «Лотоса» нет (`seedStagesFor`): проект «Салон · Тверская» остаётся на старой доске без процесса, как в эталоне.
9. **Время** в комментариях, журнале и событиях берётся из часов домена (`Clock`, Москва), а не из `new Date()`. В паритете поле `at` не сравнивается.
