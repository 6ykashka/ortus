# W6.20 «Объекты»: список, карточка 1a «Сводка», работы и допработы, назначение прораба (страницы на MSW)

Этап 6 · подволна 6a · вид `frontend` · размер L. Зависит от W6.00 (контракт `0.12.0-stage6`, MSW `repairs`), W6.10 (домен). Блокирует W6.21–W6.26 (они кладут свои вкладки в реестр вкладок карточки) и W6.90.

## 1. Цель

Страница `repair` («Объекты», `/t/:tenantId/repair`, ADR-0001: `?obj=&tab=&filter=&q=`) по эталону `design-2026-10-19` («Ортус CRM.dc.html» `:1921–2124`, `repairVM` `:4267–4428`, `assignForeman` `:4429`; разбор `docs/plan/v2/analysis/dor/repair.md` §1.2):

- список объектов: таблица (владелец, контент ≥ 880 px) или карточки (прораб всегда; владелец уже 880 px), фильтры «Активные · Требуют решения · До договора · Сданы» (у прораба «Активные · Сданы»), поиск «Адрес, заказчик, прораб», «Сначала то, что ждёт решения», пустые состояния;
- карточка объекта: шапка (чипы, готовность «по объёмам», кнопки), вкладки по правам (`repairs.finance.read`), вариант 1a «Обзор» («Требует решения», «Объёмы работ», «Фотоотчёт», «Как попасть на объект», «Люди на объекте», «Деньги», «Лента»);
- вкладка «Работы»: объёмы, «Отметка за сегодня» (прораб своего объекта: работа, объём, материал, бригада, фото), список отметок и «Принять объём» (`repairs.work_logs.review`);
- «Допработы»: форма прораба, чипы статусов, «Оценить в смете» (переход во вкладку «Смета»);
- диалог «Назначить прораба?» (`modal-assign-foreman`, `repairs.projects.manage`).

## 6. Решения по умолчанию

- Q-W6.20-1: вкладки других WS — заглушка «{Вкладка}: раздел ещё не подключён» с пунктами «Требует решения» этой вкладки (эталон: «в прототипе нет данных этого объекта»).
- Q-W6.20-2: «Демо: добавить фото» заменено выбором файла (`repair_evidence`, владелец `repairs/project`) без «Демо:» (Q-W4.00-repair-9); отметка и допработа требуют минимум одно фото.
- Q-W6.20-3: материалы формы отметки — остатки на объекте (`listProjectStock`, нужно `repairs.supply.manage`); без права — только «Без материалов» (дыра контракта: чтение остатков объекта прорабом).
- Q-W6.20-4: прораб для «Назначить» — первый активный участник с профилем `foreman` (как эталон); при нескольких — выбор в диалоге; нет — диалог «Нет сотрудника с ролью «Прораб»».
- Q-W6.20-5: «Маршрут» неактивна (Q-W4.00-repair-22); «Вернуть» (RS-09) без кнопки (Q-W4.00-repair-3).
- Q-W6.20-6: источники «Главной» и бейдж меню «Объекты» принадлежат домену и оболочке — в `integratorNotes`.
