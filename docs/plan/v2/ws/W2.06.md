# W2.06 ★ · Приёмка смены, проверка расходов, начисления (`modules/fleet/review`, `modules/finance`)

Этап 2 · подволна 2c · дорожка Б · истории S2-10…S2-12 · AC-05 · размер L · два ревьюера · путь показа 18.10 (бронь → осмотр → выезд → расходы → сдача → **приёмка менеджером**).
Зависит от W2.05 (рейс `submitted`, расходы `claimed`, `fleet.trip_reviews` в `TripPlan.lastReview`), W2.04 (осмотр сдачи — пробег), W2.02 (статус машины из состояния рейса, `sched.reservations`), W1.04 (оценщик: `blocked_by_function` закрывает `fleet.earnings.*` функцией «Водитель»), W1.10 (входящие). Блокирует W2.30 (конкурентность приёмки), W2.32, режим `stand` W2.21.
Слот 7: Vite `5207`, Storybook `7207`, API `HTTP_ADDR=127.0.0.1:8107`, эталон `4107`, compose `ortus-s7`, `ORTUS_SLOT=7`. Страниц нет; integration — testcontainers, сквозь стек — `cmd/api` (стек-тест) и набор изоляции.

## 1. Цель

1. **`modules/fleet/review`** — приёмка смены менеджером (S2-10, S2-11):
   - `reviewTrip` (If-Match рейса, Idempotency-Key): только из `submitted`, иначе 409 `invalid_transition` «Смена уже обработана». Решения:
     - `approve` — рейс `accepted` (`reviewed_at`, `reviewed_by`), **машина освобождается только здесь**: статус машины W2.02 считается из состояния рейса, пробег машины — из осмотра сдачи, потреблённая бронь укорачивается до момента приёмки (интервал снова свободен); все расходы `claimed` рейса подтверждаются (Q-W2.21-5);
     - `maintenance_required` — то же, машина «Недоступна · нужен ремонт» (`service_state = maintenance`, Q-W2.00-5);
     - `rework` — рейс `rework`, машина остаётся занятой; нужен непустой комментарий («Опишите, что нужно исправить») и хотя бы один раздел (`photos, odometer, expenses, checklist`; «Отметьте хотя бы один раздел для доработки»);
     - `reject` — 422 «В пилоте смену принимают или возвращают на доработку.» (Q-W2.00-5); `steps` не у доработки — 422.
   - строка `fleet.trip_reviews` (попытка = число решений + 1), аудит `fleet.trip.review`, событие `fleet.trip.reviewed.v1`, уведомление водителю («Смена {номер} принята. Машина свободна.» / «… возвращена на доработку: {комментарий}»). Ответ — Trip 0.1.
   - `reviewTripExpense` (If-Match расхода): `approve | reject` расхода `pending` (иначе 409 «Расход уже проверен.»), пока смена не принята; аудит `fleet.expense.review`, событие `fleet.expense.reviewed.v1`.
   - доступ: `fleet.trips.review` / `fleet.expenses.review` над подразделением рейса (владелец — любой); невидимый рейс — 404, видимый без права — 403; **водитель рейса не принимает свою смену и свои расходы** — 403.
2. **`modules/finance`** — начисления отдельным маршрутом (S2-12, AC-05, Q-55 по постановке 18.10: менеджер создаёт начисление отдельным действием после приёмки; минимальный ledger):
   - `getTripEarnings`, `listTripEarnings`, `setTripEarnings` над `finance.earnings`; начисление есть только у принятого рейса с водителем: до первой записи это черновик 0 ₽, ревизия 1 (контракт: «record with zero amount/revision 1 … updates always use If-Match»); `setTripEarnings` с If-Match создаёт или меняет запись (ревизия + 1);
   - ledger: каждая запись — строка аудита `finance.earnings.set` с `sensitivity = restricted` (было → стало, примечание расчёта); примечание `calculationNote` читается из последней такой строки (колонки в 0002 нет);
   - доступ: `fleet.earnings.read` / `fleet.earnings.manage` над подразделением рейса, без «своего» (водитель своё начисление не видит); функция «Водитель» закрывает начисления оценщиком — 403 `function_blocked` (D-10, ADR-0011); до приёмки — 404 «Начисления по рейсу нет: оно появляется при приёмке смены.».
3. **Подключение** — `cmd/api/fleet_review.go` (наложение тега Fleet) и `cmd/api/earnings.go` (сервер тега Earnings); по одной строке в `newFleet` (`fleet.go`) и `Servers` (`main.go`).
4. **Изоляция** — `fleet_review.yaml`, `fleet_review_gate.yaml`, `finance.yaml`, `finance_gate.yaml` (красные до хендлера); `authz.yaml`: строка `getTripEarnings` с `pending: W2.06` — по факту хендлера (id подразделения — не рейс → 404).
