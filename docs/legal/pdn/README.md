# ПДн в Ортус CRM: пакет черновиков (W3.04)

Статус: **черновики для юриста**. Это не юридическое заключение (так же сказано в `design/docs/15-quality-security.md`). Ни один документ пакета не вводится в действие и не публикуется, пока юрист не ответил на вопросы из [questions-for-lawyer.md](questions-for-lawyer.md). Реальные персональные данные в продукт не принимаются, пока не закрыты Q-W3.04-1…Q-W3.04-6 и не подано уведомление в Роскомнадзор (ответ владельца 17.10, ПДн п. 3).

## Исходные решения (следовать им)

- Роли сторон (ПДн п. 1, 17.10): двойная. Для данных тенанта Ортус обрабатывает по поручению клиента; для аккаунтов входа Ортус сам оператор. Юрист подтверждает.
- Локализация (п. 2, ADR [0006](../../adr/0006-hosting-storage-secrets.md), D-05): российское облако, одна зона, включая бэкапы и логи с ПДн. Провайдер пока не назван (W3.00 отложен).
- РКН, политика, согласия (п. 3): уведомление до приёма реальных данных; политика на сайте; согласия сотрудников пилота оформляет работодатель (трудовые отношения); согласия клиентов SPA это этап 5.
- Сроки после расторжения (п. 4): `read_only` 30 дней с выгрузкой, удаление через 90, бэкапы 30 дней, полное удаление не позднее 120 дней; зафиксировать в договоре.
- Медицинские сведения SPA (п. 5): не собираются; вместо текста противопоказаний отметка «клиент подтвердил отсутствие противопоказаний».
- Геоданные (п. 6): не собираются. EXIF вырезается на клиенте (W2.44, Q-W2.44-4…6); GPS, телематика и маршруты вне v1 и требуют отдельного решения с согласием.

## Как поддерживать

Новая миграция или поле контракта с ПДн добавляет строку в карту в том же PR (владелец W3.04 или ответственный за ПДн). Колонка «Сверено» в карте хранит коммит, на котором строка сверена со схемой. Проверка карты по миграциям вручную: `Select-String backend/migrations -Pattern "full_name|phone|email|plate|vin|contact|address"`.

Сроки в картах: «факт» — что делает код сейчас, «цель» — что обещано владельцем 17.10 и ещё не реализовано. Расхождения собраны в разделе 5 карты.
