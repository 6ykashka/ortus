## 1. Цель

После W2.24 приложение Ортус устанавливается как PWA (манифест, service worker, иконки), а водитель «Альты» без связи (D-09, ADR-0010, ответ владельца 17.10):

- снимает фото осмотра — слот «На устройстве · ждёт связи», фото сжато и хранится на устройстве (IndexedDB), уходит само, когда появится связь;
- заполняет осмотр перед выездом — черновик сохраняется на устройстве и переживает перезапуск; **«Выехать на маршрут» без связи недоступна** (онлайн нужен только на «Выехать»), бронь — только онлайн;
- сохраняет расход — «Сохранить на устройстве», тост «Расход сохранён на устройстве. Отправится при появлении связи», строка «Локальный черновик» с чипом «На устройстве»;
- сдаёт машину — «Сохранить сдачу на устройстве», тост «Сдача сохранена на устройстве и ещё не принята сервером», карточка «Сдача сохранена на устройстве» с чипом «Ожидает отправки»;
- видит очередь отправки со статусами: ожидает («На устройстве», «Ожидает отправки»), отправляется («Отправляется», «Отправляется…», баннер «Связь восстановлена.»), отправлено (тост «{операция} — принято сервером», строка «Принято сервером»), ошибка («Ошибка», «Ошибка отправки: {сообщение}», тост «{операция}: {сообщение}»), повтор («Повторить» и автоматически при появлении связи);
- в баннере «Нет связи.» видит число ожидающих операций «(ожидают отправки: N)».

Повтор отправки идёт с тем же `Idempotency-Key` (сервер не создаёт второй расход и вторую сдачу, Q-W2.22-9).

## 4. Контракты

Контракт `0.5.1-stage2`, WS его не меняет. Очередь отправляет те же операции, что экран онлайн:

| Операция очереди | Шаги | Идемпотентность |
|---|---|---|
| Расход (`expense`) | чек на устройстве → `uploadPhoto` (initiate → PUT → complete → `ready`); `createTripExpense` | ключ элемента — один на все повторы |
| Сдача (`return`) | фото на устройстве → `uploadPhoto`; `submitInspection` (return); `getTripPlan` (ETag) → `returnTrip` | два ключа элемента (осмотр, сдача); принятый осмотр не отправляется повторно |
| Фото черновика осмотра | `uploadPhoto` при появлении связи | сессия загрузки на попытку |

Публикуемые интерфейсы: `src/pwa/status.ts` — `useQueueStatus(tenantId)` для баннера оболочки; `src/pwa/store.ts` — `deviceStore()`, `clearDeviceData()`; `src/pwa/plugin.ts` — `pwa()` для `vite.config.ts`; `src/pwa/register.ts` — `registerServiceWorker(env)`.

## 10. Риски и решения по умолчанию

1. **Workbox не подключается** (ADR-0002 и 14-engineering называют Workbox): service worker написан вручную (~100 строк: предкэш по графу сборки, навигация «сеть, иначе кэш», `/api` мимо кэша) — новая зависимость не нужна. Переход на Workbox — решение интегратора.
2. **MSW и service worker приложения** занимают одну область `/`: в режиме mock и в dev service worker приложения не регистрируется; установка и оболочка без связи проверяются e2e на production-сборке (`pwa.spec.ts` собирает приложение и раздаёт его своим сервером).
3. **Без связи в режиме mock** ответы даёт service worker MSW, `context.setOffline` их не обрывает: очередь решает по `navigator.onLine`; сетевой сбой посреди отправки — сценарий `offline` (как `inbox.spec.ts`). На стенде `setOffline` обрывает настоящую сеть.
4. **Ручной «Повторить»** у ошибки отправки — нет в эталоне (03 §10.2: повтор только переключением связи, §15 п. 9): по умолчанию добавлена кнопка «Повторить» (подпись эталона слота фото) у строки расхода и у карточки сдачи; при появлении связи повтор идёт сам.
5. **Удалить элемент очереди** (ошибка, которую повтор не исправит, например 422) — нет в эталоне; по умолчанию не делается — вопрос владельцу.
6. **Хранение на устройстве**: IndexedDB `ortus-device`, ключи по организации и пользователю; фото — уже сжатые (1600 px, JPEG без EXIF); черновик и фото удаляются после принятия сервером, черновики старше 7 дней — при старте; при выходе из аккаунта — всё (15-quality-security). Предупреждения о неотправленном перед выходом нет — вопрос владельцу.
7. **Перезапуск без связи**: оболочка из кэша открывается, но смена (`/me/context`, рейс) не кэшируется — без связи после перезапуска — кадр загрузки оболочки с баннером «Нет связи.» (возврат 2; до него — ошибка загрузки); рабочий пакет смены для чтения без связи — вне карточки (07-ux §6 «может»), вопрос владельцу.
8. **Онлайн-команды** («Сохранить расход», «Сдать машину», «Выехать на маршрут») — один `Idempotency-Key` на повтор одной и той же команды (Q-W2.22-9).
9. **Обновление service worker** — без `skipWaiting`: новая версия активируется после закрытия всех вкладок приложения.
10. **Возврат 1** (ревью и проверяющий страницы):
    - карточка «Сдача сохранена на устройстве» без «Повторить» — цель Tab (`tabIndex=0`, имя по заголовку, рамка `:focus-visible`): иначе axe `scrollable-region-focusable` на `#ox-main` при 390 (как W1.54); фильтр правила в e2e снят;
    - выход из аккаунта во время отправки: `Outbox.close()` — ни записи на устройство, ни следующих операций, ответ запроса, начатого до выхода, отбрасывается; `clearDeviceData` ждёт записи очереди; оболочка ждёт очистки до 1,5 с;
    - элемент с ошибкой сервера повторяется только при появлении связи и по «Повторить» (обычный проход — монтирование экрана, таймер — его пропускает);
    - несколько вкладок: изменение списка — чтение, правка, запись под замком (Web Locks, иначе замок вкладки), отправка — одной вкладкой, BroadcastChannel — перечитать;
    - хранилище: таймаут 5 с и отказ — запасное в памяти (экран не висит на скелетоне); оболочка берёт «(ожидают отправки: N)» из устройства до экрана водителя;
    - предкэш — оболочка и маршруты водителя и входа (~0,9 МБ), шрифт значков — отложенно после установки и при первом запросе, модули других ролей не кэшируются.
11. **Возврат 2** (ревью и проверяющие страниц):
    - черновик осмотра (`useDeviceDraft`) подписан на `onDeviceClear`: выход закрывает область — отложенная запись снимается, правки, размонтирование и фото слотов (`savePhoto`) на устройство не пишутся, запись, начатая до выхода, выходом дожидается;
    - выход в одной вкладке останавливает очередь и черновик в других вкладках того же пользователя (BroadcastChannel `ortus-device:clear`; ключи удаляет вкладка, где нажали «Выйти»);
    - после перехода на запасное хранилище в памяти выход удаляет данные и из IndexedDB (`purge`, с таймаутом);
    - осмотр показывается после чтения черновика с устройства (до этого скелетон, чек-лист запрашивается параллельно); правки до восстановления ложатся поверх черновика с устройства;
    - «Завершить рейс» — повтор с тем же Idempotency-Key (как остальные команды экрана);
    - запуск без связи: кадр загрузки оболочки с «Нет связи» в шапке и баннером «Нет связи.» эталона с числом ожидающих на устройстве (по очередям организации маршрута — пользователь до `/me/context` неизвестен) вместо ошибки загрузки; связь появилась — `/me/context` запрашивается снова.
