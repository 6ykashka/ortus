## 1. Цель

После W2.25 «Главная» (`/t/:tenantId/home`, стартовая страница владельца и офисных сотрудников) в режиме `mock`:

- шапка страницы: «{дата} · {область}», `h1` приветствие по часам («Доброе утро, Дарья»), сводка «Требует решения: N. Сначала то, что блокирует работу.» / «Срочных вопросов нет.»;
- **«Требует решения»** — очередь `getMyDecisionQueue` (лимит 8, «показано 8 из N»), карточки собирает **реестр источников**: модуль кладёт провайдер `packages/domain/src/home/sources/<m>.ts` (виды `kind` → иконка, тег, заголовок, текст, кнопка, переход), реестр `sources.gen.ts` генерируется скриптом, общий VM (`home/queue.ts`) не правится при новом источнике. Источники этапа 2: `fleet` (блокирующий дефект → «Решить» → `review?trip=`, смена на приёмке → «Проверить», рейс без водителя → «Найти в пуле» / «Открыть пул» → `pool`), `tenant` (пробный период завершён / осталось N дней, место > 85 % → `modules`), `access` (сотрудники без роли → «Назначить» → `users?tab=people`). Неизвестный `kind` — нейтральная карточка без действия (контракт `DecisionItem.kind`). Источники этапов 4–7 (задачи, SPA, ремонт, обращения, документы, чаты, касса) — allowlist `out-of-stage` со сроком снятия;
- «Начало работы» (только владелец, пока не 3 из 3), «Сегодня в работе» (карточка «Логистика» по рейсам и машинам; пунктирные карточки неподключённых отраслевых модулей с «Подключить» у владельца), «Рейсы сегодня» (рейсы дня с чипом состояния), «Последние события» (входящие участника, до 5; «Событий пока нет»);
- состояния: загрузка (скелетон), пусто («Решений не требуется. Новые вопросы появятся здесь.»), ошибка очереди с «Повторить», офлайн (баннер оболочки, страница из кэша), организация только для чтения (карточка «Пробный период завершён»); раскладка 390/768/1440.

Компонент `@ortus/ui` `DecisionQueue` (заглушка W0.10, `OWNERS.DecisionQueue = W2.25`) заменяется реализацией по эталону (`:1733–1744`): заголовок со счётчиком, карточки с полосой тона, иконкой, тегом, текстом и одной кнопкой, пустое состояние.

## 10. Риски и решения по умолчанию

1. Дата «Среда, 1 октября» захардкожена в эталоне (Q-61) — реализация вычисляет дату по часам (в e2e часы 01.10.2026 10:30 МСК дают ту же строку).
2. Шаг «Назначить роли с областью» в эталоне выполнен, когда роль есть у Марины Котовой (Q-66). По умолчанию — выполнен, когда в очереди нет карточки «сотрудники без роли»; кнопка ведёт в «Пользователи и роли» (`?tab=people`).
3. Шаг «Пригласить сотрудников» (`members.length > 7` эталона) — выполнен, когда в организации больше одного участника.
4. «Последние события» эталона — адресные события участника; реализация берёт входящие (`listMyNotifications`, 5 последних).
5. Карточки «Салон и SPA», «Задачи» в «Сегодня в работе» и источники задач, SPA, ремонта, обращений, документов, чатов, кассы в очереди — модули этапов 4–7, `out-of-stage`.
6. Кто видит карточки организации — только владелец (вопрос 3 черновика S2-18; так решает сервер).
