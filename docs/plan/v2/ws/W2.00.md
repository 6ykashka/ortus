Решения по умолчанию в контракте:

- `TripPlan` — рейс от плана до приёмки (`fleet.trips`, 9 состояний `TRIP_STATE` + `cancelled`); `Trip` 0.1 — проекция той же строки после `startTrip` (тот же `id`, та же `revision`). Начислений в `TripPlan` нет (AC-05). Водитель с функцией «Водитель» видит только рейсы, где он водитель (прототип `view()`, D22).
- «Назначить на рейс» логиста — `assignTripVehicle` (рейс `planned|assigned`, проверка совместимости `compat` и брони, прежняя машина освобождается, hold брони на окно рейса); водитель бронирует `reserveVehicle` с `tripId`.
- Блокирующий дефект при выезде: `submitInspection` с `defects[].severity = blocking` → осмотр `requires_review`, дефект `in_review`, рейс `defect_review`, машина недоступна; `decideInspectionDefect`: `allow_departure` → дефект `resolved` («признан некритичным»), рейс `inspection` (выезд — обычный `startTrip` водителя); `confirm_out_of_service` → дефект `confirmed_out_of_service`, машина снята с рейса, рейс `planned`. Повторное решение → 409 `invalid_transition`. С шага 4.1 (W4.24) дефект становится задачей (D-29).
- Доработка: `reviewTrip` с `rework` требует непустой `comment` и ≥ 1 раздела (422 `validation_failed` с текстами прототипа «Опишите, что нужно исправить», «Отметьте хотя бы один раздел для доработки»); повторная сдача — новый осмотр `return` с `attempt + 1`.
- «Требует решения» — персональная лента по одной организации (как `listMyNotifications`): каждый источник фильтрует свои карточки правами участника; элемент — структурные поля (`kind`, `tone`, объект, параметры текста), текст собирает клиент из словаря; сортировка danger → warn → info → neutral, затем порядок источников.
