## Осталось fixme / открытые вопросы

Значения по умолчанию действуют; интегратор переносит в `docs/plan/decisions.md`.

- **Q-W7.11-1.** Роль в чате хранится в `chat.chat_members` (материализация источников), а не назначением `access.role_assignments` с областью `chat`: схема tenant 0001 такой области не допускает (`check scope_kind in (tenant, unit, project, warehouse, resource, self)`). Права в чате = действия шаблонов роли чата + то, что оценщик даёт в области организации или подразделения. Владелец бизнеса — неявная роль `owner` во всех чатах, кроме личных (в состав не пишется).
- **Q-W7.11-2.** В миграции 0060 нет колонок для ссылки «сообщение → задача», карточки документа, причины удаления и признака «сжато»: первые три лежат в `chat.messages.system_card` обычного сообщения (ключи `tasks`, `document`, `deleted`), последний — в `chat.chats.overrides.compressed`. Стюарду контракта — миграция 0063+: `messages.task_refs`, `messages.document_card`, `messages.deleted_reason`, `attachments.compressed`.
- **Q-W7.11-3.** Источник `relation` (прораб объекта) решает порт `Relations`; `nil` — никого (этап 6 приносит объекты ремонта). `trip_driver` — по `fleet.trips.driver_person_id`. Чат записи видит тот, у кого есть право на запись (`fleet.trips.read`, `repairs.projects.read`): для связанного с записью участника оценщику передаётся `Related = Persons = [я]` (область `relation`).
- **Q-W7.11-4. Закрыт возвратом 1.** Было: файлы чата: модуль `files` цель `chat_attachment` не знает (нет в `rules.go` и группах `quota.go`, нет родителя `chat.chat`), поэтому загрузить вложение через `initiateUpload` пока нельзя; `fileIds` проверяются по `files.objects` (цель `chat_attachment`, загрузил автор, `ready`). Правка модуля `files` — владельцу W1.09 (integratorNotes).
- **Q-W7.11-5.** Виды `Notification.kind` и `DecisionItem.kind` для `chat.*` в контракте нет — уведомления «Входящих» и карточка «Требует решения» не создаются, только события outbox (W7.15).
- **Q-W7.11-6.** Подсказка `chat.changed`: порт `Hints` (`nil` — не шлёт), вызывается после коммита с участниками чата; подключает W7.12.
- **Q-W7.11-7.** Временные сообщения не требуют `chat.ephemeral.send` (его нет в роли чата, расхождение DoR §5.1 п. 5): в личных чатах пишут все участники, в рабочих политика `temp = off` запрещает; одноразовые файлы — модератор и политика `temp ≠ off`.
- **Q-W7.11-8.** `history = none` ведёт себя как `since_join` (макет 1b даёт «За 30 дней», в контракте три значения `all / since_join / none`).
- **Q-W7.11-9.** Лимит места чата нельзя снять через API: в `ChatPolicyPatch.quotaMb` `null` неотличим от отсутствия поля (генерация даёт `*int64`). Значение можно задать, но не вернуть к «без лимита».
- **Q-W7.11-10. Закрыт возвратом 1.** Было: выгрузка истории: задание строится `Sweep` (CSV или JSON, текст после маски), но записи в объектное хранилище нет (в `platform/storage` только presign и чтение) — адаптер `chatBlobs.Save` возвращает ошибку, задание получает `failed`.
- **Q-W7.11-11.** Пересчёт составов — периодическая задача (`Runner`, интервал `SUBSCRIPTION_SWEEP_INTERVAL`, как у `lifecycle`; вне prod выключен, в prod 1 минута) вместо потребителей outbox: воркер событий в `cmd/api` не подключён. Изменение роли, группы, блокировки, прораба или водителя доходит до чатов за один период.
- **Q-W7.11-12.** Анонимные опросы требуют `CHAT_POLL_VOTER_KEY` (base64, не меньше 32 байт); вне prod ключ выводится из константы, в prod без ключа анонимный опрос — 503 `dependency_unavailable`.
- **Q-W7.11-13.** Заголовок личного чата в БД — «Личный чат» (колонка обязательна), клиенту отдаётся имя собеседника; при увольнении или блокировке собеседника чат у второго только для чтения (Q-W4.00-chats-23).
- **Q-W7.11-14.** Посев шаблонов ролей чатов новым тенантам и демо-данных «Альты» и «Лотоса» в `cmd/seed` не сделаны: шаблоны `chat_*` есть в каталоге контракта, роли организации создаёт владелец; существующим тенантам не добавляются (AUTH-09, Q-W4.00-chats-18).
- **Q-W7.11-15.** Анти-паттерны линтера: цикломатическая сложность (порог 13) превышена у операций-цепочек проверок; они помечены `//nolint:gocyclo // …` с причиной (30 функций и 20 тестов-сценариев). Декомпозиция — отдельная задача; `ListChats` и `PostMessage` уже разобраны.
- «Задача из сообщения»: задача создаётся в своей транзакции модуля задач до фиксации транзакции чата; сбой после — «осиротевшая» задача (порт `Tasks`).
- «Ознакомлен» и счётчик `ackWaitCount` считаются только у явных участников; владелец бизнеса, не вошедший в состав, подтверждений не ждёт.

### Что исправлено

1. **Вложения чата (major).** Модуль `files` теперь знает цель `chat_attachment` (`rules.go`: допустимые типы — документы задач плюс `video/mp4`, `video/webm`, `audio/mpeg`, `audio/ogg`; `scan.go`: сканер принимает их по содержимому; `quota.go`: группа «Вложения») и родителей `chat/chat` и `chat/export` (`files/chat.go`, регистрация в `cmd/api/files.go`). Читает файл участник чата (и владелец бизнеса во всех рабочих чатах, кроме личных): `ChatHider` закрывает чаты, где субъекта нет; новую загрузку не принимают архивный чат, роль «читатель» и объявления без ранга модератора. Теперь штатный путь `initiateUpload → PUT → completeUpload → проверка → postChatMessage(fileIds)` работает без прямых вставок в `files.objects`.
2. **Выгрузка истории (major).** В `platform/storage` добавлен `Uploader` (`S3.Upload` подписанным PUT, `Mem.Upload`); `files.Put` записывает серверный файл: проверка квоты (`quota_exceeded`), объект, строка `ready`, журнал, событие. `chatBlobs.Save` вызывает её, владелец файла — выгрузка (`chat/export`), читает создавший при праве `chat.export`. Задание `Sweep` теперь заканчивается `done` с файлом; тест скачивает файл и находит в нём текст сообщения.
3. **Запись в чужую схему (major).** `chatBlobs` больше не содержит SQL по `files.*`: `Move` → `files.Reparent`, `Remove` → `files.Release` (файл `rejected`, байты уходят из `committed_bytes`, журнал `release`; объект удаляется из хранилища после коммита транзакции чата — `Files.Remove` возвращает функцию для `afterCommit`), `ViewURL` → `files.ReadyKey`. Квота после очистки сходится (тест сверяет `files.usage.committed_bytes`).
4. **Попутно найдено тестом.** `createChatCleanup` с `olderThanDays: 0` (контракт допускает 0) падал в 503: колонка `chat.cleanups.older_than_days` требует ≥ 1. Теперь 0 и «не задан» пишутся как NULL (`olderThanColumn`).
5. **TDD (minor).** Красный тест возврата — `9027023b1` (три сценария `TestStackChatAttachments`, `TestStackChatExport`, `TestStackChatFileToRecord`; хвост красного прогона: `initiateUpload to a chat by a person outside it: 422, want 404`, `sql: no rows`, `initiateUpload to a chat by its owner: 422, want 201`); зелёные коммиты после него. Тесты `Upload` хранилища и `chat_test.go` модуля `files` (мелкие регрессии той же правки) написаны вместе с кодом. Задним числом красные коммиты для старых сценариев (место, очистка и др.) не восстановить; ограничение остаётся в отчёте как было.
6. **Тесты, закреплявшие набор Hider-ов** (`tasks_test.go`, `fleet_pool_test.go`, `files_parents_integration_test.go`), обновлены: четвёртый Hider — закрытые чаты.

### Открытые вопросы возврата (значения по умолчанию действуют)

- **Q-W7.11-16.** Родитель `chat/chat` читается по `files.read` (а не `chat.read`): шаблоны ролей `chat_*` существующим тенантам не посеяны (Q-14), и проверка `chat.read` закрыла бы файлы участникам. Доступ по членству держит `ChatHider`. Следствие: участнику нужны `files.read` и `files.upload` в области подразделения чата. Не учтено: чат «Финансы» для водителя и право на запись у чата записи (чат им закрыт, файл — только по членству).
- **Q-W7.11-17.** Файл выгрузки — в хранилище организации с целью `chat_attachment` (отдельной цели в контракте нет), владелец `chat/export`, читает создавший его при `chat.export`; считается в квоте; предел 20 МБ (`MaxBytes`), больший — `validation_failed` и задание `failed`.
- **Q-W7.11-18.** Медиа чата: добавлены `video/mp4`, `video/webm`, `audio/mpeg`, `audio/ogg`; `video/quicktime`, `audio/mp4`, `audio/aac` сканер не распознаёт — отклоняются `mime_mismatch`.
- **Q-W7.11-19.** Объект удалённого файла стирается из хранилища после коммита; сбой удаления оставляет сироту (запись в журнале приложения), строка файла при этом уже `rejected`.
- **Q-W7.11-20.** `olderThanDays = 0` в очистке означает «любого возраста» и пишется в журнал очисток как NULL.
- **Q-W7.11-21 (важно для показа).** Роли организации из посева не содержат действий `chat.*`: состав чата пропускает таких людей («У ролей сотрудника нет модуля «Чаты»»), так что на свежем стенде чатом пользуется только владелец. Тесты выдают роль SQL-ом (`chatterOf`). Нужен посев роли или шаблонов (Q-14) — пункт для W7.15/сида.
