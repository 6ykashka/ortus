### 4.2 CLI `tools/ci/pipeline.mjs`

`--job <id>` — шаги одной job (все шаги выполняются, job падает, если упал хотя бы один); `--all` — job по порядку `needs`, остановка на первой упавшей; `--list` — список job и шагов; `--dry-run` — вычислить охрану и напечатать команды без запуска. Вывод: `▶ <job>/<step>: <команда>`, `⏭ <job>/<step>: пропуск: <причина>`, `✔`/`✖`. Экспорт: `JOBS`, `makeContext(root, env)`, `planJob`, `runJob` (для тестов и W0.05). Скрипты `package.json`: `ci:local` = `node tools/ci/pipeline.mjs --all`, `ci:job` = `node tools/ci/pipeline.mjs --job`.

### 4.3 Нумерация миграций (`check-migrations.mjs`)

- Файлы верхнего уровня `backend/migrations/<control|tenant>/*.sql`; подкаталоги (`drafts/`) и не-`.sql` (`embed.go`, `README.md`) не проверяются.
- Имя — `^\d{4}_[a-z0-9][a-z0-9_]*\.sql$`, иначе `<файл>: имя не по шаблону NNNN_<slug>.sql`.
- Номер уникален в своей БД: `tenant: номер 0003 повторяется: 0003_a.sql, 0003_b.sql`.
- Номер внутри блока этапа: `tenant: 0075_x.sql вне блоков этапов (план §3.5)`.
- Без дыр: внутри блока номера идут подряд от его начала (`tenant: дыра — нет 0004 (блок этапа 1: 0003–0009)`); каждый блок до последнего занятого непуст (`tenant: блок этапа 0 (0001–0002) пуст, а занят блок этапа 1`). Неиспользованный хвост закрытого блока — не дыра (так резерв блоков §3.5 согласуется с «без дыр»).
- Блоки tenant: этап 0 — 0001–0002 (v0.2, W0.06), 1 — 0003–0009, 2 — 0010–0019, 4 — 0020–0039, 5 — 0040–0049, 6 — 0050–0059, 7 — 0060–0069. Control: этап 0 — 0001–0003, далее один открытый блок 0004–9999 (план: «0004+ по тому же принципу», границ нет — §10 п.3). Тест сверяет таблицу tenant с текстом §3.5 плана.
- Вывод при успехе: `migrations: control 3, tenant 2 — ок`. Нет `backend/migrations/` → `migrations: нет backend/migrations — пропуск`, exit 0.

### 4.4 «Право есть в каталоге» (`check-permissions.mjs`)

- Спецификация — все `*.yaml`/`*.yml` под `api/openapi/` (корень и `paths/<tag>.yaml`, `components/<tag>/` по PD-56), кроме каталогов `examples/`. Значение `x-permissions` — список строк (пустой допустим); иначе `<файл>:<строка>: x-permissions должен быть списком строк`.
- Каталог — `api/permissions.yaml`: ключи действий — ключи отображений `actions` на любой глубине (`modules.<m>.actions`, раздел на модуль по §3.5). Ключ, объявленный дважды, — ошибка. `prototype_renames` используется только для подсказки.

- Успех: `permissions: 118 ссылок в 3 файлах, каталог 97 ключей — ок`. Нет `api/openapi/` → пропуск, exit 0; есть спецификация, нет каталога → ошибка.
