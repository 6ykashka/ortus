## 1. Цель

В каждом прогоне `ci.yml` job `unit` даёт шесть аннотаций `X` (уровень `failure`, путь `.github`) на **проходящих** подтестах `tools/gen/codegen.test.mjs`:

- «operations.gen.go: строка операции с правами»;
- «problems.gen.go: код → статус и title»;
- «router.go: Servers с полем на тег; тег без реализации — 501».

Каждый даёт две аннотации: строки `# Subtest: …` и `ok N - …`.

**Причина (проверено на run `38790795342`, job `116615652760`, строки лога 3119–3132).** Шаг `actions/setup-go` регистрирует problem matcher `go` (`matchers.json` на закреплённом SHA `b7ad1dad…`):

```
^\s*(.+\.go):(?:(\d+):(\d+):)? (.*)
```

Шаблон рассчитан на ошибки компилятора и `go vet` вида `x_test.go:12:3: сообщение`. Пара «строка:колонка» в нём необязательна, поэтому под шаблон попадает и любая строка вывода с `<что-то>.go: <текст>`. Строку `t.Errorf` (`x_test.go:42: сообщение`, без колонки) шаблон, наоборот, не ловит: после `.go:` он ждёт либо пробел, либо обе цифры. Это и есть имена трёх подтестов: TAP печатает их в `# Subtest: <имя>` и `ok N - <имя>`. Раннер помечает такие строки `##[error]`, файл `operations.gen.go` в корне не находит и пишет аннотацию на `.github` с номером строки лога. stderr дочернего процесса и слово «error» в имени теста здесь ни при чём: аннотации дают только эти три имени.

Цель:

1. Переименовать три подтеста так, чтобы имя не совпадало с шаблоном matcher'а (`<файл>.go — …` вместо `<файл>.go: …`). Смысл и проверки тестов не меняются.
2. Не скрывать настоящие ошибки: matcher `go` остаётся. Он нужен для ошибок компиляции тестов Go (`[build failed]`) в той же job: `pnpm run test` → `test:go`, и в `integration`/`isolation`. Выключать его через `::remove-matcher` или фильтровать вывод нельзя.
3. Не допустить повторения. Добавить в `tools/ci/problem-matchers.mjs` копию matcher'ов, которые действуют в job, с источником (action и SHA), и симулятор раннера (`annotate(lines)`). Для локального воспроизведения добавить CLI: `… | node tools/ci/problem-matchers.mjs`. Добавить охранный тест: ни одно имя теста в репозитории не даёт аннотацию в выводе TAP и spec, а реальный прогон `tools/gen/codegen.test.mjs` даёт 0 аннотаций.
