## 2. Сводка

- Оператор платформы — отдельная персона `operator` (демо-панель → `Оператор платформы`), без `memberId` (`MEMBER.operator = null`, `Ортус CRM.dc.html:2297`). Стартовая страница `tenants` (`:2301`).
- Для оператора mock-адаптер отдаёт только `{ platform, operatorOnly: true, flags }` — бизнес-данных тенантов (`members`, `trips`…) в ответе нет (`ortus/api.js:186`). Все VM оператора читают только `db.platform`.
- Оболочка: тёмная шапка `#1C2A26` с подписью `Управление платформой` / `управление платформой`, без колокольчика, инициалы `ОП`, боковое меню с одной группой `Платформа` из 5 пунктов (`:2971–2974`, `:3032–3042`).
- У оператора нет AccessGate и баннеров (`gateVM` и `bannersVM` возвращают пусто, `:3056`, `:3086`). Нет уведомлений (`events = []`, `:3018`).
- Пять страниц: `tenants` «Организации», `usage` «Использование», `requests` «Заявки на тариф» (бейдж = число pending), `accounts` «Пользователи», `plans` «Тарифная сетка».
- Все опасные действия идут через единый диалог `opConfirm` (иконка `admin_panel_settings`, секция «Последствия», кнопки «Отмена» / подпись действия) и завершаются тостом `Готово · запись добавлена в журнал` (`:2796–2798`).
- Каждое действие пишет строку в `platform.audit` (`{ at, text, by: 'Оператор (демо)' }`), первые 6 строк видны на странице «Организации» (`:3566`).
- Данные платформы: 4 организации (`t-alta`, `t-lotos`, `t-remstroy`, `t-cargo`), тарифная сетка v1 (архив) и v2 (действует с 01.10.2026), 2 заявки (SR-12 pending, SR-9 approved), 13 именованных аккаунтов + 45 сгенерированных, 6 операторов (`ortus/mock-data.js:92–144`, `:21–39`).
- Демо-дата «сегодня» — 01.10.2026 (`usageVM`, `:3746`; `README.md:163`).
- Состояния тенанта в прототипе: `trial / active / restricted / suspended` (`models.js:151–156`); канон ТЗ (PLAT-02): `provisioning / trial / active / grace / read_only / suspended / closing / closed`; `restricted` ≈ `grace`/`read_only` (`docs/README.md:56`).
- Место занимает каждый участник со входом (`active` + `invited`); заблокированные, карточки без входа и операторы — бесплатно (`docs/17:30–41`, SQL view `tenant_seat_usage`).
- Цена = ступень по числу мест × срок (1/4/8/12 мес) со скидкой от помесячной цены; версия сетки неизменяема, новая — запланирована на дату, отменяется до неё (`docs/17:48–66`).
- Роли операторов `owner / admin / billing / support`; в прототипе роли НЕ ограничивают действия (демо-оператор — владелец; `docs/17:182`, `README.md:164`). Ограничения действуют только внутри «Ортус · Платформа» (`iAmOwner`).
- Создание организации (с владельцем и пакетом) и приостановка/возобновление «с причиной» есть в бэклоге (S1-01, S1-04) и OpenAPI (`TenantCreate`, `TenantPatch.reason`), но **в прототипе UI для них нет** — см. §6 «Открытые вопросы».

### 4.6 Состояния оболочки
- Загрузка (`:182–190`): `role="status" aria-label="Загрузка"`, 4 блока `background:#DFE4DC/#E6EAE3;animation:ox-pulse 1.4s`, текст `Загружаем рабочее пространство…`. Показывается при `!ready || loading || dbPersona !== persona` (`:2827–2829`). Триггер: смена персонажа, `Сбросить`.

## 7. Инварианты и правила

1. Оператор не получает бизнес-данных тенантов: ответ API для оператора содержит только `platform` (`api.js:186`); UI оператора не должен иметь доступа к `members/trips/…`.
2. Любое действие оператора записывается в `platform.audit`/`platform_audit` и завершается тостом `Готово · запись добавлена в журнал` (`:2797`; `docs/17:116`).
3. Отказ по заявке только с причиной — проверка и в UI (тост `Напишите причину отказа в поле комментария`), и в API (`Укажите причину отказа`), и в SQL (`check status<>'rejected' or decision_note…`).
4. Блокировка входа только с причиной — UI (`Укажите причину блокировки`), API, SQL (`accounts_lock_reason_chk`). Блокировка не меняет членства и места (`docs/17:39, 112`).
5. Подтверждение заявки меняет `seatsLimit` сразу; `trial/restricted → active`; `plan.version = priceBook.current`; `paidUntil` по сроку (`api.js:340–344`).
6. Одна открытая заявка на организацию (`api.js:319`, SQL `scr_one_pending_uq`).
7. Место занимает `active` + `invited`; `blocked/suspended/ended` и карточки без входа — нет (`api.js:57`, `docs/17:30–41`).
8. Операторы: ≥2 активных владельцев (понижение/отключение последнего → 409); себя менять/отключать нельзя; владельцем — только активный с 2FA; приглашать сразу владельцем нельзя (422); почта только `@ortus.example` и не совпадает с аккаунтом клиента (`api.js:382–407`, `docs/17:176–184`).
9. В прототипе роли операторов не ограничивают действия вне «Ортус · Платформа» (`README.md:164`); внутри — только `iAmOwner` управляет операторами.
10. Тарифная сетка: версия неизменяема; одновременно одна запланированная; при публикации `cur.to = 'до {from}'`; отмена возвращает `to=null`; ступени строго возрастают по местам и цене; безлимит только последним; скидка 0–49% (`api.js:348–374`, `docs/17:60–66`).
11. Расчёт: `month = round(tier.month × (1 − off/100))`, `total = month × months`, `save = (tier.month − month) × months` (`:3572–3577`).
12. Пороги сигналов «Использование»: места ≥85% / =100%, хранилище ≥75% / ≥95%, trial ≤14 дней, неактивность >7 дней; «сегодня» = 01.10.2026 (`:3746–3770`; `docs/17:195–205`).
13. Полосы: `#A13A33` при 100%, `#B7791F` при ≥85% (`usageVM`), >85% (`opVM` хранилище) или >80% (`opVM` места).
14. Карточка организации всегда показывает кнопку продления trial (даже для `active`) — повторить как в прототипе или см. открытый вопрос.
15. Escape закрывает диалог; клик по подложке закрывает; при ошибке API диалог остаётся открытым, тост `error`.
16. При `Нет связи` все команды отклоняются с `Нет связи с сервером. Операция не выполнена.` (warn-тост), в шапке чип `Нет связи`.
17. Доступность: все списки-выборы — `button[aria-pressed]`, realm-список — `button[aria-current]`, группы фильтров — `role="group" aria-label=…`, диалог — `role="dialog" aria-modal aria-labelledby="dlg-title"`, предупреждения — `role="status"`/`role="alert"`, тост — `aria-live="polite"`.
18. Минимальная высота интерактивных элементов 44px (основные), 36px (фильтры/вторичные), 32px (внутри таблицы черновика).

## 9. Открытые вопросы

1. **Создание организации** (владелец + пакет; S1-01, PLAT-01, `TenantCreate {name, ownerEmail, timeZone, planKey}`) — ⚠ в прототипе нет ни кнопки, ни диалога, ни метода адаптера. Нужен дизайн: где кнопка (страница «Организации»), какие поля, какой тост.
2. **Причина** для приостановки/возобновления/продления (S1-04, PLAT-02, `TenantPatch.reason`, `PlatformSubscriptionUpdate.reason` 5–507) — ⚠ в диалогах прототипа поля нет. Решить: добавить обязательное поле в `opConfirm` для этих действий (аналогично блокировке аккаунта).
3. **Состояния тенанта**: прототип `restricted`, API/SQL `grace|read_only|suspended|…`, OpenAPI `Tenant.status` только `provisioning|active|suspended|closing`, а `Subscription.status` `trialing|active|past_due|grace|read_only|cancelled`. Нужна единая карта статус → чип (`TENANT_STATE` имеет 4 записи).
4. Кнопка `Продлить пробный период на 14 дней` показывается и для `active`/`suspended` организаций; `extendTrial` переводит статус в `trial` (`api.js:254`) — для действующей подписки это ломает модель. Уточнить правило показа.
5. `extendTrial`: `trialEnds` для не-`t-alta` становится строкой `через N дн.` (заглушка); в реализации нужна настоящая дата.
6. Цена в карточке заявки считается по текущей версии сетки, а не по `price_version` заявки (`requestsVM`, `ver = tierList(db)`); SQL хранит `quoted_minor` на момент заявки. Канон — зафиксированная котировка.
7. `Срок оплаты` → `4 месяцев` / `8 месяцев` (нет склонения); в карточке организации используется `4 мес`. Решить формат.
8. Пороги полос различаются: `opVM` хранилище `>85%`, места `>80%`; `usageVM` `>=85%`. Унифицировать.
9. Роли операторов не влияют на права вне «Ортус · Платформа» (`README.md:164`); в реализации — применять `platform.*` ключи (`docs/17:120–130`), включая скрытие/блокировку действий для `support`/`billing`.
10. Временный доступ поддержки (`support_grants`, ≤60 мин, с согласия владельца) упомянут в правилах и SQL, но UI нет — ⚠ не найдено в источниках.
11. `tenants` для «Пользователей» и «Использования» показывает `brand.short` первую букву; `Карточка организации` и попап используют только `name`. Логотип (`brand.mark`) показывается только в списке «Организации».
12. Удалённая в новой версии ступень и продление подписки на неё — B-07 (`docs/17:78, 215`).
13. Пустое состояние «Требуют внимания» и пустые списки организаций в seed недостижимы без цепочки действий — для TDD нужны фикстуры с пустыми данными.
14. `data-screen-label` у `pg.tenants` отсутствует (у остальных есть); для скриншот-тестов добавить `Оператор · организации` (⚠ значение придумано — не из источников).
