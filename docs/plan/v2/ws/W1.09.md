## 1. Цель

1. **Сессия загрузки (S1-20, FILE-01/02)** — `initiateUpload` → presigned PUT → `completeUpload` → проверка → `ready`/`rejected`:
   - `initiateUpload`: проверка тела (размер ≤ 20 МиБ → иначе 413 `payload_too_large`; MIME из списка назначения → иначе 422 `validation_failed`), проверка родителя (`owner` существует в тенанте, виден актору, назначение допустимо для вида родителя; невидимый или несуществующий → 404), право `files.upload` на родителе (`permit` с ресурсом родителя), **резерв квоты условным `UPDATE files.usage`** (0 строк → 409 `quota_exceeded`, параллельные загрузки не превышают квоту — PLAT-07, A-10), строки `files.objects` (`reserved`), `files.upload_sessions` (`issued`), `files.quota_ledger` (`reserve`) и событие истечения сессии в outbox — одной транзакцией; ответ 201 `UploadTicket` с presigned PUT на 15 минут в карантинное пространство (`quarantine/<tenant>/<file>`, имя объекта формирует сервер — FILE-01);
   - `getUploadSession`: только своя сессия (чужая → 404); просроченная закрывается при чтении (`expired`, резерв освобождён); `issued` → `uploaded`, если объект уже в карантине;
   - `completeUpload`: своя живая сессия; `sha256` тела совпадает с заявленным; объект есть в карантине, размер равен заявленному, `Content-Type` — заявленный, SHA-256 содержимого совпадает (иначе 422; объекта нет → 409 `invalid_transition`); затем одной транзакцией: сессия `completed`, файл `scanning` (`quarantined` в API), резерв → занято (`files.usage`, `files.quota_ledger` `commit`), событие `files.file.uploaded.v1`; ответ 202 `File`. Повтор после завершения → 409 `invalid_transition` (один эффект — AC-07);
   - `abortUpload`: своя сессия; `issued`/`uploaded` → `aborted`, резерв освобождён, объект карантина удалён; `completed` → 409; `expired`/`aborted` → 204;
   - **проверка** (worker, событие `files.file.uploaded.v1`): содержимое из карантина → `Scanner` (сигнатура EICAR → `malware_detected`; фактический MIME не совпадает с заявленным → `mime_mismatch`); чистый файл копируется в постоянное пространство (`files/<tenant>/<file>`) и становится `ready`; отклонённый — `rejected`, его байты освобождаются (`release`), объект карантина удаляется; события `files.file.ready.v1` / `files.file.rejected.v1`. Повторная доставка — без эффекта;
   - **истечение**: событие `files.upload.deadline_reached.v1` с `available_at = session_expires_at` закрывает незавершённую сессию (`expired`, резерв освобождён) — уборщик без отдельного цикла.
2. **Скачивание с проверкой родителя (S1-21, FILE-03)**: `getFile`, `getFileDownload`, `listFiles`:
   - родитель файла невидим актору (нет действия чтения родителя на его ресурсе) → файл «не существует» (404, в списке отсутствует, родитель не раскрывается); родитель виден, но нет `files.read` в его области → 403 `forbidden_action`;
   - `getFileDownload`: только `ready` (иначе 409 `photo_not_ready`), presigned GET на 60 секунд (`Content-Disposition` с именем файла); проверка — на каждом запросе, без кеша (AC-10: отзыв роли → следующая ссылка не выдаётся);
   - `listFiles`: фильтр `files.read` (`scopeQuery`) **и** чтения родителя (предикат действия чтения вида родителя) — до пагинации; новые сначала; курсор непрозрачный (`created_at`, `id`); фильтры `status`, `purpose`; `ownerTitle` из родителя; файлы закрытых и просроченных сессий не показываются.
3. **Данные экрана «Хранилище» (S1-22, PLAT-06/08)** — тег `Billing`:
   - `getStorageUsage`: квота (`files.usage.limit_bytes`), занято = файлы (`committed_bytes`) + оценка БД (`pg_database_size`), резерв загрузок, корзины `attachments`, `database`, `versions`, `trash`, `reserved_uploads`, `writeStatus` (`blocked`, если занято + резерв ≥ квоты), `consistency: estimated`;
   - `getStorageBreakdown`: четыре группы эталона (`photos` — `inspection`, `repair_evidence`; `documents`; `attachments` — `knowledge_attachment`, `form_attachment`; `other` — база, версии, `expense_receipt`) и модули-владельцы (по `owner.moduleKey`, `core` — база); каждая разбивка в сумме = `committedBytes`;
   - `requestStorageChange`: `quote` — расчёт 10 ₽ за ГиБ в месяц (как MSW W0.13), `quoteId` действует 1 час; `commit` — только с действующим `acceptedQuoteId` того же объёма; новая квота ниже занятого + резерва → 409 `downgrade_below_usage` (текст как в примере); применение — сразу (Q-12), аудит `billing.storage.change`.
4. **Платформа хранилища** `platform/storage`: клиент S3 на stdlib (подпись AWS SigV4: заголовки и presigned URL, path-style для MinIO), `Store` (presign PUT/GET, `Stat`, `Open`, `Copy`, `Delete`, `EnsureBucket`), `Mem` (in-memory для unit-тестов), конфигурация из env (`S3_*`), `miniotest` — MinIO на testcontainers с образом стенда.

## 4. Контракты

Контракт не меняется (входы — 0.3.0 и 0.4.0-stage1 в `main`). Операции: `Files` — `initiateUpload`, `getUploadSession`, `completeUpload`, `abortUpload`, `getFile`, `getFileDownload`, `listFiles`; `Billing` — `getStorageUsage`, `getStorageBreakdown`, `requestStorageChange` (`getTenantSubscription`, `requestSubscriptionChange` — W1.08).

- `files.Service` (+ `Server` — `filesapi.StrictServerInterface`; `Billing` — `billingapi.StrictServerInterface`, базовый сервер тега: операции подписки отвечают 501, их накладывает W1.08 — `subshttp.NewBillingServer(files.Billing{…}, subs)`, возврат 1).
- `files.ParentKind` — родитель вложений: модуль и вид (`ObjectRef`), действие чтения родителя, допустимые назначения, SQL строки области (`unit_id`, `project_id`, `person_a`, `person_b`, `title`). `files.Parents` — явный реестр (без `init()`); `files.FleetParents()` — брони, рейсы, машины, осмотры, расходы пилота (таблицы tenant 0002; модуль fleet заберёт их в этапе 2).

- `files.Register(*events.Registry, Worker)` — обработчики `files.file.uploaded.v1` (проверка) и `files.upload.deadline_reached.v1` (истечение) для `cmd/worker`.
