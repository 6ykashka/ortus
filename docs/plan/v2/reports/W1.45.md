## Причина

Run `38790795342`, job `unit` (`116615652760`). `gh api repos/6ykashka/ortus/check-runs/116615652760/annotations` возвращает 6 аннотаций: `annotation_level: failure`, `path: .github`, `start_line` 2750/2751, 2756/2757, 2762/2763. В логе job это строки 3119–3132:

```
##[error]    # Subtest: operations.gen.go: строка операции с правами
##[error]    ok 2 - operations.gen.go: строка операции с правами
##[error]    # Subtest: problems.gen.go: код → статус и title
##[error]    ok 3 - problems.gen.go: код → статус и title
##[error]    # Subtest: router.go: Servers с полем на тег; тег без реализации — 501
##[error]    ok 4 - router.go: Servers с полем на тег; тег без реализации — 501
```

Шаг `actions/setup-go@b7ad1dad…` (v7.0.0) регистрирует problem matcher `go` (`matchers.json`):

```
^\s*(.+\.go):(?:(\d+):(\d+):)? (.*)
```

Пара «строка:колонка» в шаблоне необязательна. Поэтому под него попадает любая строка вывода с `<что-то>.go: <текст>`, в том числе имена трёх подтестов `tools/gen/codegen.test.mjs`. TAP печатает каждое имя дважды: в `# Subtest:` и в `ok N -`, отсюда 6 аннотаций. Раннер не находит файл и пишет аннотацию на `.github` с номером строки лога.

stderr дочернего процесса и слово «error» в имени теста здесь ни при чём. Остальные matcher'ы job (`tsc`, `eslint-stylish`, `eslint-compact` из `setup-node@82076278…`) этих строк не трогают. В других job того же run аннотаций 0.

Теперь T-2 проверяет ошибку компиляции, а для `t.Errorf` фиксирует, что аннотации нет. Во время green нашёлся и собственный тест «…без «.go: » аннотаций не дают»: охрана T-4 его поймала, имя переписано.
