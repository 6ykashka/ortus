# Показ заказчику 18.10.2026, 13:00 — сценарий

Показ идёт на этом ПК, на локальном стенде. Длительность 20–25 минут. Цель показа — путь водителя на стенде: бронь машины → осмотр с пятью фото → выезд → расходы → сдача смены → смена у менеджера на приёмке. Перед ним коротко показываем готовую платформу этапа 1, после него — изоляцию организаций и дорожную карту этапов 4–7 в эталонном прототипе.

Подготовил W2.90. Проверено 18.10 в 01:00–01:40 на слоте 12: e2e `journeys/stage2/driver-shift.spec.ts` проходит на стенде и в mock, ручная проходка на 390 и 1440 сделана на стенде и в mock. Снимки лежат в `.claude/tmp/W2.90/shots`.

### Стенд одной командой

Финальный шаг «Стенд показа» делает интегратор. Команда из корня репозитория:

```powershell
$env:COREPACK_ENABLE_DOWNLOAD_PROMPT='0'
node docs/demo/demo-stand.mjs --slot 0 --serve --env .env
```

Скрипт выполняет по порядку:

1. compose слота 0 (postgres, MinIO, Mailpit, OTel) → бакет → `migrate`;
2. `seed demo` — базовый сид и пресет `logistics-ready`: «Логистика» в «Альте» подключена, Марина Котова — «Менеджер логистики» в «Север Логистик»;
3. cmd/api (`APP_ENV=e2e`, dev-вход) и cmd/worker;
4. Vite в режиме e2e с адаптером http.

Остановить — `Ctrl+C`. Стенд при этом остаётся; снять его — `node deploy/compose/stand.mjs down -v --env .env`. Без `--env` скрипт создаёт свой env-файл в `.claude/tmp/demo-stand/s0/`. Логи cmd/api, cmd/worker и Vite лежат в `.claude/tmp/demo-stand/s<слот>/`.

Если стенд поднимают вручную, нужны те же шаги. Сид показа — `node deploy/compose/stand.mjs seed demo`; простой `seed` оставляет «Логистику» выключенной.

Эталон: `corepack pnpm run reference` (порт 4173). Запасной mock — в отдельном окне PowerShell:

```powershell
$env:VITE_ADAPTER='mock'; node frontend/apps/web/scripts/dev.mjs --mode e2e --host 127.0.0.1 --port 5180 --strictPort
```

### Перед репетицией (12:00) и перед показом (12:40)

1. **Пересоздать стенд.** Путь водителя одноразовый: после сдачи Р-208 ждёт приёмки, а приёмки на сервере нет. Окна рейсов считаются от запуска сида: Р-208 начинается за час до часа сида и длится 4 часа, Р-211 начинается через 5 часов после Р-208. Поэтому после репетиции: `Ctrl+C`, `node deploy/compose/stand.mjs down -v --env .env`, затем снова `demo-stand.mjs … --serve`. Сид в 12:40 даёт Р-208 с 11:00 до 15:00.
2. **Самопроверка на своём слоте** (около 3 минут, слот 0 не трогает): `node docs/demo/demo-stand.mjs --slot 12 --e2e`. Ожидаемый итог — `demo-stand: @stand пройдено 4, пропущено 5, упало 0` и `✔ demo-stand: готово`. Пять пропусков ожидаемы: путь водителя идёт только в проекте 390, а приёмка помечена `fixme` до W2.06.
3. **Фото.** Положить 6 любых фото (JPEG или PNG) в папку, например `C:\demo\photos`: пять для осмотра и одно для чека. Камера ПК не нужна: слот фото открывает выбор файла.
4. **Окна браузера** (Chrome):
   - окно A — http://127.0.0.1:5200, ширина 1440: владелец, логист, оператор, «Лотос»;
   - окно B — http://localhost:5200, DevTools → «Toggle device toolbar» → 390 × 844: водитель.
   - Разные хосты дают разные cookie, поэтому водитель и логист работают одновременно.
5. Открыть вкладку эталона http://127.0.0.1:4173/Ортус%20CRM.dc.html и вкладку запасного mock.

## Запасной путь (mock)

- **Страницы без пути водителя:** http://127.0.0.1:5180/?persona=owner. Состояние mock живёт во вкладке. «Логистику» владелец включает на «Модули и место» → «Подключить».
- **Путь водителя и приёмка:** вручную в mock фото не загружаются. Браузер не обслуживает адрес хранилища mock, это блокер W2.22, патч адаптера у интегратора. Поэтому путь показываем прогоном e2e в видимом браузере (около 20 с, водитель → логист → «Смена принята»):

  ```powershell
  $env:ORTUS_SLOT='13'; $env:E2E_OWN_REFERENCE='1'; $env:COREPACK_ENABLE_DOWNLOAD_PROMPT='0'
  corepack pnpm --filter @ortus/web exec playwright test e2e/journeys/stage2/driver-shift.spec.ts --grep "@mock" --project=mobile-390 --headed
  ```

  Ещё один запасной вариант — эталонный прототип: там весь путь, включая приёмку.
