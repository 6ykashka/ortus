## 4. Контракты (публикуются; менять после слияния — через интегратора)

### 4.1 `profile.json`

`{ version, decision: "D-08", status, params: { <ключ>: { value, unit, source, status: "assumption" | "source", assumption?: "A-NN", note } }, targets: { readP95Ms: 500, writeP95Ms: 800, errorRate, checksRate }, stages: { smoke, pilot, stress } }`. Ключи параметров — §6 п.1. Изменение числа = правка `profile.json` и таблицы в `load-profile.md` в одном коммите (тест согласованности).

### 4.2 Теги и пороги k6

Каждый запрос тегируется `op` (operationId OpenAPI), `kind` (`read` | `write` | `transfer` | `auth`), `tenant` (`pilot` | `noisy`). Пороги:

- `http_req_duration{tenant:pilot,kind:read}`: `p(95)<500`;
- `http_req_duration{tenant:pilot,kind:write}`: `p(95)<800`;
- `http_req_failed{tenant:pilot}`: `rate<errorRate`;
- `checks{tenant:pilot}`: `rate>checksRate`.

`transfer` (PUT по presigned URL) и `auth` (вход) в пороги не входят (NFR-03: «без transfer файла»). `queryDataset` — POST только для чтения, `kind: read`. Запросы «шумного» тенанта под пороги не попадают: проверяется, что пилот держит цели, пока шумит соседний тенант.

### 4.3 Переменные окружения k6

`BASE_URL` (по умолчанию `http://127.0.0.1:8108`; только local и compose — PD-18, Q-102), `ORIGIN` (= `BASE_URL`), `LOAD_STAGE` (`smoke` | `pilot` | `stress`), `DEV_LOGIN_PATH` (по умолчанию `/api/v1/dev/login`), `CSRF_COOKIE` (`ortus_csrf`), персонажи `load-pilot-driver-NNN`, `load-pilot-manager-NN`, `load-noisy-owner-01`. Вход через dev-провайдер — **допущение**: точный путь и cookie задаёт W0.09/W1.03, W3.01 поправит одну константу.

### 4.4 Образ k6

`grafana/k6:2.3.0@sha256:9c2dee7f8ed74d317e4027c06a10f169b625638189de8d4555d0b3486a5aeb34` (релиз 21.09.2026). Новых npm/Go-зависимостей нет.

## 6. Тесты первыми

`node:test` без зависимостей: `node --test "backend/test/load/test/*.test.mjs"`.

1. `model.test.mjs` — модель:
   - `profile.json`: все параметры §1 есть, у каждого `value > 0`, `unit`, `source`, `status`; у `assumption` есть `A-NN`; цели 500/800; стадии `smoke`, `pilot`, `stress`;
   - `OPS`: 20 операций §3 п.5, метод и путь совпадают с OpenAPI 0.1; `kind` (GET и `queryDataset` → `read`); `idempotent` и `ifMatch` совпадают с OpenAPI (`returnTrip`, `reviewTrip`, `reviewTripExpense` — `If-Match`);
   - `pathFor`: подставляет параметры, кодирует, бросает при пропуске; query-строка;
   - `idempotencyKey`: 16–128 символов, `^[A-Za-z0-9._:-]+$`, уникален по (сценарий, VU, итерация, шаг);
   - тела запросов: обязательные поля схем `ReservationCreate`, `UploadCreate`, `InspectionCreate`, `TripStart`, `TripReturn`, `TripExpenseCreate`, `TripReview`, `ExpenseReview`, `DatasetQuery`; время — UTC с `Z`; деньги — `amountMinor` целое; `Quantity` — строка;
   - `deriveRates`: смены в минуту пика `= vehicles × peakDayUtilization × departureWindowShare / departureWindowMinutes × scale`; фото на смену `= 5 + 5 + receipts = 12` (PLAT-09); объём фото в месяц ≈ 28,8 ГБ при значениях PLAT-09;
   - `requestsPerShift`: число запросов смены водителя по видам (read/write/transfer) согласовано со сценарием;
   - `buildOptions`: для каждой стадии сценарии `driverShift`, `managerShift`, `noisyExport`, `noisyUploads` с `exec`, корректными executor’ами и VU; smoke — по одной итерации; пороги §4.2; неизвестная стадия → ошибка.
2. `doc.test.mjs` — `docs/plan/v2/load-profile.md`: таблица параметров содержит каждый ключ `profile.json` с тем же значением; таблица производных совпадает с `deriveRates`/`requestsPerShift` (округление); упомянуты D-08, PLAT-09, NFR-03, цели 500/800 мс, «шумный» тенант, образ k6 с digest.
3. `check-k6.mjs` (Docker) — red до `main.js`: `k6 inspect` для `smoke`/`pilot`/`stress` возвращает JSON с `scenarios` и `thresholds`; smoke против `fake-api.mjs` на `:8108` проходит все `check` и пороги.
