## Осталось fixme / открытые вопросы

`@stand-spec` `гость: страница направления → обращение → личная ссылка → оценка решения` — `test.fixme`: backend портала (W7.31, операции `PublicService`) в `main` не влит; внешняя причина, не «на потом». Остальных `fixme`/`skip` нет.

Вопросы владельцу (в `docs/plan/decisions.md` не пишу — файл не мой), значения по умолчанию, по которым сделано:

- **Q-W7.33-1.** Оценка визита (экран 2) не имеет операции контракта. По умолчанию — `submitPublicServiceRequest` с `workToken`: 4–5 — тип «Спасибо …», 1–3 — «Жалоба»; причины, комментарий и «Свяжитесь со мной» уходят в текст обращения. Вариант «без просьбы связаться — в очередь „Низкие оценки“ без срока» (подпись под макетом) требует операции `ratePublicVisit` или ответа публичной формы (`submitPublicForm`, W4.21) — тогда W7.00/W7.31 добавляют операцию.
- **Q-W7.33-2.** Вложения. Билет загрузки (`initiatePublicServiceUpload`) выдаётся по токену обращения, поэтому на первой форме фото нельзя — только после отправки, в поле «Написать» на странице обращения. По умолчанию так; если нужно на первой форме — билет по `slug` (контракт).
- **Q-W7.33-3.** Карточка «Ваш визит · 1 октября, 11:30 · SPA-ритуал» и подписи под строками типов («Рассмотрим за 10 дней») — в `PublicServicePage` нет полей (`hint` у типа есть в схеме, но сценарный сервер его не отдаёт). По умолчанию не показываем; нужен ответ по `workToken` (метка работы) и `hint` у типов.
- **Q-W7.33-4.** «Мои обращения · N» хранятся в `localStorage` браузера клиента (операции `listPublicMyServiceRequests` в контракте нет). По умолчанию так, до 20 на направление; вход «телефон + код из SMS» — после SMS-провайдера (Q-W4.00-service-9).
- **Q-W7.33-5.** Ссылка из SMS `alta.ortus.ru/m/7KX2` (короткая) и маршруты `/s/{slug}`, `/r/{token}` — адреса приложения; короткий домен и редирект на них — W7.37/развёртывание.
- **Q-W7.33-6.** Блок портала в кабинете заказчика ОТД (зависит от W6.24) и вход по коду/бот — не вошли (М-объём по разбору); страница направления ОТД и ГРЗ работает теми же компонентами (группы из типов направления: «Гарантийный случай» — `warranty`, «Повреждение или недостача груза» — `cargo`), условие «гарантия до …» — на стороне сервера.
